# 你的数据

## 文件夹里有什么

空间文件夹里装着空间的一切：

- `space.sqlite`：文档、表格、对话、agent 会话及其历史、人、组和机器；
- `objects/`：大于 256 KB 的文件；
- `tls/`：自签证书和它的私钥；
- `web-push/`：发浏览器通知用的密钥；
- `logs/`：每次模型调用一行：token 数、耗时、失败。

文档是 markdown，表是 SQLite，都在一个你可以自己打开的数据库里。

每次模型调用也是 `inferences` 表里的一行：谁发的、哪个模型、输入、缓存和输出的 token、耗时、错误。和其他表一样查，比如 `wuhu query "SELECT model, sum(output) FROM inferences GROUP BY model"`。

## 文件夹外面有什么

有几样东西故意放在跑服务器那个用户的家目录里，这样复制空间的时候不会把它们带上：

- `~/.wuhu/credentials/<space-id>.json`：你的模型账号和 provider 的 key；
- `~/.wuhu/secrets/<space-id>/`：每个组的密钥；
- 每台机器上的 `~/.wuhu/machine/`：它的密钥和 runner 设置。

## 备份

停掉服务器再复制文件夹。或者在它跑着的时候对整个文件夹做文件系统快照（APFS、ZFS、Btrfs）。别对着正在运行的服务器文件夹一个文件一个文件地复制：数据库正写到一半，复制出来的可能打不开。

上面那些凭证和密钥另外单独备份，这样以后不用重新登录一遍就能拿回来。

## 换一台主机

1. 停掉服务器。
2. 复制空间文件夹，外加那个空间的 `~/.wuhu/credentials` 和 `~/.wuhu/secrets`。
3. 在新主机上用同样的 `--origin` 启动，把 DNS 指过去。

保留 `tls/`，设备和 runner 就继续信任它。地址换了的话，每台设备都要重新发一条邀请。

同一个空间永远不要同时跑两份。它们会共用一个身份，然后各走各的。

## 升级

升级之前先备份。如果新版本需要一次它自己跑不了的数据库迁移，服务器会拒绝启动，并把那次迁移的名字说出来。

## 还有谁能看到

- **你的模型厂商**能看到你的 agent 发给它的东西：对话，以及它们读进对话里的内容。
- **搜索、图片和转写 provider**，如果你配了的话，能看到发给它们的查询、提示词和音频。
- **Wuhu 的通知中转**，用于 iPhone、iPad 和 Mac 上的通知。Apple 只替 App 的开发者投递推送，所以你的服务器把每条通知交给我们的中转 `notifications.wuhu.ai`，它再转给 Apple：标题、发送者、消息预览，以及用来路由的 id。
- **你浏览器的推送服务**，用于网页通知，直接由你的服务器发出。
- **下载**：`wuhu upgrade` 从 wuhu.ai 取构建。
- **没有别人**。没有 Wuhu 账号，也没有空间的云端副本。
