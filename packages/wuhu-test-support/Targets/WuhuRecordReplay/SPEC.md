# WuhuRecordReplay

`withRecording` injects HTTP fetch and the WebSocket connector for the duration of a passing asynchronous test body. Replay is offline and is the default. `RECORDING=1` records every scope; another nonempty value records scopes whose names start with that value. Fixtures live in `Recordings/<name>` beside the calling file, or in `RECORDINGS_ROOT/<name>` when recording. Fixtures are replaced only after the body succeeds; a thrown body leaves existing fixtures untouched.

HTTP fixtures remain numbered `.request.json` and `.output.sse` pairs. Matching, ignored body fields, UUID comparison and exact embedded argument strings retain their existing behavior.

## WebSocket effects

Recording wraps the connector captured from the surrounding dependency scope. Install `WebSocketConnector.live` explicitly to record network effects, or inject a fake connector for offline recording tests. Replay never calls that connector. Connections belong to the recording scope: scope teardown aborts any surviving socket, cancels and joins its receive pump before persistence.

Each numbered `.websocket.json` file is one physical connection, including a redacted handshake (URL, headers, limits, TLS policy, timeouts), upgrade headers or typed dial failure, and an ordered two-way application-message journal. Reconnects are separate files. Text and binary retain their opcode; close code/reason, send/close failure, receive failure, EOF, client abort and scope-owned abort are distinct journal entries. Client action positions are reserved before invoking the real effect, and their recorded outcome is updated when that effect returns, preserving causality when a fast peer responds before send returns. Ping/pong is transport-internal and is not recorded.

Replay claims independent sockets by handshake plus first client action, not dial order. Pre-send inbound events are supported when the handshake uniquely identifies a fixture; mixed dial outcomes or ambiguous pre-send events fail rather than selecting a socket by arrival order. Accepted upgrade headers must agree between unclaimed matching handshakes because they are returned before the first send. Each expected client send gates subsequent server events. Wrong opcode, payload, order, close or missing client action fails replay. Unclaimed fixtures or unconsumed journals fail scope completion, including scopes that never open a socket. Replay performs the same scope-owned teardown as recording; it never consumes an omitted explicit client abort, close or send. Request fields excluded by `matchIgnoringBodyFields` apply only to HTTP, never to WebSocket creates.

Response ids and call ids use separate, connection-scoped bijective renaming maps. Server identities reserve their names before later client references are checked, so `previous_response_id` and cached tool-result `call_id` are never ignored. IDs established in a full client request are projected into replayed server events consistently. UUIDs in ordinary string fields are also compared by a connection-scoped bijection; embedded `arguments` strings are byte-exact, including JSON whitespace. A new connection cannot borrow aliases from an earlier one. Reference-only positions (`previous_response_id`, `response_id`, `call_id` except in an explicitly typed `function_call`, `item_id` and `item_reference.id`) must match literally or use an identity established earlier on that connection; they never invent aliases on first mention. Client full-request item identities may establish aliases. Output-item ids (`fc_…`) use a separate item namespace with the same establishment/reference rule. At reconnect, an unestablished continuation reference therefore matches literally, and a typo fails even if an earlier connection emitted the intended response/call id.

Sensitive request values, known authentication/account/session/cookie/routing fields, their echoed values, individual quoted or unquoted cookie credentials and bearer-token material learned during or after the handshake are redacted before collection. Response and metadata headers are allowlisted (protocol, content type/date, retry, rate-limit and named Codex quota headers); other values are redacted, including subsequent echoes into client messages. Refusal bodies, binary messages and error diagnostics receive the same value redaction. Redaction scans original bytes once and never revisits replacement markers. URL credentials and arbitrary custom TLS configurations are rejected by the wrapper; system-default TLS and pinned fingerprints are supported. Live fixtures still contain prompt/model content and require deliberate trivial inputs and review before committing.

## Offline contract checks

`bazel test //packages/wuhu-test-support:WuhuRecordReplayTests` covers ordered two-turn replay, a recorded round trip, reversed socket arrival, exact arguments, bijective and generation-local IDs, incorrect previous/call references, typed refusals and send/receive failures, close codes, binary messages, redaction, untyped/unknown output-item references, array reference propagation, and reconnect typos that fail verification. Existing WuhuAI HTTP/SSE fixture tests remain unchanged.
