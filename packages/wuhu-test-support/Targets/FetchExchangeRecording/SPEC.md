# FetchExchangeRecording

Generic bounded one-shot Fetch exchange recording/replay, separate from SSE and without machine concepts. Each exchange stores the complete request method/URL/headers/body and response status/headers/body, including HTTP failures. Effects are explicit typed-name input/output records. Replay requires exact request identity and effect equality, never dispatches live work, and exposes completion/exhaustion/mismatch errors. Body and exchange/effect counts are capped; headers have a 16 KiB aggregate cap, and each encoded effect shares the body cap. Sensitive request headers, Authorization, Proxy-Authorization, Cookie, Set-Cookie and supervisor nonce headers are refused rather than recorded; named credential headers are also rejected in live/replayed responses. Callers must use synthetic safe bodies: this support module cannot discover arbitrary secrets in payloads. The recorder is intended for a sequential contract driver; concurrent exchange ordering is completion-order and is not promised reproducible. Live transport failures are thrown, not fictional HTTP responses.
