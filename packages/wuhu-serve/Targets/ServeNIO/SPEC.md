# ServeNIO WebSocket transport

Normal WebSocket `close()` writes a close frame before closing the channel. `abort()` closes the NIO channel directly, without a preceding write or flush. It ends inbound and fails pending writes even when the peer is not reading, so callers do not need to await a graceful close under backpressure.

## Request-body cancellation and early close

Cancelling a pending inbound body read finishes its buffer with CancellationError and resumes its waiter, including when cancellation races waiter registration. A cancelled or failed body is never drained for HTTP/1 keep-alive reuse. A handler response containing the Connection: close token skips the unread body drain, writes its response immediately and closes the connection. This permits bounded upload refusals without waiting for a peer to finish a trickling body; ordinary keep-alive responses still drain healthy unread bodies within the existing byte/inactivity bounds.

## Peer disconnect

Closing the peer channel cancels its retained connection task, including when the channel closes before task registration. An HTTP/1 response committed to Connection: close discards further inbound request parts before removing the pipelining read gate, so Darwin can observe peer EOF while an idle response is unfinished. This does not alter ordinary keep-alive pipelining. Buffered or later requests on that closing connection never dispatch effects. An idle producer on a closing connection receives cancellation without requiring another emitted chunk or server shutdown.

## Bounded binary upgrade

The opt-in Serve bounded upgrade requires the requested subprotocol to be offered and emits it on the upgrade response. Extension offers are not selected; unsupported RSV bits are refused after upgrade. Limits validate before upgrade. Reassembled binary messages default to 64 KiB, and queued receive bytes default to 1 MiB. Each queued message is charged the larger of its payload size and 1024 bytes until receive consumes it. The queue therefore holds at most floor(bufferedReceiveBytes / 1024) messages (1024 at the default 1 MiB budget, 65,536 at 64 MiB), including empty and one-byte messages; a budget below 1024 bytes cannot queue a message. This is a payload/queue-accounting budget, not an exact allocator-memory ceiling. Each received frame is bounded by the existing ServeOptions maximumWebSocketFrameBytes decoder cap and the selected bounded message cap. Fragment accumulation has its own total check. No queued bytes are silently dropped: overflow terminates receive with `webSocketLimitExceeded` and aborts the connection. Unexpected continuation, text messages, missing client masking and RSV bits fail explicitly. Ping/pong stays transport-internal. Pong writes require channel writability and have a fixed cap of 16 outstanding writes; completion releases a slot, and saturation fails receive with `capacityExceeded` and aborts instead of queuing another pong. Write failure aborts with `connectionClosed`. Pending send/read release when abort or server shutdown closes the channel; bounded session tasks are retained and cancelled by the server's existing connection lifecycle. Legacy WebSocket upgrades still use the previous bridge unchanged.

The bounded transport advertises maxMessageBytes as the minimum of BoundedWebSocketLimits.messageBytes and ServeOptions.maximumWebSocketFrameBytes, and uses that cap for sends. Tunnel rejects head/chunk configurations that cannot fit this effective decoder cap before application traffic begins.

## Shutdown completion

Shutdown closes the listener first, so a connection arriving from then on reaches another process. It then sends HTTP/2 GOAWAY (last stream ID the largest, no error) on every HTTP/2 connection, and waits for the requests already running to write their responses, for at most the drain's bound (`ServeOptions.gracefulDrain`: its timeout, waited out on the caller's own wait, so a test drives the boundary; unset waits without a bound); an HTTP/1.1 response written during the drain carries `Connection: close`, and its connection closes after it. Past the bound, or as soon as they have all answered, it closes what would never end on its own — WebSockets, responses whose body streams (`Body.endsByItself` false), and connections with no request in flight — cancelling their connection tasks and draining them before invoking onDidShutdown exactly once. A handler that never returns holds the drain only until the bound, and a cancelled bound leaves the wait at once; past the bound that handler is cancelled and its connection closed, and a handler whose await ignores cancellation — a continuation nothing resumes, a task-group wait — still holds shutdown until its task ends, as every request did before the drain had a bound. Completion is published only after that synchronous hook returns: waitUntilShutdown, runUntilCancelled and concurrent or repeated shutdown calls await both the drain and the completed hook.

## Drain reporting

Each shutdown reports one graceful-drain outcome through `ServeNIOHooks.onGracefulDrain`, after the wait and before the force-close: `.drained(after:)` when the requests already running answered, `.boundExpired(ending:)` when the bound ran out on them, and `.cancelled(after:leaving:)` when the shutdown's own task was cancelled first. An `ending` or `leaving` entry is one `ServeNIOInFlightRequest` per request the wait still tracks: its method, the path of the request the head parser built (no query and no userinfo; path segments are not redacted), its HTTP version, its age since the head was read, and its activity — `.receivingRequest` while the body is still arriving, `.awaitingResponse` once the head is read and the response has not finished, whether the handler still runs or its buffered response is being written, so a slow backend and a response blocked on the client look the same. A streaming response, whose handler already returned, an upgraded socket and the HTTP/2 parent connection are not tracked and not listed. No route carries a bearer token in a path; path segments are logged as they are, so one that did would need caller-owned redaction. The head is recorded when it is read and cleared when the connection parks. What to log stays the caller's policy. The close phase after the drain reports through `ServeNIOHooks.onShutdownProgress`: `.step(_:after:)` for each await of the shutdown — the listener close, the GOAWAY writes, the drain, the channel closes, the connection wait — and `.stillClosing(after:connections:)` at one and ten seconds while the connection wait continues (from the bound's own clock, never ending or shortening the wait), naming each still-registered connection's kind — plain request, streaming response or upgraded socket — method, path, age, `channelClosed` and `taskCompleted`. Every GOAWAY is written without waiting — a write still queued behind backpressure fails when the connection is force-closed — and every remaining await on a peer is bounded by the TLS shutdown timeout or the drain's bound; the connection wait itself stays unbounded and watched. A TLS connection's close waits one second for the peer's `close_notify` before NIO SSL forces it (`TLSServe` sets the server configuration's `shutdownTimeout`, where NIO SSL defaults to five).

## Listening beside another process

The listener sets `SO_REUSEADDR` and, except for a Unix domain socket, `SO_REUSEPORT`. Two servers — the outgoing and the incoming process of a release — therefore bind one address and port at once, and the kernel spreads new connections over both until the outgoing listener closes. A bind that fails is reported through onStartupFailure and thrown; nothing is listening.

## Inherited listener


NIO retains an upstream debug-build assertion on the Darwin F_SETFL EINVAL path: it can terminate the process during socket construction before ServeNIO receives the error and can dispose the descriptor. This accepted residual is not changed by the adoption wrapper.
