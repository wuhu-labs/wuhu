# FetchTunnelURLSession

An Apple-only URLSessionWebSocketTask adapter builds on macOS, iOS and visionOS, without NIO or process targets. The caller supplies a URLSession which owns certificate policy (including any custom trust delegate); no alternate session or trust policy is selected. Only ws/wss URLs are accepted. Headers, including sensitive Fetch RequestHeaders, are supplied explicitly. The adapter offers `wuhu-fetch-tunnel.v1`, starts the task, waits for a transport ping/pong and validates the selected protocol before returning or sending any application frames. URLSession can report one ping's outcome more than once when the socket is cancelled while the ping is pending and the connection then tears down; the first outcome settles establishment and later ones are dropped. Cancelling connection establishment cancels the socket and throws CancellationError at once, without waiting for the ping's outcome; URLSession may never report one (for example after the peer's close frame). The caller supplies the dial deadline through its owning task/session policy and relies on this to end a dial. A refused or incorrectly negotiated connection fails, never switches transport, and is cancelled.

The adapter exposes one pull receive, no application receive queue, and sequential sends. URLSession's maximumMessageSize and an explicit post-receive byte check enforce the configured message cap; messages must be binary. The returned transport exposes that cap as maxMessageBytes so Tunnel rejects incompatible frame limits before IO. No application body is buffered outside the tunnel's exchange caps. `bufferedReceiveBytes` is a server/NIO queue budget and has no queue to govern here; URLSession's private network buffering is owned by the OS, not an application AsyncStream. Cancelling IO or aborting cancels the socket promptly. This adapter performs no replay or reconnection. API callers keep their own full exchange deadline; dial/read/write failures are surfaced, not retried.
