# FetchTunnelURLSession

An Apple-only URLSessionWebSocketTask adapter builds on macOS, iOS and visionOS, without NIO or process targets. The caller supplies a URLSession which owns certificate policy (including any custom trust delegate); no alternate session or trust policy is selected. Only ws/wss URLs are accepted. Headers, including sensitive Fetch RequestHeaders, are supplied explicitly. The adapter offers `wuhu-fetch-tunnel.v1`, starts the task and awaits the task delegate's `didOpenWithProtocol`, validating the selected subprotocol before returning or sending any application frames. Establishment sends no ping: URLSession can hold a pong behind an unread application message the peer sent immediately after upgrading. Task completion with an error ends establishment; cancellation cancels the socket and throws CancellationError without waiting for a delegate callback. The caller supplies the dial deadline through its owning task/session policy. A refused or incorrectly negotiated connection fails, never switches transport, and is cancelled. An optional `upgraded` callback runs once the expected subprotocol is accepted, before connect returns. The task delegate does not implement trust challenges, which still reach the session's own delegate.

The adapter exposes one pull receive, no application receive queue, and sequential sends. Messages received by the OS before connect returns stay available to the transport's first receive, in wire order. URLSession's maximumMessageSize and an explicit post-receive byte check enforce the configured message cap; messages must be binary. The returned transport exposes that cap as maxMessageBytes so Tunnel rejects incompatible frame limits before IO. No application body is buffered outside the tunnel's exchange caps. `bufferedReceiveBytes` is a server/NIO queue budget and has no queue to govern here; URLSession's private network buffering is owned by the OS, not an application AsyncStream. Cancelling IO or aborting cancels the socket promptly. The returned socket pairs the transport with `ping`, one transport ping that returns at its pong; on a silently dead path it waits until cancelled. URLSession can report a ping's outcome more than once during cancellation and teardown; the first outcome wins and later ones are dropped. Cancelling the ping's waiter throws CancellationError without waiting for its outcome. A pong waits behind every earlier unread message, so callers run ping alongside the transport's receive loop, never await ping before starting that loop. A ping issued first completes once the independently started receive loop drains those messages. The adapter runs no ping schedule of its own: liveness policy is the caller's. This adapter performs no replay or reconnection. API callers keep their own full exchange deadline; dial/read/write failures are surfaced, not retried.
