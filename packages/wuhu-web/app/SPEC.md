# Web history loading

Conversation identity is its durable ID and acting group; transcript identity also includes generation. Every initial connection and reconnect fetches one bounded recent page (100 messages or 200 complete committed entries), paints it, then opens forward observation after that page's exact head. Sparse message ordinals are not counts. Empty transcript heads use position -1. Existing nonpaged server/CLI consumers remain unchanged.

`conversationSubscription` requests `/v1/conversation/:id/messages?tail=100&paged=true`, and earlier pages with exclusive `before` plus `tail=100`. `directSubscription` requests `/v1/session/:id/transcript/page?limit=200`, and earlier pages with both expected `generation` and exclusive `before`. Claude pages additionally return an optional `historyEpoch`; older pages and the paged direct stream pin it through an encoded `epoch` query. Kernel epochs are null. A changed epoch on bounded bootstrap discards old same-generation retained ranges/origins, while a mismatched older response is rejected and reboots the tail. It streams `/direct?paged=true&generation=G&position=P`. A reset, including a same-generation lag reset, cancels outstanding page work, clears retained records and origin companions even for the same generation, and reboots the bounded tail. `409 generationChanged` replaces the old projection. Only `503 transcriptPreparing` uses cancellable 250ms preparation retries; ordinary connection failures retain the existing capped exponential backoff. There is no whole-history fallback.

Paged feeds use the existing `observeStore`, `ViewerCache` scope, keys and per-entry budgets (1 MB conversation, 2 MB transcript), not a second history cache. Version 1 cache envelopes record canonical positioned entries, separate origin companions, generation and optional history epoch, loaded ranges with earlier-edge exhaustion, and a forward head independent of the backward boundary. Old event-array caches are discarded. Warm cache paints immediately; a same-generation tail refresh merges durable records. Disjoint lower cached ranges are retained but hidden behind an explicit missing-history edge until a bounded backward read bridges the gap. Retention eviction adjusts range boundaries and exhaustion, never asserting that evicted history remains complete; active reading is not trimmed by disk eviction. Whole entries retain complete payloads rather than a reduced copy.

Older history loads only through a manual keyboard-operable action or explicit upward wheel/key/touch intent at the upper viewport edge. Layout, an empty or short initial page, programmatic scrolling and live arrivals cannot cascade page requests. One wheel/touch gesture consumes one edge request; a new gesture or leaving and returning to the edge permits another. The feed owns single-flight cancellation and rejects stale requests/streams after unsubscribe, identity or generation change. Backfill never advances or rewinds the forward cursor, and live content remains usable after a backward-page error.

The edge is inside each timeline: Loading, Preparing history…, an actionable retry, Load older/Load missing history, or quiet Beginning of history. Stable row identities and viewport offsets are retained across prepend, live append, refolding and delayed layout measurement. A timeline follows bottom only while already following; both surfaces expose Jump to latest while reading away from the tail. Generation resets dismiss generation-specific inspection and clear streamed attempts; renaming changes neither caches nor cursors.

Origin companions attribute only loaded result rows, never introduce unrelated origin text/calls or claim intervening history is loaded. A visible receipt uses the real origin tool name, arguments and matched result. Missing results in a partially loaded projection are Unknown, not assumed Running. The first unfinished call can be Running only for a live, materialized current assistant inference with an explicit tool-use stop and active runtime work. A new attempt, cancellation, newer committed assistant or reset/rebootstrap discards that execution evidence; session-global working alone never revives an older aborted inference. Origin companions cannot provide execution evidence. Only this accepted execution evidence marks the next unfinished call Running; later unsettled calls in that same inference are Queued. Cancellation, idle or unknown activity renders unsettled calls Unknown, without a perpetual spinner.

The CI web `test` target exercises page/cache/reset lifecycle, sparse and overlapping pages, gaps, stale responses, preparing/backoff, origin joins and user-intent policy. HTML snapshot references for history-edge states are checked under the same target; browser proof captures the actual product components at desktop and compact sizes separately.

# Inference transcript projection

One committed assistant entry, identified by session/generation/entry position, is one inference. Raw content-part ordinals remain stable even when an unsupported block is omitted. The latest committed inference stays exposed through completed tool results, context notices, idle transitions and speculative attempt/delta events. Only the next committed assistant entry, including an empty entry, makes older work foldable. Reasoning with unavailable text remains inspectable; a reasoning-only entry never fabricates an outward answer.

Text from entries declaring calls is preamble work; text without calls remains outward output. External inputs, recognized message sends/reports, outward output, generation heads and unloaded gaps separate work segments. Consecutive sends create no empty summaries and trailing work starts a new segment. Eligible older work folds to one Worked row at the first hidden source position. Counts describe represented calls exactly once; duration uses available source/result timestamps only. Duplicate result delivery retains the first matched outcome. Origin-only receipts remain attributable result rows without inventing an assistant inference. When an earlier page supplies a declaration, its absorbed receipt source ID anchors the represented call or folded summary without adding rows or counts. Bookmarks remain visible standalone boundaries. Zero-tool summaries omit a tool-count label. A streaming attempt, even before its first text delta, shows Working without advancing the latest committed inference.

Summaries open chronological mixed Work history, never inline expansion. Reasoning, preamble, tool and notice rows open full detail in the same modal. Back restores the durable visible history item and its viewport offset plus selected-item focus, even when a pending older page extends the segment while detail is open. The same anchor preserves position across live history updates; close restores the triggering timeline row (or its new folded summary). Direct latest-item activation opens detail without an invented history. Wide views use the inspection dialog; narrow views use the full-height surface with explicit Back and close actions. Escape closes inspection without also opening the compact sidebar. Copy/selection remains available for full arguments, matched result/error and source body. The history cache retains whole bodies, so this web flow does not introduce a separate truncated-body fetch.

Context notices stay quiet and indented. Instructions loaded and its concise subject come only from explicit AGENTS.md source markers; details retain all source paths and raw text. Compaction requested and other recognized explicit notice kinds keep their meaning. Unknown/malformed metadata falls back to Context updated with reachable raw content. Intervening notices inherit the loaded preceding inference for folding; without it they remain standalone annotations.

Inspection is local to session/generation/history epoch. Reconnect and renaming preserve valid targets; replacement generations/epochs dismiss incompatible detail. A work history's durable first-source anchor can follow an extended segment after prepend. Hidden source anchors retain viewport identity when work refolds. The shared public-core semantic fixtures drive TypeScript and Swift expected projections and prefix invariants. Ten production-component HTML goldens are asserted by the web CI test target; they are markup snapshots, not pixel tests. Production SPA Chrome/TLS-h2 captures and interaction assertions are kept as separate review evidence in the transcript proof harness.

# Native Settings embedding

The native Settings web view registers `window.webkit.messageHandlers.wuhuEmbedded` in WebKit’s page world before navigation. The SPA detects its callable `postMessage` synchronously during render only in the top frame (`window === window.top`). With the signal present, the space layout renders every route body without AppShell, sidebar, agent list, topbar or composer, including the enrollment-to-home hop and links leaving Settings; route context, Settings tabs, data providers and account/AI-sharing actions remain available. `/_/enroll` stays standalone and uses the same body padding. Embedded bodies honor the native `--wui-safe-*` insets and keyboard inset without reserving space for SPA chrome.

The signal is presence-only; the SPA does not post to it. It is separate from the `wuhuShell` content SDK protocol, which embeds space documents and carries context/navigation. Ordinary browsers and older native apps without `wuhuEmbedded` retain the full SPA shell. Child frames retain their normal layout even when WebKit exposes the signal in those frames. Older SPA bundles ignore the new signal.

# Content-page proxied fetch

The page-only `wuhu:space` browser module exports `fetch` with the standard browser signature, Request input and AbortSignal support. Collecting a streaming request body is abort-aware: abort cancels its reader and rejects before native fetch, without waiting for the producer to finish. It proxies through POST /_/space/fetch on the page's own origin, passing method/target headers/page path as encoded query values and raw request bytes as body. Internal data calls explicitly use globalThis.fetch so this export cannot recursively proxy them. An Authorization header is a SpaceError refusal before network I/O. Responses marked Wuhu-Fetch-Result upstream are returned unchanged, including backend 4xx/5xx and a streaming body; unmarked policy responses reject as SpaceError. There is no direct-fetch fallback. The server authorizes the current read-cookie viewer and group-local /fetch.json, strips cookies and signs a short-lived token; scripts cannot supply credentials. The page worker passes marked Wuhu-Fetch-Result responses through without write-epoch changes, query-cache purges or unauthorized-shell notifications, including backend 401 responses. run_script's ambient native fetch is unchanged; the proxied export is content-page only.
