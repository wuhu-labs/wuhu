# Web history loading

Conversation identity is its durable ID and acting group; transcript identity also includes generation. Every initial connection and reconnect fetches one bounded recent page (100 messages or 200 complete committed entries), paints it, then opens forward observation after that page's exact head. Sparse message ordinals are not counts. Empty transcript heads use position -1. Existing nonpaged server/CLI consumers remain unchanged.

`conversationSubscription` requests `/v1/conversation/:id/messages?tail=100&paged=true`, and earlier pages with exclusive `before` plus `tail=100`. `directSubscription` requests `/v1/session/:id/transcript/page?limit=200`, and earlier pages with both expected `generation` and exclusive `before`. Claude pages additionally return an optional `historyEpoch`; older pages and the paged direct stream pin it through an encoded `epoch` query. Kernel epochs are null. A changed epoch on bounded bootstrap discards old same-generation retained ranges/origins, while a mismatched older response is rejected and reboots the tail. It streams `/direct?paged=true&generation=G&position=P`. A reset, including a same-generation lag reset, cancels outstanding page work, clears retained records and origin companions even for the same generation, and reboots the bounded tail. `409 generationChanged` replaces the old projection. Only `503 transcriptPreparing` uses cancellable 250ms preparation retries; ordinary connection failures retain the existing capped exponential backoff. There is no whole-history fallback.

Paged feeds use the existing `observeStore`, `ViewerCache` scope, keys and per-entry budgets (1 MB conversation, 2 MB transcript), not a second history cache. Version 1 cache envelopes record canonical positioned entries, separate origin companions, generation and optional history epoch, loaded ranges with earlier-edge exhaustion, and a forward head independent of the backward boundary. Old event-array caches are discarded. Warm cache paints immediately; a same-generation tail refresh merges durable records. Disjoint lower cached ranges are retained but hidden behind an explicit missing-history edge until a bounded backward read bridges the gap. Retention eviction adjusts range boundaries and exhaustion, never asserting that evicted history remains complete; active reading is not trimmed by disk eviction. Whole entries retain complete payloads rather than a reduced copy.

Older history loads only through a manual keyboard-operable action or explicit upward wheel/key/touch intent at the upper viewport edge. Layout, an empty or short initial page, programmatic scrolling and live arrivals cannot cascade page requests. One wheel/touch gesture consumes one edge request; a new gesture or leaving and returning to the edge permits another. The feed owns single-flight cancellation and rejects stale requests/streams after unsubscribe, identity or generation change. Backfill never advances or rewinds the forward cursor, and live content remains usable after a backward-page error.

The edge is inside each timeline: Loading, Preparing history…, an actionable retry, or Load older/Load missing history; nothing once the whole history is in. Stable row identities and viewport offsets are retained across prepend, live append, refolding and delayed layout measurement. A chat page follows the bottom only while already following; there is no Jump to latest. Generation resets clear streamed attempts; renaming changes neither caches nor cursors.

The CI web `test` target exercises page/cache/reset lifecycle, sparse and overlapping pages, gaps, stale responses, preparing/backoff, origin joins and user-intent policy. HTML snapshot references for history-edge states are checked under the same target; browser proof captures the actual product components at desktop size.

# Shell

One layout for every route (`@wuhu/ui` `AppShell`): the app backdrop, a rail of sidebar views, one sidebar, the page and a floating composer row. Desktop widths only; there is no compact or touch layout. The sidebar and the page scroll the full window height under the floating top bar and composer; nothing clips or fades their edges. A page is laid out one of three ways: `scroll` (chat, markdown, settings) pads its own column by `--wui-titlebar` and the composer's live height `--wui-composer-h`; `framed` (directory, image, text, file, `.table`, `.view`, HTML by default) draws in a fixed card whose top lines up with the sidebar's first card, whose left edge follows the sidebar (with the sidebar hidden, the toggle's left edge) and whose bottom edge stops short of the one-line composer row (plus the chip row when shown) (its height plus its bottom margin) by the same gap as between the top buttons and its top, so it sits symmetric and a taller composer floats over it; `immersive` (an HTML page whose `stat` carries `layout: "immersive"`) fills the window and receives every inset, the composer's live height included, through the content SDK. While a node other than Markdown loads, the page already on screen stays, layout and content, until the node is known; a first open draws nothing under the whole window, and loading Markdown draws nothing in the scroll layout. So a frame neither blinks off between framed pages nor stands empty before an immersive one. Neither the window nor the area around a frame scrolls. The page pill names a session or channel by its title, an HTML page by its `<title>` (from `stat`) and a Markdown document by its frontmatter title, else the title of the custom-sidebar row that opened it, else the file name, without the extension for `.md`, `.html`, `.view` and `.table` (the folder's for an `index.*`). Returning from Settings keeps the row title the page had.

The sidebar toggle stands centred over the rail and never moves; Settings and + start at the sidebar cards' left edge. ⌃⌘S toggles the sidebar. Hidden, the sidebar takes Settings and + with it, and back/forward slide over to sit next to the toggle; while Settings is open New Agent is hidden and its Settings button is black and stays (back/forward then sit next to it), and clicking it returns to the page Settings was opened from.

The rail lists Everything, then shared's `/.sidebars/*.json` in path order; the personal group is not shown. Everything draws one card per live top-level agent, oldest first (its child agents one level down; tasks and grandchildren are not listed), and one Channels card when a channel exists. Every agent row shows its state under its title; avatars carry no status dot. A selected row is a grey fill: the whole card when it is one row, else a rounded fill inset in the card. A custom sidebar's first section turns each root row into a card with one level of children; each later section is one card titled with the section, children hidden. Unread counts come from `notifications` past the viewer's watermark, counted in SQL.

A session or channel opens as a chat page: Messages-style runs (one sender, at most 15 minutes apart), the paint-worklet bubble with a tail on a run's last bubble once `CSS.paintWorklet` has loaded it and a plain bubble before that and elsewhere, and a centred stamp ("Today 20:13", "Yesterday 09:02", "Oct 14 09:02"; English whatever the browser locale) at each day change or gap over 15 minutes. In a channel, another sender's run has their name above it and their 34px photo beside its last bubble, bottoms aligned. A box has one page, its session's: opened by its conversation id it goes to the session address. In a box, the box's agent's runs are bare and anyone else's run has a name line with a small photo before the name; every left bubble keeps one edge. `@name` renders as a mention. A task opens directly as its read-only transcript. An agent's title pill opens a glass menu with Transcript, then Start over and Archive (both confirmed; Archive first refuses busy work with the server’s busy-session list, then offers a separate “Stop work and archive” force confirmation). Start over restores model/group, effort, and an optional opening message; it goes through the SDK’s AI-sharing consent gate. Compact is absent. Transcript is a journey page (`?view=transcript`), so Back returns to chat. It uses the Markdown reader’s exact column width, insets and themed content/code styles; names, avatars and stamp times match chat. Empty events are omitted, string tool output is preformatted verbatim. It renders inputs and attachments, assistant text, collapsible reasoning/tool calls/results, notifications, bookmarks and generation summaries over the existing paged direct feed.

# Conversation composition

A conversation whose server-provided kind is `dm_user` and has a session member is read-only history: it has no page composer or reply action, regardless of the session's kind, lifecycle or presence in the roster. Membership alone does not classify a DM: a `box` or `users` conversation can also have exactly one session and one user, and keeps its existing composition rules even when opened through `/_/conversations/<id>`. Its messages remain readable through direct URLs, space links, custom sidebar destinations and old push notifications. Person–person `dm_user` conversations, group conversations and agent boxes retain their existing composition rules. Any other page, a read-only DM included, offers the dock: the remembered agent box (kept per space in the browser; opening an agent box or choosing its composer chip moves it), else shared's oldest live top-level agent, named in the placeholder ("Ask <agent> about this page") and addressed to that box. The composer's agent chip lists eight unique recent live agent targets, most recent first; choosing one retargets without navigation, preserving each target’s draft. The chip sits above the desktop composer row, leading-aligned with 8px inset and a 220px maximum width. It appears on docked pages only, plain text with no menu when there is just one recent target; an agent’s own box always aims at itself and hides the chip. Opening a task or archived session preserves the remembered dock target. Recents are browser-local per space; archived/unavailable ids are purged from storage. Channels keep their own target. Settings and tasks have no composer. The composer sends text only; received attachments still render in bubbles.

Every send names the page on screen as `viewing`: the path the node page has rendered at the current address, spelled `wuhu://<group>.localspace/<path>` in the URL's group. The space layout holds that page (`lib/use-shown-node.ts`) and the node route renders it, so the composer and the screen read one state; while the next node loads, the screen keeps the page it replaces and a send names none. At `/` that is the homepage it resolved; a homepage created while `/` stays open is not named until the page shows it. The root listing names no page: the root has no entry to stat, so the server refuses a send naming `/`. A page still loading or failed to open, a box, conversation, session view, screen and a path the server would refuse send none (`lib/viewing.ts`). The composer reads the value at Send, so a page left before Send never travels. When the server refuses the page (`reason: viewing`), the message goes again once without it, and the console says so without naming the page.

# Content-page proxied fetch

The page-only `wuhu:space` browser module exports `fetch` with the standard browser signature, Request input and AbortSignal support. Collecting a streaming request body is abort-aware: abort cancels its reader and rejects before native fetch, without waiting for the producer to finish. It proxies through POST /_/space/fetch on the page's own origin, passing method/target headers/page path as encoded query values and raw request bytes as body. Internal data calls explicitly use globalThis.fetch so this export cannot recursively proxy them. An Authorization header is a SpaceError refusal before network I/O. Responses marked Wuhu-Fetch-Result upstream are returned unchanged, including backend 4xx/5xx and a streaming body; unmarked policy responses reject as SpaceError. There is no direct-fetch fallback. The server authorizes the current read-cookie viewer and group-local /fetch.json, strips cookies and signs a short-lived token; scripts cannot supply credentials. The page worker passes marked Wuhu-Fetch-Result responses through without write-epoch changes, query-cache purges or unauthorized-shell notifications, including backend 401 responses. run_script's ambient native fetch is unchanged; the proxied export is content-page only.

HTML, XHTML, SVG and XML conversation attachment links download the raw file with `?download=1` instead of opening an inline document. Attachment paths do not enter HTML, directory, or view-provider frames. Image attachments retain their image views; other attachments use file cards, including `.view` definitions. Conversation image previews remain inline.

# Document observations

`SpaceClient.read`, `stat` and `list` paint the kept value, fetch once, and follow matching changes (at the path or above it, and for a listing also under it) from the group's change feed. `space-feeds` owns the single `**` SSE per group through `observeStore`; file reads own no stream, reconnect or network lifecycle. The feed starts at the revision it last reached, kept, else at the head revision `ls /` reports; there is no tree crawl. If a cold start cannot reach the server, the feed starts at latest and asks again on its first open; the recovered revision replaces its cursor, so subsequent replay supplies intervening changes without a pending-event buffer. Sidebar definitions come from a live listing of `/.sidebars`. Ordinary cursor-resuming reconnects do not refresh successful reads. Unreachable and service/auth/provider failures retry on the next group snapshot. File answers (`notFound`, `invalidArgument`, `forbidden`, `unsupported`, `invalidPath`, `byteLimitExceeded`, `unknownKind`, `conflict`) park until a matching change. Successful equal values are not emitted twice, and cache failures cannot hide a successful read. App writes keep acknowledged content and tokens. Callers never choose kept versus fresh or reopen reads themselves.

The shown-node projection still composes asynchronous stat/read dependencies for homepage resolution without reopening them; sharing a stream does not replace that composition. The route and composer share its resolved-page state. Tables never ask for a text read; view-provider frames use the observed definition token. Sidebar definitions consume their own read observations; the `/.sidebars` listing supplies their membership. Markdown editing retains its existing dirty/saving/conflict ownership. A shared coalesced-refresh helper serializes file refreshes and the feed's start discovery; the group observeStore folds only the revision, the theme and session photos. Compositional tests use each boundary's own fake to pin cold recovery/cursor replay, single-feed and one-initial-read behavior, refusal parking, deduplication, reconnect retry, cache recovery, acknowledged writes and projection dependency reuse, without polling.

GlassMenu delegates keyboard navigation, focus return, dismissal, radio semantics and collision-aware positioning to Base UI Menu rather than maintaining a second menu state machine. Figure small-widget notes truncate with an ellipsis.
