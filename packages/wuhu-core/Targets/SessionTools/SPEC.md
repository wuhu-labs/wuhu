# SessionTools

The worker depends on MainHub’s existing `Main` contract. MainHub owns `Hub`; SpaceServer composes it with ToolExecutor and Scripts. Tests keep using the real Hub rather than a fake Main.

## Automatic scope context

On the first machine touch, the tool result is followed by that machine's notes; repository touches add AGENTS.md and skill listings from the git root down to each newly visited folder. Within one generation, notices deduplicate files by delivery kind and SHA-256 of their exact, unnormalized UTF-8 text, across folders, checkouts and machines, including earlier files in the same notice. Full-text delivery and skill-listing delivery have separate namespaces: a listing never suppresses full text that the model has not seen. An identical AGENTS.md contributes one generation-neutral line: `<path> is identical to <first-path> (loaded earlier)`. An identical skill keeps the listing shape: `- <name> — identical to <first-path> (loaded earlier) (<path>)`. These historical pointers remain accurate in retained compaction tails. Different text always loads, even if paths, skill descriptions or the capped AGENTS.md prefix match. AGENTS.md keeps its 32 KiB display cap; skills remain name/description/path listings, never inlined bodies, and use the complete SKILL.md text as their identity. Each skill listing and its hash derive from the same single read, so an intervening edit cannot mark unseen description text as delivered. Machine-note loading does not resolve each skill path again; a missing or unreadable file is non-fatal and records no delivery hash. Folder tracking remains path-based, so a previously visited folder is not rescanned mid-generation. Both folder tracking and delivered-content hashes reset after compaction or Start over, including when historical notices remain in a retained tail; ordinary session/server restart within the generation reconstructs them from persisted notices. There is no manual-loading mode or feature flag.

## Messages

`send_message` accepts `conversation` or `session`, never `user`. No target posts into the caller's own box; `session` opens or uses a session–session DM. A legacy `user` argument is a typed tool failure, not an ignored field or a fallback to the box. Posting by any person DM's conversation id, whether person–person or an old person–session DM, is refused by `SessionStore.post`. Both refusals say exactly: "There is no DM between human and agent. If you want to notify a human that has talked in your conversation box, simply post that box, optionally specifying the reply target's message ID." Existing DM history stays readable with `conversation()` and `dm()` in `wuhu:space`; that module has no independent message-post export. Script HTTP posts use the same server/tool post path. Space attachment-copy sources use the direct file-read policy, including channel readership before group readability, and recheck readership when reading the bytes. A session copies a channel attachment only while its group reads the source group; losing that read edge prevents later copies.

## Script stream delivery

Script answers, detached notifications and ending-waiter completion are queued with their state transition and drained in that order by one sender outside the execution mutex. Stream termination and cancellation callbacks never run while that mutex is held; an execution's final notification cannot overtake an earlier queued result or update.

## Script archive

`archive(id, { force: false })` in `wuhu:session` defaults to non-force. Its control bridge forwards the force flag to the runtime after checking the caller's rights on the root. `force` must be a boolean. A busy refusal rejects with the full id/title list. A descendant-only busy refusal does not claim that the caller itself is mid-turn. Force self-archive is always refused, including from a detached script. Non-force self-archive is refused mid-turn because the call keeps the session busy. A detached script that outlives the turn can archive it once it has settled; this archives its whole subtree, subject to the same non-force busy check.

Archiving a session takes its entire parent-chain subtree, leaves first and root last. A separately created top-level agent has no parent and is not included. Only the root's archive rights are checked. Without force, every session is checked for the existing unfinished-work condition (retired sessions are never busy, even with queued input); refusal archives nothing and names every busy session by id and title. With force, busy sessions are interrupted before any archive write, and every open request in the subtree, including an undrained request, is closed with a final-kind message saying the session was archived before reporting. Its requester receives that message even outside the subtree. Unarchive remains single-session, subject to the archive grace window.

## Cron timers

Five-field cron schedules match UTC Gregorian minute, hour, day-of-month, month and weekday fields. Day-of-month and weekday combine with OR when both are restricted. A cron search converts its input date to an integer Unix minute ID once (`floor(unixSeconds / 60)`), starts at the next ID, and performs all candidate increments, day/hour skips and UTC field decomposition in integer space. Only the matching minute ID converts back to a date, with exact whole-minute Unix seconds. A result is strictly later than its input and matches the expression.

After a recurring fire, the next slot is computed strictly after the later of the current wall clock and the due time just fired. Missed slots are not replayed. Existing off-minute stored due times need no migration: they fire once under their existing deterministic notification identity, then advance to an exact cron minute.

The firing registry treats completion as an event and reloads durable registrations before re-arming. It retains ongoing observations across marker/delivery updates, but never retains a finished firing task merely because its arming key is unchanged. Only a proven non-advancing reschedule (a rejected persisted timestamp or a successful recurring fire leaving its stored due unchanged) logs an error and stops that arming instead of entering a fire/deduplication loop. Every other firing failure logs the actual error and re-arms from the stored row after a continuous-clock backoff of 1, 2, 4, 8, 16, 32, then at most 60 seconds. The same retry rule applies to cron timers, one-shot timers, request deadlines, park retirement and observation delivery; a clean observation-stream end or operational observation-read error also retries rather than silently stopping. A changed arming starts with a fresh backoff. Retries preserve deterministic delivery identities and only advance observation markers after a successful store write. Invalid observation queries retain their explicit error-notification-and-retirement behavior; failure to write that retirement is retryable. A changed durable arming can be started again. Superseded tasks and all tasks on registry exit are cancelled and awaited.

One-shot timer delays, request deadlines and archive grace remain relative durations and retain fractional-second inputs; they do not compute recurring calendar boundaries.

A request deadline is delivered to the parent queue and the owner notification feed atomically with slot retirement; failure of either delivery retries the still-armed deadline.

`cancel(id)` is the one stop for what a session started; `cancel_observation`, `cancel_timer` and `stop_script` are gone. The id's prefix routes it: `obs.`, `timer.`, `stall.` and `deadline.` go to the owner's subscription cancel, which looks up only the caller's armed slots; `script.<id>` goes to `Scripts`, and `exec.<id>` to the owner's exec jobs. A bare 8-hex script id and any other prefix are `invalidArgument`. An id the caller does not own reads as unknown: `notFound`, never a distinct "not yours". A subscription that is not armed is `notFound` whether it ended (a fired one-shot timer, a second cancel) or never existed: nothing durable remembers a subscription past its slot. `alreadyEnded` is only where existing records know it: an exec whose record is terminal, and a script that ended in this process (a bounded registry of 4096, lost on restart, after which the id is `notFound`). Results name the target and how it ended: subscriptions keep their `cancelObservation`/`cancelTimer` payloads; a script result says whether it stopped on the abort or was killed after the 5 s grace. Script ids are shown as `script.<id>` everywhere (run_script results, notifications, restart notices). `wuhu:session` exports `cancel(id)`, resolving to `{ id, message }` or throwing an `Error` with `code`. `<session-state>` lists a persisted generation-start snapshot of armed subscriptions and running scripts/exec jobs. `LoopConfig.runningWork` (`Scripts.running(of:)` plus the exec jobs) is read only when starting a generation, never while rendering its history. The head stays byte-identical through work completion, subscription retirement and server restart; query `subscriptions` for live registrations.

`request` and `create_session` take `stall_seconds`: absent means 1800, `0` arms nothing, and a value between 0 and 1 is refused. On `create_session` it needs `expects_reply`. Scripts pass `stallSeconds` to `request(id, message, { deadlineSeconds, stallSeconds })` and `createSession`. The firing registry runs a stall slot's due time through `checkRequestStall`, passing the sessions with a `run_script` execution running in the `Scripts` it was built with (handler firings excluded), and the check writes its own next due time; `cancel` refuses a stall slot like a deadline. `Scripts.stopScripts(of:)` asks each of a session's `run_script` executions to stop without waiting for it; each ends within the stop grace.

`request` takes the request terms `kind`, `key`, `schema` and `fields` flat, `create_session` under `request` (with `expects_reply`), and scripts pass them the same way. Bad terms (a key without a kind, an empty kind or key, an invalid schema, non-object fields) are `invalidArgument` before anything is written. A taken key answers `existing: true` with the holding request and task, posting and creating nothing; the `report` tool refuses a final that breaks the schema with the violations and the refusals left.

## Machine exec receipt and retention

The ordinary exec tool withholds output ACKs until its receipt is durably stored, preserving byte-zero crash replay. It keeps the caller leg alive through receipt storage, sends a terminal ACK covering the whole received output, then closes the leg. A failure before receipt storage sends no terminal ACK. A received output-cut marker is included in the result text; the exit code remains the process's real status.

## Machine exec liveness

An exec tool or script stops waiting when the server records `machine-lost`, reporting that the remote process outcome is unknown rather than claiming an exit. For other terminal records, one additional caller connection may drain retained output; a second sever without an exit event fails as no longer replayable. Successful server-local connections do not reset that terminal drain budget. Transient reconnects for live execs and the byte-exact replay/retention policy are unchanged.

## Machine exec lifetime

An exec tool call without `max_lifetime_seconds` gets 1800 s; exec and run_script both refuse a `max_lifetime_seconds` above 14400 or not above 0 with `invalidArgument`, never clamping it, and exec refuses its old `timeout_seconds` name the same way. The values live together in `ToolLifetimes`. When the lifetime ends the machine agent kills the command's whole process group, so a child it backgrounded without `setsid` goes too. When the machine reports that the lifetime ended it (`ExecExit.timedOut`, never the caller's clock), the result text ends with a line saying it was killed after N s and whether that was the default (with a pointer to detached start and run_script) or its own `max_lifetime_seconds`; the output tail stays and the exit code is the process's real status. A v2 lifetime stop reports the supervisor's real termination; when none arrives within a 30 s grace, or the verdict lacks one, the exit is `timedOut: statusUnknown` and the call fails as `requestDeadline`, never as a plain `requestCancelled` or an invented exit code. Script `machine().exec` timeouts are unchanged.

## Exec jobs and wait_seconds

An exec is a worker-owned job that outlives its call. The call waits up to `wait_seconds` (default 300, `ToolLifetimes.waitDefault`; at most the lifetime plus 10 s) then returns an `ExecResult` containing JSON `{status: "running", id: "exec.<id>", tail, note}` and exit code 0. HTTP claim carries the worker’s opaque rejoin spec; the wait cut sets `tool_end_owed` through the detach route before returning running. End delivery clears it through the delivered route after the durable result or notice, before terminal acknowledgement; transport uses `ExecSession` over main’s WebSocket API. An awaited end becomes the tool result without a separate store receipt; its caller-leg exit acknowledgement waits for the loop’s `ToolOutcome.committed` callback after transcript append. A dropped result never acknowledges, so a retry replays the relay’s retained bytes. A running result first enters a detaching phase: its end still belongs to the call until the loop commits that result. A retry of an uncommitted running result takes the end back as its tool result, or cuts again under its own wait. Only a committed running result permits the detached end to become a notification. A detached end is appended as one exec notification, deduplicated by the deterministic session/call notice id, then acknowledged. A terminal SessionStoreError refusing a detached notice retires the local job even if authenticated delivery cleanup is refused; transient append failures retain the owed-end obligation for recovery. Cancelled jobs clear the obligation and acknowledge without a notice; archive records cancellation before revoking the token. A retried call whose job still lives waits on it again. `cancel("exec.<id>")` kills the process group (TERM then KILL 5 s later), suppresses the end notice, and waits up to 10 s for its verdict; ended execs are `alreadyEnded`, unknown or foreign execs `notFound`. Interrupt kills an awaited call only; archive kills every job before token revocation. Adoption happens when a worker mounts a session: it reads the session's owed tool-call exec records, including terminal ones, skips calls still pending in the hydrated transcript, and follows the rest as adopted jobs (main's boot scan wakes every session owed an exec end, so a restart mounts them). A hand-off releases the session's detached jobs without acknowledgement (phase `released`), leaving their ends to the next worker; an undecodable spec or unreachable caller leg produces the existing outcome-unknown notice. No `exec_jobs` table or exec receipts are written. Registry drivers live through terminal acknowledgement and teardown and are joined on worker shutdown; the process continues remotely for restart recovery. Running jobs supply generation-head snapshots and request-stall waits. run_script retains the same wait JSON and defaults; `timeout_seconds` and `on_timeout` are refused with `invalidArgument`.

Both calls also stop waiting early once something waits for the session (`WaitCut`): SpaceCore's `observePendingArrivals` reports, per `ArrivalUrgency`, the earliest unseen queue item as a `PendingArrival` with its enqueue time: `direct` for a person's message in the session's own box or a person's DM, `other` for anything else but context notices. Its grace, 10 s (direct) or 90 s (other), runs from that arrival, so a call that starts after it has passed returns at once; the earliest end wins, and the call returns the same `running` JSON whose note says a message arrived.

## Capability modules and image tool

The always-installed `wuhu:web_search` module exports named/default `webSearch(query, { provider?, count? })`. The always-installed `wuhu:ai` module exports `generateImage(prompt, { destination, provider?, model?, quality?, size? })`, `editImage(images, prompt, options)` and `transcribe(audio, { provider?, model?, language?, timestamps?, diarize? })`, plus `CapabilityError`. Unknown options are rejected, not ignored. All three shipped system skills teach these exact imports/signatures. Search returns normalized sources; transcription returns the shared rich metadata type, with seconds throughout and unavailable fields absent. Capability provider failures are code/message/hint JS errors; space authorization failures retain the space code/message/hint in the same JS error envelope.

Each invocation rereads `/capabilities.json` in shared through CapabilityClient; explicit bad active/override providers never fall back. Missing capability configuration uses the existing Codex login automatically, with no feature flag. The existing `generate_image` declaration remains unconditional and accepts optional provider/model/quality/size fields, using this same resolver. No script export exposes credentials.

Audio/reference inputs are server-read private space/readable-group/authorized-machine files. Inputs are size-checked before buffering; machine reads use the existing ranged transport with revision checks. Foreign group/machine access follows ToolExecutor.resolve; system files cannot serve as private capability inputs. Audio extensions select wav/mp3/m4a/mp4/webm and share the 25 MiB/two-hour container bound. MP4/M4A fragments are accepted when track/decode/sample timing establishes the bound. Unknown duration is rejected with invalid_argument before provider I/O; re-encode unreadable containers. Images accept PNG references and return only path/mimeType/bytes/width/height; generated bytes are never returned to JS.

Outputs keep existing create-only/foreign-home/system-write guards. Up to four script image calls run at once; per-run machine claims prevent duplicate same-destination calls. Space creates are atomic; machine writes are still stat/write guarded rather than cross-process atomic. Cancellation propagates to all pending provider calls and prevents placement. There is no new image receipt/replay mechanism for scripts; the standalone image tool keeps its existing receipt contract.

## Checked tables and document templates

`wuhu:space` in `run_script` exports `createTable(path, {columns}) -> {rev, token}`, `tableSchema(path, {rev?}) -> {header, token}`, `alterTable(path, header, {ifMatch, allowDropColumns?}) -> {rev, token}`, `instantiateTemplate(template, {in?}) -> {path}`, and `remove(path, {ifMatch?})`. HTTP table.create/table.schema/table.alter/table.mutate and new use the same checked SpaceToolContext service as scripts, including readable-group, protected-layer and session-home checks; no caller-supplied identity is used. Pages retain their existing data subset and do not gain these script-only exports.

Headers are ordered, bounded to 256 columns, and use string/integer/number/boolean/json wire types. Names are nonempty, case-insensitively unique, at most 256 UTF-8 bytes, contain no controls, and cannot be id (the implicit primary key). Create is create-only. Alter requires ifMatch; token comparison and header replacement are in the same transaction. Omitted existing columns require allowDropColumns: true; in-place type changes remain invalidArgument. Stale alter/remove calls return conflict with the current token when available. Schema inspection returns notFound for a missing path and invalidArgument for a non-table; historical inspection checks the requested revision and reads the schema/token at that point. Templates allocate/create atomically, read the source under the caller’s scope, and check the explicit destination or default template parent for writing, including foreign homes.

The CLI records create/alter/mutate tokens. `wuhu table alter` uses its recorded token (use `wuhu stat` to refresh it) and accepts `--allow-drop-columns`; it never silently omits the precondition. `.table` remains forbidden to ordinary file writes. New script calls use structured SpaceError code/message/hint/token errors; unknown options are invalidArgument, with no wallet or CLI fallback. The generated actual module namespace inventory is served at `wuhu://system/module-exports.json` and pinned by an offline runtime contract test.

Refresh the runtime-generated inventory by running `bazel test //packages/wuhu-core:SessionToolsTests --test_filter=ScriptModuleExportsTests --test_output=all`; the test prints one `MODULE_EXPORTS=<json>` line. Format that JSON into `SystemFiles/Sources/System/module-exports.json` and re-run the contract test. It compares actual installed namespace keys, not a hand-maintained list of source spellings; the internal wuhu:space-core transport helper is deliberately not a public module in this inventory.

## Files, history, exec ownership and discovery

The script-only `wuhu:space` file APIs return versioned results: `readBytes(path, {rev?}) -> {data: Uint8Array, token, rev}` and `readText(path, {rev?}) -> {content, token, rev}`. System files are readable and have no space revision. Writes accept bytes (ArrayBuffer or typed array) or UTF-8 text: `writeBytes/writeText(path, content, {ifMatch}) -> {token, rev}`. `ifMatch` is required; null creates atomically, and a string replaces only that exact current version. File writes still refuse `.table` paths. `stat(path)` returns entry metadata; `list(path, {rev?, hidden?}) -> {rev, entries}` reserves a 24 MiB listing allowance before storage retrieval, fetches at most 501 entries plus fixed hidden-root overhead at storage and refuses results larger than 500 visible entries. `history(path, {after?, limit?}) -> {entries, next}` returns ascending revision entries (100 by default, at most 500), with an exclusive revision cursor or null. `checkout(path, rev, {ifMatch})` restores historical content or a table under an explicit current token, or restores a missing path atomically with null. Missing or invalid guards are invalidArgument; HTTP omission retains its existing unguarded behavior. Create-only conflicts say already exists and suggest a different path. Remove/move/checkout preserve revision history. All failures, including move failures, use structured SpaceError. All space addresses reject machine paths and revision suffixes; historical reads use the explicit rev option.

`find(glob, {path?, limit?, hidden?, noIgnore?, step?}) -> {paths, step, scanned, skipped}` and `grep(pattern, {path?, limit?, hidden?, noIgnore?, step?}) -> {matches: [{path, line, text}], step, scanned, skipped}` run the find and grep tools' own implementation (the FileSearch engine) as the session, so globs, regexes, ordering, limits, skips and cursors are the tools': `limit` is their `matchLimit` (default 50, capped at 1000, must be positive). Regexes are ICU's (NSRegularExpression). `skipped` is always an array of `{reason, count, example}`, one per reason the walk passed entries over. A result stops at the limit or at one of FileSearch's page budgets with a non-null `step`, never on time; a search still running after 30 s fails `unavailable`; passing it back as `step` resumes exactly there, and `step` is null only when the scan finished. `path` defaults to `/` and takes a hostless path, `wuhu://<group>.localspace/<path>` in a group the session's group reads, or `wuhu://system/`, and results name paths in the form the caller used. Failures are SpaceErrors: a bad regex, cursor or limit is `invalidArgument`, a malformed path `invalidPath`, a missing path or a group the session does not read `notFound`, and a `machines://` path `unavailable` (scripts have no machine search seam). A non-string pattern, a non-integer limit or an unknown option is a TypeError before any call. Pages export the same two functions over `GET /_/space/find` and `/_/space/grep`, as the page's group.

A file read/write is capped at 16 MiB. Reads reserve 24 MiB in the shared script-buffer budget before I/O to cover binary encoding, preflight metadata before reading, then check the resulting bytes again. Reservation failure advises consuming buffered response bodies or machine output, not reading a smaller file. Serialized UTF-8 file-result size is counted without constructing escaped JSON (including control-character expansion), capped at 24 MiB and checked against the remaining script-buffer room before delivery to the engine; their temporary reservation ends on host-call completion. Listings keep their upfront allowance through result sizing and release excess room after sizing; cursor hydration stops with invalidArgument on byte allowance overflow, even below the entry cap. Read metadata and history results use the same result-budget check. Engine-owned objects then count against the JS engine's memory limit, not unread host buffers.

`wuhu:machine` exports `execs()`, `execStatus(id)`, and `killExec(id)` for the calling session's durable execs, including execs started by previous scripts or its exec tool. Listing includes only live execs; status may return terminal records. Another caller's id and an unknown id both return notFound. Ownership is checked by the same SpaceToolContext service used by session-authenticated HTTP exec routes before any kill effect.

`wuhu:space` exports `context() -> {session, group, contentHost}` and `groups() -> [{id, member, readable, admin}]`. Context resolves the stored caller identity afresh and the configured HTTPS content origin; an unconfigured standalone script host returns null for contentHost. Groups matches HTTP discovery: all live group IDs are discoverable, with membership/readability/admin flags refreshed per call. `wuhu:session` exports `toolRoster()`, returning the same `{rosters:[{executor, tools:[{name, description, parameters}]}]}` as HTTP; runtime hosts inject their declared roster, while an unconfigured standalone host returns unsupported. `wuhu:ai` exports `capability(kind)` for image/transcription/web_search. It checks provider configuration only, never spends money or resolves credentials, and returns `{kind, provider, dialect, model, authentication:"not_checked", features:{edit,timestamps,diarize}}`. It never returns credential names, endpoints or account identity; unavailable login, quotas, entitlement and region are deliberately not checked. Explicit broken configured providers still never fall back.

## One-shot completion

`complete(promptOrMessages, {model, schema?})` from `wuhu:ai` returns the assistant's text string, including JSON text when a schema is requested. `model` is required and names `provider/model` from the shared `/models.json`, reloaded per call; it uses that model's configured default effort and output budget. For Anthropic-dialect models, default effort `none` is emitted as disabled reasoning rather than adaptive thinking; this keeps none-only, no-opaque-replay providers usable without a replay scope. Input is a nonempty prompt string or a nonempty array of `{role, content}` messages with string content. Roles are `system`, `user` and `assistant`; system messages must come first. No tools, hosted tools, tool messages or tool options are accepted. `schema` is a JSON schema object sent through the provider's native structured-output field, never implemented by a hidden tool or a model/provider fallback. DeepSeek's Anthropic dialect rejects schemas with `unsupportedSchema`; other providers may reject unsupported schemas through their inference error.

`CompletionError` is exported with `name`, `message` and `code`: `missingModel`, `unknownModel`, `providerNotConfigured`, `invalidArgument`, `unsupportedSchema`, `unsupportedTarget` `inferenceFailed` or `oidcSigningFailed`. The signing-failure code also carries `provider` and a safe message naming the provider; it never carries signer diagnostics. Missing/malformed catalog, invalid provider configuration, unavailable credentials and incompatible authentication fail without switching models or providers. Errors do not expose credential material or raw upstream bodies. A completion is one inference attempt, with no automatic retry; the script's signal cancels it. Successful, failed and cancelled provider attempts record usage, served model, timing and outcome against the calling session and its group through the ordinary runtime inference metrics sink. Standalone script hosts record the same normalized fields directly in `inferences`. Handler and `run_script` executions share this binding and caller identity; completions do not append hidden assistant turns to the session transcript. A configured WebSocket model uses its same endpoint's stateless SSE transport for the one-shot call.

## Script fetch identity

Global `fetch(url, init)` accepts `identity: true`. Omitted or false keeps the ordinary fetch implementation unchanged, without an identity token. A non-boolean value (including null) or identity true with any case-insensitive Authorization header rejects with a TypeError carrying `code: "invalidArgument"`. Request inputs retain their headers for the conflict check. Identity is an init option, not a Request property.

The server identity transport mints once per call, with a 60 s lifetime and claims `iss`, `aud` (the named URL’s canonical origin), `iat`, `exp`, `jti`, `space`, `group`, `session`, and `sub = <group>/<session>`. Only hops with that original origin receive the bearer; cross-origin redirects are followed without it, never with a newly minted token. Verifiers discover the issuer’s JWKS through its well-known configuration, check the signature, aud and exp. No allow-list applies to scripts. Missing identity transport or a mint/signing failure rejects with `code: "fetchIdentityUnavailable"`, with no unauthenticated retry, secret, or provider fallback.

`Scripts` accepts a server-owned identity-fetch closure; its protection callback registers each minted token before network I/O. The run’s masking registry best-effort redacts exact token echoes from response headers (names and values), status text and whole bodies (text or bytes), errors, console, result and update, including later ordinary fetch calls. This is not a security boundary: an upstream can split or encode a token so it reaches JavaScript. The security guarantee is audience binding to the origin the script named plus the 60 s lifetime; an echoed token is usable only against a server the script can already reach with identity true. Ordinary stored-secret masking uses the same registry. The server closure throws `ScriptIdentityUnavailable(message:code:)` only for mint/configuration/signing failures: directory confirmation failures become directoryUnavailable, and other failures keep the default fetchIdentityUnavailable code. DNS, transport, timeout and invalid-redirect failures retain ordinary fetch TypeError behavior without that identity error code.

`identity()` from `wuhu:space` is read-only server identity discovery: `{defaultIssuer, overrides, publicationFailure, issuerFor(origin)}`. The first two fields contain resolved issuer URLs; `publicationFailure` is the current directory failure code or null when confirmed/not using the directory; `issuerFor` synchronously canonicalizes an exact HTTP(S) origin and returns its override or the default. It refuses userinfo, paths, queries, fragments, wildcards and invalid ports. The function uses the returned snapshot, not later configuration changes. Issuer settings and private keys are never space documents and cannot be changed by scripts. A script host without identity configuration returns a typed unsupported error.

## Channels

`wuhu:space` exports `createChannel({ title?, people })` returning the channel id, `addChannelMembers(id, people)`, `removeChannelMembers(id, people)` and `renameChannel(id, title)` returning null. A null or absent title shows members' names. Creation homes the channel in the script session's group; the session does not join. Members are people only; naming a session returns `SpaceError` with `code: "invalidArgument"`. Unsupported options, malformed people arrays and blank titles fail with that same typed code. Missing or unread channels fail with `code: "notFound"`. Sessions in groups reading the channel read it with `conversation(id)` and post with `send_message({ conversation: id, message })`. The CLI offers the same create/add/remove/rename operations under `wuhu channel`.

## Durable subscription handlers

`observe({sql | url, throttle_seconds?, handler?, name?})` and `timer({message, in_seconds? | cron?, handler?, name?})` accept a space script module path and a readable `name` (1 to 64 bytes, no control characters; default the handler file's name). Without `handler`, existing model notifications and arming baselines are unchanged. With it, a firing imports the current module and invokes its default function with `{rows, state, wake}` for observations or `{fireTime, state, wake}` for timers. Rows are an array of row objects; JSON/boolean declared columns are rehydrated. `fireTime` is the scheduled UTC ISO-8601 time. `state` is null initially and then the previous successful return, canonical JSON bounded to 16 KiB. Returning undefined/non-JSON, throwing, a missing module or exhausting the 60-second budget is a failed firing; no default handler or provider is substituted.

Each slot runs one handler at a time, throttled like its ordinary observation. The handler receives the owning session's full script rights, including `wuhu:session` operations and the same secrets/machines/model configuration as its ordinary scripts. `wake(text)` is available globally and as an argument; up to 32 wakes/64 KiB are buffered and committed atomically with the next state and subscription progress only after the entire execution succeeds. `result()` and `update()` are run_script-only and fail in handlers. Module edits apply on the next firing. Ordinary file/row/message/provider effects happen immediately and can repeat after a crash; handlers needing idempotence must key those effects themselves.

Failure leaves saved state and observation marker unchanged, records `last_error`, and wakes the owner once per persisted failure streak. Successful execution clears the streak/error. A failed firing reruns the same input (the same rows, the same `fireTime`) with backoff doubling from one second to five minutes, until it succeeds or the slot is cancelled or re-armed; nothing advances meanwhile. State/marker and buffered wakes are guarded by arming incarnation and attempt token, so a cancelled, rearmed or superseded attempt cannot advance or wake. A process restart reruns pending firings from the last saved state. Compaction and Start over preserve handlers like other subscriptions; archive preserves registrations and saved state during its grace window but cancels running handler executions. A firing while archived retires the registration without running handler code or waking the session; an observation fires only when its result differs from the saved marker, not when its task restarts for an archive lifecycle change. Unarchive before such a firing resumes the retained registration.

A `url` observation is a `stream` slot whose marker is the id of the last event taken. `SubscriptionFiring` dials it through MainHub's `EventSources` (SpaceServer's `signed(by:in:)`: a 60-second identity token naming the owner, audience the URL's origin, over the no-redirect `scriptHop`) with `Last-Event-ID` set to the marker. With a handler, each event is one firing with `event: {id, type, data}`; a failed firing drops the connection and redials from the marker, so the same event comes again. Without one, events batch into one `observed N events` notification per throttle, at most 64 KiB (a lone oversize event is cut); the marker advances to the last event in the batch and the rest carry to the next. The body is pulled as events are taken (`sseEvents(after:)`), never buffered ahead. An empty `id:` resets the marker to empty, which redials without `Last-Event-ID`. The slot retires only when a firing or wake finds its owner archived, so an idle stream survives archive's grace. A drop, a 408/429 or a 5xx redials with backoff from 1 s to 5 min, at least `Retry-After` (seconds or an HTTP date); any other answer retires a session slot with one notification and pauses a group observer.

Group observers (`createObserver(group, {name, handler, observe: {sql | url, throttleSeconds?} | timer: {inSeconds | cron}, sessionsPerHour?})`, `cancelObserver(group, name)` and `observers(group)` in `wuhu:session`, over `/v1/group/:id/observers`) run their handler as `ScriptActor.observer`: main mints a token for that one firing, and every call the handler makes goes through main's API with it. An observer handler has the space modules, its group's secrets, `complete()` billed to its group (OIDC refused), `wuhu:machine` on its group's machines, and `createSession`, `request` and `sendMessage`; capabilities, `setTags`, `archive`, `interrupt`, `cancel` and the other session verbs refuse it. `complete()` time is not counted against the 60-second firing budget for any handler.

`sendMessage({message, conversation?, session?, reply_target?, attachments?})` in `wuhu:session` forwards the existing `send_message` implementation and target/attachment authorization; no `user` target or extra option is accepted. It returns `{messageId, conversationId}`. With no target it posts the caller's box; `session` posts the caller's session–session DM, not the target's box. Like other immediate script writes, message posts are not rolled back when a handler later fails.

## Machine transport selection

Normal tools and `machines://<name-or-id>/...` paths select the transport by machine registration. The existing `machine(reference)` script helpers use the same routed file and exec backends. A v2 registration runs only through OperationClient; v1 registrations keep the channel transport. There is no separate v2 script module export or alternate operation-handle API. A missing v2 kind is a typed `unknownKind` failure naming that kind; rejected operation input (including invalid regex syntax) maps to `invalidArgument`, authorization to `unauthorized` and protocol/dialect support failures to `unsupported`. An admitted operation that vanishes or expires without terminal evidence is `unavailable`, not a missing user file. Transport or configuration errors never fall back to v1.

Read/write tokens, result shapes, output budgets, timeout stops and group-secret resolution retain the existing tool contract. The server injects session CLI credentials into v2 exec input, never accepts caller-supplied credential fields and masks the injected values. Credentials expire after at most 24 hours and are not renewed. `credentialExpired` is explicit; it never switches to anonymous access or a wallet identity. Search keeps match/entry limits and opaque continuation tokens; v2 resumes in traversal order rather than sorted order. Cursors are bound to the machine and search, malformed/foreign cursors are invalidArgument, and concurrent tree changes may skip/repeat entries without invalidating the cursor.

## Model group targets

`create_session` accepts `modelGroup`; `wuhu:session.createSession` accepts `modelGroup`. Both are mutually exclusive with provider/model and share template precedence, requested-target inheritance and group validation. An explicit target replaces the inherited/template target as a whole. Children inherit a requested group rather than its pinned provider. Group session creation requires a prepared route and stores it atomically with the new session. Stored sessions.executor_config remains concrete provider/model/effort; requested group intent lives in session_model_routes and is reconstructed by session APIs for inheritance. Template discovery includes modelGroup. `complete()` and capabilities remain concrete-only in v1; completion requests naming a group (bare or as the provider portion) fail with `unsupportedTarget` before credentials/provider I/O.

Provider definitions remain in /models.json; session group declarations live in /model-groups.json with the same strict group shape (kind: group). Provider/group IDs must not collide. complete() loads both files so a group request is unsupportedTarget instead of an unknown concrete provider, while capability/session catalog configuration remains independently validated. A missing group file means no groups; malformed group data is never ignored.

A create receipt replay uses the recorded session’s executor/pin without model or group revalidation and without another placement. Catalog edits or unavailable alternate credentials cannot prevent returning an already-created session; any owed template clone or message/request recovery still runs.

## Execution owner boundary

`Main` is the one Sendable boundary used by session loops, inference, tools and scripts. The directly conforming `Hub` actor owns persistence and injected credentials, metrics, identity, model-placement and machine capabilities; its initializer stores dependencies without scans, tasks or worker startup. Worker types retain only `any Main`, never a concrete hub, writer, store or blob backend. Parent composition can configure the concrete hub before binding a worker. There are no per-facet owner protocols, forwarding adapters or in-memory codecs.

Session reads and queue/claim effects are typed members. `append(session, SessionEvent)` preserves the existing store validation, transaction ordering and typed errors; compaction/handoff commit durably before local execution proceeds, retaining claim identity and epoch checks. Model documents are read live through `capabilityDocument`; prompt activation and reads use the frozen prompt revision. `OwnerMediaResolver` leaves external media to the provider and resolves owned references through Main before fitting in execution. Credential bindings retain authoritative identity epochs, including through OAuth refresh; unavailable inference signing retains its existing 422 error. Metric delivery awaits the injected sink. Worker tests use this same hub with SQLite in memory. Narrow injected session-access hooks can delay or fail real operations; they cannot supply substitute replies.

`ToolExecutor(owner:)` and `Scripts(owner:)` execute without concrete main dependencies. ToolExecutor dispatches roster calls locally and reaches persistent effects through main’s API; local scripts, completion/provider calls and image generation remain in execution. Image authorization, receipts, input reads and placement retain their order. Script host calls retain their file/table/query/stream, conversation/channel, secret, identity, machine-authorization and notification operations. `ScriptDataOperation` is a closed set of domain verbs, not database or closure RPC.

A script freezes its module revision, acting group and readable groups once, while every dynamic host operation derives the caller's current principal in the parent. System modules remain binary-local. Owner streams preserve their previous newest-snapshot observation buffering and ordered file events; cancellation terminates their parent pumps. Secrets may be transiently supplied to trusted fetch execution for substitution and masking, but no execution object owns a secrets store. Identity responses include the values to protect even when signing or fetching fails, so error/output masking is preserved inside the same server process.

`SubscriptionFiring` requires the composed `Worker` for script activity and handler execution; it owns registration, scheduling, admission and guarded state/wake commits in main. `Worker.fire` accepts a `ScriptHandlerInvocation` and returns saved state plus buffered wakes. Identity configuration belongs to hub construction or main configuration, not worker downcasts. Persistent tool receipt, authorization, budget, cancellation, restart cleanup and handler success-before-wakes behavior are unchanged.


Machine script helpers retain the normal file/exec owner seams; there is no script-only v2 facade. The parent routes those seams by registration and owns the durable OperationClient, store, credentials and trace sink. A `killExec` on an owned ID without a machine backend retains the prior `internal` failure code; unreadable IDs remain `notFound`.

The tool owner facet exposes scope-context delivery after execution, so contract harnesses read receipts through the same boundary rather than downcasting to parent adapters. Watch cancellation is tested through the production parent relay with a recorded upstream observation: ending the script consumer cancels the relay pump, cancels the intermediate mutation stream and terminates the parent observation.



## In-process execution ownership

`Main` machine operations receive the exact calling session. `ScriptMachineAccess` exposes its files/exec facets for hub composition; handlers use the same authorization as ordinary scripts.

`Scripts` owns interpreter execution locally, including stop/archive control and cancellation. There are no remote lifecycle registration or routed stop callbacks. The composed worker executes handlers through its scripts/tools and returns state plus buffered wakes; results carry no transport receipt. Subscription firing commits state/wakes through the existing guarded store operation. On restart, the hub announces persisted script-exec owners once before ordinary execution starts; live heaps do not survive restart.

Normal machine text/image reads and write/edit results retain opaque filesystem tokens instead of requiring a numeric mtime. Legacy numeric machine receipts keep their mtime representation. Overwrite guards compare opaque tokens exactly and pass the read token into the remote write, so a change between stat and write remains a conflict rather than a clobber.

## Execution ownership

The composed worker constructs Scripts and ToolExecutor together. Main-side tool routes and subscription firing use Worker, not concrete interpreter objects. Handler invocation/results live in MainHub; no forwarding handler protocol is required. Discovery configuration lives on Hub, reached through typed Main discovery operations. Machine bindings retain only typed machine/exec values and streams; Hub owns caller-leg transport and connection policy.

## Group creation

`createGroup({alias, owner})` from `wuhu:space` returns `{id, alias}`. This is the only session group-creation surface, transported by a script credential rather than an exec token. The owner is a live non-guest human space member, named by account id, persona id or current/retired person alias; only that human gains admin. The new group starts open, with a permanent three-word id from the session/persona allocator. `memberRequired`, `invalidAlias` and `aliasTaken` are typed `SpaceError` codes. The alias is renameable by a group admin, has no hyphens, and shares its permanent reservation namespace with people and machines. File addresses and module imports resolve current and retired aliases before access checks; imports still use the execution's frozen revision and readable-id snapshot.
