# LoopCore

## Archive

`SessionService.archive(id, force: false)` implements subtree archive. `SubtreeArchiveBusy.sessions` carries every busy node's id and title, and `message` renders the list. The service reserves settled runtime actors before committing any archive, so an idle pass cannot start work between the tree check and its archive. Failed preflight releases those reservations.

Archiving a session takes its entire parent-chain subtree, leaves first and root last. A separately created top-level agent has no parent and is not included. Only the root's archive rights are checked. Without force, every session is checked for the existing unfinished-work condition (retired contractors are never busy, even with queued input); refusal archives nothing and names every busy session by id and title. With force, busy sessions are interrupted before any archive write, and every open request in the subtree, including an undrained request, is closed with a final-kind message saying the session was archived before reporting. Its requester receives that message even outside the subtree. Unarchive remains single-session, subject to the archive grace window. `LoopConfig.archived` runs after each session's `SessionExecution.archive` returns; it defaults to a no-op.

Reservations make wake and enqueue return promptly: queued deliveries remain durable and a released live actor resynchronizes its queue before resuming. `SessionError.archiveInProgress` rejects conflicting control while reserved. An executor change that invalidates the runtime reservation fails with `SessionError.archiveReservationLost` rather than asserting; this runtime race can leave already-committed descendants archived, and a retry completes the remaining subtree. A reservation also blocks creation of children below that node; children attached before a parent is reserved are included by the final tree scan. A pending kernel compact command is not consumed while reserved, and resumes after a refused archive releases its reservation.

## Inference lifecycle

`InferenceReply.committed` receives the actual assistant entry and resulting transcript only after successful durable append and in-memory commit; it is never invoked for discarded/retried/cancelled inference. Provider IDs have already been replaced by kernel IDs and the entry preserves their map. Compaction by either path, Start over, archive/unarchive, retirement and shutdown await `LoopConfig.invalidateInference`. Defaults are no-ops, preserving existing SSE and executor clients.

An outage (a throttle or an unreachable network) retries without bound. A throttle that carries `retryAt` (from `Retry-After`, delta-seconds resolved against the injected `\.date`) waits until that instant, at most one hour; that wait draws no jitter and leaves the exponential schedule around it unchanged. A `retryAt` that is not in the future counts as absent: like every other outage, it backs off exponentially with full jitter up to 300 s. Both waits run on the injected clock and are cancelled by interrupt, archive and shutdown alike.

A provider `malformedModelMessage(message:reason:)` retries at most twice from the last committed transcript with the same injected-clock exponential backoff. This separate runtime-owned budget resets after a successful inference commit, not after an intervening outage, transient failure or mechanical compaction. It survives inference-pass exits and compaction within the live session. The third failure durably errors the session with the typed diagnostic, including during forced compaction; it never invokes fallback compaction. Failed attempts commit no assistant content, tool calls or results and never invoke `InferenceReply.committed`.

Cancellation immediately after a durable `committed` callback stops the pass before a forced-compaction fallback; the already-committed assistant remains durable, but no mechanical compaction runs after cancellation. This applies equally to SSE and WebSocket replies.

Cancelling `SessionService.start()` joins both live-pass drainage and registry shutdown. It returns only after every loaded actor’s shutdown, awaited inference invalidation, and live-pass cancellation cleanup complete, including cancellation during boot. Each failed boot wake is logged with its session ID and error, marks that session errored where possible, and leaves other sessions and registry admission running. Errored sessions are not automatically woken. Registry shutdown closes admission before joining its reaper and actors, so late work signals cannot rematerialize a session after shutdown.

Parent-service and standalone actor park reminders capture their monotonic sleep deadline when scheduled, before spawning the sleeper task. Task admission lag must not move the requested wake time. Retry backoff uses the same deadline capture, including bounded Retry-After waits; cancellation still joins the sleeper.

A session-specific boot eligibility failure is logged and marked errored without suppressing other eligible sessions. A work-signal wake failure uses the same per-session actor discard and visible error transition as boot unless it explicitly indicates transient SQLite busy/locked or an eviction race. Transient wakes retry at most three times after injected-clock delays of 1, 2 and 4 seconds, then park errored; healthy sessions keep receiving signals during backoff. Repeated signals for an in-flight wake coalesce without losing subsequent work. Cancellation joins pending backoff without marking the session errored. Start over remains available for unreadable transcript/settle history and preserves old payloads in prior generations.

Resume refuses unreadable stored data with `SessionError.unreadableData(id)`, whose description directs the caller to Start over. A readable errored session still resumes normally. A terminal loop failure stops its in-memory pass even if error persistence fails; persistence failures are logged, not assertions.

An outbound `requestTooLarge(limitBytes:)` uses the existing out-of-band compaction path immediately, without backoff or dropping individual items. One payload compaction is allowed between successful inference commits; the budget survives pass exits, outages and intervening compactions. If the compactor itself rejects the payload or the next inference is still oversized, the session errors with `requestTooLargeAfterCompaction(limitBytes:)`, including during forced compaction. A successful inference resets the budget.

Before a kernel inference turn, context fullness at or above the configured soft threshold writes one ordinary context notification durably into the transcript, with its current percentage and timestamp. The subsequent request is rendered entirely from that transcript. Retries and re-entry into an unfinished turn, including service restart hydration, reuse that entry; successful assistant output follows it, and future turns may append a new notice. Budget-resolution awaits are cancellation/lifecycle-fenced before any live-state read or notification write. Reconnect, HTTP/SSE replay and restart hydration keep the historical entry verbatim. Compaction drops old pressure notices from retained tails in both model/bookmark and mechanical paths; the new generation can receive its own notice if still above the threshold. Old transcripts need no schema change; notices omitted by older builds cannot be reconstructed retroactively.

`capacityExceeded(code:message:status:)` is deterministic, not an outage. `websocket_backpressure` gets at most two retries between successful inference commits, then durably errors with the typed provider diagnostic, including during forced compaction. This runtime-owned budget survives inference-pass exits and mechanical compaction and resets only after a successful inference commit; outages and transient failures do not reset it. `response_too_large` and `websocket_message_too_large` use the same one-compaction-between-successful-commits budget as local oversized requests, without backoff; an oversized compactor or repeated rejection errors with the typed provider diagnostic. Real throttles retain the existing unbounded retry/Retry-After behavior.


Start over dismounts the live actor state and invalidates inference continuation, clearing live retry budgets and park wakeups while the store clears error/hold/run state and park reminders. It preserves queued deliveries, armed observations/timers/request deadlines, children and open requests. The next kernel generation opens with an empty-summary head carrying the durable subscription snapshot; pending queued deliveries wake it and reach its first inference. A bare head containing only subscriptions and a restart note remains inert (summary or pre-reads, rather than subscriptions, constitute head work). Detached scripts continue independently of the session actor.


The kernel `compact` tool refuses an empty or whitespace-only summary with the typed `CompactArgumentsError.emptySummary`, rendered as an ordinary model-readable tool failure; no generation is opened and the turn continues. Pre-reads do not waive the summary requirement. Its optional `model` (provider/model or a model group id) and `effort` name the target the next generation continues on; an empty model (`emptyModel`) or an effort without a model (`effortWithoutModel`) is the same kind of typed argument failure. A target is resolved before anything is written: refusal is an ordinary tool failure naming the target, nothing folds, and the turn continues on the current route. Mechanical compaction never carries a target. Start over resets retained requests' park-reminder pacing as well as live retry state, drops unreadable pending queue inputs with an explicit count in its note, and continues with readable pending input in its original order.

## Removed executor

The loop runs only kernel sessions. Boot errors every live stored `claude-code` session with "executor no longer supported", including idle agents; enqueue stores input without materializing an actor. Resume cannot clear that error. Start over onto a kernel provider uses the store path and preserves identity and retained queue/subscriptions. The retired discriminator remains decodable but is never executed.

Before tool dispatch, inference (including retries), idle decisions and mechanical compaction, the loaded transcript reconciles observation/timer state against the current durable registration IDs. A handler one-shot that retires without a wake stays silent: no delivery or inference is triggered, and its next unrelated turn no longer advertises the retired timer. Compaction filters carried subscription snapshots against the registrations in its write transaction, so retained tool results cannot resurrect a retired observation or timer. Request deadlines keep their existing delivery-driven semantics.

`SessionService.shutdown()` stops the assembly-started registry reaper and session actors, including when `start()` was never called. It is idempotent.

Live-state reads and work mutations by an ongoing loop pass are cancellation-fenced; pass-exit bookkeeping is fenced by mount identity. Archive, Start over, retirement and shutdown cancel the mounted looper before dismounting state; a pass resumed at an async helper boundary exits as cancellation, never reads dismounted state and never parks the session errored. A cancelled old looper cannot read a freshly remounted generation, update its idle/compact-claim bookkeeping, or clear its long-running work handle. Unarchive rematerializes on the next wake with a new looper.

A standing compact command is claimed against the hydrated generation, with nonempty instructions materialized idempotently into that generation in the same store transaction. The command remains pending until the forced assistant reply or mechanical compaction commits, and its acknowledgement is part of that same commit. Shutdown/eviction during claim or inference cannot lose an instructions-less command or its instructions. A replacement command is not acknowledged by an older claim. Start over deletes pending commands and discards already-materialized instructions with the old transcript; a stale generation cannot materialize or complete a claim in the new one.

Start over optionally carries a prepared `SessionModelRoute` through service/actor/repository to the store's single generation-reset transaction. It does not update the pin after resuming the actor. Ordinary compaction and lifecycle recovery preserve the pin in this slice.
## Replay binding boundaries

`ReplayBoundaryRequired` is a local pre-request safety boundary, not a provider failure or routing signal. The loop finishes committed kernel calls before attempting inference, projects a portable handoff, conditionally commits a new generation and binding, invalidates transport state, then resolves again before the next request. A credential identity change or adoption of legacy unscoped opacity therefore cannot send a source account's records to the next account. An in-flight compact command remains pending across the boundary and is reclaimed in the new generation. Boundary projection or storage failures durably park the session errored without ending its mounted looper; Resume can wake it again. Only real task cancellation dismounts the pass. No provider fallback is introduced.

## Owner boundary

Each `SessionActor` is given a session-scoped repository backed only by `SessionExecutionOwnerClient`; subscription refreshes use that same repository instead of reaching through it to `SessionStore`. Parent `SessionService` composition may supply an owner client explicitly, or use the existing in-process store adapter. Session placement, boot admission and archive coordination stay in the parent. This changes dependencies, not durable boundaries or lifecycle behavior.

## Execution placement seam

`SessionExecutionClient` is the registry-facing execution/lifecycle contract. `SessionExecution` implements it with local `SessionRegistry`/`SessionActor` instances and their liveness tracker. `SessionService(sessions:execution:archiveGrace:)` keeps boot scanning, work signals, archive reservations, subtree admission and persisted lifecycle state in the parent store while delegating registry verbs. Its original initializers construct the local implementation and preserve in-process behavior. A remote service has no parent actor registry. `SessionExecutionRetired` is the retryable dropped-callback outcome; boot and work-signal wakes share the bounded retirement/backoff policy. `enqueue` commits directly to the parent store, then best-effort wakes execution: a post-commit wake failure never escapes to invite input replay.

A strict `StaleCompactClaim` is command supersession, not a terminal session error: the loop reloads persisted hydration and continues with the replacement command. `LoopConfig.executionActivity` acknowledges active-pass admission before work and releases it through uncancelled cleanup; its default is a no-op for local execution.

## Compaction placement and last-resort route transitions

`prepareCompaction` runs after an ordinary compacted generation is produced, with the compact tool's requested target when there is one, and can supply a portable atomic route transition; nil preserves the route and history. A throw for a requested target is the refusal above, not a session error. `ReplayBoundaryRequired` optionally carries a replacement route and expected epoch; the loop projects locally, preserves receipts/input, commits handoff and pin together, invalidates inference state, then restarts the generation. `ModelRouteWaiting` is a nonterminal, cancellation-aware clock wait, never a reply/report or user timer subscription. Rehydration retains the persisted deadline and no new episode is opened merely by waiting. Route context notices do not answer obligations.

## Parent-owned park reminders

`SessionService` owns park-reminder deadlines independently of its execution actors. A settled actor may be evicted while a reminder is pending; expiry wakes execution through the service's execution client and hydrates fresh state before deciding whether a nag is still owed. Deadlines are derived from durable transcript/environment state on boot, requiring no new stored schema. Interrupt, successful archive and Start over cancel pending reminders; service shutdown cancels and joins them. Wake transport failures retry with injected-clock backoff and visibly error the session after exhaustion; failure persistence is logged.

`LoopConfig.scheduleWake`, when supplied, delegates scheduling and cancellation (`nil`) outside the actor. A standalone `SessionExecution` without this callback retains actor-local scheduling. Service-managed executions always use parent-owned reminders.

## Execution assignment handoff

`SessionExecution.yieldAssignment` closes admission for that session on this execution owner and waits until the current inference, tool or compaction operation and its durable writes finish. It does not cancel that work or start the next loop operation. Queued external lifecycle actions finish first; an archive reservation keeps the old assignment until released. End-of-pass owner activity must be acknowledged before release. Once released, later verbs are rejected as `SessionExecutionRetired` before any effect, rather than lazily rehydrating on the old execution owner. Cancelling a handoff waiter does not release a still-running assignment. Ordinary eviction remains independent of handoff.

## Deferred execution ownership

`SessionService(sessions:execution:archiveGrace:deferredSessions:)` may defer a fixed set of sessions until the space is reopened after another host is fenced. Wake and reminder scheduling are no-ops for those sessions; enqueue still persists ordinary input. Startup eligibility failures cannot mark them errored. Interrupt, resume, restart, unarchive and archive reject with `SessionExecutionDeferred` before execution or state mutation; archive preflights every descendant before reservations, so a deferred child cannot partially archive its parent subtree. Other sessions retain ordinary behavior.

## Cut model streams

`InferenceError.streamCut` uses the bounded transient retry schedule, without escalating the idle-timeout schedule. The cut attempt commits no assistant message or tool calls; a successful retry completes the turn without a human resume.
