# LoopCore

## Service ownership

`SessionExecution` is the sessions' runtime and the one thing the routes hold: it builds the scripts and the tool executor, and runs the loops on the space's worker (`Space.worker`: wuwei's shared backend over the space's own database). Nothing runs before `start`, which gives that worker the loops' kinds and their `LoopClient` and starts it (mail waits in the store, so main's API can be bound to the tools first; a second `start` does nothing), or after `shutdown`, which stops that worker. Session cells are therefore shared-backend only. Its verbs check what a verb needs before mailing it (existence, busy and archived refusals; permission is the routes'); the cell makes every write of a verb.

Every input is mail and returns once it is durable; nothing waits for the cell, so a verb's reply is computed by main, not read back. An input reaches the queue only through the cell: `put` queues it (on a topic it replaces the unseen input there; a `throttle` makes it due no sooner than that long after the model last saw the topic) and `clear` takes back the unseen input on a topic, each then mailing the cell a `look`, a step of its own. Main sends both as `SessionMail` rows in the transaction of whatever caused them (a post, a request, an observation delivery, a timer, an exec or script notice) and pokes the cell once that commits; mail nobody poked for is found by the worker's scan, which is also all a boot does. Until the cell has taken a `put`, the session's `work` does not show it. `look` has the cell look at its tables and tells the work at hand when to yield to what waits. `retitle` and `retag` write the record. `interrupt` writes the hold on a live, unheld, unerrored kernel session and stops its job. `resume` clears the hold or error, counts the resume and advances. Runtime `lost` mail for the current inference on a non-stopped session runs those same interrupt and resume transitions in one step, starting a fresh `step_try` address; stale, unrelated and stopped-session losses are ignored. The upgrade backfills creators for non-done inference jobs from their durable addresses, so pre-upgrade in-flight inference can take this path without decoding old params. Loss of a tool call or compaction is not recovered by this hook, and their creators are not backfilled. `archive` mails cancel to every script in the cell's run membership and stops its current job in the same step, marking the session interrupted if one was working, archives it and invalidates inference. `unarchive` and `restart` write, invalidate inference and advance; a restart finding a job working on an unstopped session (one started after main's check) is dropped, and queued input waits for the new generation. `cancel` stops the job and nothing else (a resume that could not read the session marked it errored). A verb the cell finds invalid (unknown session, grace expired) throws: its write rolls back and the mail is consumed. Archive (unless forced) and restart first read that the session is settled: the session stopped (interrupted, errored, not live) or with no mail on its way to its cell, nothing to do and no job working. Resume refuses unreadable stored data with `SessionError.unreadableData(id)`, whose description directs the caller to Start over.

## The session cell

`SessionCell` (id = session id) has no state beyond the session tables: every call hydrates the session, applies what it brings and advances it, writing through `SessionRows` on the cell step's own connection (the host's GRDB `Database`). What the session works on is the job named by the cell's write counter, its slot (generation, position): `<s>:<g>:<p>` for a `CompactionJob` and a `ToolCallJob`, `<s>:<g>:<p>:<stepTry>` for an `InferenceJob`. A job that exists works, except a step that ended cancelled or parked. A job's answer (`stepped`, `called`, `compacted`) for a slot the transcript has left, or for a session no longer live, is dropped.

Advancing writes every step that needs no job and stops at the first that does: a pending fold runs only on a delivery; then the next pending tool call (kernel tools `bookmark` and `compact(park:)` are written at once, `compact` starts a fold, `run_script` starts a `ScriptJob`, any other starts a `ToolCallJob`); then a queue drain; then work (the generation head's next re-establishing read, else a normal step); then, after a model stop, a nag. A nag due when the model stops is written with its reply, so the session never reads settled while it owes one. The work at hand learns when to give the turn back by mail, `yield(by:)`: a step or a tool call by the earliest grace of the due input it has not seen (from when that input came due: a person's message to the session itself 10 s, anything else 90 s, the session's own context deliveries none); a tool call started while input waits has it in its params. A compaction never yields. An input can be delayed (`due_at`) or put on a topic, which replaces the unseen input on that topic; until it is due it is not drained and does not count as work, The cell's `nextWake()` is the earliest of the next delayed input's due time, a stopped model's next park reminder (`NagState.nextTimer`), and the next cache-warming ping (the last reply plus its schedule's interval, and none while a ping is in flight: its reply re-anchors it); its `wake()` is a look, then that ping.

The cell keeps its next move in `session_state` (`SessionTurn`): generation; `position`, a write counter independent of line positions; `turn` = `inert` / `converting` / `model` / `tools(calls)` / `idle` / `folding(call)`; the head's unanswered `reestablish` reads; `replied`; and `nags`, the owed conversations and park-reminder backoff. Its other columns are `held` (scope-notice lines waiting behind the current reply's last tool result), `binding` (the generation's replay identity and epoch), `bookmarks` (names to stored line positions, with the empty name naming the last), `origin` (the latest substantive input's cache-warming classification), and `warming` (the last reply's warming schedule, the cell step time it landed at, and the pings spent since). The row is authoritative, never reconstructed or checked against a typed transcript; a generation roll carries `warming` and `origin` into the new turn, while Start over and restart write a fresh one. A missing row is seeded inert using a metadata-only line count; existing rows need no line read. Droppability is an EXISTS query used only at a pointer decision, against the generation before a reply is appended. Nags are initialized once when the turn row is read. Compaction and Start over leave nags unchanged. A scope notice flushes after the last answer, at a park or when closing the generation; a notice still held by the pre-cut runtime is not recovered.

`session_seen` (`Seen`) records files and their revision, instruction-bearing folders and git roots, and delivered instruction-text hashes with their first source paths. Its `position` is the tool result's line position. A fold keeps only file rows whose positions fall in the kept range and resets their positions to zero; folders and text deduplication reset. Start over keeps none. A tool call reads this state through the cell, not from historical messages.

`session_armed` (`Armed`) records timers, observations and streams armed through tools. `SessionExecution.arm` / `disarm` call the cell after main checks arguments and query baseline: the step records the answer and arms or cancels once. A repeated call gets its recorded answer. A missing subscription produces `notFound`. Slots that end themselves notify their owner or are forgotten when their ending delivery drains. Generation heads snapshot these rows, and a plain timer suppresses an open-request park reminder; handlers and observations may stay silent and do not. Compaction and Start over keep armed rows. A session predating them fills them from the subscription stores at its first step.

A legacy generation has `session_pointers` but no transcript lines. Its first step with anything to do (queued input, an owed turn, a job at the current slot or a due nag), or any old job answer, starts one `legacy` compaction, after incrementing the slot counter and marking the row `converting`. It drops old job answers without decoding typed items. A restarted old inference or nonlegacy compaction job detects its own legacy generation, finishes without running an inference or fold, and mails `look`; the cell converts it. The new head explains the cut and names `SELECT generation, position, kind, payload FROM session_legacy_items WHERE session_id = '<id>' ORDER BY generation, position` for history. The frozen old tables are otherwise unread. Pre-cut compaction answer mail with an incompatible payload is consumed without conversion; interrupt followed by Start over recovers a session left at its completed compaction slot.

## Inference

An inference step is an `InferenceJob`. It reads the generation's stored lines (`LoopClient.lines(session, generation)`) before every attempt and owns the attempts, their records, the waits between them and the outcome; a wait is kept as an absolute `retryAt` with its jitter, so a restart waits out the rest of it. Every outcome ends the job, and a step that already ended answers again with that outcome, so a reply is never paid for twice. A resume increments `stepTry`, so the step after it is a fresh job.

A cache-warming ping is an ordinary step with `ping` set, which the cell sets while the latest substantive input was a warming notice (the notice's own step and its tool continuations). It makes one attempt: any failure ends it as `pingFailed`, never a retry, a park or a recorded route failure, and the cell ends warming and leaves the session idle with the notice as an unanswered line. Its reply carries the next warming schedule.

A step first checks the compaction thresholds: at or past hard it answers `full` and the cell starts a pointer compaction; past soft with no pending pressure notice it answers `full` and the cell writes one context notice with its percentage, which retries and restarts reuse. A reply carries its fullness: a model that stopped past the hard threshold gets the same before anything else. So do `contextTooLong` and `requestTooLarge`. A generation that holds only its head and pressure notices has nothing a pointer could drop: past the hard threshold (before a step, or by the usage of the reply to it), or refused by the provider for size (`contextTooLong`, `requestTooLargeAfterCompaction(limitBytes:)`), it errors the session instead, so a prompt that does not fit its model cannot loop. `capacityExceeded` is handled as `requestTooLarge`.

`InferenceReply.committed` receives the assistant entry (provider ids replaced by kernel ids, their map kept) before the job answers; the cell then renders and writes that entry once. Reply fullness is API total tokens divided by usable tokens; cache expectation uses the last line carrying inference metadata. It is never invoked for a failed or cancelled attempt.

An outage (a throttle or an unreachable network) retries without bound. A throttle that carries `retryAt` (from `Retry-After`, resolved against the injected `\.date`) waits until that instant, at most one hour, drawing no jitter; a `retryAt` not in the future counts as absent and backs off exponentially with full jitter up to 300 s. Idle timeouts escalate 120 s, 300 s, 900 s and park after the third in a row; other unretryable failures park after eight. `streamCut` uses the bounded transient schedule. Waits run on the injected clock and end on `interrupt` or at the step's yield deadline; a step cancelled while it waits out a retry keeps the rest of that delay, which its next start waits out.

## Tool calls and compaction

A tool call is a `ToolCallJob` with the generation's shown state. Its non-exec calls run through a LoopClient effect. Read-only file tools (`read`, `find`, `grep`, for space, system and machine paths alike) keep bounded materialized output only in that effect: on a roll they discard its uncommitted output, including a canceled effect's late success, and return unfinished, and the replacement job repeats the whole effect even when its row was already started. The direct session file mutation tools are `write` and `edit`; the broader HTTP/CLI/script filesystem verbs (`copy`, `rm`, `mv`) are not ToolCallJob calls. A finished mutation success is answered and committed even if its task was canceled while draining: a known result is not replaced by an unknown one or a repeat. A canceled finished failure cannot reliably distinguish a drain/socket failure from an independently failed operation, so it remains unanswered, like a canceled throw. Started unanswered `write` and `edit` calls never repeat: the replacement answers `unavailable` with an `outcomeUnknown:` prefix and directs the caller to read the path before retrying. This policy intentionally covers both space and machine `write`/`edit`, not just remote mutations. Interrupt still answers interrupted rather than repeating the effect; yield still reaches the running effect. Other tools finish their bounded work on quiesce where appropriate, and otherwise answer `serverRestarted`; a start finding one of those calls started and unanswered does the same. Exec is direct mail to `MachineCell`: the job persists machine/op identity, the absolute wait deadline and the earliest yield deadline, commits that identity and those deadlines with its one start mail, and receives finished, yield or interrupt. Taking finished mails taken in the same step as its one tool answer. Drain cancellation propagates without an answer or handoff; the replacement job resumes the committed wait, taking any already-queued finish, without preparing or starting the command again. An exec crash before committing its start intent reruns preparation. Only reaching the original wait/yield deadline mails detach and answers running; a background finish is then a session notification. Exec never answers serverRestarted for a roll. Interrupt mails only abandon, answers interrupted and suppresses any later exec-end notice. The cell, not the tool job, owns remote deadlines, output progress and the bounded tail. `run_script` bypasses ToolCallJob and belongs to ScriptJob: a script may yield its running result, but a restart ends it without rerunning it, even when it called a mutating HTTP/script filesystem verb. That script-level lifecycle is separate from direct write/edit result handling.

A `CompactionJob` folds the generation its id names: the model's `compact` call (`fold`), a pointer (`pointer`: no inference, no summary and nothing kept; the head's summary is `SessionPrompt.pointerSummary`, which names the closed generation's files under `/_/session-transcripts/<id>/`) a legacy pointer (`legacy`), or a portable handoff (`handoff`). Nothing forces the model to compact: there is no forced step, no pinned tool choice and no compact verb for a person. It gathers what lies outside the session (running work, the requests the session awaits with when each task last reported, placement through `prepareCompaction`, open requests) into the next generation's head; the cell writes it and invalidates inference. The new generation's turn is the model's. A compaction that fails errors the session.

The kernel `compact` tool refuses an empty or whitespace-only summary with `CompactArgumentsError.emptySummary`, as an ordinary tool failure; pre-reads do not waive it. A named bookmark must precede the assistant reply holding the compact call; a bookmark in that same reply is an ordinary tool refusal before either folding or parking. The cell validates this from stored positions; the compaction job treats an absent or later bookmark as an invariant violation. Its optional `model` (provider/model or a model group id) and `effort` name the target the next generation continues on; an empty model (`emptyModel`) or an effort without a model (`effortWithoutModel`) fails the same way, and a target `prepareCompaction` refuses is a tool failure naming it: nothing folds and the turn continues. With `park: true` (not with `model`: `parkWithModel`) the tool writes only its closing result and the turn row is `folding(call)`: no work, pending calls, nags or compaction. Park is refused with `ParkRefusal` while the session owes an owed reply (`owesReply`) or an open request's final report (`owesReport`). The next delivery runs the fold first, so the delivered input lands in the next generation.

`ToolRosterChanged` ends a normal step with `roster`: the binary's tools differ from the generation's stored list (a tool added, removed or changed), so the cell appends one `tool-roster` context notice naming them and starts the next step, which sends the stored list as before; the notice's text is its own key, so a generation hears of one binary once. `ReplayBoundaryRequired` ends a step with `handoff`: the cell starts a handoff compaction, which writes a pointer head, an account-neutral recent tail of at most 8192 estimated tokens, and a replay-handoff notice into a new generation and binding. Carried lines lose inference metadata; portable assistant content replaces encrypted reasoning with its readable summary or nothing and hosted records with digests. It carries no older digest or protected input bodies and performs no destination-fit gate; the next step resolves again. A compaction placement that cannot fit its kept tail drops the tail instead.

## Streams

A session's `url` observation without a handler is a `StreamJob` the cell creates in its `arm` step at `<session>:<subscription>`, its row in the job's `streams` table (url, armed at, last event id and the outstanding event id), which the `subscriptions` view, Start over's `<session-state>` and `cancel` read. The job dials `LoopConfig.sources` with `Last-Event-ID` set to the last event its owner acked, and sends its owner one event at a time as `Streamed.streamed`, typed by a retyped `Recipient`: the next only after `acked`. The cell appends the event to the unseen input on the subscription's topic (the first one due no sooner than the throttle past the last the model saw) and acks at once. Sending an event and recording its outstanding cursor commit together; taking its ack, advancing the cursor and clearing the outstanding cursor commit together. A restarted job waits for that outstanding ack before it dials or sends again, including when the ack is already queued. If the owner's streamed step throws, consuming the mail without acking, the stream stays silent until cancelled; the job does not resend. All source events are sent, including repeated or inherited ids; an empty id resets the cursor to empty. This applies to handler streams as well as plain streams; a handler acks only after successful firing. A drop, a 408/429 or a 5xx redials with backoff from 1 s to 5 min, at least `Retry-After`; any other answer deletes the row and sends one ending notice. The cell's `disarm` step and `archive` mail `stop` to the job, which deletes its row; an event that finds the session archived stops it too.

## Transcript lines

`TranscriptTail` is a socket to the session cell carrying the generation's lines (`session_lines`) as the store wrote them; `SessionExecution.lines(_:after:as:)` attaches one, and its stream ends when the cell closes it. On attach the cell closes the socket of a viewer who does not read the session's group (`GroupCell.reads`, the rule `SpaceCell.readable(by:)` and the routes filter by; not `GroupCell.role`, which gives the anonymous --dev seat nothing and a page its own group's role, where reading goes by its viewer); otherwise it sends `reset(generation, lines)` with every line of the current generation or, when the opening's cursor names the current generation, the lines past it plus the prompt lines (`StoredTranscriptLine.isPrompt`), which the store writes into the first positions after later ones. Every call of the cell, whichever handler it reaches (`around`), marks where the lines end before it runs, when a socket listens, and sends what it wrote after: the new lines, or a reset with the whole generation when the generation changed. Main stores the prompt lines during an inference, outside the cell's calls, so `stepped`, until the generation has a reply of its own (`replied` on the turn row, read before the reply is written), sends the generation's prompt lines again before it writes the step's outcome: a late prompt reaches a live tail with the first reply, and later steps do not repeat it (a tail attached since gets the prompt lines on attach or reset). Before every send the cell checks the viewer again and closes the socket of one who no longer reads the group. Attempt deltas are not on the socket.

## Removed executor

The loop runs only kernel sessions. A stored executor other than `kernel` is retired: its cell queues what it is sent and runs nothing, interrupt is a no-op, resume and unarchive are refused with `ExecutorUnavailableError` ("executor no longer supported"), and its transcript reads empty. Start over onto a kernel provider preserves identity and retained queue/subscriptions.

## Archive

`SessionExecution.archive(id, force:)` walks the live sessions of the parent-chain subtree, best effort; only the root's archive rights are checked. Without force, every one must be settled (`revoke(.whenSettled)`; retired sessions are never busy), else nothing is mailed and `SubtreeArchiveBusy` names every busy session by id and title. Then, for each, main closes its open requests with a final-kind message saying the session was archived before reporting, trims its slots (retiring ones and handler firings) and mails `archive`, which also stops its streams. A session that turned busy after the check is archived anyway, as with force; one created during the walk is missed.

## Park reminders

The space's worker runs on SpaceCore's `DependencyScheduler`: wuwei's live scheduler on the injected `\.date` and `\.continuousClock`, so `client.now()`, wuwei's timers and the store read one clock and a test that moves time moves all three. A stopgap until the store and main run on wuwei.

## Telemetry

The loop emits no spans of its own; `model.attempt` spans come from the inference closure, with the cache expectation the transcript's last reply predicts.

## Shutdown

`SessionExecution.quiesce()` quiesces the space worker and closes scripts without releasing leases. `shutdown()` is a full stop: it quiesces, then releases leases through `Space.stopWorker()`, so another worker in the same process can restart immediately.

`SessionExecution` supplies each tool client with a credential factory taking the session and the call's declared lifetime; it does not cache a session-wide bearer.

Handler SQL slots are reconciled by `ObserverCell.look` from their existing `subscription_slots` row: its own durable `observer_watched` row makes a repeated look silent, while arm/pause/cancel/end sends exactly the required watch/unwatch to the space's `ObservationJob`. The job echoes the callback incarnation; the observer validates it before converting rows to handler input. Plain SQL slots are armed/unwatched by their session cell, which validates incarnation once per reply and converts rows to queue input; children replies retain the errored-id marker and quiet recovery policy. Throttles remain at the owners, not in the SQL watches. A slot that ends on an archived owner's firing unwatches in that same owner step.

`SessionCell.rewatch`, used only by migration 035, is removed; no live sender remains.

## Script runs

`SessionCell` mints `script.<8hex>` and creates `ScriptJob` (`<session>:<handle>`) directly for each `run_script`, with `session_scripts` membership in the same step. Handle minting skips every existing job id, including tombstones. Membership stays after the initial tool answer and is removed only by the job's last `scriptEnded` mail. Running-work snapshots read this membership, and archive cancels every member without waiting. Before archiving, the cell resolves an unanswered current script call with an interrupted tool result in that same step, so unarchive/resume cannot rerun it. `scriptAnswered` uses the ordinary tool-answer writer; it and `scriptPosted` drop deliveries to an archived session, while `scriptEnded` still removes membership.

The immutable caller, handle and tool call stay in job params. The job owns `script_runs`: phase, absolute wait/lifetime/yield/kill deadlines, answered/resulted markers and delivery progress. One structured effect evaluates JavaScript; results and updates return as job mail. The first result answers the tool, or the wait/yield timer answers running and the later result becomes a notification; updates remain ordered. Answer/post/end mail is staged before the row write carrying its progress. Cancel only reads the owned run's row, mails cancel and returns abort signalled; the job allows five seconds of cooperative abort before interrupting the engine, at cancel and lifetime alike. Ended rows remain tombstones for alreadyEnded across restart.

Drain cancels and awaits the runtime and commits its terminal mail. A new incarnation seeing running never evaluates JavaScript again: it ends with the restart tool failure if unanswered, or one restart notification if already answered, never both. Machine operations are not tracked or released by this job: teardown closes its ExecSessions. MachineCell owns callerGone on stream close and orphan detection on a replacement wake; unopened reservations expire after 60 seconds. HandlerJob's at-least-once firing, retry, lifetime credits and wakes stay independent; command scripts remain scoped to their command caller.

## Session handlers

`SessionExecution.init` provides the loop client and registers the session/observer cells and jobs on the space worker; `start()` starts its scan. There is one execution composition per worker. Host session handler functions are defined in LoopCore, with same-name `SessionStore` APIs; SpaceCore retains no session-cell-dependent host implementation. `SessionEffects` carries creation and named-observer operations into MainHub as an explicitly injected client.

Creation validates its input and reads parent liveness/depth, admits an observer firing in that observer cell, allocates a session name through `Space.allocate`, then calls the newborn session cell once. That step inserts the session, runtime, route/history and optional generation head and mails the parent to watch its children; the prompt row stays absent until first inference. No transaction spans addressables. A crash after allocation burns a name; a crash after admission consumes its hourly unit; a parent archived after the read still receives the child.

Route/history and prompt revision maps are cell reads; prompt invalidation and error marking are mail. Inference produces the prompt/route proposals, so their host APIs are inference-specific: `promptForInference`, `storeInferencePrompt`, `establishInferenceModelRoute` and `updateInferenceModelRouteFailure`. They use read handles and mail, never a local `worker.call`: an inference job may be hosted separately from its session cell. A committed matching prompt or held route wins; otherwise the one inference job for the turn answers with its proposal and mails the session before its outcome. Missing-prompt activation reads the acting/readable groups’ revision map through the space cell in one grouped journal statement, then captures generation and opening policy and mails that exact pending prompt; no journal is read on delivery. Compaction, Start over and explicit post-template invalidation delete the prompt row in the session step; the next inference captures the new map. Rendering stages blob bytes outside the cell; its mail stores only a still-pending matching generation/map and never replaces a winner. Route establishment retains the existing write checks; failure mail applies only to the expected current epoch. Tool-context prompt lookup reads the rendering already stored by the preceding inference. No call-only variants remain.

A group's observer is keyed by group and name, not its generated subscription id. Arm/cancel are calls on that cell; a standing armed name refuses, a paused name may be rearmed. The cell counts its own committed admission timestamps over the last hour, pauses at its cap and returns the refusal so the pause commits. Original subscription identity accompanies handler answers and group stream-job keys, so a firing that finishes after cancel/rearm cannot change the replacement slot. Session subscription arming is a session-cell call; cross-owner subscription lists are reads of the space cell.

Tool mutations never rerun after a lost job effect. There are no session or API answer receipts and no template-clone recovery debt. An unfinished creation reports the created session; a new call is a new operation. Message/request/report identities derived from call ids remain independent of removed receipts.

`registerSessionCells(in:)` provides the space's `SessionStore` and registers only the session and observer cells, once per unstarted worker. `SessionExecution.init` uses that same registration before providing its loop client and jobs. Offline provisioning can create idle, parentless agents without starting jobs or composing execution; cell clocks read the worker scheduler directly.
