# ComputerFiles

Desktop-only `read.v1`, `find.v1`, `grep.v1`, `stat.v1`, `list.v1`, `write.v1`, `mkdir.v1`, `remove.v1` and `move.v1` kinds register through `fileOperationKinds(files:)` and use only the common operation verbs. They do not depend on v1, exec or supervisors. `ComputerFileSystem` is an injected async streaming companion to VirtualFileSystem, whose existing children/readData methods materialize entire directories/files and therefore cannot implement these bounds. Local effects run on a dedicated Dispatch IO queue, not the operation control actor. One blocked effect per operation can remain in the kernel until it returns; cancellation cannot preempt a kernel syscall. Runtime admission bounds outstanding operations; cancellation is checked before the next effect or publication and on every directory entry, including excluded symlinks. The walk awaits the operation cancellation check between individual directory effects, so protocol stop and local lease expiry interrupt a single next() without relying on Task.cancel().

Read accepts an absolute regular-file path, decimal-string offset/length and optional ifMatch. Reads are at most 64 KiB, at explicit offsets, and await bounded channel publication before the next read. A version includes device, inode, size, mtime and ctime at nanosecond precision; the path is checked before and after every read and at completion. Mutation/replacement is fileChanged (412), never claimed as an immutable snapshot. Already-consumed prefixes are not retracted on failure. A bounded requested range uses the same kind; no separate shortcut endpoint is installed. The result is version, decimal byte count and reachedEOF.

Find walks in native unsorted traversal order and publishes one path/kind record at a time. `*` does not cross a slash; `**` does; `?` matches one non-slash UTF-8 byte. `**/` also matches zero directories. Patterns are bounded to 4096 UTF-8 bytes and evaluated by bounded dynamic programming, never a regex engine. Symlinks are included only when requested and are never followed. Traversal retains at most 128 open directory frames, with 4096-byte paths; depth overflow is capacityExceeded. An inaccessible or symlink-excluded root is a typed error, never an empty success. Nested unreadable directories and entries are skipped and counted. Search roots strip trailing slashes before the no-follow check. Traversal uses fstatat/openat relative to held directory descriptors; regular-file entries carry a bounded ComputerFile reference anchored to that parent descriptor. Grep reads and verifies that reference, not a reopened absolute path. Replacing or renaming a parent cannot redirect traversal or reads outside the opened tree. Symlinks are never followed even during an open race. The walk does not materialize or sort directory contents.

Grep advertises `literal` and `regex` dialects. Regex uses Foundation NSRegularExpression (ICU), preserving v1 syntax, Unicode character classes, inline flags and case-sensitive defaults. Patterns are at most 4096 UTF-8 bytes and compile before admission; invalid syntax is invalidInput, an unsupported dialect is unsupportedDialect, and neither performs filesystem effects. The matcher imports only NSRegularExpression and NSRange from Foundation; these corelibs types are not supplied by FoundationInternationalization on Linux. ICU linkage remains the deliberate v1-parity dependency. Reads are at most 16 KiB and lines are incremental, bounded by maxLineBytes (1...65536). Newline separators are excluded from exact UTF-8 line records; carriage returns are retained. Binary (NUL or invalid UTF-8), oversized lines/encoded records, changed files and unreadable files are skipped so neighboring text remains searchable. The completed result includes `skipped` integer counts keyed by binary, oversized, changed and unreadable; find includes applicable traversal counts too. A prefix already published before discovering a later file problem is not retracted. Output publication suspends before scanning more lines; prefetched bytes are bounded by one chunk plus one line. File-version changes are checked around each read. Cancellation/deadline checks occur between files and reads and during matching; output and encoded-record caps still apply. Regex matching runs outside the operation-control actor in a structured child task. Its ICU `.reportProgress` callback stops enumeration when that task is cancelled; a sibling checks the operation cancellation and local lease every 10 ms and cancels the match. The scope joins both children before returning, including shutdown. Operation stop/deadline and 60-second lease expiry therefore interrupt pathological backtracking rather than leaving an unattended match. A cancelled matcher throws typed requestCancelled; the common runtime publishes its existing stopped verdict/reason for protocol stop or lease expiry, while caller deadline remains the client's typed callerDeadline failure. Linux and macOS tests exercise `(a+)+$` on a 32 KiB adversarial line and require stop/lease terminal evidence plus orderly shutdown within two seconds.

Entry limits in find/grep count all yielded walk entries, including directories and nonmatches. Reaching the cap calls OperationCancellation.stop(reason: "entryLimit"), producing a real stopped verdict, not a completed page/cursor. A cap exactly equal to the number of entries is still limited because no speculative extra traversal proves exhaustion. Without matchLimit a caller limits matches/bytes by stopping consumption. Optional matchLimit/resumeEntries/resumeLine inputs enable completed bounded pages with nextEntry/nextLine; resumeEntries counts the same yielded walk entries, including directories, and resumed entries do not consume the new page budget. Directory entries never match. Pages follow native traversal order, and concurrent tree changes can skip/repeat entries.

Named production Handler/client examples cover range exactness/mutation, incremental lines and explicit skip counts, traversal order and limit stop, invalid syntax/unsupported dialect refusal before effects and ICU Unicode parity, full-window suspension with responsive state/stop, and desktop live regular-file smoke on Linux/macOS. No process/service behavior is claimed by these tests.

## Filesystem parity

`ComputerFileOperations` injects asynchronous stat/list/write/mkdir/remove/move effects alongside the existing streaming read/walk effects. Stat returns MachineContract entry metadata using the same opaque version as read. List holds one directory descriptor, emits one metadata record per entry (including symlinks themselves), and does not sort/materialize the directory on the agent. Its result is a decimal count, so a large directory is not constrained to a 64 KiB result. The client compatibility adapter sorts a bounded materialized listing for v1 consumers.

Write consumes at most 64 KiB of input at a time into an exclusively created sibling staging file. Start input declares length and SHA-256; mismatched bytes, a missing end or failed digest cannot publish the target. It checks optional ifMatch before staging and again immediately before commit, rejects nonregular existing targets, requires write access to an existing regular target without truncating it, preserves existing mode bits, syncs the staging descriptor and renames it into place. The writer exposes a preparation phase for metadata/fsync separately from its rename commit. Protocol/task cancellation is checked after preparation and immediately before rename; a stop during slow fsync removes the stage and leaves the target unchanged. Rename is the commit point: after it succeeds, the kind publishes immutable completed/written evidence even if stop or lease expiry arrived during the non-preemptible rename or before publication. Tokens are opaque and shared with stat/read; stale or missing entries with an expected token fail fileChanged. A nil token retains the v1 machine VFS's unconditional write semantics; the normal tools enforce their read-before-write policy above this adapter. Before the commit point, stop/lease/cancellation closes and unlinks the stage without replacing the target. A process crash can leave an unused randomly named stage; filesystem kinds do not claim exec-supervisor restart recovery. Like v1, token check and filesystem mutation are separate syscalls, not an atomic conditional write against unrelated local writers. Local writers serialize token comparison, rename and receipt generation per parent directory across all local filesystem instances in this process. The lock key is the opened parent directory’s device/inode, stable across target replacement and shared across all local filesystem instances. Sibling commits deliberately serialize, including case-folded and Unicode-equivalent basenames on filesystems that equate them, without guessing volume normalization rules. Parent-directory aliases share the lock; different directories remain independent. Lock entries are retired after the last holder or waiter leaves. This does not coordinate external processes or mutations outside the local writer.

Mkdir creates intermediate directories. Remove recursively unlinks without following symlinks, with a 128-directory depth cap and cancellation between entries; a stopped recursive removal may have removed a prefix. Move uses the platform's exclusive rename primitive and refuses any existing destination, including a dangling symlink. Local mutations pin parent directory descriptors before acting; list and recursive remove open final directories with O_NOFOLLOW. Read/search's existing ancestor semantics remain: an explicitly addressed parent's existing symlinks may resolve during initial parent open, but a swapped final symlink is never followed by data reads, listing or write. Recursive descent stays relative to opened descriptors. Root stat/list/mkdir are supported; deleting, moving or replacing the root is invalidInput. Local IO errors retain errno in typed fileUnavailable details, allowing the compatibility client to distinguish notFound, conflict and io without parsing messages.

Metadata kinds run their effects in a structured child with a cancellation watcher; protocol stop and lease checks cancel the child between disk effects, including during recursive removal. A kernel syscall itself is not preemptible. Tests drive the production Handler and OperationClient through all six kinds, large streamed input/listing, exact injected-effect replay, a lost input receipt with one start and no duplicated bytes, owner reuse/payload conflicts, token recheck, no-follow symlinks and stopped/expired/bad-digest stage cleanup. The same desktop cases run in Linux and macOS pool tests.

Source metadata lookup failures carry a lookup marker distinct from mutation failures. The compatibility adapter maps failed stat/remove/move-source lookup (including ENOTDIR and EACCES) to v1 notFound, while a supplied stale/missing remove token remains conflict and mutation permission failures remain io.

The notFound compatibility category requires an explicit failed-lookup marker, never ENOENT alone: missing destination parents for write/move remain io. Read/list first establish metadata existence; missing/inaccessible metadata lookups are notFound, while failed data/directory opens after a successful lookup remain io.

## Machine composition

`ComputerAgent(machine:files:kinds:external:audit:)` is the computer machine's Handler, usable without exec, supervisors or NIO (the App Store Mac build links only this). It serves the file kinds over the injected `ComputerFileSystem` (a mount table, granted roots or `/`), extra in-process `AnyOperationKind`s and at most one `ExternalKind` whose operations live outside the process (exec supervisors, composed by ExecSupervisor). Kind names are unique across all three, or init fails; the combined registry passes the same descriptor checks an `OperationAgent` applies (`OperationAgent.validate(descriptors:limits:)`), and the external reservation must lie in `0 ... 64 MiB`. Only the `ExternalKind` type and its init are public. The external backend's usage must be nonnegative (otherwise describe and start fail `supervisorUnavailable`), and admission sums use checked arithmetic, an overflow reading as `capacityExceeded`. Describe lists the external kind first, then files, then the extra kinds in the given order. One authorization gate (the path's machine id), one admission budget (4,096 receipts, 64 MiB; no active-operation cap) covering in-process, external and not-yet-returned starts with a generation guard, and operation-id routing: an id the external backend owns goes there, everything else to the in-process runtime; neither can adopt an id the other holds. `leave()` refuses new starts, stops in-process work, asks the external backend to leave, waits for both to settle and then for the server's `?leaveAck=true` describe, all within one lease; the timeout and loss semantics are ExecSupervisor's ("Authenticated installed runtime composition"). The optional `audit` callback sees each admitted start once, in-process or external, after the backend answered 201: an `AdmittedStart` with operation id, kind, input and the server's `StartRequest.caller` (nil when no session caused it). It is the hook for the app's local Activity list; the caller is display-only and never authorizes. Black-box tests cover extra kinds over injected files, audit of admitted starts with their caller, shared admission with an external backend, unique names, external descriptor/reservation validation, invalid and overflowing usage, and the in-process leave handshake.
