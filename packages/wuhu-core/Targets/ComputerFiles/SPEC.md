# ComputerFiles

Desktop-only `read.v1`, `search.v1`, `stat.v1`, `list.v1`, `write.v1`, `mkdir.v1`, `remove.v1` and `move.v1` kinds register through `fileOperationKinds(files:)` and use only the common operation verbs. They do not depend on v1, exec or supervisors. `ComputerFileSystem` is an injected async companion to VirtualFileSystem (whose children/readData materialize entire directories/files): ranged reads, metadata effects and a FileSearch source per search root. Local effects run on a dedicated Dispatch IO queue, not the operation control actor. One blocked effect per operation can remain in the kernel until it returns; cancellation cannot preempt a kernel syscall. Runtime admission bounds outstanding operations; cancellation is checked before the next effect or publication.

Read accepts an absolute regular-file path, decimal-string offset/length and optional ifMatch. Reads are at most 64 KiB, at explicit offsets, and await bounded channel publication before the next read. A version includes device, inode, size, mtime and ctime at nanosecond precision; the path is checked before and after every read and at completion. Mutation/replacement is fileChanged (412), never claimed as an immutable snapshot. Already-consumed prefixes are not retracted on failure. A bounded requested range uses the same kind; no separate shortcut endpoint is installed. The result is version, decimal byte count and reachedEOF.

`search.v1` runs one FileSearch page (find or grep, the engine and its budgets are FileSearch's) over the local disk and returns it as the bounded result; it publishes no records. Input is the flat `SearchQuery` and nothing else; `validate()` refuses a bad pattern, glob, limit or step at admission with `details.search` naming the SearchError code (invalidInput), before any effect. A missing root is fileUnavailable, the 30 s deadline kindFailed, both with `details.search`. The local source follows the root if it is a symlink; below it every path is reached by `openat` from the root one `O_NOFOLLOW` component at a time, so a directory swapped for a symlink mid-walk is unreadable, never a way out. Ancestors' `.git` and `.gitignore` files are opened as they are. Hidden means a name starting with `.`. A listing reads the directory in one pass keeping at most twice the requested names, and stats only those it returns. Each disk effect runs on the Dispatch IO queue and is abandoned, not awaited, once the search is cancelled; an abandoned effect runs to its end and holds one admission receipt until then. Files are read with `pread` on a held descriptor, taken inside each read's effect and closed only after its last read, so a read abandoned before it ran never holds it. Protocol stop and lease expiry are not task cancellation: a sibling polls the operation cancellation every 10 ms and cancels the walk, which also stops an ICU match stuck backtracking.

Named production Handler/client examples cover range exactness/mutation, search paging, gitignore and hidden names, symlink containment, unreadable neighbors, ICU syntax, query refusal at admission, deadline and stop/lease ends, full-window suspension with responsive state/stop, and desktop live regular-file smoke on Linux/macOS. No process/service behavior is claimed by these tests.

## Filesystem parity

`ComputerFileOperations` injects asynchronous stat/list/write/mkdir/remove/move effects alongside the existing streaming read/walk effects. Stat returns MachineContract entry metadata using the same opaque version as read. List holds one directory descriptor, emits one metadata record per entry (including symlinks themselves), and does not sort/materialize the directory on the agent. Its result is a decimal count, so a large directory is not constrained to a 64 KiB result. The client compatibility adapter sorts a bounded materialized listing for v1 consumers.

Write consumes at most 64 KiB of input at a time into an exclusively created sibling staging file. Start input declares length and SHA-256; mismatched bytes, a missing end or failed digest cannot publish the target. It checks optional ifMatch before staging and again immediately before commit, rejects nonregular existing targets, requires write access to an existing regular target without truncating it, preserves existing mode bits, syncs the staging descriptor and renames it into place. The writer exposes a preparation phase for metadata/fsync separately from its rename commit. Protocol/task cancellation is checked after preparation and immediately before rename; a stop during slow fsync removes the stage and leaves the target unchanged. Rename is the commit point: after it succeeds, the kind publishes immutable completed/written evidence even if stop or lease expiry arrived during the non-preemptible rename or before publication. Tokens are opaque and shared with stat/read; stale or missing entries with an expected token fail fileChanged. A nil token retains the v1 machine VFS's unconditional write semantics; the normal tools enforce their read-before-write policy above this adapter. Before the commit point, stop/lease/cancellation closes and unlinks the stage without replacing the target. A process crash can leave an unused randomly named stage; filesystem kinds do not claim exec-supervisor restart recovery. Like v1, token check and filesystem mutation are separate syscalls, not an atomic conditional write against unrelated local writers. Local writers serialize token comparison, rename and receipt generation per parent directory across all local filesystem instances in this process. The lock key is the opened parent directory’s device/inode, stable across target replacement and shared across all local filesystem instances. Sibling commits deliberately serialize, including case-folded and Unicode-equivalent basenames on filesystems that equate them, without guessing volume normalization rules. Parent-directory aliases share the lock; different directories remain independent. Lock entries are retired after the last holder or waiter leaves. This does not coordinate external processes or mutations outside the local writer.

Mkdir creates intermediate directories. Remove recursively unlinks without following symlinks, with a 128-directory depth cap and cancellation between entries; a stopped recursive removal may have removed a prefix. Move uses the platform's exclusive rename primitive and refuses any existing destination, including a dangling symlink. Local mutations pin parent directory descriptors before acting; list and recursive remove open final directories with O_NOFOLLOW. Read/search's existing ancestor semantics remain: an explicitly addressed parent's existing symlinks may resolve during initial parent open, but a swapped final symlink is never followed by data reads, listing or write. Recursive descent stays relative to opened descriptors. Root stat/list/mkdir are supported; deleting, moving or replacing the root is invalidInput. Local IO errors retain errno in typed fileUnavailable details, allowing the compatibility client to distinguish notFound, conflict and io without parsing messages.

Metadata kinds run their effects in a structured child with a cancellation watcher; protocol stop and lease checks cancel the child between disk effects, including during recursive removal. A kernel syscall itself is not preemptible. Tests drive the production Handler and OperationClient through all six kinds, large streamed input/listing, exact injected-effect replay, a lost input receipt with one start and no duplicated bytes, owner reuse/payload conflicts, token recheck, no-follow symlinks and stopped/expired/bad-digest stage cleanup. The same desktop cases run in Linux and macOS pool tests.

Source metadata lookup failures carry a lookup marker distinct from mutation failures. The compatibility adapter maps failed stat/remove/move-source lookup (including ENOTDIR and EACCES) to v1 notFound, while a supplied stale/missing remove token remains conflict and mutation permission failures remain io.

The notFound compatibility category requires an explicit failed-lookup marker, never ENOENT alone: missing destination parents for write/move remain io. Read/list first establish metadata existence; missing/inaccessible metadata lookups are notFound, while failed data/directory opens after a successful lookup remain io.

## Machine composition

`ComputerAgent(machine:files:kinds:external:audit:)` is the computer machine's Handler, usable without exec, supervisors or NIO (the App Store Mac build links only this). It serves the file kinds over the injected `ComputerFileSystem` (a mount table, granted roots or `/`), extra in-process `AnyOperationKind`s and at most one `ExternalKind` whose operations live outside the process (exec supervisors, composed by ExecSupervisor). Kind names are unique across all three, or init fails; the combined registry passes the same descriptor checks an `OperationAgent` applies (`OperationAgent.validate(descriptors:limits:)`), and the external reservation must lie in `0 ... 64 MiB`. Only the `ExternalKind` type and its init are public. The external backend's usage must be nonnegative (otherwise describe and start fail `supervisorUnavailable`), and admission sums use checked arithmetic, an overflow reading as `capacityExceeded`. Describe lists the external kind first, then files, then the extra kinds in the given order. One authorization gate (the path's machine id), one admission budget (4,096 receipts, 64 MiB; no active-operation cap) covering in-process, external and not-yet-returned starts and abandoned disk effects (`ComputerFileSystem.abandonedEffects`) with a generation guard, and operation-id routing: an id the external backend owns goes there, everything else to the in-process runtime; neither can adopt an id the other holds. The optional `audit` callback sees each admitted start once, in-process or external, after the backend answered 201: an `AdmittedStart` with operation id, kind, input and the server's `StartRequest.caller` (nil when no session caused it). It is the hook for the app's local Activity list; the caller is display-only and never authorizes. Black-box tests cover extra kinds over injected files, audit of admitted starts with their caller, shared admission with an external backend, a receipt held by an abandoned disk effect until it ends, unique names, external descriptor/reservation validation, invalid and overflowing usage.
