# ComputerFiles

Desktop-only `read.v1`, `find.v1` and `grep.v1` kinds register through `fileOperationKinds(files:)` and use only the common operation verbs. They do not depend on v1, exec or supervisors. `ComputerFileSystem` is an injected async streaming companion to VirtualFileSystem, whose existing children/readData methods materialize entire directories/files and therefore cannot implement these bounds. Local effects run on a dedicated Dispatch IO queue, not the operation control actor. One blocked effect per operation can remain in the kernel until it returns; cancellation cannot preempt a kernel syscall. Runtime admission bounds outstanding operations; cancellation is checked before the next effect or publication and on every directory entry, including excluded symlinks. The walk awaits the operation cancellation check between individual directory effects, so protocol stop and local lease expiry interrupt a single next() without relying on Task.cancel().

Read accepts an absolute regular-file path, decimal-string offset/length and optional ifMatch. Reads are at most 64 KiB, at explicit offsets, and await bounded channel publication before the next read. A version includes device, inode, size, mtime and ctime at nanosecond precision; the path is checked before and after every read and at completion. Mutation/replacement is fileChanged (412), never claimed as an immutable snapshot. Already-consumed prefixes are not retracted on failure. A bounded requested range uses the same kind; no separate shortcut endpoint is installed. The result is version, decimal byte count and reachedEOF.

Find walks in native unsorted traversal order and publishes one path/kind record at a time. `*` does not cross a slash; `**` does; `?` matches one non-slash UTF-8 byte. `**/` also matches zero directories. Patterns are bounded to 4096 UTF-8 bytes and evaluated by bounded dynamic programming, never a regex engine. Symlinks are included only when requested and are never followed. Traversal retains at most 128 open directory frames, with 4096-byte paths; depth overflow is capacityExceeded. An inaccessible or symlink-excluded root is a typed error, never an empty success. Nested unreadable directories and entries are skipped and counted. Search roots strip trailing slashes before the no-follow check. Traversal uses fstatat/openat relative to held directory descriptors; regular-file entries carry a bounded ComputerFile reference anchored to that parent descriptor. Grep reads and verifies that reference, not a reopened absolute path. Replacing or renaming a parent cannot redirect traversal or reads outside the opened tree. Symlinks are never followed even during an open race. The walk does not materialize or sort directory contents.

Grep advertises `literal` and `regex` dialects. Regex uses Foundation NSRegularExpression (ICU), preserving v1 syntax, Unicode character classes, inline flags and case-sensitive defaults. Patterns are at most 4096 UTF-8 bytes and compile before admission; invalid syntax is invalidInput, an unsupported dialect is unsupportedDialect, and neither performs filesystem effects. The matcher imports only NSRegularExpression and NSRange from Foundation; these corelibs types are not supplied by FoundationInternationalization on Linux. ICU linkage remains the deliberate v1-parity dependency. Reads are at most 16 KiB and lines are incremental, bounded by maxLineBytes (1...65536). Newline separators are excluded from exact UTF-8 line records; carriage returns are retained. Binary (NUL or invalid UTF-8), oversized lines/encoded records, changed files and unreadable files are skipped so neighboring text remains searchable. The completed result includes `skipped` integer counts keyed by binary, oversized, changed and unreadable; find includes applicable traversal counts too. A prefix already published before discovering a later file problem is not retracted. Output publication suspends before scanning more lines; prefetched bytes are bounded by one chunk plus one line. File-version changes are checked around each read. Cancellation/deadline checks occur between files and reads and during matching; output and encoded-record caps still apply. Regex matching runs outside the operation-control actor in a structured child task. Its ICU `.reportProgress` callback stops enumeration when that task is cancelled; a sibling checks the operation cancellation and local lease every 10 ms and cancels the match. The scope joins both children before returning, including shutdown. Operation stop/deadline and 60-second lease expiry therefore interrupt pathological backtracking rather than leaving an unattended match. A cancelled matcher throws typed requestCancelled; the common runtime publishes its existing stopped verdict/reason for protocol stop or lease expiry, while caller deadline remains the client's typed callerDeadline failure. Linux and macOS tests exercise `(a+)+$` on a 32 KiB adversarial line and require stop/lease terminal evidence plus orderly shutdown within two seconds.

Entry limits in find/grep count all yielded walk entries, including nonmatches. Reaching the cap calls OperationCancellation.stop(reason: "entryLimit"), producing a real stopped verdict, not a completed page/cursor. A cap exactly equal to the number of entries is still limited because no speculative extra traversal proves exhaustion. A caller limits matches/bytes by stopping consumption, not by pagination.

Named production Handler/client examples cover range exactness/mutation, incremental lines and explicit skip counts, traversal order and limit stop, invalid syntax/unsupported dialect refusal before effects and ICU Unicode parity, full-window suspension with responsive state/stop, and desktop live regular-file smoke on Linux/macOS. No process/service behavior is claimed by these tests.
