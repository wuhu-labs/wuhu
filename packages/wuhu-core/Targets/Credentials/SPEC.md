# Credentials

Credentials are space-scoped private files, atomically replaced under a cross-process lock. Existing version-1 files continue to decode without metadata. Credential resolution lazily adds private `identityEpochs`, `environmentIdentityEpochs` and `identityKey` fields; no SQL schema changes or transcript account identifiers are introduced. Epochs are random UUIDs, not hashes of keys or account IDs. Private keyed fingerprints detect replacement without exposing the key in a replay scope.

`CredentialResolver.live` resolves the effective credential and identity together under the store lock, including OAuth refresh. An ordinary refresh preserves the identity while saving rotated tokens and their new private fingerprint. A refresh unexpectedly changing account identity rotates the epoch. Re-login or `auth set` uses `CredentialsStore.replace` and always rotates the identity, even when the supplied credential value is identical. `update` detects changed provider credential values; direct file replacement is detected by the private fingerprint on the next resolution. Removing a credential retires its identity.

Environment API keys retain precedence when enabled. Their opaque identities are persisted independently from stored credentials and rotate when the selected environment key changes; returning to stored credentials retires the older stored affinity. The fingerprints and their key remain only in the owner-only credentials file, never in scope IDs or transcripts. With no store, `environmentOnly` verifies the selected API key by private in-memory equality and permits opaque replay using a process-local random identity. Repeated resolution of an unchanged key preserves its epoch; key replacement or observed removal retires it. Nothing is persisted, and process restart creates a new scope, requiring a portable runtime boundary before continuing an old transcript. This verification is specific to the environment API-key resolver; arbitrary legacy credential closures remain fail-closed.

`CredentialResolver.bound` accepts an atomic resolver returning `CredentialBinding(credential:identityEpoch:permitsOpaqueReplay:)`. Its implementer owns the epoch stability/replacement contract. The legacy credential-only initializer keeps ordinary credential resolution available but cannot establish verified replay affinity; its process-local UUID changes on credential replacement and opaque replay is disabled.
