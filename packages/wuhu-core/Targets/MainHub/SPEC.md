# MainHub

`Hub` implements `Main` against the real space store, provider credentials and machine contracts. Construction is inert: it opens no database and starts no tasks. The composition owner supplies an already-open `Space` and owns the Hub's lifetime. A retained Main never retains a session execution or its reminder registry. Worker hydration uses the store’s execution read, which atomically refuses main’s archive reservation; plain store hydration remains available to archive bookkeeping.

Main has 59 requirements. Notifications use `append(.inputEnqueued(.notification(...)))` and its queue-position acknowledgement; boot recovery consumes stale script owners directly from Space, once, before appending one notification per owner. Notification append does not activate or refresh the generation’s prompt revision.

The agent's file tools (read, write, edit) run in the worker over main's HTTP API with the fold's access log as their guard; Hub touches files itself only to place a generated image and to read an attachment. The session verbs (send_message, request, report, create_session, set_title, manipulate_ui, observe, timer, the subscription half of cancel, machines, templates) are Hub methods the session gate calls as the session; the worker reaches them only as API requests keyed by the tool call. Each verb owns its idempotency: its answer is looked up and recorded in the transaction that makes its effect (a slot armed or cancelled, a device command, a title set, a session created), or the effect is keyed by an id derived from the call (a message, a request, a report), so a retry of the call, or a twin of it running at once, gets the first answer and acts again on nothing. `Main` has no spawn, message, request, subscription, title or device member; `setTags`, `control` and scripts’ machine exec operations remain typed Main members, along with inference and capability operations. Per-call exec jobs and their cancellation never enter Hub; main exposes the registry and relay over HTTP/WebSocket, and `owedExecs` supplies owed tool-call records for worker recovery.

MainHub contains no interpreter or worker dependency. SpaceServer composes a Hub with SessionTools and LoopCore; main-only clients and MainHubTests can use the real Hub without compiling either worker target or QuickJSKit.

The seven-member Worker has no restart command; main owns that store operation after settled revocation. The shared Main/Worker contracts, typed command/handler/activity values, event/reply values, arguments, rendering and machine/module/cron/wait policy live with Hub. SessionTools depends on this module; this module never depends on the worker or interpreter. Scripts reach machines through Main value operations: usable machine snapshots, authorized file operations, exec start returning an ExecID and typed event stream, and exec input (write, close-stdin, acknowledge-through, kill, release). Hub owns caller-leg transport, reconnect and teardown; release cancels and joins the connection job. Script death kills minted execs and releases their caller legs before releasing durable script ownership. Worker-side process buffers retain byte accounting, masking and consumption acknowledgements.

SubscriptionFiring owns subscription scheduling and handler task lifetimes in main. It calls Worker.fire and reads typed activity; it never retains Scripts or an interpreter-facing handler adapter. Discovery configuration belongs to Hub and scripts request typed discovery operations through Main.

Main owns machine exec records, not per-call jobs. `pendingArrivals` exposes queue urgency for the worker’s wait cut; `owedExecs` reads owed tool-call exec records, terminal or live, and their opaque worker specs. The worker owns end settlement, acknowledgement, cancellation and restart adoption. Generation heads remain snapshots and are not rewritten by exec completion.
