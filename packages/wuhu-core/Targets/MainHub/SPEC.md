# MainHub

`Hub` implements `Main` against the real space store, provider credentials and machine contracts. Construction is inert: it opens no database and starts no tasks. The composition owner supplies an already-open `Space` and owns the Hub's lifetime. A retained Main never retains a session execution or its reminder registry. Worker hydration uses the store’s execution read, which atomically refuses main’s archive reservation; plain store hydration remains available to archive bookkeeping.

Main has 60 requirements. Notifications use `append(.inputEnqueued(.notification(...)))` and its queue-position acknowledgement; boot recovery consumes stale script owners directly from Space, once, before appending one notification per owner. Notification append does not activate or refresh the generation’s prompt revision.

The agent's file tools (read, write, edit) run in the worker over main's HTTP API with the fold's access log as their guard; Hub touches files itself only to place a generated image and to read an attachment. The session verbs (send_message, request, report, create_session, set_title, manipulate_ui, observe, timer, the subscription half of cancel, machines, templates) are Hub methods the session gate calls as the session; the worker reaches them only as API requests keyed by the tool call. Each verb owns its idempotency: its answer is looked up and recorded in the transaction that makes its effect (a slot armed or cancelled, a device command, a title set, a session created), or the effect is keyed by an id derived from the call (a message, a request, a report), so a retry of the call, or a twin of it running at once, gets the first answer and acts again on nothing. `Main` has no spawn, message, request, subscription, title or device member; `setTags`, `control` and the exec members stay on it until the cut that moves exec into the worker, `refuseUnlessLive` and the capability members until the cut that moves inference and capabilities over the API.

MainHub contains no interpreter or worker dependency. SpaceServer composes a Hub with SessionTools and LoopCore; main-only clients and MainHubTests can use the real Hub without compiling either worker target or QuickJSKit.

The seven-member Worker has no restart command; main owns that store operation after settled revocation. The shared Main/Worker contracts, typed command/handler/activity values, event/reply values, arguments, rendering and machine/module/cron/wait policy live with Hub. SessionTools depends on this module; this module never depends on the worker or interpreter. Scripts reach machines through Main value operations: usable machine snapshots, authorized file operations, exec start returning an ExecID and typed event stream, and exec input (write, close-stdin, acknowledge-through, kill, release). Hub owns caller-leg transport, reconnect and teardown; release cancels and joins the connection job. Script death kills minted execs and releases their caller legs before releasing durable script ownership. Worker-side process buffers retain byte accounting, masking and consumption acknowledgements.

SubscriptionFiring owns subscription scheduling and handler task lifetimes in main. It calls Worker.fire and reads typed activity; it never retains Scripts or an interpreter-facing handler adapter. Discovery configuration belongs to Hub and scripts request typed discovery operations through Main.

Exec settlement retires the in-process job and fulfills its end waiters synchronously with the SQLite commit that records the receipt or queues the end message and deletes the durable job. Running-work snapshots cannot list an exec after observing its committed end. The independent `ExecJobs.drivers` TaskScope owns the remaining terminal acknowledgement and caller-leg teardown; `closeExecJobs` cancels and joins those drivers even when no job remains in the running map. Shutdown leaves unfinished durable jobs for adoption, not local transports or tasks. A completed job is not re-adopted after restart; its receipt, end notification and terminal machine record remain durable. Generation heads are snapshots and are never rewritten by exec settlement.

Exec cancellation chooses under the same job gate as settlement. A cancel that captured the job before its end but acquires the gate afterward is `alreadyEnded` and emits no kill. A cancellation admitted first marks the end unannounced and sends its kill before settlement can proceed.
