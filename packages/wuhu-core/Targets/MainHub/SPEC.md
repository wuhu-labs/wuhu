# MainHub

`Hub` holds the session verbs against the real space store, provider credentials and machine contracts. Construction is inert: it opens no database and starts no tasks. The composition owner supplies an already-open `Space` and owns the Hub's lifetime.

Boot recovery consumes stale script owners directly from Space, once, and enqueues one notification per owner.

The agent's file tools (read, write, edit) run in the tool executor over main's HTTP API with the fold's access log as their guard; Hub touches files itself only to place a generated image and to read an attachment. The session verbs (send_message, request, report, create_session, manipulate_ui, machines, templates) are Hub methods the session gate calls as the session; the tools reach them only as API requests keyed by the tool call. For `observe` and `timer` Hub only checks the call (`arming`: the source, the schedule, the handler path, the name, and a query's baseline rows read as the subscriber) and the gate hands the `Arming` to the session's cell, which arms it; the subscription half of `cancel` goes to the cell alone. Each verb owns its idempotency: its answer is looked up and recorded in the transaction that makes its effect (a device command, a session created), or the effect is keyed by an id derived from the call (a message, a request, a report), so a retry of the call, or a twin of it running at once, gets the first answer and acts again on nothing.

MainHub contains no interpreter or loop dependency. SpaceServer composes a Hub with SessionTools and LoopCore; MainHubTests use the real Hub without compiling either or QuickJSKit.

SubscriptionFiring owns subscription scheduling and handler task lifetimes in main. A subscription is owned by a session or by a group (an observer); a group's handler fires as `ScriptHandlerInvocation.Runner.observer` with the firing id, and the kernel mints that firing's token (`ExecTokens.runSessionless`). Each handler firing is one `subscription.firing` span carrying the subscription, firing id, kind, observer name and outcome. A failed firing reruns the same input with backoff (1 s doubling to 300 s). `Hub.armObserver(group, input)` validates the terms, runs an observation's query once as the observer to refuse what the group may not read and to pin the baseline, and arms `obs.<uuid>` or `timer.<uuid>`; who may arm, cancel or list is the route's to admit. It mails a handler slot's observer cell through the closure it is given.

Main owns machine exec records, not per-call jobs. `pendingArrivals` exposes queue urgency for the worker’s wait cut; `owedExecs` reads owed tool-call exec records, terminal or live, and their opaque worker specs. `openRequests` reads the requests the session is the task of that are still open; the `requests` table is the only record of what a session owes. The worker reads it when `compact(park: true)` decides whether to refuse, at the step-end nag, when a parked session schedules its park wake, and for a portable handoff, which keeps those requests' briefs; group switching reads it for its handoff too. The worker owns end settlement, acknowledgement, cancellation and adoption on mount. Generation heads remain snapshots and are not rewritten by exec completion.
