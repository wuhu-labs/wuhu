# CLIKit

## Wallet assertion cache

HTTPS server spellings with an implicit scheme, case-insensitive host, omitted default port, or trailing slash share one owner-only `assertions.json` entry keyed by lowercase `host:port` (default 443). HTTP origins and nondefault ports remain separate. On read, legacy aliases are merged best-effort, keeping the latest-expiring well-formed, signature-valid assertion for the authoritative recorded space identity; other audiences never outrank or erase that credential. New mints remove equivalent aliases. Every cache writer holds an owner-only per-wallet `.assertions.lock` flock across a fresh read, merge and atomic rename, so migration cannot erase another process's newly cached server credential. The lock inode remains in place; unsafe/symlinked locks refuse the cache write with a nonfatal warning. Existing owner-only checks, symlink write refusal, atomic 0600 writes and nonfatal cache-write warnings still apply. Near-expired local assertions still re-mint transparently. A server 401 `unauthorized` explicitly reporting `assertion expired` fails without replay, names the server and teaches re-authentication with `wuhu login`; other server errors retain their original meaning. WebSocket expiry refusals remain final, not reconnectable transport failures.

## Session archive

`wuhu session archive <id> [--force]` posts `force` to the session archive HTTP route. Force defaults to false; other session action verbs do not accept `--force`. A busy refusal is a nonzero exit and prints the server's complete id/title list.

Archiving a session takes its entire parent-chain subtree, leaves first and root last. A separately created top-level agent has no parent and is not included. Only the root's archive rights are checked. Without force, every session is checked for the existing unfinished-work condition; refusal archives nothing and names every busy session by id and title. With force, busy sessions are interrupted before any archive write, and every open request in the subtree, including an undrained request, is closed with a final-kind message saying the session was archived before reporting. Its requester receives that message even outside the subtree. Unarchive remains single-session, subject to the archive grace window.

## Capability parity

`wuhu web-search <query> [--provider <id>] [--count <1..20>]` sends the private authenticated `/v1/web-search` request and prints normalized JSON. `wuhu image <prompt> --destination <local-png> [--image <local-png>]... [--provider id] [--model id] [--quality draft|standard|fine|ultra] [--size 1024x1024|1536x1024|1024x1536]` sends private reference bytes to `/v1/image`, then creates its local output with withoutOverwriting; an existing output is refused before spending. Images upload at most five references/25 MiB aggregate; the server also checks bounds. `wuhu transcribe [file] [--language code] [--provider id] [--model id] [--timestamps words,segments] [--diarize] [--json]` sends the same options to `/v1/transcribe`; default output is text, --json emits optional rich seconds-based metadata. No file probes availability as before. Audio is bounded to 25 MiB/two hours with locally established duration; MP4/M4A fragments require readable track/decode/sample timing; unknown duration is rejected with invalid_argument and a re-encode hint before provider I/O.

Capability requests use the authenticated long-operation transport without the ordinary 30-second request deadline; ordinary CLI requests retain their existing transport. All CLI capability operations use the same call-time active/override resolution as code mode and dictation. Missing configuration synthesizes Codex; explicit broken configuration never falls back. Capability provider IDs/keys are native server credentials, not script secrets. Auth help now names both model and capability provider IDs; `auth set` remains a human-on-server stdin operation, not a remote credential-upload API.

## Session exec identity

Any non-empty `WUHU_EXEC` marks a session exec. With `WUHU_IDENTITY` unset, empty or `session`, the CLI uses only `WUHU_TOKEN` and `WUHU_SPACE_URL`, never the cwd wallet or device keys. Missing or rejected credentials fail without falling back. V2 exec supplies WUHU_TOKEN_EXPIRES_AT epoch seconds; malformed metadata is refused and an expired timestamp raises the typed SessionCredentialExpired error rendered as credentialExpired before wallet access or HTTP. Tokens do not renew. A cwd pinned to another space cannot redirect the session. `--group` and non-empty `WUHU_GROUP` are refused; the server uses the token's session group.

`WUHU_IDENTITY=wallet` explicitly ignores the session credentials and locates the wallet from cwd up, acting as its owner on its space. `wuhu user list` is refused as a session but available with this opt-in. CLI-local session refusals print `not available to a session; set WUHU_IDENTITY=wallet to act as the wallet's owner`; the server's HTTP-only session gate keeps its bare refusal. Group selection is the normal wallet precedence: `--group` > `WUHU_GROUP` > wallet config > server default. Invalid groups, unsupported group selection, malformed wallet/persona data the command uses and failed persona minting are errors, not fallback gates. Wallet repair (`use`, `login`) does not consult an old pin or its persona. Wallet mode prints one stderr line describing the identity on the command's actual target: `acting as <persona> (wallet)`. A request without a wallet bearer is labeled `anonymous`, even when another space's persona is cached. `use` establishes and looks up the new target, never the old pin. Local-only commands use `the local user`; wallet-free local verbs (`serve`, `upgrade`, offline `user` recovery) do not locate a wallet. Help opens no identity and prints no announcement. Outside an exec, the CLI uses the wallet as before, ignores `WUHU_IDENTITY` and prints no announcement.

`session create` without the opt-in creates a session child in its group, inheriting its model unless overridden. Wallet mode follows the human path: it requires explicit provider/model or a template supplying them, and creates a human-owned root agent rather than a child. Help distinguishes these paths.

## AI provider disclosure

`serve --ai-disclosure <json-file>` passes the disclosure file to server startup. The optional file is an object with a nonempty `version` and a nonempty `providers` array; every provider has nonempty `name`, `location`, `via` strings and an absolute HTTPS `policy` URL without credentials. The file is read and validated before the server creates its store or binds listeners; an unreadable or invalid file is a typed startup error, never an omitted disclosure. Without this option server discovery remains unchanged.

Policy URLs must use the literal lowercase `https://` scheme prefix and have no leading or trailing whitespace. Host config and server startup reject, rather than normalize, other spellings.

## Guarded table alteration

Table create/alter responses carry rev/token, both printed and recorded. Table mutate records its revision as the current table token. `wuhu table alter <path> <header-json> [--allow-drop-columns]` requires a recorded token (use `wuhu stat` to refresh it), sends ifMatch, and never bypasses the precondition. Omitting existing columns requires the flag; in-place type changes remain refused by the server. `wuhu rm` deletes tables; there is no separate drop or index-management command. HTTP row edits stay positional, whereas script mutateRows edits are named fields. The HTTP space toolbox and kernel roster are distinct surfaces; scripts now expose checked tables and atomic document templates without requiring the CLI.


`wuhu identity` prints resolved default/override issuer URLs as JSON. `wuhu identity issuer-for <origin>` prints a single issuer URL. `wuhu identity set default <self|directory>` changes the default; `wuhu identity set <origin> <self|directory|inherit>` sets or removes an exact origin override. These setters are refused locally in session execs and require a human space-admin account at the server. No identity state is written into the wallet or space. Verifiers must trust both issuers during issuer migration.

`wuhu identity rotate` (human space-admin-only) starts the persisted 90-day key rotation early, preserving issuer URLs and overlapping old/new keys for one day before switching and one day after. `wuhu identity register-new` (also human space-admin-only) replaces a stale directory id with a fresh registration. This changes the issuer for every directory-selected audience and requires verifier migration; it is not an automatic fallback for ownership failures. Both commands are refused locally to session execs and post to the corresponding `/v1/identity/rotate` and `/v1/identity/register-new` routes.

## Channels

`wuhu channel create [--title T] [person...]`, `add <id> <person...>`, `remove <id> <person...>`, and `rename <id> <title>` manage human-only channels through the HTTP channel contract. `rename <id> --clear` removes a title. Creation prints the channel id; mutations emit no output on success. A person creator joins; a session creator does not. Typed refusals preserve server error codes.

## Live people management

Without `--space`, `user add --name <name> [--admin] [--ttl <seconds>]`, `user invite <account-id> [--ttl <seconds>]` and `user admin <account-id>` act as the enrolled person on the pinned HTTPS server. They refuse session identity locally and refuse an unenrolled wallet rather than using the anonymous dev owner. Each live operation resolves one authenticated client and retains its bearer across discovery and every mutation; losing the recorded host identity mid-operation cannot switch subsequent requests to anonymous. Bearer remint failure is an error, not a fallback. Add posts `{name, admin}` to `/v1/accounts`, prints the new account id, then posts `{account, capabilities:["device"], ttlSeconds?}` to `/v1/enroll` and prints its one-time enrollment link. If invite minting fails after creation, the printed id remains usable for a subsequent `user invite`; the command exits nonzero. Invite prints only the link; admin posts `{admin:true}` to `/v1/accounts/:id/admin` and prints the promoted id. Add/admin require an admin of `shared`; invite is self or an admin of `shared`. An admin of a different group is insufficient.

Invites default to 3600 seconds, with positive `--ttl` seconds accepted; expiry notes go to stderr. Link minting first reads `/v1/server` without swallowing errors, uses its advertised origin (or the pinned address when no origin is configured), and uses the enrollment output's space id and optional generated-certificate fingerprint. Neither a discovery error nor an identity error switches to an offline or anonymous path. Live invite refuses `--server`.

The existing `user add`, `user invite` and `user reset` commands with `--space` retain their offline dispatch, flags, output and recovery behavior. Offline add still prints only its account id and does not accept `--ttl`; admin is a new live-only verb.

## Machine v2 installation

`machine-v2 install <machine-id> --binary <signed-wuhu>` and `upgrade` install only `~/.wuhu/machine-v2/<id>/bin/wuhu`; they never modify the ordinary CLI, server, machine-v1 home or key. Enrollment is separate and must already exist. The displaced binary is kept at `bin/previous`; `machine-v2 rollback <id>` explicitly restores it and restarts only the v2 agent. A failed service restart is typed and retains that previous binary for explicit rollback, never an automatic fallback. Install, rollback and uninstall hold an exclusive nonblocking per-machine `flock` descriptor for their entire operation. The owner-private `.install-lock` inode stays in place. Each mutation explicitly unlocks before closing on success or failure, so an inherited descriptor in a concurrent fork cannot retain ownership after the call returns. Process death or reboot also releases ownership once no inheriting process holds the descriptor; a stale file alone never wedges recovery. The descriptor is close-on-exec so service-manager children cannot retain it across exec. Symlink installation paths/lock files, nonprivate lock files and unsafe IDs are refused.

Linux uses the user unit `wuhu-machine-v2@<id>.service`, `KillMode=process`, `UMask=0077`, and `machine-v2 run <id>`, restarted always except after exit status 0 (`Restart=always`, `RestartPreventExitStatus=0`), with no start limit (`StartLimitIntervalSec=0`): a version crash-looping every `RestartSec=2` nearly spends systemd's default 5 starts per 10 s, so a rollback's restart would otherwise be refused and leave the unit failed with nothing to restart it. Before install creates installation directories, locks, staged binaries or service definitions, and before upgrade stages or swaps a binary (upgrade checks under its lock first), it verifies the candidate is executable, resolves the local username, requires `loginctl show-user <user> -p Linger --value` to report `yes`, and checks `systemctl --user show-environment`. Disabled or unreadable lingering fails with `preflightFailed` and the exact remediation `sudo loginctl enable-linger <user>`; an unavailable user bus also fails before installation writes. Existing live/previous binaries and unit files remain unchanged on these failures. Every Linux installer service-manager command preserves a nonempty `XDG_RUNTIME_DIR`, otherwise deriving `/run/user/<uid>` without modifying the caller environment. macOS uses `ai.wuhu.machine-v2.<id>` with `AbandonProcessGroup`, private logs, the same run mode and `KeepAlive` `{SuccessfulExit: false}`, which relaunches every exit but status 0. A revoked machine is the one clean end of `run`, so it alone stays down; a crash, a kill or any other failure exits otherwise and is restarted, and a turned-off machine or a lost network never exits. `install` writes the unit or plist, and it is the only writer: `machine-v2 upgrade` and an auto-upgrade swap the binary in place and restarts the job under the definition as installed (systemd `restart`; launchd bootout, then bootstrap of the plist on disk), and the agent never rewrites it; an upgrade checks for the installed definition under its lock, before any preflight or binary change, and without one refuses (`notInstalled`, naming `install`), so a concurrent uninstall never leaves it swapping and restarting a job with no definition. A hand edit survives every upgrade, and a definition change reaches an installed machine only through an explicit `install`. The plist sets `EnvironmentVariables` `PATH` to the v1 agent's: `~/.wuhu/bin:/opt/homebrew/bin:/opt/homebrew/sbin:/usr/bin:/bin:/usr/sbin:/sbin`. A revoked agent running as its job (its own unit in `/proc/self/cgroup` under systemd, `XPC_SERVICE_NAME` equal to its label under launchd) stops that job rather than trust the loaded definition to keep a clean exit down, since an older one restarts every exit: `systemctl --user stop` on its own unit, which is never restarted and leaves the unit enabled, or a launchd bootout of its own job, whose plist loads again at the next login. When that stop or bootout fails, the agent parks: it stays alive and idle with no network, reconnect or exec, logs `revoked; parked`, and ends only on a signal such as the uninstall's stop. An agent outside its job (a foreground `run`) just exits. Before launchd installation, the private staged signed candidate is run by a one-shot launchd job in `machine-v2 preflight <id> <result-path>` mode before changing the live binary, previous binary or service definition. macOS install-over-existing/upgrade and rollback boot out the v2 service, then poll `launchctl print gui/<uid>/<label>` until an explicit service-not-found response confirms unload (100 ms spacing, 10-second budget, at most 101 probes) before bootstrap. Rollback can therefore restore an unloaded service rather than relying on kickstart. All installer launchd bootouts, including preflight cleanup and uninstall, confirm disappearance. Bootstrap retries only the typed command exit status 5, for at most five attempts with 250/500/1000/2000 ms backoff; other failures are immediate. Exhaustion reports loaded, left unloaded or unknown from a fresh print probe, and gives inspection/recovery commands; the live plist and previous binary remain available for explicit recovery. Preflight jobs share this sequencing but their failure recommends rerunning the installer, not bootstrapping a deleted temporary plist. `CommandFailure` carries the executable arguments, exit status and stderr across the CLI executable/service-command injection seam; the live seam is `capturedProcessOutput`, which runs the command through swift-subprocess and returns only after reading both pipes, unbounded, to EOF, so a short output is never lost to a race with process exit; retry classification never parses diagnostic prose. A `launchctl bootout` failure explicitly reporting `Could not find specified service` or `Boot-out failed: 3: No such process` is an already-unloaded success, including retry after a failed bootstrap; other bootout failures remain `serviceFailure` and preserve the service definition. A denied Local Network grant is `localNetworkDenied`; other probe failures/timeouts are typed preflight errors, never another transport or interactive/tmux workaround.

`machine-v2 uninstall <id>` completes a logical leave and waits for drain/terminal acknowledgements before stopping/removing the v2 service. A home marked revoked skips the leave: that agent has retired its supervisors and exited, and no control socket is left. An explicit `leaveUnacknowledged` deadline still removes/stops the service and exits with that typed error; the server records lost rather than detached. Other leave failures leave the service running with `drainFailed`. Binary, key, operation receipts and logs remain for diagnosis and explicit recovery. All installer verbs are wallet-free and refused to a session identity. Installer and runtime refusals identify the command as a person action and print an explicit `WUHU_IDENTITY=wallet wuhu machine-v2 <verb> ...` command template before local mutation or network traffic; they never silently switch identity. Exec supervisors survive service-manager restart and binary replacement within their remaining 60-second lease; service stop alone is never presented as a clean detach.

## Authenticated machine v2 runtime

`machine-v2 join <https-origin> [sha256:<fingerprint>] [--name <name>] < token` consumes only an explicit v2 enrollment token at `/v1/machine-v2/enroll`, then independently verifies membership with a fresh signed challenge. Refused v1 tokens never mutate v1 enrollment. Only after verification is the private `~/.wuhu/machine-v2/<id>/config.json` and `machine.key` written. Runtime commands are wallet-free and refused to session identity unless the established explicit wallet override is used; no device key, wallet bearer, v1 configuration or alternate identity is used.

`machine-v2 run <id>` loads that exact home, installed `bin/wuhu`, private operations and Unix control socket, and clears the home's `revoked` marker. When the tunnel's 401 `machineNotAuthorized` reads as revoked, it retires every exec supervisor, writes the owner-private `revoked` marker, stops its own job or parks (as above), and otherwise prints the error and exits 0. On macOS its new exec children disclaim TCC responsibility rather than attributing privacy prompts or inherited grants to the box agent; the Direct app embedding path is unchanged. If the SPI is unavailable, the agent logs `tccDisclaim: unavailable` once and keeps normal spawning. It proves enrolled-key possession on each connection using `/v1/machine-v2/challenge`, the v2 signing domain and canonical machine IDs, and negotiates exactly `wuhu-fetch-tunnel.v1` through the bounded NIO adapter. Join reads any existing user certificate pin without mutating it; the chosen pin is persisted only inside the verified v2 config. Runtime HTTPS connections use that exact per-machine pin or system trust, independent of later v1 trust-store changes; no URLSession trust bypass exists. Reconnection creates a new generic tunnel and never replays exchanges. After successful logical leave, the owner remains alive for private control/uninstall but never dials another tunnel; a server closing the detached connection cannot accidentally re-enroll presence. Logical operations are authorized per addressed machine, not inferred from the connection.

`machine-v2 leave <id>` uses an owned, lifecycle-scoped one-thread NIOPosix HTTP client and only the owner-private local socket and waits for explicit logical server acknowledgement after exec/file terminal/output drain. No raw-stop alternative exists. A lost final acknowledgement after completed drain is `leaveUnacknowledged` after one lease; timeout while supervisor creation/operation/output drain remains incomplete is `drainFailed` and preserves the service. Installer cleanup may finish only for the explicit completed-drain acknowledgement failure, and the server records lost rather than detached. Other drain failures preserve the running service. `machine-v2 preflight <id> <result-path>` probes the configured authenticated HTTPS/tunnel path and writes a new owner-private JSON receipt `{ok,code?,message?}` in the v2 home. It is launched by the installer under launchd, never a terminal/tmux alternative.

Diagnostic recording is opt-in only: `WUHU_MACHINE_V2_RECORDING=<existing owner-private 0700 directory>` creates a fresh `agent-<UUID>` directory per incarnation. Each admitted handler exchange writes a bounded private `exchange-NNNN.json` pending receipt before dispatch, then atomically replaces it with a `FetchExchangeRecording.ExchangeRecording` containing the completed sanitized request/response and explicit handler-response effect. No queue or accumulated transcript is retained in memory, and the incarnation admits at most 4096 diagnostic exchanges of at most 1 MiB per body. Authentication headers, exec environment, session credentials and resolved secret fields are omitted; exec output is already supervisor-masked. Commands/paths and nonsecret channel bytes are retained for deterministic canaries, so this mode must only be enabled with deliberately nonsecret inputs. Handler transport failures retain a typed effect without arbitrary error prose. Recording failures fail the diagnostic exchange rather than silently disabling proof.

The private local leave success receipt is a bounded JSON literal `true`, decoded with standard Fetch `Body.json(Bool.self)`. The production HTTP/1.1 Unix request explicitly sends Host:localhost; missing Host was the observed plaintext-400 pre-handler defect, not a demonstrated root-scalar codec failure. Negative, malformed, empty, oversized and unreadable receipts are typed drainFailed, never converted to a successful uninstall. Typed requestDeadline error receipts distinguish incomplete drain from completed drain with a missing final acknowledgement.

The published-supervisor expiry exception is explicit: an observed leaseExpired stopped verdict or authenticated unknownOperation is loss evidence, never inferred from a timer. After every other backend is settled, it yields leaveUnacknowledged with affected operation IDs/reason rather than a clean departure, so cleanup is allowed but the machine/operation remains lost/unacknowledged, not detached or consumed. Missing evidence or another unsettled operation is drainFailed and preserves the service.

## Machine v2 automatic upgrade

A standalone box agent follows the server's `MachineV2Upgrade` (MachineContract SPEC); the Direct app's machine never does. Only `machine-v2 run` started as the installed `~/.wuhu/machine-v2/<id>/bin/wuhu` checks, after each tunnel connect and every 10 minutes, with a key-signed `GET /v1/machine-v2/:id/upgrade`. A target equal to the running version is a no-op. Any status but `ready`, a missing artifact for this platform, or an unreachable server leaves the agent as it is and logs one line per distinct reason to stderr and the private `upgrade.log`. A `ready` target is downloaded (pinned TLS when the artifact shares the configured server origin), its archive SHA-256 checked, saved under the fixed name `upgrade/<uuid>/artifact` (never a name taken from the URL), unpacked into a private `upgrade/<uuid>/payload` holding exactly one regular executable `wuhu`, on macOS checked as a strictly valid signature carrying the running agent's team identifier when that has one, and run with `--version`, which must report the target. A mismatch, bad archive, bad signature or unrunnable candidate is refused without touching the installed binary and recorded as a failure for that version.

Before launching anything the agent reserves the trial in the owner-private `upgrade.json` under a fresh owner token, so a check during the launch sees an upgrade in progress; a failed spawn releases the reservation. The verified candidate goes to a detached helper, `machine-v2 apply-upgrade <id> <candidate> <version> <token>`, launched in its own process group so the service restart it causes does not stop it. The helper proceeds only while the trial is its token's, and on every outcome clears only a trial it owns. It runs the ordinary installer upgrade (previous binary kept, service restarted, supervisors untouched) and polls once a second, the last poll at one 90-second deadline on its own continuous clock, for the new agent to mark the trial healthy, which it does on its first tunnel connect when its own version is the trial's. Only a mark the helper reads by that deadline counts, with 250 ms of slack for the read that wakes at it; the mark's wall time is informational and never compared, so a wall-clock step changes nothing and a helper suspended past the deadline rolls back as soon as it wakes. Otherwise, or when the install fails after the swap, it restores the previous binary through the installer rollback and records `healthCheckFailed` or `installFailed`. A busy installer is not a failure, nor is a failed Linux host preflight (username, lingering, user bus), which never runs the candidate; the trial is cleared and the next check retries. On macOS a `preflightFailed` comes from running the candidate and is recorded as `installFailed`. A trial left by a dead helper is abandoned after 10 minutes: one marked healthy is complete; otherwise it is recorded as `interrupted` for its version, and when the agent noticing it runs that version a rollback stays pending in `upgrade.json`: every check launches the detached `machine-v2 rollback <id>` and does nothing else until an agent of another version, normally the trial's previous one, runs and clears it. Recorded failures survive rollback and restart, are never retried while the target names that version, and clear once the agent runs the target or the target changes. While one stands, the agent's describe reply carries `upgrade.failed` (OperationProtocol SPEC). Cooperative health means a target that predates this behaviour never marks itself healthy and is rolled back.

`tools/infra/wuhu-machine-v2/upgrade-live.py` proves this with the real user service manager against a scripted HTTPS server and the real fetch tunnel, starting from the published previous release (pinned by digest, re-signed ad hoc on macOS so it accepts the ad hoc candidate): hold states download nothing, a ready target swaps while a running exec keeps streaming, the definition the old installer wrote stays byte-identical through the new agent's start and through the new agent's own upgrade and its rollback, a target that never connects is rolled back, reported in describe and not fetched again, a killed agent is restarted, and a revoked one stays down with one refusal and still uninstalls. The macOS target `//tools:machine-v2-upgrade-live-test` is manual, excluded from automatic test discovery: the pinned previous installer writes into the executor's real launchd domain. Do not run it on a shared executor. Automatic macOS coverage retains installer recorded-effect tests for the installed plist (including KeepAlive and PATH), service-definition preservation and launchd command sequencing, but does not currently prove real launchd restart into the upgraded binary or its runtime environment. Re-enable the live target only against a disposable macOS VM pool label, after five live runs including a SIGKILL run prove that no test service or process survives VM teardown. The pinned installer must run unchanged inside the VM. Linux still runs the live script in CI's `machine-v2-linux-systemd` job.

## Model group targets

`session create` and `session restart` accept `--model-group <id>`, mutually exclusive with `--provider`/`--model`. Explicit targets replace template/inherited targets as a whole; omitted targets keep existing defaults. A child inherits its parent’s requested group, not its active account. Start over retains the requested group but reselects its initial route. `wuhu models [--json]` discovers concrete providers/models and separate group entries with policy and ordered member aliases; JSON returns separate provider-keyed providers and group-keyed groups objects. Discovery reads providers from /models.json and groups from /model-groups.json; provider/group IDs cannot collide. `models update` adds missing provider/model defaults only in /models.json and never writes /model-groups.json.

`session list` includes requested_model_group, active_provider, active_model and model_route_phase, reading group intent from session_model_routes.group_id and resolving active values from the scoped route projection and preserving concrete sessions with no route. `session inspect <id>` prints the server’s structured requested target and route JSON, including placement reason, score evidence and recorded decisions; it never infers group usage from a summed account allowance.

The stored sessions.executor_config remains the concrete provider/model/effort shape readable by dev.114. Group intent is additive state in session_model_routes, not a new executor_config variant. Conceptual session APIs and inspect requestedTarget still expose modelGroup by reconstructing it from that route. Group creation requires a supplied pin and stores intent plus concrete config atomically.

Before models update writes provider defaults, it validates the proposed provider catalog with the existing group declarations. A seed-provider ID colliding with a group ID is a typed configuration error and leaves both catalogs unchanged; no group is silently skipped or overwritten.
## Model replay policy and credential replacement

`wuhu models update` remains merge-only: existing provider values, including `opaqueReplay`, win over the basis. The separate /model-groups.json declarations are preserved without adding a provider-shaped models map. The DeepSeek basis explicitly declares `opaqueReplay: affine`; custom gateways otherwise need an operator declaration before replaying opaque account-bound records.

`wuhu auth set` and `auth login` replace the provider credential through the identity-aware store and retire its replay epoch even for an identical submitted value. `auth remove` and `auth logout` retire the stored identity with the credential. Epoch metadata remains private to the credentials file.

## Machine registration

`wuhu machine add [--name N] [--group G]` sends optional `name` and `group` in the registration body. The verb-local `--group` and global `wuhu --group G machine add` select the same group; giving both is a usage error. Only an explicit flag sets the registration target: either spelling goes in the body, never into the acting-group `Wuhu-Group` header for this verb. Environment (`WUHU_GROUP`) and folder configuration still select the acting group but do not set the registration target. Without an explicit flag, the body omits `group` and a person's machine goes to their personal group. An explicit target requires an admin of that group (`403 adminRequired`); an absent target is `404 unknownGroup`. Sessions keep their principal's group.

The server echoes the actual placement in `MachineAddOutput.group`. When a target was requested, a missing or different echo fails the command with an upgrade/machine-move remedy instead of reporting successful placement. Since registration already created the machine, its id and one-time join token remain printed for recovery. Without an explicit target, responses from older servers that omit the echo remain accepted.

`wuhu machine-v2 add --name N [--group G]` uses the same explicit registration-target parsing, body, authorization and confirmed placement as `machine add`, at `/v1/machine-v2`. Both flag positions are supported; implicit environment/configuration groups never become registration targets.

## Minimal agent

`wuhu agent [--log <path> | --resume <path>]` runs [MinimalAgent](../MinimalAgent/SPEC.md) in the current directory with the JSON request read from stdin, dispatched before identity resolution, so no wallet, pin or session token is read and a missing or bad `WUHU_TOKEN` in a session's exec does not stop it; it works offline. A terminal stdin and passing both flags are usage errors (64). Success prints `{"result": …}` on stdout and exits 0; an `AgentError` prints `<code>: <message>` on stderr, credential masked, and exits 1.

## Exec ID tokens

`wuhu id-token --audience <origin> [--json]` is dispatched before identity resolution, like `agent`: it reads only `WUHU_ID_TOKEN_URL` and `WUHU_ID_TOKEN_REQUEST`, never a wallet, pin or `WUHU_TOKEN`, and sends one `GET <url>?audience=<origin>` with `Authorization: Bearer <request>`. Either name unset or empty fails (exit 1) without traffic. A 200 prints the token, or with `--json` the server's `{token, expiresAt}`; any other status prints `id-token: <server message>` and exits 1. A missing `--audience` is a usage error (64).

## Retained execution images

Upgrade installation and version-directory pruning share the execution image store lock at `<config>/execution-images/lock` with worker image staging. SHA256 references protect matching version bytes in addition to current/previous and the mtime keep count. An existing retained version cannot be replaced even if its version name is reused. Corrupt, foreign-owned, substituted or unreadable reference evidence refuses replacement/pruning rather than assuming no live image; failed prune remains a reported warning after an otherwise completed installation. Rollback does not release image references. The private image copies survive version-directory removal by other software; external installers/pruners must use the same advisory lock and digest-reference gate before deleting or replacing source versions.

## Server execution

`wuhu serve` runs loops, inference, scripts and handlers in the server. There is no execution-placement flag, child-worker bootstrap or admin-exec command; unknown options use ordinary usage errors.
