# ImageRetention

`transaction(root:_:)` opens an owner-private mode-0700 store and takes its persistent mode-0600 `lock` with exclusive advisory flock. Every cooperating stage, installation and prune decision holds the same lock through filesystem mutation; the lock file is never removed. Root substitution, a replaced lock inode after acquisition and unsafe files refuse. Before invoking the closure, each transaction recovers validated interrupted stage publications, reconciles lease-backed preparations and sweeps only verified SHA256-named images without references. Malformed JSON is `invalidEvidence`; unsafe storage operations are typed retention errors, while closure errors preserve their original type. No transaction closure suspends.

The existing SHA256-named mode-0500 image copies, mode-0600 UUID JSON references and optional `.lease-<UUID>` files remain readable for install/prune protection and recovery. This target creates no launch preparations or references and binds no worker processes. `references` includes every durable reference regardless of liveness or age; `protects` compares candidate bytes with all retained digests. Malformed or substituted evidence is an error, never an empty inventory.

`release` requires exact stored reference equality and a bound process that is absent or has a positively different OS birth. A matching process, permission failure or uninspectable identity refuses. PID reuse can retire only the old reference; another incarnation's ref keeps identical image bytes. References are never released in deinit or on parent shutdown/exec. Release is idempotent after its own reference unlink; interruption can leave unreferenced bytes but cannot delete a referenced image. An unbound lease-backed preparation can retire only after the lease is independently lockable; a bound preparation additionally needs absent/different-birth process evidence. Recovery runs at transactions, covering crashes before manifest publication and after reference unlink. Legacy unbound references without leases remain conservatively pinned. A two-link `.stage` is removable only when its sole in-store peer has the expected canonical name, mode and verified digest/reference; external, ambiguous or malformed links refuse recovery. No age-based expiry is provided.

The store is credential-free and outside the space database. External ops pruners must hold the same flock and preserve any source binary whose SHA256 appears in a reference, failing closed on unknown evidence.
