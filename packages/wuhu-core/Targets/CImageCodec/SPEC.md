# CImageCodec

Linux-only internal codec bridge for SpaceCore. Bazel compiles pinned BCR libpng and libjpeg-turbo; no host codecs or shell commands participate. Swift receives RGBA8 pixels and performs orientation and resampling itself. Every returned allocation belongs to the caller and is released with `image_codec_free`; failure returns zero or a null pointer, never a process abort.

`image_decode` checks positive dimensions, pixel-count and RGBA allocation-size bounds before allocating pixels. Before the simplified PNG API runs, a chunk scan bounds dimensions, validates lengths and CRCs, requires a complete terminal IEND, and filters the input to IHDR/PLTE/IDAT/IEND, tRNS and fixed-size gAMA/cHRM/sRGB fields. Text, ICC, eXIf and all other ancillary chunks are omitted without decompression; Swift applies eXIf orientation separately. Thus compressed metadata cannot allocate expanded text/profile buffers during begin-read. PNG then uses libpng's simplified API to normalize palette, transparency, grayscale and 16-bit samples to RGBA8; reported warnings/errors fail decoding. JPEG uses TurboJPEG 3's C error boundary, warning rejection, 100-scan cap and 128 MiB internal-memory cap, and handles 8-bit JPEG. Unsupported, malformed, truncated or oversized input fails without returning pixels.

PNG encoding keeps RGBA alpha. JPEG encoding takes already-composited RGBA8 and a requested quality and writes 4:2:0 JPEG, without metadata. Encoders enforce the same 40-million-pixel cap and validate dimension/size arithmetic before calling the libraries. The Swift caller supplies image dimensions from a successful bounded decode and an equal-or-smaller resize.
