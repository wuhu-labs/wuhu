# ExecSupervisor

A macOS/Linux-only exec implementation beside machine v1. The signed `wuhu machine-v2 supervise <operation-directory>` mode owns one operation; argv, environment and resolved secrets arrive in the one authenticated POST, never command arguments or disk diagnostics. A version-2 supervisor creates no socket: it dials the agent's `ctl.sock` and receives that POST and every later request through the rendezvous tunnel (see Rendezvous socket). Only legacy version-1 supervisors, started by an older agent and recovered by this one, keep their own socket and are reached over HTTP over Unix. The internal `ExecSupervisorRegistry` routes actual operation requests to independent supervisors and overwrites the diagnostic agent-instance header. It never retries a start, invents running evidence, reruns an ambiguous launch, or renews a lease during identity discovery. `recover()` reads each bounded manifest in isolation and binds without contacting responders; malformed/torn manifests become per-ID typed tombstones naming the manifest path. Decoding errors become invalidConfiguration; a changed machine name becomes supervisorIdentityMismatch, isolated to that directory. Nonregular manifest files are rejected without blocking on a FIFO. The first addressed request authenticates the persisted nonce, machine, operation and protocol version with a separate two-second identity deadline before forwarding. One SIGSTOP/hung responder cannot delay describe, discovery or a different healthy exec. A failed responder remains an unavailable receipt and does not prevent describe/other operations; its identity must validate before any forwarding. Missing, invalid and misconfigured responders are typed failures; no alternate identity, stack or TCP path exists.

The computer-agent composition holds its owner-private persistent `.agent.lock` for the body's lifetime, then explicitly unlocks before closing on either return or throw. A duplicate or concurrently inherited open-file description does not extend lock ownership past that boundary; while the body runs, a second owner remains refused.

Operation UUID spelling is case-insensitive on start and subsequent requests; the gate compares parsed UUID values rather than canonical strings.

The operation directory is exclusively created 0700 and manifest 0600, owned by the agent user. Manifests contain only a protocol version, machine, operation, 256 random nonce bits, the exact socket path and an optional exec-child responsibility policy. New starts write version 2: the socket is the machine's one rendezvous socket `ctl.sock` beside the operations directory, and the operation directory holds nothing but the manifest. Version 1 manifests, written only by older agents, name the supervisor's own listening socket `<operation-directory>/control.sock` or #607's compact `<operation-directory>/s`; recovery accepts both exact paths without moving receipts or changing the operations-root lock, and such supervisors keep their socket and version-1 nonce protocol. No other socket path is accepted, and every path must fit 103 UTF-8 bytes. Older agents cannot recover version-2 manifests, so downgrading the agent strands operations started after the upgrade as tombstones. IDs are never adopted by PID. A single service owner holds a close-on-exec file lock; restart may remove only its owner-owned stale agent and rendezvous sockets after taking that lock. The agent lifecycle reaps only its own launched supervisor children with nonblocking waitpid; supervisor identity still never uses PIDs. The registry requires one owner and reserves 32 active operations and bounded receipt/channel budgets; authenticated nonrenewing identity metadata restores reservations and active counts. Old responders retain conservative reservations until actual terminal/consumed replies; consumed old receipts retain a 64 KiB stdin reservation. New snapshots charge retained stdin and unfinished finite tails, plus a conservative 1 MiB masking/pipe staging allowance until both final offsets exist. Missing self-expired directories release registry receipts on describe/start. Dead supervisor directories remain bounded unavailable tombstones, never rerun; operator cleanup is required if a supervisor died before it could remove its directory.

`ExecKind` validates nonempty NUL-free argv, absolute cwd and valid environment names. posix_spawn creates a separate process group and pipes; no Swift work runs in a fork child. The child environment removes inherited identity/group and session names, overlays caller values and resolved secrets, then installs only the supplied session credential. Optional expiresAt epoch seconds become server-owned WUHU_TOKEN_EXPIRES_AT, never inherited or caller-overridden; the supervisor masks the bearer on both output pipes. Secret masking and its bounded cross-chunk lookbehind live in the supervisor. stdout and stderr have independent 256 KiB windows, stdin 64 KiB plus an 8 KiB partially written pipe chunk, and each output pipe at most one bounded masked staging chunk/lookbehind. Full rings stop pipe reads, not control requests or direct-child observation. Offsets acknowledge accepted stdin retained in the supervisor, not physical pipe consumption.

Installed macOS box agents (`runComputerAgent`, used by `machine-v2 run`) request TCC responsibility disclaiming for new exec children. The private manifest persists the policy so independent supervisors apply `responsibility_spawnattrs_setdisclaim` to the actual child spawn, not to the app or agent process; exec input cannot change it. Protected folders without a grant can therefore fail immediately instead of asking the headless agent for consent. Disclaimed children do not inherit grants charged to their parent agent. `withComputerAgent`, including the Direct app, keeps normal inheritance and interactive prompts; local-agent diagnostics and Linux keep normal spawning too. Old manifests omit the policy and retain their original behavior; already-running children are not changed. If the weak-linked SPI is missing, the installed agent logs one `tccDisclaim: unavailable` warning at composition and creates children normally instead of disabling exec. An available SPI returning an error is a typed spawn failure.

Direct-child wait evidence is observed independently with waitid(WNOWAIT). At that observation each pipe freezes the bytes currently in the kernel pipe; only that finite tail is drained under backpressure. Future descendant writes are outside the output contract. Terminal evidence is published before tail draining, with final offsets absent until each finite tail ends. Natural completion never kills a deliberately detached daemon; such daemons should redirect inherited pipes. Stop/lease expiry sends process-group SIGTERM then SIGKILL after five seconds, keeps the leader unreaped until escalation is complete, and reports stopped only on observed exit with its exit/signal result. Escaping a process group and unkillable kernel work are not sandbox guarantees. Spawn failure is spawnFailed, not an invented exit 127.

`ExecSupervisor.launchDetached` starts any argv the way supervisors start (own process group, standard descriptors on /dev/null) and `reapIfExited` reaps it without blocking; the machine v2 upgrade helper uses them.

The supervisor grants its own 60-second monotonic initial lease, renewed only by valid operation requests. Recovery within its remaining lease preserves child, rings, stdin and masking state; discovery alone cannot revive it. Host reboot or supervisor death does not recover execution. Receipt and output retention follow OperationRuntime; the supervisor exits and removes its own manifest/socket after receipt expiry, never because an active operation has run 24 hours. A launch with no received POST expires after its initial lease. Credentials still expire independently; no credential renewal is added here.

`wuhu machine-v2 local-agent <machine> <operations-directory> <agent-socket>` is a private Unix-only diagnostic runner for recordings, not enrollment or the public server route. It uses the production computer composition, including the rendezvous socket beside `<operations-directory>`, and exposes its private `PUT /leave` on the separate owner-private agent socket; a rehearsal drives ordinary machine describe and `?leaveAck=true`, never a test-only departure model. Its socket parent must be owner-private and its HTTP adapter disallows redirects/replay. The user systemd template in tools/infra/wuhu-machine-v2 explicitly uses KillMode=process so service restart kills only the agent. It is not a production installer; authenticated dial-out/enrollment, macOS launchd preflight and logical leave/uninstall are slice 5. Never uninstall by merely stopping this diagnostic unit: supervisors remain governed by their lease.

The real macOS launchd recording uses an isolated label with AbandonProcessGroup and verifies the same supervisor nonce/PID across restart while stdout is full and stdin is pending. Its restart explicitly boots out the owned label, confirms disappearance with bounded print polling, then bootstraps the plist (at most five attempts for exit 5 only) and waits for the private agent endpoint; it does not kickstart a possibly absent job. Its exact output and one-start evidence replay through the production OperationClient offline. The production canary remains responsible for real server-process restart; a local-agent recording does not claim that proof.

Tests exercise production handlers/pipe effects, torn manifest and hung discovery isolation, reaping, independent output rings, inherited-daemon pipes, split masking, spawn evidence and finite tails. Offline replay runs the production OperationClient and MemoryOperationStore over recorded HTTP outcomes: emitted cursors and input offsets must match, output must be committed before acknowledgement, terminal evidence must validate, and coordinator recreation uses the same persisted store. Only JSON formatting, diagnostic echo headers, and equivalent default query fields from the original Python driver are normalized. Fixture effects describe observed live evidence, not simulated C effects; a live TERM-ignore test runs production escalation in both CI host lanes. Deleting the production SIGKILL escalation was mutation-tested and makes that test fail with timeout. Recorded HTTP exchanges and effect logs prove real crash/restart, modeled coordinator cursor handoff (not a server process restart), process-group escalation, full-ring/pending-stdin recovery and real systemd restart. A further live recovery-isolation recording SIGSTOPs three responders and creates a torn manifest while a healthy exec survives agent restart in under five seconds. A release compatibility rehearsal must supply an explicit previous supervisor executable; unsupported versions are typed errors, never substituted with the new executable. The first-generation recording pins its baseline supervisor build and drives it with a later agent build.

## Rendezvous socket

The agent listens on one Unix socket per machine, `ctl.sock` in the machine's private directory (the parent of the operations directory: `~/.wuhu/machine-v2/<id>/ctl.sock` for the CLI, the app's machine directory for Direct). Composition checks its length before anything else: a path over 103 UTF-8 bytes (the bound NIO enforces on every platform, Darwin's `sun_path` without its NUL) is invalidConfiguration whose message and details name the path, its length and the limit, so a long home directory fails at start with a fixable error instead of a bind failure later. It then takes the operations-root lock, recovers manifests, removes a stale owner-owned socket, binds and chmods 0600, and unlinks the socket when the agent stops.

Every version-2 supervisor dials `ctl.sock`; it never creates a socket. Frames are a 4-byte big-endian length and at most 64 KiB of payload. Both ends first check the peer's uid against their own (SO_PEERCRED on Linux, LOCAL_PEERCRED on Darwin). The supervisor sends a hello `{protocol: "wuhu-supervisor-rendezvous.v1", machine, operation, nonce}`; the agent admits it only for a known version-2 manifest of this machine whose nonce matches in constant time, and otherwise replies with a typed refusal (peerCredentials, unsupportedProtocol, malformedHello, unknownOperation, manifestVersion, machineMismatch, nonceMismatch) and closes. A handshake frame that does not arrive in two seconds closes the connection. After acceptance the connection carries a Fetch tunnel: the agent is the client and the supervisor serves its existing nonce-authenticated gate, so every forwarded request still carries the nonce header and the same identity, lease and receipt contracts as the version-1 HTTP socket. A newer link for an operation replaces the older one.

The registry sends a version-2 request over that operation's link, waiting at most two seconds for the supervisor to connect (supervisorUnavailable `supervisorNotConnected`), then bounds the exchange at two seconds for identity and 25 for forwarded requests (supervisorUnavailable `supervisorTimeout`). Version-1 manifests keep the HTTP-over-Unix clients. A supervisor whose dial fails or whose link drops keeps its command running and redials with backoff from 50 ms doubling to 1 s, resetting after an accepted link, so an agent restart reattaches every live supervisor within about a second without replaying a start. A version-1 manifest handed to a new supervisor (an older agent launching a newer executable) still binds its own socket and does not dial.

## Unavailable tombstone cleanup

At most 4,096 manifests of at most 4,096 bytes are admitted; recovery checks the same count before inserting. Unavailable operations keep conservative reservations and can exhaust admission rather than release an unproven live buffer. A supervisor-owned expired receipt removes its directory itself; describe/start reconcile those missing directories without renewing leases. For a crashed supervisor, stop the diagnostic agent, verify no supervisor or exec process from the affected operation remains (host reboot is conclusive), remove only that owner-private operation directory, and restart the agent. Never use a PID alone to adopt, signal or recreate an operation. If process ownership cannot be established, leave the tombstone and report supervisorUnavailable. Logical production drain/uninstall is deferred to slice 5.

## Compatibility rehearsal

Run `python3 tools/infra/wuhu-machine-v2/record-runs.py --new-binary <absolute-new-wuhu> --new-sha <full-source-sha> --old-binary <absolute-previous-wuhu> --old-sha <full-previous-source-sha> --output <fixture-directory> --case old-supervisor-new-agent`. Both explicit versions and matching source stamps are mandatory; full SHAs are used for current artifacts and the exact published dev113 historical stamp prefix is allowlisted for its immutable previous artifact. The old executable must report the exact validated full SHA or allowlisted historical prefix in its embedded `--version` stamp; other abbreviated/unknown metadata fails closed. Old/new executables must have different SHA-256 content hashes, recorded with the validated old version. A pinned baseline may be built with a Bazel workspace-status command emitting its full checked-out git SHA (no source changes); every-release full-stamp/artifact selection is part of the slice-5 release gate. An unsupported previous executable fails and no current-binary replacement is permitted. The actual published dev113 supervisor is started exactly once, both stdout/stderr rings fill while stdin remains pending, and the new agent recovers by nonce then drains byte-exact output. Pending output cursors block production logical leave; after output is consumed, an explicit describe must still remain non-detached until a matching terminal acknowledgement is accepted by the old supervisor. The production CLI then waits for final server leave acknowledgement. macOS PR CI and release gates invoke real `machine-v2 uninstall` against an isolated launchd service and verify service stop/unload plus definition removal. Linux pool tests still exercise explicitly logical-only leave proof, but relevant PRs and every main push additionally require real `machine-v2 uninstall` on the dedicated `linux-systemd` worker using the pool-built static candidate. Release builds hand the staged Linux binary/archive to the same real-manager gate before upload; release receipts must carry `realManager` and bind the actual candidate/archive hashes. Missing user-systemd or failed drain fails closed. Worker cleanup stops only marked compatibility units, tolerates link removal by disable, waits for isolated supervisors to expire their own lease, then removes only marked owner-private temporary state. `--service-proof real-manager` exercises the actual Linux installer and user systemd on that authorized scratch host. The immutable dev113 fixture records this real systemd uninstall with supplemental clean candidate provenance, not final-head rollout proof. Every-release artifact selection, both-platform live enforcement and recorded replay are wired by the slice-5 release gate before rollout.

## Authenticated installed runtime composition

`withComputerAgent(machine:operationsDirectory:executable:files:kinds:audit:)` holds the exclusive operations-root lock, recovers supervisors, listens on the rendezvous socket and runs ComputerFiles' `ComputerAgent` with the supervisor registry as its external exec kind for the duration of a body; an embedding host (the Direct Mac app) serves `agent.handler` and calls `agent.leave()` itself, with an explicit short operations root and its own supervisor executable path. `runComputerAgent` (the CLI's entry, unchanged signature: local files, no extra kinds) adds the private Unix control socket (`PUT /leave`) around it while running the injected generic Fetch handler transport. Temp-directory contract tests drive the public `withComputerAgent`: describe lists exec, the file kinds and an injected extra kind, `read.v1` runs over the injected file system, the lock is held for the body's lifetime, and on both return and throw the body's value or error comes back unchanged, the lock is released and the in-process runtime is shut down. A narrower test of the internal composition shows the registry's run loop polls only while the body runs. All private Unix supervisor clients (including the diagnostic runner) use an explicit one-thread NIOPosix group on macOS and Linux, not AHC’s platform-default Network.framework transport. The owner shuts down HTTP pools and its owned group on success/failure/cancellation; no transport fallback or alternate path is attempted. It recovers independent exec supervisors and composes exec/read/find/grep behind one machine authorization gate and one diagnostic agent instance. Admission probes both registries and includes in-progress starts; a generation guard rejects stale concurrent admission snapshots rather than exceeding the combined 32-active/64-MiB/4096-receipt caps. Neither backend can adopt an operation ID already claimed by the other. The shared cap is not allocated twice; each backend retains its own defensive limits underneath.

The private control `PUT /leave` refuses new starts, stops file work and requests supervisor leave without disconnecting the tunnel. Supervisors stop their operations through the existing operation runtime and retain terminal/output evidence until server acknowledgements. Authenticated nonrenewing `/departure` probes establish whether each supervisor has fully settled; unavailable/torn/unsupported responders are typed failures, not process-kill workarounds. The local waiter completes only when the server sends machine describe `?leaveAck=true` after consuming the ordinary `leaving` response. An acknowledgement before settlement is invalidInput. The complete local handshake is bounded by one 60-second lease. Timeout while starts/supervisors/files are still draining is requestDeadline with message drainFailed, so uninstall preserves the service. Only timeout after drain completion while waiting for the final server acknowledgement is leaveUnacknowledged; subsequent describes cannot report leaving or renew presence. Dropping the tunnel alone never satisfies departure.

## Published supervisor departure capability

A nonce-authenticated explicit 404 unknownOperation from `/leave` or `/departure` selects the published v1 supervisor capability, not another machine stack. The agent sends the existing idempotent v2 operation stop and observes its real terminal snapshot and acknowledged output receipt through forwarded server polls. A drained legacy receipt requires its real terminal verdict, outputConsumed and a matching terminalAck accepted by that supervisor in a successful operation GET. Accepted terminal tokens observed before capability discovery are retained; a caller request, failed acknowledgement or mismatched token is not proof. LeaseExpired verdicts are checked before output/ack state and always remain loss, including empty or already acknowledged output. While a receipt is not drained, capability probes do not locally consume its output or renew its execution lease. A full local lease duration permits a state observation, never an invented exit verdict. An observed stopped verdict explicitly caused by leaseExpired, or an authenticated unknownOperation, is retained as distinct lease-loss evidence, not drained output. If an unresolved legacy receipt disappears locally, the registry retains its manifest/evidence and returns typed supervisorUnavailable with legacyReceiptDisappeared, unacknowledged and cleanupAuthorized:false; local absence alone cannot become a clean departure or authorize loss cleanup. Already authenticated loss evidence remains loss after local receipt removal; fully proved clean receipts alone may be pruned. Only after all other exec/file work is also settled may that evidence return typed leaveUnacknowledged with affected operation IDs and legacyLeaseExpired reason, permitting lost/unacknowledged cleanup. It never reports leaving, outputConsumed or a clean goodbye. A timer alone or an unavailable responder remains pending/typed failure and preserves the service. Non-404 auth/transport/protocol errors never select legacy behavior, and no start is replayed. Actual published dev113 binaries are exercised by the release compatibility lifecycle gate.

Private successful leave/departure replies remain bounded JSON Boolean literals decoded with standard Fetch `Body.json(Bool.self)`. Malformed/oversized/unreadable receipts remain typed failures. The actual scratch uninstall defect was missing Host in the CLI's HTTP/1.1 Unix request, which Serve rejected with a plaintext 400 before dispatch; registry Unix requests already set Host:localhost. The CLI now sets that same explicit Host, and a real Unix HTTP regression exercises the production leave client and handler rather than only response parsing. No alternative parser or transport is attempted.

The launchd recording waits up to ten local seconds for a successful describe over the recreated agent socket after both bootstrap and kickstart; a fixed post-restart sleep is not readiness evidence. Failure diagnostics and recordings are written outside the temporary agent home before cleanup. Every recording finally boots out its owned launchd job, removes its plist, closes its processes and removes all owned temporary homes (including the initial home replaced by a compatibility run). Cleanup proceeds to the remaining resources even when an earlier cleanup step fails; no pre-existing service or directory is swept by this per-run cleanup.
