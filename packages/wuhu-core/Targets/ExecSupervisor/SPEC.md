# ExecSupervisor

A macOS/Linux-only exec implementation beside machine v1. The signed `wuhu machine-v2 supervise <operation-directory>` mode owns one operation; argv, environment and resolved secrets arrive in the one authenticated POST over its Unix HTTP socket, never command arguments or disk diagnostics. The internal `ExecSupervisorRegistry` routes actual operation requests to independent supervisors and overwrites the diagnostic agent-instance header. It never retries a start, invents running evidence, reruns an ambiguous launch, or renews a lease during identity discovery. `recover()` reads each bounded manifest in isolation and binds without contacting responders; malformed/torn manifests become per-ID typed tombstones naming the manifest path. Decoding errors become invalidConfiguration; a changed machine name becomes supervisorIdentityMismatch, isolated to that directory. Nonregular manifest files are rejected without blocking on a FIFO. The first addressed request authenticates the persisted nonce, machine, operation and protocol version with a separate two-second identity transport before forwarding. One SIGSTOP/hung responder cannot delay describe, discovery or a different healthy exec. A failed responder remains an unavailable receipt and does not prevent describe/other operations; its identity must validate before any forwarding. Missing, invalid and misconfigured responders are typed failures; no alternate identity, stack or TCP path exists.

Operation UUID spelling is case-insensitive on start and subsequent requests; the gate compares parsed UUID values rather than canonical strings.

The operation directory is exclusively created 0700, manifest 0600 and Unix socket 0600, owned by the agent user. Manifests contain only protocol version 1, machine, operation, 256 random nonce bits and the exact local socket path. IDs are never adopted by PID. Overlong Unix socket paths are invalidConfiguration: configure an explicit shorter private operations root. A single service owner holds a close-on-exec file lock; restart may remove only its owner-owned stale agent socket after taking that lock. The agent lifecycle reaps only its own launched supervisor children with nonblocking waitpid; supervisor identity still never uses PIDs. The registry requires one owner and reserves 32 active operations and bounded receipt/channel budgets; authenticated nonrenewing identity metadata restores reservations and active counts. Old responders retain conservative reservations until actual terminal/consumed replies; consumed old receipts retain a 64 KiB stdin reservation. New snapshots charge retained stdin and unfinished finite tails, plus a conservative 1 MiB masking/pipe staging allowance until both final offsets exist. Missing self-expired directories release registry receipts on describe/start. Dead supervisor directories remain bounded unavailable tombstones, never rerun; operator cleanup is required if a supervisor died before it could remove its directory.

`ExecKind` validates nonempty NUL-free argv, absolute cwd and valid environment names. posix_spawn creates a separate process group and pipes; no Swift work runs in a fork child. The child environment removes inherited identity/group and session names, overlays caller values and resolved secrets, then installs only the supplied session credential. Secret masking and its bounded cross-chunk lookbehind live in the supervisor. stdout and stderr have independent 256 KiB windows, stdin 64 KiB plus an 8 KiB partially written pipe chunk, and each output pipe at most one bounded masked staging chunk/lookbehind. Full rings stop pipe reads, not control requests or direct-child observation. Offsets acknowledge accepted stdin retained in the supervisor, not physical pipe consumption.

Direct-child wait evidence is observed independently with waitid(WNOWAIT). At that observation each pipe freezes the bytes currently in the kernel pipe; only that finite tail is drained under backpressure. Future descendant writes are outside the output contract. Terminal evidence is published before tail draining, with final offsets absent until each finite tail ends. Natural completion never kills a deliberately detached daemon; such daemons should redirect inherited pipes. Stop/lease expiry sends process-group SIGTERM then SIGKILL after five seconds, keeps the leader unreaped until escalation is complete, and reports stopped only on observed exit with its exit/signal result. Escaping a process group and unkillable kernel work are not sandbox guarantees. Spawn failure is spawnFailed, not an invented exit 127.

The supervisor grants its own 60-second monotonic initial lease, renewed only by valid operation requests. Recovery within its remaining lease preserves child, rings, stdin and masking state; discovery alone cannot revive it. Host reboot or supervisor death does not recover execution. Receipt and output retention follow OperationRuntime; the supervisor exits and removes its own manifest/socket after receipt expiry, never because an active operation has run 24 hours. A launch with no received POST expires after its initial lease. Credentials still expire independently; no credential renewal is added here.

`wuhu machine-v2 local-agent <machine> <operations-directory> <agent-socket>` is a private Unix-only diagnostic runner for recordings, not enrollment or the public server route. Its socket parent must be owner-private and its HTTP adapter disallows redirects/replay. The user systemd template in tools/infra/wuhu-machine-v2 explicitly uses KillMode=process so service restart kills only the agent. It is not a production installer; authenticated dial-out/enrollment, macOS launchd preflight and logical leave/uninstall are slice 5. Never uninstall by merely stopping this diagnostic unit: supervisors remain governed by their lease.

Real server-process restart and macOS service-manager restart are deferred to slice 5.

Tests exercise production handlers/pipe effects, torn manifest and hung discovery isolation, reaping, independent output rings, inherited-daemon pipes, split masking, spawn evidence and finite tails. Offline replay runs the production OperationClient and MemoryOperationStore over recorded HTTP outcomes: emitted cursors and input offsets must match, output must be committed before acknowledgement, terminal evidence must validate, and coordinator recreation uses the same persisted store. Only JSON formatting, diagnostic echo headers, and equivalent default query fields from the original Python driver are normalized. Fixture effects describe observed live evidence, not simulated C effects; a live TERM-ignore test runs production escalation in both CI host lanes. Deleting the production SIGKILL escalation was mutation-tested and makes that test fail with timeout. Recorded HTTP exchanges and effect logs prove real crash/restart, modeled coordinator cursor handoff (not a server process restart), process-group escalation, full-ring/pending-stdin recovery and real systemd restart. A further live recovery-isolation recording SIGSTOPs three responders and creates a torn manifest while a healthy exec survives agent restart in under five seconds. A release compatibility rehearsal must supply an explicit previous supervisor executable; unsupported versions are typed errors, never substituted with the new executable. The first-generation recording pins its baseline supervisor build and drives it with a later agent build.

## Unavailable tombstone cleanup

At most 4,096 manifests of at most 4,096 bytes are admitted; recovery checks the same count before inserting. Unavailable operations keep conservative reservations and can exhaust admission rather than release an unproven live buffer. A supervisor-owned expired receipt removes its directory itself; describe/start reconcile those missing directories without renewing leases. For a crashed supervisor, stop the diagnostic agent, verify no supervisor or exec process from the affected operation remains (host reboot is conclusive), remove only that owner-private operation directory, and restart the agent. Never use a PID alone to adopt, signal or recreate an operation. If process ownership cannot be established, leave the tombstone and report supervisorUnavailable. Logical production drain/uninstall is deferred to slice 5.

## Compatibility rehearsal

Run `python3 tools/infra/wuhu-machine-v2/record-runs.py --new-binary <absolute-new-wuhu> --new-sha <full-source-sha> --old-binary <absolute-previous-wuhu> --old-sha <full-previous-source-sha> --output <fixture-directory> --case old-supervisor-new-agent`. Both explicit versions and full hexadecimal source SHAs are mandatory. The old executable must report the exact full SHA in its embedded `--version` stamp; abbreviated/unknown metadata fails closed. Old/new executables must have different SHA-256 content hashes, recorded with the validated old version. A pinned baseline may be built with a Bazel workspace-status command emitting its full checked-out git SHA (no source changes); every-release full-stamp/artifact selection is part of the slice-5 release gate. An unsupported previous executable fails and no current-binary replacement is permitted. The old supervisor is started exactly once, stdout fills its ring, stdin remains pending, and the new agent recovers by nonce then drains byte-exact output. The initial fixture pins the supervisor baseline before the later transport/accounting changes. Every-release artifact selection/bootstrap and both-platform release-stage enforcement are deferred to slice 5, and must land before any v2 rollout.
