# ExecSupervisor

A macOS/Linux-only exec implementation beside machine v1. The agent runs every exec in an exec worker process, `wuhu machine-v2 exec-worker <worker-directory>`, launched detached so execs outlive an agent restart or upgrade. One worker, the current one, takes every new start; argv, environment and resolved secrets arrive in the authenticated POST, never command arguments or disk diagnostics. Workers create no socket: each dials the agent's `ctl.sock` and serves the operation protocol over that link (see Rendezvous socket). The internal `ExecWorkers` actor routes each operation request to the worker holding it and overwrites the diagnostic agent-instance header. It never retries a start, invents running evidence or reruns an ambiguous launch. Version-2 supervisors an older agent launched, one per operation (`wuhu machine-v2 supervise <operation-directory>`), are adopted and drained the same way until they exit; a version-1 supervisor (its own listening socket) is not adopted. Its operation answers unknownOperation with details `{outcome: unknown, reason: supervisorNotAdopted}`, its id stays taken; at recovery the agent sends it a nonce-authenticated `PUT /retire` over its socket (one that predates `/retire` stops its exec when its own 60-second lease runs out) and removes its directory when nothing listens there.

The computer-agent composition holds its owner-private persistent `.agent.lock` for the body's lifetime, then explicitly unlocks before closing on either return or throw. A duplicate or concurrently inherited open-file description does not extend lock ownership past that boundary; while the body runs, a second owner remains refused.

Operation UUID spelling is case-insensitive on start and subsequent requests; the gate compares parsed UUID values rather than canonical strings.

## Workers

A worker's directory is `<machine directory>/workers/<worker>`, created 0700 by the agent with a 0600 `manifest.json` (machine, worker id, 288 random nonce bits, the exact `ctl.sock` path, the optional exec-child responsibility policy and a receipt-retention override only tests set). The worker holds the directory's close-on-exec `.lock` (`flock`) from its start until it exits. Its inventory, `operations.json`, names every operation it retains, those among them still unsettled, and those it dropped before they settled; it is replaced whole (written beside it, then renamed) whenever it changes: before a start runs, before every hello, after a terminal acknowledgement and on a 100 ms tick. On exit the worker removes the directory, or leaves an inventory naming only what it dropped unsettled. Protocol identities never use a PID; installed cleanup uses lifetime-locked process-group receipts.

Evidence (an inventory, the loss ledger) is at most 1 MiB: writers refuse more, and a worker whose inventory cannot be written truncates it to empty, which no reader accepts. A missing file is no evidence; one that exists and cannot be read whole (malformed, empty, oversized, wrong mode) is an `unreadableEvidence` error, never an empty record.

Lifetime: a worker exits once it holds no operations and it is not the linked, current worker. A launched worker that never links exits after a 10-second grace. A worker the agent refuses stops its running execs (reason `refused`), never redials, and exits under the same rule.

A worker admits a start only while it is linked and current. A request for an operation whose start it admitted but has not yet answered waits for that start, so it never answers unknownOperation for it. It writes the start's id into its inventory first and then checks for the `superseded` marker in its directory, refusing the start (supervisorUnavailable `workerNotCurrent`) if it is there. A recovering agent writes the marker before it reads the inventory, so the inventory it reads names every operation the worker can ever hold.

Recovery: the agent loads its loss ledger, then marks and reads each live worker's inventory (its lock is held). Each operation named there is routed to that worker: a retained unsettled one is charged in full, a settled one nothing. A worker whose inventory cannot be read may hold anything: it is charged the whole budget, any id no route names is supervisorUnavailable `workerNotConnected` rather than unknown, until that worker's first hello. A recovered worker's first hello makes the agent read its inventory again: routes to operations it no longer retains go, what it dropped joins the ledger, and the rest is adopted as it now stands.

The ledger, `<machine directory>/workers/lost.json`, is the agent's record of operations dropped before they settled; it is written durably (fsync, then rename) before any evidence it summarizes is removed, since a torn ledger would fail every later recovery. It is the only file here that is fsynced: every other file the agent, workers and exec children write describes processes a host crash ends, so it only has to be visible to other processes, and a sync would stall exec spawns behind the publication lock. A dead worker (its lock free) adds its inventory's unsettled and dropped operations plus every unsettled operation routed to it, and only then is its directory removed while the agent holds the lock, so no late writer races the removal; if the write fails the directory stays for the next probe. A dead worker whose inventory cannot be read, and whose operations no route names (its inventory was never read), keeps its directory: an id no route names answers unknownOperation `{outcome: unknown, reason: workerUnaccounted}`. A ledger that cannot be read fails recovery. A worker that answers unknownOperation for an operation last seen unsettled (never for one whose start is still on its way: that answer says nothing yet), and a route unrequested for one receipt retention window plus a second (the worker drops that receipt), add that operation unless it had settled. A ledger id answers unknownOperation with details `{outcome: unknown, reason: workerLost}`; the ledger survives agent restarts. The agent judges every worker by its lock; until its first link, a worker it launched counts as starting while its PID still names a process. A launched worker is reaped by a detached thread of the agent's process that waits for its exit, so reaping outlives the agent's scope (an app whose machine turned off keeps no zombie). When the current worker dies the agent launches the next one (backoff from 100 ms doubling to 5 s while launched workers never link).

Routing: a start goes to the current worker, waiting for it to link at most two seconds, or while a worker this agent launched is still within its ten-second first-link grace (supervisorUnavailable `workerNotConnected`). A routed id goes to its owner, waiting at most two seconds for it to (re)link. Any other id is in the ledger, unavailable while some recovered inventory is unreadable, or else unknownOperation at once. Forwarded requests are bounded at 25 seconds (supervisorUnavailable `supervisorTimeout`), and the deadline cancels the forwarded stream.

Admission is charged from routes alone: each routed operation its descriptor windows plus 16 KiB read staging until its worker's snapshot reports `bufferReservationBytes`, then that (plus the staging until both final offsets exist); a settled operation nothing, so an operation that settles after an inventory was read releases its charge through its ordinary poll. A start whose answer was lost stays charged, since it may be running; one the worker refused is forgotten. The shared caps are 4,096 receipts and 64 MiB with no active-operation cap.

Restart: the agent takes the operations-root lock, recovers live workers, the loss evidence of dead ones and version-2 supervisor manifests, binds `ctl.sock`, and launches its own current worker. Workers from the previous agent redial within a second, hold their operations to the end and then exit, so the machine returns to the agent plus one worker.

`ExecKind` validates nonempty NUL-free argv, absolute cwd and valid environment names. posix_spawn creates a separate process group and pipes; no Swift work runs in a fork child. The child environment removes inherited identity/group and session names (including WUHU_ID_TOKEN_URL/WUHU_ID_TOKEN_REQUEST, which only the server supplies, in env and secretValues), overlays caller values and resolved secrets, then installs only the supplied session credential. Optional expiresAt epoch seconds become server-owned WUHU_TOKEN_EXPIRES_AT, never inherited or caller-overridden; the worker masks the bearer on both output pipes. Secret masking and its bounded cross-chunk lookbehind live in the worker. stdout and stderr have independent 256 KiB windows, stdin 64 KiB plus an 8 KiB partially written pipe chunk, and each output pipe at most one bounded masked staging chunk/lookbehind. Full rings stop pipe reads, not control requests or direct-child observation. Offsets acknowledge accepted stdin retained in the worker, not physical pipe consumption.

Installed macOS box agents (`runComputerAgent`, used by `machine-v2 run`) request TCC responsibility disclaiming for new exec children. The private worker manifest persists the policy so workers apply `responsibility_spawnattrs_setdisclaim` to the actual child spawn, not to the app or agent process; exec input cannot change it. Protected folders without a grant can therefore fail immediately instead of asking the headless agent for consent. Disclaimed children do not inherit grants charged to their parent agent. `withComputerAgent`, including the Direct app, keeps normal inheritance and interactive prompts; local-agent diagnostics and Linux keep normal spawning too. Old manifests omit the policy and retain their original behavior; already-running children are not changed. If the weak-linked SPI is missing, the installed agent logs one `tccDisclaim: unavailable` warning at composition and creates children normally instead of disabling exec. An available SPI returning an error is a typed spawn failure.

Direct-child wait evidence is observed independently with waitid(WNOWAIT). At that observation each pipe freezes the bytes currently in the kernel pipe; only that finite tail is drained under backpressure. Future descendant writes are outside the output contract. Terminal evidence is published before tail draining, with final offsets absent until each finite tail ends. Natural completion never kills a deliberately detached daemon; such daemons should redirect inherited pipes. Stop/lease expiry sends process-group SIGTERM then SIGKILL after five seconds, keeps the leader unreaped until escalation is complete, and reports stopped only on observed exit with its exit/signal result. Escaping a process group and unkillable kernel work are not sandbox guarantees. Spawn failure is spawnFailed, not an invented exit 127. An operation dropped while its finite tail still drains kills the rest of its process group.

`ExecSupervisor.launchDetached` starts any argv the way workers start (own process group, standard descriptors on /dev/null) and `reapIfExited` reaps it without blocking; the machine v2 upgrade helper uses them. `launchReaped` (what the agent launches workers with) adds the detached reaper thread.

Receipt and output retention follow OperationRuntime: an operation is dropped at once when it settles, else 60 seconds after its caller's last request, never because it has run 24 hours. Agent restart preserves running children, rings, stdin and masking state, since they live in the worker. Host reboot or worker death does not recover execution. Credentials still expire independently; no credential renewal is added here. An adopted version-2 supervisor keeps its own 60-second lease, renewed by operation requests, and exits once its operation is dropped; the agent asks it to retire once its operation is released.

`wuhu machine-v2 local-agent <machine> <operations-directory> <agent-socket>` is a private Unix-only diagnostic runner for recordings, not enrollment or the public server route. It uses the production computer composition, including the rendezvous socket beside `<operations-directory>`, over a separate owner-private agent socket. Its socket parent must be owner-private and its HTTP adapter disallows redirects/replay. The user systemd template in tools/infra/wuhu-machine-v2 explicitly uses KillMode=process so service restart kills only the agent. It is not a production installer; authenticated dial-out/enrollment, macOS launchd preflight and uninstall are slice 5. Never uninstall by merely stopping this diagnostic unit: workers keep their operations until those are dropped.

The real macOS launchd recording uses an isolated label with AbandonProcessGroup and verifies the same supervisor nonce/PID across restart while stdout is full and stdin is pending. Its restart explicitly boots out the owned label, confirms disappearance with bounded print polling, then bootstraps the plist (at most five attempts for exit 5 only) and waits for the private agent endpoint; it does not kickstart a possibly absent job. Its exact output and one-start evidence replay through the production OperationClient offline. The production canary remains responsible for real server-process restart; a local-agent recording does not claim that proof. The Mac check runs it against `wuhu_unstamped`, whose `buildProvenance` says `unstamped` and which replay rejects; the checked-in fixture is re-recorded with the `manual` `//tools:machine-v2-launchd-recording`, whose stamped binary names its commit.

Tests exercise production handlers/pipe effects, worker lifetime with real worker processes (several execs share one worker, a crashed worker's exec is lost and the next worker takes over, restart returns to one worker, a retired worker exits and is reaped after the agent's scope ended, a revoked one having released its receipts and a turned-off one once they lapse, with the loss evidence kept for the next agent), reaping, independent output rings, inherited-daemon pipes, split masking, spawn evidence and finite tails. Offline replay runs the production OperationClient and MemoryOperationStore over recorded HTTP outcomes: emitted cursors and input offsets must match, output must be committed before acknowledgement, terminal evidence must validate, and coordinator recreation uses the same persisted store. Only JSON formatting, diagnostic echo headers, and equivalent default query fields from the original Python driver are normalized. Fixture effects describe observed live evidence, not simulated C effects; a live TERM-ignore test runs production escalation in both CI host lanes. Deleting the production SIGKILL escalation was mutation-tested and makes that test fail with timeout. Recorded HTTP exchanges and effect logs prove real crash/restart, modeled coordinator cursor handoff (not a server process restart), process-group escalation, full-ring/pending-stdin recovery and real systemd restart. A further live recovery-isolation recording SIGSTOPs three responders and creates a torn manifest while a healthy exec survives agent restart in under five seconds. A release compatibility rehearsal must supply an explicit previous supervisor executable; unsupported versions are typed errors, never substituted with the new executable. The first-generation recording pins its baseline supervisor build and drives it with a later agent build.

## Rendezvous socket

The agent listens on one Unix socket per machine, `ctl.sock` in the machine's private directory (the parent of the operations directory: `~/.wuhu/machine-v2/<id>/ctl.sock` for the CLI, the app's machine directory for Direct). Composition checks its length before anything else: a path over 103 UTF-8 bytes (the bound NIO enforces on every platform, Darwin's `sun_path` without its NUL) is invalidConfiguration whose message and details name the path, its length and the limit, so a long home directory fails at start with a fixable error instead of a bind failure later. It then takes the operations-root lock, recovers manifests, removes a stale owner-owned socket, binds and chmods 0600, and unlinks the socket when the agent stops.

Every worker and version-2 supervisor dials `ctl.sock`; neither creates a socket. Frames are a 4-byte big-endian length and at most 64 KiB of payload. Both ends first check the peer's uid against their own (SO_PEERCRED on Linux, LOCAL_PEERCRED on Darwin). A worker sends a hello `{protocol: "wuhu-supervisor-rendezvous.v1", machine, worker, nonce}`, a supervisor `{protocol, machine, operation, nonce}`; the agent admits only a worker or supervisor it knows on this machine whose nonce matches in constant time. The reply tells a worker whether it is current. Otherwise the agent replies with a typed refusal (peerCredentials, unsupportedProtocol, malformedHello, unknownOperation, manifestVersion, machineMismatch, nonceMismatch, unknownWorker) and closes; a refusal is permanent, and the dialer stops its operations and never redials. A handshake frame that does not arrive in two seconds closes the connection. After acceptance the connection carries a Fetch tunnel: the agent is the client and the dialer serves its nonce-authenticated gate. A worker's tunnel admits `MachineV2Connect.tunnelStreams` concurrent streams, the same as the server's. A newer link from the same dialer replaces the older one.

A dialer whose dial fails or whose link drops keeps its execs running and redials with backoff from 50 ms doubling to 1 s, resetting after an accepted link, so an agent restart reattaches every live worker within about a second without replaying a start.

## Authenticated installed runtime composition

`withComputerAgent(machine:operationsDirectory:executable:files:kinds:audit:)` holds the exclusive operations-root lock, recovers workers and supervisors, listens on the rendezvous socket and runs ComputerFiles' `ComputerAgent` with `ExecWorkers` as its external exec kind for the duration of a body; an embedding host (the Direct Mac app) serves `agent.handler`, with an explicit short operations root and its own executable path, which answers `machine-v2 exec-worker`. `runComputerAgent` (the CLI's entry: local files, no extra kinds) runs the injected generic Fetch handler transport. Both hand the body a `retire` function besides the handler or agent (see Retirement). Temp-directory contract tests drive the public `withComputerAgent`: describe lists exec, the file kinds and an injected extra kind, `read.v1` runs over the injected file system, the lock is held for the body's lifetime, and on both return and throw the body's value or error comes back unchanged, the lock is released and the in-process runtime is shut down. Rendezvous links use an explicit one-thread NIOPosix group on macOS and Linux. ComputerAgent's one admission budget covers in-process, external and not-yet-returned starts; neither backend can adopt an operation ID already claimed by the other.


## Retirement

A machine that stops serving stops everything it runs. `retire(.turnedOff)` and `retire(.revoked)` refuse new starts, send each operation without a verdict the standard stop with reason `retired` (SIGTERM to the process group, SIGKILL after five seconds, a real `stopped` verdict) and each adopted supervisor a nonce-authenticated `PUT /retire`. A start in flight is refused or included: its route exists from its service check, retirement waits for its answer, and an operation it started then gets the stop. The agent waits at most ten seconds for the verdicts; a revoked machine, whose receipts no server will read, then reads each ended operation's output to its end and acknowledges its terminal, so its worker releases it. Last it cuts every worker's link; a worker that redials hears it is not current, and exits under its lifetime rule once its receipts lapse, 60 seconds after their last request. Retirement returns how many operations still have no verdict. Nothing is signalled by PID. Retirement never waits for the server to acknowledge output.

- Turned off: the app retires before it stops serving. The machine's private directory stays, and the next run resumes in it.
- Revoked: the tunnel's 401 `machineNotAuthorized` (the key is no longer live, or the server does not know the machine) retires with `.revoked`. A rejected handshake, `keyInvalid`, may be a spent challenge and stays `enrollmentFailed`. The app retires on a tunnel or signed-read revocation and on removal. With `withComputerAgent`, the machine's private directory, the parent of the operations directory, is removed after the lock is released, and only when it is a directory owned by this user with no group or other permission bits. The installed CLI agent keeps its home, which holds its key, configuration and executable: it records the revocation, exits with `revoked` and status 0, which its service definition does not restart, and uninstalling removes the rest without contacting an agent.

The launchd recording waits up to ten local seconds for a successful describe over the recreated agent socket after both bootstrap and kickstart; a fixed post-restart sleep is not readiness evidence. Failure diagnostics and recordings are written outside the temporary agent home before cleanup. Every recording finally boots out its owned launchd job, removes its plist, closes its processes and removes all owned temporary homes (including the initial home replaced by a compatibility run). Cleanup proceeds to the remaining resources even when an earlier cleanup step fails; no pre-existing service or directory is swept by this per-run cleanup.

## Deployment administration separation

Computer-agent composition retains a close-on-exec lifetime machine-role lock and checks the fixed root-owned `/etc/wuhu/admin-exec.json` policy before recovering workers, binding sockets or admitting operations. An allowed administrator UID, unsafe policy or unavailable role lock refuses startup. No policy file leaves existing machine-agent behavior unchanged.

Supervisor request waiters obey the shared deadline and cancellation. Transport workers remain named in the supervisor transport scope until their adapter returns; shutdown cancels this scope but does not await non-cooperative adapters. Control work drains separately. Worker inventory persistence drains before directory removal, so no late inventory write can recreate a removed directory.


## Installed cleanup

`stopInstalled(operationsDirectory:)` runs after the service is stopped, without contacting an agent or server. Workers and supervisors write their process-group PID and leader birth anchor into an owner-private `.lock` receipt under an exclusive lifetime flock; each live exec group has an additional locked `.exec-<uuid>` receipt. A short per-directory publication flock serializes exec spawn and PID publication with cleanup. The existing executable self-reinvokes a hidden exec-child entry; that child publishes its own PID and birth anchor before exec, retaining the publication flock until publication is complete even if the worker crashes. An exec-error pipe preserves typed spawn failures. Exec children inherit their receipt lock on descriptor 3 so a worker crash does not make a live exec look stale; the worker unlinks that receipt before reaping the leader. Cleanup acquires the publication lock, freezes each receipt owner, kills the exec groups its receipts name and then the owner group. A free lock means stale evidence, which is removed without signalling its PID. A held lock alone is insufficient identity: each signal checks an extant leader against its recorded birth anchor; mismatch or lookup failure skips signalling and reports the receipt. Explicit leader absence permits signalling surviving group members, since their live process-group ID cannot have been reused. Invalid or inaccessible live receipts produce `supervisorUnavailable` with a `localStopFailed` message naming every failed receipt path and structured `paths` details; cleanup still attempts the other groups. Repeated cleanup is safe. The CLI wraps that error and still removes the service definition. Naturally completed commands may leave user-owned detached daemons; uninstall does not adopt those.
