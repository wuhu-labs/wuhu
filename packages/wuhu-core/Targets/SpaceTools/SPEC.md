# SpaceTools

## Checked file, history and discovery services

SpaceToolContext is the authority boundary shared by HTTP tool/file routes and script hosts. Every session write checks the destination group's readability, protected instruction layer, and own-home restriction. File byte writes, text write/edit, remove, both move endpoints and checkout all meet the same home/layer policy. Human and page principals retain their existing distinct write policy. Machine-note aliases resolve to their canonical machine-id path before storage. System files are readable but never writable, and `.table` paths cannot be written as ordinary bytes.

`readBytes(address, rev?, byteLimit?)` returns `{token, rev, data}` and can bound a result with a metadata preflight and post-read check. `writeBytes(address, data, ifMatch, createOnly:false)` returns `{token, rev}`. Existing HTTP byte/text clients retain their optional-token behavior; scripts require an explicit token or null and select createOnly for null. Create-only conflicts report `already exists` with advice to choose another path, never advice to replace the existing entry. Stale replacement reports conflict with the current token when available. Both checks occur inside the storage transaction; revision-addressed writes are refused before the direct live write. Checkout accepts an optional ifMatch on the existing HTTP verb and compares it inside the restoration transaction; scripts require an explicit token for replacement or null for an atomic create-only restoration. History supports after (exclusive non-negative revision) and limit (1–500, default 100), returning entries plus next. Storage fetches only one page plus its lookahead, never an entire journal for paging. `list(address, rev?, hidden:false, limit?, byteLimit?)` uses bounded live, historical and machine-alias storage reads when a cap is supplied, with one lookahead and fixed root-hidden overhead, then refuses overflow rather than truncating. Byte allowance overflow maps to invalidArgument with advice to narrow the directory.

`ownExecs`, `ownExecStatus`, and `killOwnExec` resolve the caller from the session principal and never accept a caller-supplied owner. Another session's or unknown exec id returns notFound before any kill effect. Listing includes only live owned records; status may inspect an owned terminal record. Wire statuses match the existing MachineContract ExecStatus shape.

`discoveryContext(contentHost)` uses the stored calling session's group rather than a caller-supplied principal group and returns session/group/resolved content origin. `discoveryGroups` serves the same membership/readability view for HTTP and script discovery, refreshing read edges on every call. Live group IDs are publicly discoverable; unreadable groups carry false flags. Anonymous development discovery and human membership retain their existing policy.
