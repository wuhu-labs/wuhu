# ExecutionOwner

`ExecutionOwnerClient` is the semantic persistence boundary of kernel execution. Its session facet, `SpaceCore.SessionExecutionOwnerClient`, supplies hydration, enqueue/drain, transcript append, scope context, queue/command reads, compact-request claims and completion, lifecycle writes and registered subscriptions. The inference facet supplies the current model document, session record, frozen prompt home, principal/device display names, referenced media bytes, attempt trace sinks, provider credential resolution, inference identity signing and metric delivery. No method accepts a database, store, blob store or caller-provided transaction/operation closure.

`InProcessExecutionOwnerClient` implements this boundary against the parent's existing `Space`, session store and injected metric sink. `InProcessSessionExecutionOwnerClient` is the narrower parent adapter for session-only composition. Neither exposes its concrete dependencies to execution. Reads and writes preserve existing store behavior, errors and transaction ordering: append/compaction must complete before local state and inference acknowledgement advance; a compact request claim is passed back when its completion commits. Prompt activation and reading use the same frozen prompt revision, while model documents are read live on each request. Media references are resolved under the reading session's group; fitting remains in execution, and a missing owned reference throws rather than disappearing. Metric delivery awaits the owner's sink. Credential loading/refresh and inference signing execute in the parent, returning request credentials/tokens and opaque verified binding identity to execution; unavailable signing retains the existing 422 error. `providerCredentialBinding` resolves the credential and its authoritative identity epoch together through the owner's credential resolver; execution never reconstructs identity from bearer values. Routine OAuth refresh retains the identity epoch, while credential replacement retires it. `inferenceBindingIdentity(audience:session:)` forwards the optional parent-owned stable OIDC binding identity seam, returning nil when absent; nil grants no opaque replay authority. The credential-only method derives its value from the same binding resolution. Neither seam exposes the credential store or a generic caller-supplied operation closure to execution. Portable handoff writes pass expected generation, source transcript and projected transcript through both owner adapters to the existing conditional session-owner commit, without a storage bypass.

`OwnerMediaResolver` leaves non-Wuhu media URLs to the provider adapter, and resolves Wuhu references through the owner before applying the existing image-fitting policy.

Session placement, boot/work-signal admission and archive coordination remain parent services. Script/tool host calls extend the in-process semantic boundary; there is no remote implementation or worker transport.

The adapter contract suite takes an owner factory and checks queue/drain/append and compaction ordering, lifecycle/error parity, live model/frozen prompt inputs, media reads and awaited metric delivery. Existing loop/store/server tests remain the behavioral regression suite.

Attempt trace files are parent-owned. `AttemptLogConfig` composes a sink in the parent; execution receives only `AttemptTraceClient`/`AttemptTraceSink`. Opening preserves truncation on each HTTP fetch and once per WebSocket attempt, append remains awaited best-effort, and each chunk is written before forwarding so partial trace evidence survives cancellation. No filesystem path enters inference execution.

Model group declarations are a separate live `modelGroupDocument` read; absent `/model-groups.json` returns nil. `modelDocument` remains provider-only and is the only catalog input to concrete budget resolution. A malformed group file therefore cannot inflate a direct or already-pinned concrete member's usable budget. The owner supplies current route reads and binding establishment; group intent remains additive while persisted executor_config stays compatible with dev.114. Prepared Start-over routes cross the restart owner method and commit with the generation reset, preserving append-only placement history. `inferenceReadiness(audience:)` validates the parent-owned OIDC prerequisites without issuing inference or exposing signer material; production composition injects local signer validation. Group credentials/readiness and routing are implemented through the in-process owner.


## Compaction placement and last-resort route transitions

The semantic execution-owner interface forwards epoch-checked route failure updates and optional atomic compaction/handoff route transitions. It does not expose a database writer. In-process/tool-owner forwarding preserves the complete expected epoch, route, portable generation and failure provenance rather than reducing them to ordinary compaction.
