# CExecSupervisor

Minimal POSIX effects for ExecSupervisor on Linux/macOS: posix_spawn with cwd, separate process group and three close-on-exec pipes; nonblocking parent pipe IO; waitid(WNOWAIT) for direct-child evidence; finite pipe-byte boundary; process-group signalling and explicit reap. No credentials, protocol, lease, ring or Swift runtime logic lives here. `exec_launch_detached` redirects standard descriptors to /dev/null and starts a distinct group, for exec workers and the machine v2 upgrade helper. Agent and worker ownership use owner-private close-on-exec advisory file locks. `exec_unix_request` sends one bounded request over a Unix socket, which the agent uses to retire a version-1 supervisor it does not adopt. Errors preserve errno for typed Swift failures. The owner must never signal a reaped leader by numeric identity and must close descriptors/reap children on teardown.

On macOS, `exec_spawn` optionally disclaims the child's TCC responsibility through weak-linked `responsibility_spawnattrs_setdisclaim`; callers choose the policy, while Linux ignores it. `exec_disclaim_responsibility_available` reports whether the SPI exists. An absent SPI preserves normal spawning; an available setter's error is returned before spawn, with all pipes closed. Detached supervisor/helper launches keep their existing inheritance.

`exec_spawn_with_disclaimer` is the same POSIX effect with an explicit setter function, allowing contract tests to record policy application, setter errors and missing-setter fallback independently of a host's TCC grants or default responsibility attribution. Production `exec_spawn` supplies the weak-linked macOS setter (or no setter on Linux).
