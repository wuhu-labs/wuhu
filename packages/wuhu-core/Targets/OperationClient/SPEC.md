# OperationClient

The client injects `FetchClient`, local monotonic clock, transactional `OperationStore`, IDs, synchronous exchange abort and a mandatory sanitized trace sink. The Fetch implementation must perform one transport dispatch per call, with no automatic POST retry, redirect/reconnect replay or identity/path/protocol fallback. Start bodies are deliberately non-replayable. Direct HTTP, dial-out tunnel and in-memory adapters use the same verbs.

`describe` establishes machine presence; new starts require an attached, start-accepting description supporting that kind. Detached/lost admission is `machineUnavailable {state,started:false}` without dispatch. An idle cached description is probed before a new invocation is admitted; a stale local presence cache alone is not loss evidence. Owner scope/key is independent of operation ID: `lookup`/atomic `claim` reuse the original invocation, while a changed machine/kind/input returns `invocationConflict`. Claim commits dispatch consumption before returning the one-use permission. A crash after claim but before send is reconciled by ID, never by another POST. An unanswered POST is followed by GET; definitive `unknownOperation` is honest and conclusive.

The exchange ledger times both Fetch and bounded body collection independently of transport cancellation. Operation responses use the shared 256 KiB aggregate cap. The runner budgets the actual slash-unescaped terminal metadata/result and worst-case payload during kind registration, so maximum slash-heavy results and base64 output fit as well as ordinary text. Caller cancellation is typed requestCancelled and traced cancelled, distinct from deadline expiration. It does not use a task-group timeout that waits for a noncooperative losing child. Expiration resolves the caller, invokes abort and ignores late completions. Timed-out workers retain bounded capacity until they actually return; a poisoned adapter eventually refuses further work with `capacityExceeded`, rather than accumulating arbitrary stuck tasks. The transport owner must close/replace that broken adapter explicitly, not silently detour. `shutdown()` expires outstanding exchanges. Trace failure is `traceUnavailable`, never silently unobserved dispatch. Decode and operation-silence deadlines are checked on the client's local clock as well.

Normal request bounds are 5 seconds and poll bounds 25 seconds. A caller duration can be shorter and returns `callerDeadline` with operation ID and pending knowledge, persists stop intent and attempts stop without continuing normal renewal. `reconcile` repeats stop for abandoned records and polls other records. The record becomes unknown only after a full operation lease without a complete valid answer, or immediately on a definite unknown-operation response. Description or a neighboring operation cannot refresh another operation's silence. Stop and abandoned-record reconciliation use the same full-silence accounting and remaining-lease request bound; definitive unknown-operation stop replies are persisted. A best-effort stop after loss does not erase unknown knowledge merely by returning a nonterminal snapshot. Restarted clients start a fresh full silence lease, preserve invocation/cursors/pending input/terminal evidence, and never resend starts. The persisted remaining caller duration is conservatively re-anchored locally; a real owner coordinator must stop dead scripts and persist elapsed owner budget independently across downtime.

Poll commits payload, cursor and terminal snapshot atomically before a later poll acknowledges the cursor. Input is persisted before dispatch and repeats at identical offset/payload; partial writes retain the original pending payload until fully accepted. The client takes each input/output channel exclusion before awaited cursor reads, captures dispatch state and the persisted evidence generation before each request, atomically applies unknown-operation answers only against that unchanged generation, clears superseded unknown on conclusive fresh evidence, and ignores older running snapshots after terminal evidence. It serializes each input/output channel and validates operation ID, payload unit/length, bounded result and immutable verdict. `takeOutput` transfers the retained bounded chunks to the caller; consumption/replay of arbitrary caller side effects is not an exactly-once guarantee. Only one coordinator may own a channel; concurrent independent coordinators require a durable ownership fence in the store.

The real store must implement atomic unique owner claims with immutable input identity/digest, durable consumed dispatch intent, transaction rollback, persisted evidence generations advanced with every successful snapshot/input receipt, operation receipts/stop intent/caller budget, committed payload-and-offset updates, persisted identical pending inputs and accepted offsets, and explicit retention/capacity. MemoryOperationStore is bounded test-only persistence, not the production server database. The real server must keep secret inputs encrypted/transient rather than placing raw start input in diagnostics, authorize group-filtered access, reserve per-script/machine capacity, persist presence/reasons and sanitized traces with seven-day retention/incident pins, and recover owners at startup. Existing v1 tables remain untouched in this slice.

`OperationClientTestSupport.verifyOperationStoreContract` is an importable test-support helper for owner uniqueness/conflict, output payload/cursor, pending input offset/payload/EOF and accepted offset, and rollback of every payload/cursor field. It rejects stores that drop payloads or damage them on rollback; concrete future stores must run it plus their own crash/restart tests.
