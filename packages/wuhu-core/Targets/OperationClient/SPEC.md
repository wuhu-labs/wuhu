# OperationClient

The client injects `FetchClient`, local monotonic clock, transactional `OperationStore`, IDs, synchronous exchange abort and a mandatory sanitized trace sink. The Fetch implementation must perform one transport dispatch per call, with no automatic POST retry, redirect/reconnect replay or identity/path/protocol fallback. Start bodies are deliberately non-replayable. Direct HTTP, dial-out tunnel and in-memory adapters use the same verbs.

`probe` is the background-presence variant of `describe`, with a one-second exchange deadline. It returns nil without dispatch or failure trace when the ledger is full. The first skipped probe reserves the next free ledger slot for a probe ahead of ordinary exchanges; another admitted probe consumes that reservation. Priority expires five seconds after the last skipped probe, so an unregistered machine cannot leave a permanent reservation when no replacement probe arrives. Callers retry skipped probes on their next sweep, and do not treat skipped admission as machine failure. Normal `describe` remains a required request with the usual typed/traced refusal. Probes run concurrently rather than serializing healthy machines behind a hanging one.

`describe` establishes machine presence; new starts require an attached, start-accepting description supporting that kind. Detached/lost admission is `machineUnavailable {state,started:false}` without dispatch. An idle cached description is probed before a new invocation is admitted; a stale local presence cache alone is not loss evidence. Owner scope/key is independent of operation ID: `lookup`/atomic `claim` reuse the original invocation, while a changed machine/kind/input returns `invocationConflict`. Claim commits dispatch consumption before returning the one-use permission. The optional `onClaim` callback transfers lifecycle ownership immediately after a durable claim, before dispatch or reconciliation can suspend. A crash after claim but before send is reconciled by ID, never by another POST. An unanswered POST is followed by GET; definitive `unknownOperation` is honest and conclusive.

The exchange ledger times both Fetch and bounded body collection independently of transport cancellation. Operation responses use the shared 256 KiB aggregate cap. The runner budgets the actual slash-unescaped terminal metadata/result and worst-case payload during kind registration, so maximum slash-heavy results and base64 output fit as well as ordinary text. Caller cancellation is typed requestCancelled and traced cancelled, distinct from deadline expiration. It does not use a task-group timeout that waits for a noncooperative losing child. Expiration resolves the caller, invokes abort and ignores late completions. Timed-out workers retain bounded capacity until they actually return; a poisoned adapter eventually refuses further work with `capacityExceeded`, rather than accumulating arbitrary stuck tasks. The transport owner must close/replace that broken adapter explicitly, not silently detour. `shutdown()` expires outstanding exchanges. Exchange admission and concurrent poll/consume/write refusals carry a nonempty diagnostic message and a `details.reason` (`exchangeLimit`, `concurrentPoll`, `concurrentConsume`, or `concurrentWrite`). Each local refusal emits a sanitized failure trace with `capacityExceeded` and no transport dispatch; a failed trace remains `traceUnavailable`. Trace failure is `traceUnavailable`, never silently unobserved dispatch. Exchange completion is recorded only after decoding and semantic reply validation; malformed replies record failure on the same request row. Decode and operation-silence deadlines are checked on the client's local clock as well.

Normal request bounds are 5 seconds and poll bounds 25 seconds. A caller duration can be shorter and returns `callerDeadline` with operation ID and pending knowledge, persists stop intent and attempts stop without continuing normal renewal. `reconcile` repeats stop for abandoned records and polls other records. The record becomes unknown only after a full operation lease without a complete valid answer, or immediately on a definite unknown-operation response. Description or a neighboring operation cannot refresh another operation's silence. Stop and abandoned-record reconciliation use the same full-silence accounting and remaining-lease request bound; definitive unknown-operation stop replies are persisted. A best-effort stop after loss does not erase unknown knowledge merely by returning a nonterminal snapshot. Restarted clients start a fresh full silence lease, preserve invocation/cursors/pending input/terminal evidence, and never resend starts. The persisted remaining caller duration is conservatively re-anchored locally; a real owner coordinator must stop dead scripts and persist elapsed owner budget independently across downtime.

Retained output and pending input use the advertised output/input channel window budgets, independently of start inputBytes or per-response pollBytes. A reader reserves bounded capacity before dispatch and suspends when its retained output budget is full; taking output can proceed while that poll waits. Poll commits payload, cursor and terminal snapshot atomically before a later poll acknowledges the cursor. Input is persisted before dispatch and repeats at identical offset/payload; partial writes retain the original pending payload until fully accepted. The client takes each input/output channel exclusion before awaited cursor reads, captures dispatch state and the persisted evidence generation before each request, atomically applies unknown-operation answers only against that unchanged generation, clears superseded unknown on conclusive fresh evidence, and ignores older running snapshots after terminal evidence. It serializes each input/output channel and validates operation ID, payload unit/length, bounded result and immutable verdict. `takeOutput` transfers the retained bounded chunks to the caller; consumption/replay of arbitrary caller side effects is not an exactly-once guarantee. Only one coordinator may own a channel; concurrent independent coordinators require a durable ownership fence in the store.

The real store must implement atomic unique owner claims with immutable input identity/digest, durable consumed dispatch intent, transaction rollback, persisted evidence generations advanced with every successful snapshot/input receipt, operation receipts/stop intent/caller budget, committed payload-and-offset updates, persisted identical pending inputs and accepted offsets, and explicit retention/capacity. MemoryOperationStore is bounded test-only persistence, not the production server database. The real server must keep secret inputs encrypted/transient rather than placing raw start input in diagnostics, authorize group-filtered access, reserve per-script/machine capacity, persist presence/reasons and sanitized traces with seven-day retention/incident pins, and recover owners at startup. Existing v1 tables remain untouched in this slice.

`OperationClientTestSupport.verifyOperationStoreContract` is an importable test-support helper for owner uniqueness/conflict, output payload/cursor, pending input offset/payload/EOF and accepted offset, and rollback of every payload/cursor field. It rejects stores that drop payloads or damage them on rollback; concrete future stores must run it plus their own crash/restart tests.

`OperationStore.transaction` accepts an escaping Sendable update for concrete asynchronous transactional stores. `reconcile(id, holdMs:)` can hold normal state polls, while preserving stop-only reconciliation for abandoned records. A nonzero hold does not drain output or relax deadlines.

`reconcileAbandoned` requires durable stop intent and keeps that idempotent stop deliverable after the local full-silence verdict became unknown. It does not resend a start, reset the caller budget or erase unknown without fresh conclusive evidence. `acknowledgeLeave` sends the explicit `leaveAck=true` describe request; only the runner's settled `leaving` reply confirms success. A regular description is not a departure acknowledgement.

A definitive unknown-operation response after the runner has expired its receipt cannot overwrite a persisted terminal verdict. Startup drain/ack may stop asking about that receipt while retaining the known execution outcome.

## Filesystem helpers

Internal `awaitResult(id)` polls using the advertised hold bound, retries transport/request-deadline failures within the existing operation lease/caller budget, acknowledges terminal evidence and returns only a completed JSON result. Failed verdicts throw their typed operation error; stopped verdicts throw operationEnded with the actual stop reason. It does not drain output; channel-bearing callers must consume their streams first.

Internal typed `stat`, `list`, `writeFile`, `mkdir`, `remove` and `move` helpers take machine, paths, stable OperationOwner, an optional timeout (the caller's deadline) and an optional `StartRequest.Caller`. Their admission follows generic start: describe must already establish presence. `vfs(machine:op:owner:timeout:caller:)` is the MachineContract compatibility adapter for server/CLI seams; it obtains the initial description when none is cached and returns VFSResult.error only for filesystem/input/size outcomes. Configuration, unavailable-machine, protocol, cancellation and deadline failures remain thrown OperationErrors, never a v1 fallback. Tokens from stat/read/write interoperate. Read uses read.v1 output with offset/length validation and the v1 8 MiB per-call bound (larger image attachments use the existing ranged reader). List streams metadata then sorts within an 8 MiB encoded-record budget. Both consume bounded output incrementally and acknowledge final offsets and terminal receipts. A caller that exceeds materialization bounds stops the operation rather than returning a truncated success.

Write sends length plus SHA-256 in start and streams only 64 KiB input chunks. Retried input exchanges use the persisted identical pending chunk/offset/EOF, honor partial acceptance and backpressure, and never resend start. An owner key with different bytes is invocationConflict even when the path and length match. Convenience calls persist stop intent if interrupted before terminal evidence. As with generic takeOutput, already-consumed output is not a replayable result cache for a second independent caller using the same owner.

Only `vfs` is the public filesystem compatibility entry point; the typed implementation helpers and result waiter are internal. Source lookup failure markers preserve v1 notFound for stat/remove/move sources (including ENOTDIR and EACCES), without relabeling mutation permission failures as missing entries.

The notFound compatibility category requires an explicit failed-lookup marker, never ENOENT alone: missing destination parents for write/move remain io. Read/list first establish metadata existence; missing/inaccessible metadata lookups are notFound, while failed data/directory opens after a successful lookup remain io.

`vfs` and `search` take an optional `caller: StartRequest.Caller` (session, title, group) and put it on every start they make, for the machine's audit; it is display-only, not part of the invocation identity (`canonicalData`), and nil sends no caller.

Start refuses unknownKind locally only when the stored description neither lists the kind nor names it in `availability`; missing filesystem kinds retain unknownKind and the kind name with an explicit `agent too old, upgrade` message before any start dispatch. A gated or known-but-unlinked kind is sent so the machine, which owns the gate, answers kindUnavailable or permissionDenied.

When a listed kind's input schema is closed (`additionalProperties: false`), start also refuses any top-level input field the schema does not declare: kindUnavailable with `reason:agentTooOld`, `started:false`, `inputs` (the sorted unadvertised fields) and an `agent too old, upgrade` message, before claiming or dispatching. An open or absent schema is not checked. An older agent therefore never receives a field it would reject as invalidInput or silently drop.

## Normal machine tool adapters

`search(machine:query:caller:)` maps normal find/grep requests onto record channels, preserving SearchResult shapes and bounded pages. Opaque cursors bind machine identity and query; paging follows traversal order, not sorted order. Concurrent edits may skip/repeat entries. Invalid or foreign cursors return invalidArgument. Optional matchLimit/resumeEntries/resumeLine kind inputs provide completed page results with nextEntry/nextLine, while unpaged entry-limit operations keep their stopped verdict.

Normal search requires the advertised find/grep input schema to include matchLimit, resumeEntries and resumeLine, even on the first page. An older descriptor (including dev119) or missing search kind throws kindUnavailable with `reason:agentTooOld`, `started:false` and an explicit `agent too old, upgrade` message before claiming or dispatching a start. There is no v1 fallback or unpaged substitution. Current descriptors retain paged behavior.
