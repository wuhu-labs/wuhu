# WorkerOwner

The ABI-1 owner bridge implements `WorkerOwnerClient` remotely and exports the parent's execution, tool, script and runtime facets. The worker owns no database handle. Session records, hydration, executors, transcripts, prompt homes, credentials/bindings, metrics, compact claims and spawn orders/results have explicit snapshots here; store rows do not acquire `Codable`. Existing semantic wire values such as transcript items, model routes and usage retain their established encodings. Transcript snapshots additionally preserve registered and handler subscription sets, which the persisted transcript encoding intentionally excludes.

`RemoteExecutionOwner` is admitted through a negotiated `WorkerClient`. Its synchronous `tracesAttempts` setting comes from the incarnation bootstrap. `ParentExecutionEndpoint` owns persistence, prompt/model/credential reads, signing callbacks, metrics and attempt trace sinks. Domain store/session/inference faults retain typed classifications; unknown implementation failures have static diagnostics. Model route establishment and spawn remain parent effects. `ParentSpawnEndpoint` calls the existing parent creation path with the original session/tool-call identity, preserving its durable replay receipt, placement and partial-creation result.

`SessionExecutionEndpoint` dispatches registry verbs to the worker's `SessionExecutionClient`; `RemoteSessionExecution` supplies the parent-facing adapter. It does not own or start a process. Local actor retirement remains a typed retryable outcome. Shutdown/discard are best-effort no-throw lifecycle operations; a process-owning supervisor must enforce its own bounded teardown.

Without negotiated continuity, `OwnerByteEndpoint` wraps domain operation replies in a typed owner envelope. Small requests fit the independently bounded stream metadata and download their snapshot result directly. Larger requests upload JSON bytes, then download a result correlated by call ID and operation; upload acknowledgement follows complete consumption and the parent effect. Results do not compete with control frames or inherit their 1 MiB ceiling. At most 256 uploaded results await consumption per endpoint; duplicate IDs, mismatched operations and unknown results are rejected. Results and open trace sinks are scoped to one worker incarnation, never adopted by another. A result is removed before its download is sent; transport failure does not replay effects.

Compact requests cross as an opaque parent-issued handle plus an explicit transcript snapshot, never as a command row or store token. Handles are bound to the session and the current parent claim. Unknown, foreign and consumed handles are rejected as invalid messages. Completion resolves the parent claim and validates command row, token and generation inside the same database transaction as append/compaction; replacement or generation change throws `StaleCompactClaim`, with no downstream write. A claimed append must contain items. Successful completion consumes the handle. Repeated claims of the same request reuse its handle; a new claim replaces the old session handle. Outstanding claims are bounded at 4096.

`ExecutionWorkerBootstrap` carries only two private socket paths, an incarnation token, attempt-tracing/telemetry flags, machine-facet availability and optional dedicated image-lease presence. When present, the worker validates inherited FD 3 and enables close-on-exec while keeping it open for its whole lifetime; stdin remains bootstrap-only and stderr remains discarded. It contains neither a database path nor store configuration. Both peers require ABI-1 session, inference, spawn, registry, tools, scripts, runtime and handler capabilities independently of their release strings. The bootstrap belongs on the child input pipe, not argv or an inherited environment.

Attempt trace bytes are appended to parent-owned sinks with backpressure; closing a trace releases its parent sink. At most 1024 trace sinks are open per incarnation. No-throw trace/metric publications await an uncancelled publication task so cancelled inference can still publish its terminal accounting; a failed publication logs a static diagnostic and never falls back to a worker-local store.

`ExecutionWorkerActivity` is the ABI-1 `worker.activity` snapshot for session/pass admission and release. The parent binds it to the connection incarnation and tracks overlapping pass tokens, so an old pass release cannot clear its replacement pass. Activity admission is acknowledged only after the parent-owned session lease is durable; negotiated continuity retains that acknowledgement under the original pass-admission receipt.

The optional `owner.route-transitions.v1` capability is advertised independently of the ABI-1 baseline. Route-failure updates and non-nil compaction/handoff transitions require it before any request or upload is sent; an older peer receives no partial effect and the caller gets typed `missingCapability`. Transition-free requests remain compatible. Route-failure updates retain the expected epoch and typed failure episode. Compaction and portable-handoff requests carry an explicit route-transition snapshot, including its full transient-aware transcript snapshot, and commit through the parent atomic store operation. Route/generation/transcript conflicts and recognized credential-refresh, authentication and service-refusal types retain their semantic error classifications. Worker compaction uses the same placement preparation as local execution.

The optional `owner.run-state.v1` capability carries `session.mark-compacting`, which tells the parent a forced compaction began or ended so the sessions row's `run_state` reads `inference` during it. Run state is advisory: a worker attached to a parent without the capability skips the call, so it never fails a session.


## Tools, scripts and runtime effects

The full bridge implements every `ToolOwnerClient` and `ScriptOwnerClient` method through the parent, including guarded filesystem/table mutations, image capabilities, session control/creation, messages/requests/reports, module snapshots, observations/timers and identity-signed fetch. Principal, module, filesystem, rows, machine and exec values use explicit snapshots; store rows do not become wire formats. Typed tool/store/control/channel/machine/capability/handler errors retain their semantic codes and masking information. Unknown failures use static diagnostics. The remote implementation runs the same reusable script-owner contract as the in-process implementation.

Legacy query/watch, identity response bodies and machine frames are pull-driven NDJSON record streams. A record is bounded at 64 MiB; truncation and malformed records fail rather than becoming successful EOF. Those record producers follow consumer demand, with no unbounded pump queue; negotiated query/watch continuity uses the bounded logical-reader contract below. Identity requests upload their body to the parent; signing and protected-value registration stay parent-owned. At most 256 script streams and 256 identity replies are live per incarnation, including bodies already handed to a download; EOF/cancellation releases their reservations. The normal machine adapter preserves frame boundaries and parent-owned exec claim/replay/mint/status/kill behavior, with at most 1024 live connections. Finished/cancelled streams and worker loss release their incarnation resources.

Effect requests have UUID cancellation identities. `OwnerOperations` records cancellation even before registration (bounded at 4096 tombstones), cancels registered tasks and joins them at shutdown. Legacy byte replies are consumed once; an uncertain transport result never causes replay. Cancellation uses the independent control client even while awaiting response headers. `WorkerHandlerEndpoint` applies the same cancellation contract to QuickJS handlers; `RemoteHandlerExecution` implements `HandlerExecutionClient`; legacy calls are not retried, while negotiated retained calls resume only the same journal receipt. Handler invocation/result snapshots retain rows, state, fire time and wakes, and `ScriptError` retains masked script diagnostics.

Normal machine file/search/exec RPC uses the session-scoped parent helper. The parent selects v1 or v2 by persisted registration, preserving ownership, credentials and typed tool errors with no v1 fallback for v2. The removed script-only machineV2 API has no separate worker bridge or operation-handle authority.

`WorkerRuntimeOwner` supplies parent-owned attempt publication, canonical quota usage, cache-warming decisions/schedules and lost-script recovery. Attempt start/delta/terminal records are explicitly encoded, validated for session/order and awaited for backpressure; child loss terminates outstanding attempts in the parent broker. Worker usage is a decision mirror synchronized before inference/catalog reads, not a new authority; publication failures fail the synchronization boundary rather than silently reverting to local state. Script lifecycle registration is acknowledged before execution, including detached scripts without machine execs. Normal completion removes registration. Child loss reports each registered script once and releases its processes, without replaying effects; handler callers receive failure instead of fabricated wakes/state.

Parent park-reminder scheduling crosses the runtime owner seam as `runtime.schedule-reminder`, carrying the session and optional due date (nil cancels). `RemoteExecutionOwner.scheduleReminder` requires negotiated `owner.reminders.v1` before sending an effect; older ABI-1 parents fail explicitly rather than silently retaining a worker-local timer. `WorkerRuntimeOwner.scheduleReminder` supplies the parent scheduler and defaults to an explicit unavailable error when omitted.

`SessionExecutionEndpoint` accepts an optional awaited pre-shutdown-reply callback. It runs after execution shutdown and before the parent receives the shutdown acknowledgement, so bounded diagnostic relay cleanup completes while the owner endpoint is still alive. It never changes the semantic execution shutdown result.

## Cooperative assignment handoff

The additive `execution.handoff.v1` capability gates `execution.yield-assignment`, cross-worker `runtime.stop-script` and direct `execution.stop-script` control before dispatch. Older ABI-1 workers remain compatible for ordinary registry work and explicitly refuse handoff. A yielded assignment acknowledges only after the concrete worker execution registry releases the session at a durable boundary. `WorkerRuntimeOwner` script-started/ended callbacks register script ownership independently of actor placement; script stop returns the same tool payload as local stop. Direct worker script control targets local `Scripts` and never recursively relays to the parent.

## Owner-call and stream continuity

With `owner.continuity.v1`, every semantic `OwnerRPC` call uploads an explicit receipt-bearing admission and downloads its retained `WorkerReply`. The endpoint starts one cancellation-shielded task for an exact call/payload/receipt; duplicates join it, including after a lost request acknowledgement or result body. Transport request cancellation only stops that response waiter. Explicit `owner.cancel` cancels the admitted operation, and endpoint shutdown joins all tasks. Acknowledgement occurs after semantic decoding; `owner.ack` releases the reply and advances a contiguous consumed sequence plus a bounded out-of-order set, so a delayed original upload cannot readmit an acknowledged effect. Operation failures are retained too. Legacy adapters keep their consumed-once behavior.

One endpoint retains at most 1024 effects across at most 16 receipt clients, with a 1024-sequence per-client window, 128 MiB aggregate payload/reply budget and 64 MiB individual payload/reply ceiling. Capacity refuses admission explicitly; an oversized completed reply becomes a retained capacity error, never permission to run its effect again. `owner.receipts` exposes operation, logical ID, receipt and terminal state without private payloads. Only `unavailable` transport failures cause rehello/resumption; a changed journal refuses with `unknownOutcome` and leaves pending metadata for reconciliation.

Handler calls use the parent subscription attempt UUID as their logical ID. Returned state/wakes remain in the worker receipt journal until the parent has committed or discarded that attempt and calls the idempotent `ScriptHandlerResult.acknowledge()`. The execution directory pins the original generation through acknowledgement, not merely through JavaScript return. This changes no handler state/wake transaction: the parent still owns its attempt/incarnation guard and durable commit.

Negotiated query/watch opens retain logical readers independently of a socket. Each `script.stream-next` is a retained call, so a lost pull reply is redelivered without advancing twice; query observations keep the existing latest-snapshot policy, while watch eagerly retains up to 256 ordered events and explicitly fails with `capacityExceeded` on overflow. Stream inventory exposes logical ID, kind, last pulled marker/revision; explicit cancellation removes the reader. Legacy peers keep their NDJSON stream path. Identity and machine streams retain their existing lifecycle contracts; this does not grant retransmission/adoption of machine starts.

`execution.inventory` exposes concrete assignment/pass/effect/archive/yield identities, script/session ownership, inference attempt UUIDs and outstanding owner-call metadata. It is a reconciliation snapshot, not a replay instruction or an atomic parent-exec barrier. No database, token or private effect payload appears in it.

Owner transport recovery waits 100 ms before the first retry and doubles to a 5-second cap. Consecutive failed effect requests retain this backoff even when each hello succeeds; failed hellos also increase the delay. Each retry logs its delay. Only unavailability is retried, and the original journal identity/receipt remains mandatory.


## Controlled-checkpoint prerequisites

The optional `owner.reader-suspension.v1` capability advertises recognition of an explicit, nonterminal, no-value reader-suspension record. A replacement coordinator may suspend only capable peers. A remote logical reader consumes this record and retries the read; cancellation, malformed records and ordinary reader errors still terminate it. The capability does not advertise a parent adoption or replacement entry point.

Receipt-journal checkpoints are internal, bounded handoff values. Admission closes before draining admitted effects; idle reader pulls must be suspended separately. A final checkpoint requires every admitted call to be terminal and seals further acknowledgements until rollback or restoration, preventing acknowledgements accepted after the snapshot from disappearing at replacement. The restored journal retains its identity, exact replies and consumed/out-of-order acknowledgement fences and starts with new-effect admission closed. Checkpoints must travel on an owner-private handoff channel: replies can contain credentials, so these values are not ordinary filesystem or database persistence records.

Logical-reader checkpoints retain definitions, ACKed query markers and watch cursors, plus any pulled-but-unacknowledged record identity. `OwnerByteEndpoint`'s acknowledgement callback must be connected to `ParentExecutionEndpoint.acknowledge` when composing the parent bridge. Source reopening is lazy, after restored retained replies have been acknowledged. Watch cursors preserve acknowledged event markers within the boundary revision because multiple events share a revision and live versus journal order can differ; replay suppresses only those events, not the entire boundary revision. Query reopening suppresses an unchanged initial snapshot. An overflowed watch remains explicitly failed across suspension/restoration, never silently reset. Legacy streams, streams still opening and oversized checkpoints refuse preparation rather than being silently dropped. These prerequisites do not implement worker discovery, crash reconciliation, listener inheritance or parent exec.

An `OwnerByteEndpoint` may receive shared `WorkerCredentials` when constructing its HTTP endpoint. The reverse-direction `WorkerClient` must use the same credential actor when composition enables authenticated credential rotation; the string-token overload retains fixed-credential composition. This facility alone neither advertises rotation nor persists tokens or adopts executions.

## Script ownership teardown

`WorkerRuntimeOwner.scriptStarted` must finish before acknowledging a child script/handler start; failure refuses launch. Normal exit calls `scriptEnded`. Parent runtime teardown calls `scriptLost` and then `scriptEnded` for each remaining script, so a parent that committed a loss notice can release durable ownership as well as its in-memory script directory.

## Transactional parent endpoint handoff

`ParentExecutionHandoff` binds a parent execution endpoint and byte transport as one ownership unit. `prepare()` freezes the complete handler lifecycle, including hello negotiation and credential staging/confirmation, as well as control, upload, download and acknowledgement admission, refuses unfinished non-reader effects (including shielded effects whose transport waiter has gone away), suspends retained observe/watch readers, drains their admitted pulls, and seals the receipt journal before checking resource transferability. The combined in-memory snapshot retains the original journal identity, exact terminal replies, consumed frontiers, out-of-order acknowledgement fences, reader cursors and staged values correlated to retained pull receipts. Receipt and reader snapshots share a 128 MiB encoded budget; malformed correlations refuse preparation/restoration. Snapshots redact description and reflection and have no public serialization or persistence surface.

Preparation refuses legacy/unretained byte replies and script streams, opening streams, machine frame connections, identity request/response resources, open attempt traces, compact claim handles, active runtime scripts/attempts and outstanding cancellation fences rather than dropping their state. It does not cancel effects to make them transferable. A failed or cancelled preparation resumes the original readers, journal and endpoint admission. Concurrent preparation/transfer/resume requests are refused; a successfully prepared endpoint stays paused until an explicit `resume()` or transfer.

`transfer(to:runtime:spawn:control:)` validates and restores receipts and logical readers against replacement parent services without admitting new work. A failed restore leaves the original paused and resumable. Successful transfer retires the original transport and services before returning a paused replacement, and the original can never resume or transfer again. The replacement resumes its readers before reopening journal and transport admission. A worker negotiating the replacement sees the same journal identity, so retained replies recover without replaying effects and consumed receipt fences remain effective. Endpoint creation is refused unless the coordinator is active; prepared and retired coordinators cannot mint new handlers. Existing handlers remain fenced while prepared and forever after retirement, including when their credentials actor is shared with the replacement. Callers must explicitly resume the replacement before obtaining and binding its handler; this API does not move a listening socket or a process.

This is a controlled in-memory endpoint handoff foundation, not worker adoption, parent exec, arbitrary-crash recovery, a disk checkpoint or a placement-default change. The opt-in process connection now binds this coordinator and exposes it only to internal lifecycle callers; no production path invokes prepare, resume or transfer. The bound control callback handles only `worker.ready`, `worker.activity` and `telemetry.spans`, inside the same tracked operation lifecycle; it cannot override owner effects or reader operations. Replacement services must explicitly rebind this callback, whose external state is not checkpointed. Parent-owned `worker.lease` streams are bounded at 256, release reservations on consumer cancellation, and finish on preparation or shutdown. Lease EOF prompts worker backoff/rehello rather than worker termination; leases carry no effect or cursor state and are freshly opened after resume.

`shutdown()` is terminal and no-throw even with active effects or concurrent preparation/transfer: it permanently closes transport admission, cancels and joins owned operations, and releases resources and journal tasks. An interrupted handoff cannot reopen the retired endpoint during rollback or return a resurrected replacement. External controller state and runtime resources remain outside this checkpoint; abrupt loss of a journal still requires explicit unknown-outcome reconciliation rather than resetting receipt identity.

## Exec-transfer checkpoint format

An internal `ParentExecCheckpoint` codec serializes only a successfully prepared parent endpoint snapshot. Version 1 binds the original receipt journal and logical readers to an expected space, generation, incarnation, positive process ID and process-birth identity. Import requires an exact match to the caller-supplied identity; it does not probe or authenticate a process. The caller must establish that identity separately on an owner-private handoff channel. Bootstrap credential objects, socket descriptors, listeners and external controller state are not included as checkpoint fields; opaque retained requests/replies can nevertheless contain credentials. There is no public byte export/import API or automatic production caller.

The complete JSON envelope is limited to 128 MiB, inclusive, on both export and import; import checks the raw byte length before decoding. Existing receipt, reader and correlation limits also apply. Only version 1 is accepted. A raw JSON key scan runs before Codable and rejects duplicate decoded keys in every object, including opaque application JSON; escaped aliases cannot bypass this check. The raw scan enforces a 512-level value-depth limit. Every structural field must survive decoding and re-encoding at the same position, recursively; unknown fields and optional fields explicitly encoded as null instead of omitted are rejected rather than silently discarded by Codable. Opaque operation payloads, reply values and reader markers remain application JSON, not checkpoint schema. Import errors contain only static diagnostics. The decoded checkpoint redacts description, debug description and reflection; its bytes may contain private owner replies and must never be logged or used as ordinary file/database persistence.

Export failure leaves the original prepared and resumable. Decoding validates data but does not install services, open admission, move a listener, execute the parent, discover/adopt a worker or recover from arbitrary crashes. Runtime placement defaults and existing in-memory transfer behavior are unchanged.

Reader definitions must have distinct journal/client/sequence receipts and a corresponding retained journal client. Each definition receipt must already be consumed or acknowledged, or identify an exact retained definition call whose successful owner-envelope reply returns that reader ID. A watch cursor marker must equal the last acknowledged event; an initial empty acknowledgement list requires a nil marker. Inconsistent definitions and incomplete watch markers refuse preparation/export/import instead of inventing readers or redelivering omitted acknowledged events.


## Serialized live-parent restoration

`restoreSerialized(identity:to:runtime:spawn:control:install:)` restores a prepared live parent through the complete version-1 encode, byte-buffer and strict decode path into fresh services. `ParentExecutionIdentity` is an opaque identity input, not a process authenticator or checkpoint export. The source remains sealed while the replacement journal and logical readers are reconstructed and resumed; restoring readers does not open their underlying sources. Retained replies must be acknowledged before a source reopens against the replacement services.

The asynchronous `install` callback receives an active staged coordinator and must atomically publish its endpoint or throw without publishing anything. Successful callback return is the commit point: no cancellation check or throwing validation follows publication. Success retires the original and returns the active replacement. Any pre-commit error, including encoding, decoding, reader rebinding, installation and task cancellation, shuts down the staged resources and resumes the original reader, journal and admission in an uncancelled rollback task. Unlike the existing in-memory `transfer`, failure does not leave the source paused. Explicit concurrent shutdown supersedes rollback and closes both source and staged coordinator rather than resurrecting either.

This path adds no exec trigger, listener inheritance, discovery, arbitrary-crash adoption, disk checkpoint or placement-default change. Checkpoint bytes remain internal and owner-private.

## Owner-private inherited descriptor carrier

An internal carrier exports a prepared checkpoint to an atomically close-on-exec, mode-0600 descriptor. Its random exclusive-create file is unlinked while still empty, before checkpoint bytes are written. A 16-byte magic/length frame bounds the strict version-1 JSON payload to 128 MiB inclusive. There is no pathname-based import, automatic exec trigger, listener transfer, crash recovery, worker discovery, or runtime-default change.

This carrier is stricter than the in-memory serialized codec: it refuses any retained data whose credential freedom has not been established. The current audited subset is empty reader inventories and successful `runtime.schedule-warming` receipts with an exact canonical request, UUID-form session ID, no trace context, and an exact boolean-true owner envelope. Credential operations, arbitrary request/reply JSON, errors, owner faults and reader values fail with `unprovenCredentialFreedom` before encoding or descriptor creation. No receipt is removed or rewritten. Wider reply transfer is deliberately deferred; the existing serialized restoration path is unchanged.

Only an explicitly coordinated descriptor duplication may map this descriptor into one intended exec child or the same-PID replacement image; the source remains close-on-exec throughout. The recipient must immediately consume its inherited descriptor with `take`, which first enables close-on-exec, validates an unlinked regular-file frame and independently expected identity, and closes before returning the checkpoint. Short reads, over-limit declared lengths, trailing bytes, malformed identities and failed closes refuse import. The close result is the only closure evidence: the number may be reused by another thread at once, so it is never retried or probed afterwards; EINTR counts as closed. A close failure never returns a usable checkpoint.

A real-exec fixture maps only the intended child descriptor and proves retained effect replay does not occur, unrelated and subsequent exec descendants lack it, and malformed imports close before throwing. Fixtures prove closure and absence by the open file’s device and inode, never by descriptor number, because the fixture’s own later opens (NIO selectors, inherited parent descriptors) can reuse the number. The fixture uses the Bazel runner’s `TESTBRIDGE_TEST_ONLY` filter, not ignored CLI filtering arguments; a minimal environment, matched explicit argv marker, disabled parent suite in fixture children, maximum depth two, and an explicit child success exit code independently prevent recursive fan-out or silent zero-test proof. This is an internal transport primitive, not a production parent-exec controller or a public byte-export interface.


## Composed exec handoff

Internal `ParentExecSource` and `ParentExecSuccessor` compose the audited carrier with a pinned listener export; there is still no production restart trigger or credential-eligibility expansion. The coordinator serializes transitions. Source preparation freezes execution, pauses accepts, and exports both close-on-exec handles. Failed preparation resumes execution and acceptance. Exports own their source descriptors until released and lend them only to intended-child spawn file actions; neither source FD loses close-on-exec.

The successor consumes both inherited descriptors on success or failure, protects both from further exec before importing either, strictly imports and closes the carrier, restores active parent services, and adopts the listener with accepts initially disabled. A failed import, reply restore, adoption, readiness check or acceptance activation shuts down all staged resources without unlinking the source pathname. Before acceptance activation, queued connections remain in the kernel backlog, not in a failed successor. The coordinator waits for successor failure/closure before `rollback()` resumes the source's execution and listener. Credentials and services are supplied independently, never recovered from checkpoint bytes.

After readiness, the successor serves the restored WorkerEndpoint under the same journal identity. The source stays frozen and cannot compete for accepts. Only externally confirmed readiness authorizes `finish()`: it stops the source listener, retires source execution and returns the listener cleanup capability for trusted delivery to the successor. Until that capability is consumed by `commitHandoff`, the successor does not own pathname cleanup. The capability-in-transit and lost-capability semantics remain the listener contract, not an atomic distributed commit or arbitrary-crash recovery guarantee. Post-readiness transport failure is not automatically rolled back.

The bounded real-exec fixture maps the carrier and listener together into fixed distinct child descriptors under the existing exact-filter, argv/environment, depth, minimal-environment and explicit-exit guards. It proves a queued request reaches the adopted endpoint, an uploaded retained effect's reply is recovered and acknowledged without re-execution, acknowledged replay is fenced, and each of carrier import, listener adoption, reply restoration and readiness failure leaves queued and fresh requests for the resumed source. Both source handles and adopted/imported child descriptors are absent from unrelated or nested execs. Only the source coordinator, in-transit affine capability, or committed successor may own final pathname cleanup; every carrier/export descriptor has exactly one local close owner.

## Deployment exec facade

`ParentExecutionHandoff.exportExec(identity:)` exposes the existing strict carrier through an opaque `ParentExecTransfer`, only while the source is prepared. The facade owns its close-on-exec descriptor; callers borrow it while retaining the facade and duplicate only into the intended image. No serialized bytes, credentials or broader receipt subset become public. `ParentExecTransfer.take(_:expecting:owner:runtime:spawn:control:)` consumes/closes the inherited descriptor on success and refusal, checks independently supplied identity, and restores fresh active services. The caller must supply credentials separately and coordinate listener adoption, readiness and rollback; taking a carrier is not execution ownership proof, crash adoption or permission to replay effects. Source rollback uses the existing `resume()` operation after a failed export/replacement.
