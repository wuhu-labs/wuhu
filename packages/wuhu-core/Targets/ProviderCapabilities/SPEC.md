# ProviderCapabilities

`CapabilityClient.capability(kind)` probes only configuration for `image`, `transcription` or `web_search`. It uses the same provider, dialect, endpoint validity, default model and model-feature selection as execution, but never resolves credentials, sends HTTP, spends money, or reports account identity. It returns `{ kind, provider, dialect, model, authentication: "not_checked", features: { edit, formats, timestamps, diarize } }`; this is configuration discovery, not evidence of working authentication, entitlement or regional availability. Credential IDs, endpoint URLs and headers are never included. Unknown kinds are `invalid_argument`; malformed configuration, missing explicit variants, invalid endpoints and incompatible dialects are `provider_not_configured` without fallback. The script export is `wuhu:ai` `capability(kind)`, and `GET /v1/capabilities/:kind` serves the same result/error policy.

The internal `CapabilitiesDocument` decodes the shared `/capabilities.json`, independently of the inference model catalog; clients construct `CapabilityClient` only through its public `load` factory, not a document initializer. `CapabilityClient.load(read:credentials:)` reads it at call time (the injected reader returns nil only for an absent file); malformed/unreadable configuration fails `provider_not_configured`. `CapabilityClient` owns all search, image and transcription resolution, including the existing image tool and dictation/CLI route. The old `ProviderCatalog.resolveTranscriber` ChatGPT-first picker is removed; its public low-level Codex/OpenAI transcribers remain for direct consumers, not provider selection.

Each of `web_search`, `image`, `transcription` is an optional `{ active?, providers: { id: { dialect, credential?, baseURL?, model?, models? } } }`. Persistence retains all variants and their settings together; changing active selects one at call time without replacing or deleting inactive variants. No file or no capability entry synthesizes `{ dialect: "codex" }` and resolves the configured ChatGPT credential. An empty providers map with no active also synthesizes Codex. A configured active or call override missing its variant/credential, or with a wrong/unknown dialect, returns a typed error without trying another provider. An override selects only a variant, never arbitrary credentials or an endpoint. Explicit Codex variants may omit everything except dialect. Native provider credentials are resolved per call; environment precedence/rotation remain CredentialResolver's existing contract. The config-writability trust boundary matches models.json and is deliberately not hardened here.

Dialects: `web_search` = `brave`, `exa`, `codex`; `image` = `openai-images`, `dashscope`, `codex`; `transcription` = `openai-audio`, `dashscope`, `codex`. Defaults: Brave `https://api.search.brave.com/res/v1`, Exa `https://api.exa.ai`, OpenAI `https://api.openai.com/v1`, DashScope Beijing legacy `https://dashscope.aliyuncs.com/api/v1`, Codex configured model-sheet URL/originator or `https://chatgpt.com/backend-api/codex`. API dialects default the credential ID to the variant ID. Codex uses its explicit credential ID, otherwise the existing model-sheet Codex provider or `codex`.

Model facts are `{ edit?: Bool, formats?: ["png", "gif"], timestamps?: ["words", "segments"], diarize?: Bool }`; absent fields use the adapter's known-model facts, otherwise unsupported by default. Configured facts can describe a new model without adding vendor knobs. Options are provider/model overrides plus capability-specific count, image quality/size and audio language/timestamps/diarize. Quality maps Qwen draft/standard/fine/ultra to the four exact shipped models; draft editing fails. Codex/OpenAI have no distinct neutral ultra tier in this v1 adapter and reject it. Model+quality overrides conflict on Qwen. Hard requested transcription features that the selected model lacks return `unsupported_feature` before upload; missing requested metadata in a successful response is `provider_unavailable`, not fabricated success.

`CapabilityError` is code/message/hint. Codes: provider_not_configured, provider_auth, provider_region, provider_entitlement, provider_rate_limited, unsupported_feature, invalid_argument, provider_unavailable. Neither transport errors nor upstream bodies/credentials/signed URLs enter errors or logs. Provider auth headers are sensitive. Storage downloads use fresh unauthenticated requests, never bearer/account auth. Configuration/credential failures never remove module/tool declarations or retry another provider.

Search returns `query`, `provider`, `sources[{ title, url, snippet?, published? }]`, optional `text`. Brave GET and Exa POST return explicit normalized sources. Publication metadata uses Brave's ISO `page_age` (not its relative human-readable `age`) and Exa's `publishedDate`. Codex uses a dedicated hosted-web-search Responses call, retains output_item.done items when response.completed omits output, and exports sources/cited text only after a completion event, rather than claiming hidden hosted source bodies are preserved. Count 1–20, default 8. No persistent result cache/corpus, index, or training/evaluation on Brave results.

`image(prompt, images:, format:, options:)` returns the bytes of a whole image of `format`, checked by `ImageInfo`; anything else is `provider_unavailable`. `ImageFormat(destination:)` names the format by extension: `.gif` → GIF, `.svg` → `unsupported_feature`, anything else PNG. Tools/CLI place it create-only. GIF needs a model whose `formats` fact lists it (known: OpenAI `gpt-image-2.6-*`; never DashScope) and no references, else `unsupported_feature` before any request; `frames` (2–16) and `frameMs` (20–2000) are GIF-only `invalid_argument`s otherwise. A GIF sends `output_format: "gif"` with `frame_count`/`frame_duration_ms` when given, and `size` only when the caller passed one. OpenAI generation is JSON and editing multipart; Codex generation/editing use JSON, with data-URL references on edits; Qwen uses the native synchronous multimodal endpoint for both and immediately downloads its result. At most five private PNG references (Qwen 3.0/dedicated editors: three, 10 MiB each; general per-reference bound 25 MiB). No masks/bboxes, regional flags, streaming or vendor-specific options. OpenAI default is gpt-image-1; Codex gpt-image-2; Qwen qwen-image-3.0. Explicit model overrides are authoritative.

`ImageInfo` reads a PNG, JPEG, GIF or WebP from its bytes alone, with no codec: MIME type, byte count, pixel size and, for a GIF, each frame's delay as a browser plays it (10 ms or less plays as 100 ms); a still image is one frame with no delays. `ImageInfo(_:)` is nil for what is not one of those images and throws `invalid_argument` for a GIF of more than 10000 frames, refused when the walk reaches frame 10001 so no frame list past the bound is ever built; `FrameSheet` shares the bound. `answer(path:)` is `generateImage`'s answer and `inspection` is `inspectImage`'s `{ mimeType, bytes, width, height, frames, durationMs, delaysMs }`.

`FrameSheet(gif:frames:)` composites a GIF's frames as a browser shows them (a transparent starting canvas, transparent indices, interlacing, frame rectangles clipped to the canvas, one wholly outside drawing and disposing nothing; disposal keep/background/previous; a truncated or corrupt LZW stream leaves the rest of that frame undrawn and play goes on) and tiles the chosen ones ⌈√k⌉ columns wide, left to right then down, as RGBA with its long edge at most 2000 px. Downscaling averages up to 4×4 samples a pixel, weighting colour by alpha. `FrameSelection` is `.indices` (1–100, in the order given) or `.count` (1–100): the frame on screen midway through each of that many equal stretches of the playing time, a frame landing twice shown once. Each shown frame reports its index and `atMs`, when it first appears. Not a GIF, a selection out of range, a canvas over 40M pixels, over 10000 frames, or over 400M frame pixels to decode through the last shown frame are `invalid_argument` before any decoding.

Transcription reads private uploaded bytes and returns one `Transcription`: required text/provider/model, optional language/durationSeconds/segments/words/confidence/usage. A span's text is required; start/end, speaker and confidence are optional. All times are seconds. Absent metadata is omitted, including a request's language hint when not returned by the provider. Speaker IDs are annotations without an accuracy guarantee. Audio is nonempty, at most 25 MiB and two hours; pure container timing parsing covers WAV, MP3, M4A/MP4 and WebM, rejecting unreadable timing rather than bypassing duration checks. MP4/M4A fragments use track timescales and tfdt decode times with trun sample durations or tfhd/trex defaults. Zero-duration movie headers never establish fragment duration; the bound conservatively covers decoded/presentation timeline ends and aggregate per-track sample duration. Missing/malformed fragment timing is invalid_argument before provider IO with a re-encode hint. WebM without Duration uses the final block time plus a conservative 120 ms Opus packet allowance. OpenAI plain transcription defaults to gpt-4o-mini-transcribe (including the direct OpenAITranscriber); explicit configured/call models remain authoritative. gpt-4o-transcribe-diarize supports timed segments and speaker labels, not words; its native diarized_json request omits timestamp_granularities and always sends chunking_strategy=auto even without requested speaker labels. Qwen defaults to qwen-audio-3.1-asr-flash-filetrans; qwen3-asr-flash-filetrans does not diarize. The managed `/files` upload → signed file URL → unsuffixed asynchronous `/services/audio/asr/transcription` → bounded task polling → unauthenticated result fetch → best-effort DELETE sequence is internal. Cleanup errors never hide the operation's result/failure; crashes/cancelled transports can leak staging files, without durable recovery machinery.

Brave/Qwen/Codex live acceptance occurs separately in a fresh test space. OpenAI/Exa adapters have deterministic synthetic offline request/response/error tests. Their October 5 live-check waiver was lifted on October 4 after fresh keys became available; all live provider checks remain the independent fresh-space acceptance phase, not evidence claimed by the implementation tests.

## Plan usage parsing

`PlanUsage` turns Codex response headers, the ChatGPT `wham/usage` read and the Codex socket `rate_limits` event into `UsageWindow`s named by their length (`five_hour`, `seven_day`, otherwise `<minutes>_minute`). A header family zero minutes long is absent, and a socket window without a positive length, a percentage in 0...100 or a reset time is dropped; a reset of 0 (the gateway's never-reported window) is no reset.
