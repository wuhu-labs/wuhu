# SpaceServer

`GET /v1/media?url=…` is the worker's single transcript-media read. It accepts `wuhu-blob:` hashes and `wuhu-space:` attachment references; hostless space paths use the session's group. Exec tokens are refused before resolving any media. Worker reads do not consult blob ownership or the session's current file-reader rules, so immutable history remains usable after access changes. Ordinary tool file reads retain their reader checks.


## In-process execution ownership

`SessionRuntime.assemble` composes one Hub actor (the session verbs main's API serves) and one `SessionExecution` wired by `KernelWorker`: session loops, provider sockets, tool execution, QuickJS scripts and handlers, all in the server process, reading and writing the session tables themselves. The tools reach main's API through `MainConnection`, in process, with the session's token; `SessionRuntime.run` starts the sessions once that API is bound. The routes call the execution's verbs directly and SQL observations reach owner cells directly from the space's `ObservationJob`. Session loops run each inference step as a wuwei job (`InferenceJob`, in `space.sqlite` on the shared backend), which owns the step's retries and attempt records. Ordinary restart reconstructs durable work, not live sockets or JavaScript heaps.

## Person–session DM refusal

`POST /v1/conversation/message` refuses opening or posting into a person–session DM, including a post by a person to an existing DM id. Person requests receive HTTP 403 with code `humanAgentDM`; session identities (including script HTTP requests) cannot post into any `.dmUser` conversation or pass `user`, including explicit JSON `null`, and receive the typed tool refusal through the session gate (HTTP 422, code `refused`). The message is exactly: "There is no DM between human and agent. To notify a human, post in your conversation box, optionally specifying the reply target's message ID: it notifies whoever wrote there last and anyone who wrote there in the past 24 hours." No post is rerouted to a box. Existing person–session DM history remains readable with the existing authorization; no migration or deletion occurs. People’s person–person DM posts, session–session DMs, box posts and their notifications, requests and reports are unchanged.

The HTTP/WebSocket projection of one Space over wuhu-serve. Machines use the v2 fetch tunnel and durable operations; exec callers retain the MachineContract/MachineChannel protocol and shared registry/admin routes.

## Machine registry (space sqlite, SpaceCore arm)

- `machines` — machine records (`mc_<8>`, owning machine account, optional
  name, created-at). Each machine is one `machine`-kind account
  (one-to-one, unique index), and its credentials are ordinary enrolled keys
  in `account_keys` with the `exec-machine` capability — minted through the
  space's unified enrollment (`join_tokens`), never a parallel credential
  store. Rotate and revoke reset the machine account's credentials (keys,
  read sessions, outstanding join tokens) and post `MachineCell.closeBoxes` mail inside the same key-changing transaction, poking after commit; delivery closes the owning worker's box sockets and tunnel even when another worker handles the route; rotate then mints a fresh one-time join token to re-enroll the box. A redial authenticates the current key. Every box attachment requires the exact public key captured by that authentication; `BoxLink` forwards it unchanged to `BoxSocket.Opening`. Before greeting or replacing a box, the cell atomically checks that the exact captured `account_keys` row still exists and belongs to the machine’s account, so revocation delivered before a queued attachment cannot leave a newly greeted stale tunnel. Expiry, capability and machine-membership checks remain in the upstream early authorization; the cell attachment check does not repeat them. Exec and file START share one effect-boundary authorization of the attachment's captured machine key; exec then resolves secrets and mints the exec credential. A purged key is a preparation failure and nothing is dispatched. Already-dispatched input and polls, stops and describes do not repeat this check. Caller acting-group authorization is checked upstream at admission only: it is not retained or chased after access loss while work is pending or running.
- `POST /v1/exec/:id/kill` accepts durable stop mail after its record lookup, including when another worker hosts the machine. `DELETE /v1/machine/:id` removes the machine and its credentials and posts `MachineCell.delete` mail in that same transaction, then pokes after commit. It returns success without waiting for the owning worker; mail delivery closes attachments and clears the cell's exec/file rows and buffers, including when another worker hosts the machine.
- `machine_presence` and `machine_operations` — rows owned by `MachineCell/<id>`, including script and tool identities. `machine_execs`, `script_execs`, `machine_v2_presence` and the encrypted exec-driver rows are dropped by migration 033 without in-flight migration. All file operations, including writes and copy, use the caller-owned cell socket below; migration 038 drops the remaining encrypted store without carrying in-flight rows.

## One listener, two planes

`serve` binds one TLS listener (`--port`, default 5530). The Host of each request picks the plane, compared lowercased and without one trailing dot, as is the `--origin` host:

- The bare host (the `--origin` host; without `--origin`, `localhost`) serves the API (`/v1/*`) and the web app. It serves no space content.
- `<group>.<host>`, exactly one label under it, serves that group's content: pages, files, `/_/session`, `/_/query`, `/_/observe`, `/_/space/*`, the shell and view providers. `shared.<host>` is `shared`. A content host answers no API route: `/v1/...` there is a content path.
- A name two or more labels under the host (`a.b.<host>`) is 421: the certificate may cover it, so a browser can reuse a connection for it, and 421 makes it retry on a fresh one to the right name.
- Every other name (an IP address, another LAN name a machine or CLI dials) reaches the API plane.

Without `--origin` the content host is `localhost`, so a browser on the serving machine reaches `<group>.localhost:<port>`; the self-signed certificate a fresh serve generates covers `*.localhost`. Serving group content to other devices needs `--origin`, which must name a host: an IP literal has no subdomains, so `serve` refuses one and points to an sslip.io name. `--web-port` and `--web-origin` still parse, for old launch configurations; each is ignored with one warning on stderr.

## The acting group

Every request on the API plane acts in one group. Hostless paths, `/v1/f/*`, tool calls and observe globs are that group's; `wuhu://<group>.localspace/<path>` names another group's, and a group the acting group does not read answers as a missing path. There is no fallback from a hostless path to another group. The space paths a conversation post attaches are hostless, read in the acting group, or `wuhu://<group>.localspace/<path>` in a group the acting group reads; an unread group is 404 `notFound`, any other form 400. A conversation's attachments live in its group and a member reads them from any group. Attachment paths supplied to a conversation post obey the same file readership as direct reads, including channel membership before group readability for hostless and qualified paths. An unreadable source returns `notFound` without posting or copying its bytes.

- A person (a verified assertion, or the ordinary dev account when no bearer is supplied) acts in the group the `wuhu-group` header names, else `shared`. The Host never names it. The group must exist and the person must read it by the one access rule (open membership, an account or acting-group entry, or space admin): a group that does not exist or was removed is 404 `unknownGroup`, one they may not read is 403 `groupForbidden`. Acting in a group takes reading it; writing in it takes its write role. The person speaks as the persona the identity routes give them: the one `?identity=` names, else the account's first. A persona of another account is 403 `identityNotYours`, a claim from a key that is not a device or seat key 403 `personaRequiresDevice`. That persona is the member for watermarks, DMs and notifications.
- An exec token acts in its session's group (see *The gate*).
- The API wall is the same on every server: a rejected bearer is refused, including on `--dev`; only a missing bearer may resolve to the live dev person. Public discovery and self-authenticating routes retain their own admission.
- On a non-dev content host, Authorization is ignored: content reads and writes retain their read-cookie/public-read admission. The read-session bootstrap endpoint alone accepts a bearer to mint its cookie; on a non-dev server it neither adopts a persona nor allocates an identity, and a viewer with no persona retains its account-id name.
- On `--dev`, content admission tries a supplied bearer, then a supplied read cookie, then the ordinary dev person when neither is supplied. A rejected credential never falls back to the dev person; an enrolled browser reads as its cookie's account.
- A content host serves the group its Host names: `<group>.<host>` is that group, `shared.<host>` is `shared`. A group that does not exist or was removed is 404 `unknownGroup` on every path. Pages, `/_/query` and `/_/observe` read that group with the cookie's viewer as the actor; the `wuhu-group` header is never read there, so a page cannot pivot into its viewer's other groups.
  - The one exception is a conversation's attachment folder:
    `/_/conversations/<id>/attachments/…` on any host is read in the group
    that homes conversation `<id>` when the host's group reads that group or
    the cookie's viewer is a member of the conversation (a cross-group DM),
    and is the host group's own path otherwise. The SPA opens an attachment on
    its own content origin at the hostless path, dropping the
    `wuhu://<group>.localspace` a reader outside the conversation's group is
    handed, so every member opens what was posted without a cookie for the
    conversation's group host.
  - `?download=1` on a file answers its raw bytes (no import map or shell
    injection) with `Content-Disposition: attachment; filename*=UTF-8''<name>`,
    the file name percent-encoded per RFC 8187: the SPA's file card links
    there, since a cross-origin `download` attribute is ignored.
  - Every file under `/_/conversations/<id>/attachments/`, whichever group homes it and whoever posted it, is message content. HTML, XHTML, SVG and XML attachments are downloads with `Content-Disposition: attachment; filename*=UTF-8''<name>`. Images other than SVG, audio, video and PDF remain inline. Attachment directories return 404 instead of resolving indexes or rendering listings. All attachment responses retain `Content-Security-Policy: sandbox allow-scripts` (an SVG's or XML's is `sandbox`; a group host appends `frame-ancestors`) and omit the import map and shell injection.
  - A read session is minted on one host with no `Domain`, binds that host's group (`read_sessions.grp`, NULL for `shared`), and admits on that host only. Every `wuhu_read` cookie sent is tried, so one a sibling host tosses at the parent domain cannot shadow the host's own. On a group host, minting and reading take a role in that group by the one access rule (403 `groupForbidden` otherwise, never a `shared` bypass); `--public-read` opens `shared.<host>` only.
  - Sibling group hosts are same-site, so `SameSite=Lax` still sends a host's cookie with its neighbour's subresource and script requests. A request is cross-origin when its `Sec-Fetch-Site` is present and neither `same-origin` nor `none`, its `Sec-Fetch-Mode` is not `navigate`, and its `Origin` is not one of the host's paired SPA origins. It gets 403 `crossOrigin` when a cookie admits it to `/_/query` or `/_/observe` on any host, or to anything a group host other than `shared.` serves; `DELETE /_/session` refuses it with or without a cookie. The pairing, and CORS, is exact: a content host pairs with the bare host, where the SPA runs for every group a person reads, as `--origin` spells it and as the bare host at the request's own scheme and port; without `--origin`, also as `127.0.0.1` and `[::1]` at that scheme and port, so the web app opened by loopback address frames and fetches its content. A sibling content host, `shared.` included, never pairs. Pairing grants no read: minting on a group host still needs membership.
  - Every group-host response carries `Content-Security-Policy: frame-ancestors 'self' <paired SPA origins>` (the origins CORS pairs), so a navigation the cookie serves cannot land in a sibling's frame. `shared.<host>` sends none.
  - Every `.svg` (`image/svg+xml`) and `.xml` (`application/xml`) file a group host serves, `shared.<host>` included, carries `Content-Security-Policy: sandbox` ahead of any `frame-ancestors`: opened directly it renders and runs no script; an SVG embedded as an image renders as before. Pages (`.html`, `.htm`, `.xhtml`, `.xht`) are not sandboxed.
  - HTML on a group host carries `<meta name="wuhu-group" content="<group>">`
    ahead of the shell script.
  - Share links. A place in a group is shared as the web app's own URL, `https://<host>/<path>?group=<group>`; `shared`'s has no `group`. A link written as `https://<group>.<host>/<path>` names the content. A top-level navigation there (`GET`, `Sec-Fetch-Dest: document`, `Sec-Fetch-Mode: navigate`) that the file wall refuses is 303 to `<bare origin>/<path>?<query>` with every `group` query item dropped and `group=<group>` appended; on `shared.` none is appended (`Cache-Control: no-store`), so an old link opens the document in the web app, which signs in. A frame, a fetch, a navigation a cookie admits, and `shared.` under `--public-read` get the content. The web app's shell carries a smart app banner whose `app-argument` folds `?group=<g>` into the host, `wuhu://<g>.<host>/<path>`.
  - TLS: `--group-certificate`/`--group-private-key` (a `*.<host>` leaf, needs `--origin` and `--cert`/`--key`, else `GroupTLSError.noOrigin` / `.noCertificate`: the generated certificate is pinned, so it serves every host; checked at boot, and a pair no handshake can use — a key off the named curves, e.g. EC with explicit curve parameters, or a key that isn't the leaf's — stops the start with `GroupTLSError.unusable`, naming the file and why) is served by SNI to names exactly one label under the host. Every other name, and a handshake without SNI, gets the `--cert` leaf.

## Page data: `/_/space/*`

A page imports `wuhu:space` for data or `wuhu:device` for device feedback; the import map every served HTML page carries points them at `/_/space.js` and `/_/device.js`. The device contract lives in `packages/wuhu-web/app/SPEC.md`. The data module is the browser transport over the shared core `packages/wuhu-web/app/app/lib/shell-sdk/space-core.js` (also served, no-cache, as `/_/space-core.js`). The core speaks these routes on the content origin; `run_script` embeds the same core over host calls. The legacy `/_/query` and `/_/observe` are unchanged.

- Reads pass the wall `/_/query` passes (a read session, `--dev` or `--public-read`, and the cross-origin refusal):
  - `GET /_/space/query?sql=&params=` answers a typed snapshot
    `{columns, rows}`: a cell is a JSON scalar, `{"blob": base64}` or
    `{"json": value}`; a BOOLEAN column is `true`/`false`, a JSON column is
    `{"json": …}` (a cell that does not parse stays `{"json": "<text>"}`).
    `params` is one JSON array of bound values (the same cell forms), else
    400. It revalidates like `/_/query`.
  - `GET /_/space/observe?sql=&params=[&throttleMs=]` is an SSE stream of
    those snapshots, the first the current result; a bad statement or `params`
    is refused before the stream opens, with the status `/_/space/query`
    gives it (below). The legacy `/_/observe` keeps its flat 422.
  - `GET /_/space/watch?glob=[&from=][&batch=1]` streams file events `{kind: write|delete|move, path, to?, rev, entry?}`. Replay is strictly after `from`. Without `from`, the stream opens with an `event: head` frame containing `{"rev": <head>}` for the watched group (which may differ from the acting group for a qualified glob), so a disconnect before the first mutation can resume from that baseline. The subscription starts before the head read, so queued mutations at or below that head are still delivered on the opening stream; the browser uses head only as a resume baseline before any delivered revision, never a delivery filter. A drop before any queued revision is delivered resumes from head as before. A completed queued revision replaces that baseline with its own revision, even when older than head, so a disconnect before the remaining queued commits replays them. The default keeps the existing individual `message` frames and bytes. Opting into `batch=1` uses the whole-revision `revision` frames of `/v1/observe`, with the same head and admission rules. The browser `wuhu:space` watch yields individual mutations from either frame kind and checkpoints a whole revision after delivering its array. A legacy per-event boundary R remains unproven: reconnect requests R−1 and suppresses previously delivered `(kind, path, to)` identities in R, retaining only that boundary revision's identities. This recovers siblings without repeating prior deliveries. The deprecated `/_/observe?glob=` route sends no head frame and is unchanged.
  - `GET /_/space/attributes?path=` runs `attributes.read`.
  - `GET /_/space/find?glob=[&path=][&matchLimit=][&hidden=][&noIgnore=][&step=]` and `GET /_/space/grep?pattern=[&path=][&matchLimit=][&hidden=][&noIgnore=][&step=]` run the `find` and `grep` tools as the page's group, answering their output: `{paths, cursor?, scanned, skipped}` and `{matches: [{path, line, text}], cursor?, scanned, skipped}`, `cursor` present exactly when more results remain. A missing glob or pattern, a limit that is not an integer, or a flag other than `true`/`false` is 400 `invalidArgument`; the tool's own refusals keep their codes (a bad regex or cursor 400, an unread group or missing path 404, a `machines://` path 503 `unavailable`, since a page has no machine seam). Other methods are 405.
- Writes are `POST /_/space/rows` `{path, ops, page}` → `{rev, ids}` and `POST /_/space/attributes` `{path, set?, remove?, ifMatch, page}` → `{token}`. `ops` are `{insert: {col: cell}}`, `{update: id, set: {col: cell}}` or `{delete: id}`, applied in one revision; `ids` are the inserted rows' ids in order. A call touching one row id twice is refused as `invalidArgument` (an update's untouched fields come from the row before the call, so two ops on one row cannot fold). The patch is `attributes.patch`'s. Admission, in order: a `Content-Type` other than `application/json` is 415; an `Origin` that is not this host's own content origin (the request's scheme and host), or a `Sec-Fetch-Site` other than `same-origin`, is 403 `crossOrigin`; no live read session for the host's group is 401 (`--public-read` admits no visitor to write; `--dev` admits its account as the viewer, a page like any other, attributed to its persona); a body past 4 MiB is 413, one that is not a JSON object 400; `page` must be the writing page's `location.pathname` — absolute and hostless, percent-decoded, a trailing slash dropped — else 400. `page` is the page's own claim; what keeps active message content from running as a page is the attachment download policy above, not `page`. Other methods on these routes are 405.
- `POST /_/space/session` (wuhu:session's createSession options plus `page`) → the `POST /v1/session` output, and `POST /_/space/message` (`{message, conversation | session, reply_target?, attachments?, page}`) → `{messageId, conversationId, n, delivered: []}`, take the write admission above and act as the viewer (including the dev person), through the hub's one create and post path. Bound: the viewer's authority intersected with the host's group, at every step. A page creates sessions only in that group, posts (its create's first message included) only into that group's conversations and boxes, and attaches only that group's files; anything else is 403 `outsidePageGroup`. A guest viewer, or one who does not write the group, is 403 `groupForbidden`; a task 403 `taskInput` (a person creates agents only); an incomplete create 422 `{code: incompleteSession, message, id}`; other refusals are 422 with their code, a server without sessions 404. `key` makes a create idempotent per viewer and group: a key never replays across groups. With `expectsReply` the create opens a request on the new agent whose `requester` is the viewer's persona: the request and the agent's reports post in the agent's box, and `request.key` is unique in the group as for a session's request.
- A page writes as `Actor.page` (SpaceCore): a non-admin agent of its host's group, through the same group write check as every other caller, recorded as the viewer. Its target is found with the viewer's reads: hostless is the host's group, `wuhu://<g>.localspace/<path>` group `g` when the viewer reads it, else 404 `notFound`. Writing there then takes a write role of the host's group in `g`, whatever role the viewer holds: a read grant is 403 `unauthorized`, and the settings group is never writable. It can write its own group's instruction layer, but no other group's. Every session home is refused with 403 `unauthorized` and message "page scripts can't write session homes; keep page data outside /_/sessions/".
- Failures carry the tool error payload (`code`, `message`, `hint?`,
  `token?`) with a status by code: `notFound` 404, `conflict` 409 (a stale
  `ifMatch`, carrying the current `token`), `invalidPath`/`invalidArgument`
  400, `unauthorized` 403, `unsupported` 422, `unavailable` 503, `internal`
  500.
- Attribution: a page write's revision records `actor`, the viewer's
  persona — the three-word id of the cookie's account, as the content
  origin's other reads name it (including the dev person) — and `via`, the page path the
  page reported in its body, in `revision_actors(grp, rev, actor, via)`, keyed by written group and revision; attributed page and handler writes add a row. `history` shows them as `by` and `via`.
  `via` is the page's own claim; only `actor` is authenticated.
- The read cookie authenticates `/_/space/*` on the content origin, never
  `/v1`.
- Every served HTML page gets
  `<script type="importmap">{"imports":{"wuhu:space":"/_/space.js","wuhu:device":"/_/device.js"}}</script>`
  at the start of `<head>` (after the `<head>` tag, else after the doctype,
  else first), since an import map must precede every module script; the
  shell script is still injected before the last `</body>`. The HTML `ETag`
  is `"<token>-shell-<12 hex>"`, the hex a digest of both injections, so a
  change to either revalidates every cached page.

## Sessions in groups

- A session lives in one group, fixed at creation. A child always takes its
  creator's group. Only a top-level agent takes `group` (`SessionCreateInput`,
  `create_session`, `createSession`, `wuhu session create --top-level
  --home-group`), defaulting to the creator's; a group the creator's group
  does not read is 403 `groupForbidden` (a tool refusal from a session).
  `group` without a top-level agent is refused. A template name resolves in
  the creator's group, or `wuhu://<group>.localspace/templates/<name>` in a
  readable one; `GET /v1/templates` lists the acting group's.
- Instructions, in prompt order: the system AGENTS.md and skills; the session's own group
  (`/AGENTS.md` and the skills under `/.agents/skills/`, hostless); the system SESSION.md; the home.
  The first is the request's system text; the group's part and the session's (SESSION.md with the
  home) are the generation's first two user-role messages, wrapped in `<group-instructions>` and
  `<session-instructions>`, so the system text is the same for every session of a kind on one binary
  (a nearer skill that hides a system skill's listing aside).
  No group's instructions reach another group's sessions. Each AGENTS.md renders as a Mustache
  template for the session; each space scope or partial is read at its group’s frozen entry in the prompt revision map, captured at first inference, and the
  rendered prompt is stored per generation, so an edit, a rename or a model switch reaches a live
  session only at its next compaction or Start over, never mid-generation. A machine's
  notes come from the machine's group, qualified when that is not the
  session's. Automatic machine/repository notices deduplicate exact file text across all paths and machines within one generation, replacing repeated AGENTS.md text or skill listings with a one-line reference to the first loaded path. Compaction and Start over reset this history; same-generation restart preserves it.
- Writing a group's `/AGENTS.md` or anything under `/.agents/skills/` takes a
  member of that group (a session of it, or a member person), else
  `forbiddenWrite`; every group, `shared` included, follows the same rule.
  Every file of the settings group takes a space admin (an `admin` of that
  group). The dev person follows the same account check.
- No dialing in. A post to a box needs the box's group readable; opening a
  DM to a session needs its group readable, and an existing DM needs that or
  the other side having posted in it; a mention or reply-target wakes a
  session only when its group is readable to the poster's, it owns the
  conversation, or it has posted there. A refusal reads as `unknownSession` /
  `unknownConversation`. A new DM is homed in the opener's group; a created
  conversation in the acting group.
- Each delivered message records the poster's group (the `message_groups`
  side table; a session's own group, else the acting group) and whether the
  poster is an admin of the recipient's group. The header renders
  `<sender-group>` only when the poster's group differs from the recipient's,
  and `<sender-admin>yes|no</sender-admin>` always. `senderGroup` is on every
  message a surface returns: `ConversationMessagePayload` (HTTP, `observe`,
  the CLI log), a script's `conversation()`, `message_senders` and the push
  relay's data.
- A person's post (`POST /v1/conversation/message`, and the opening message of `POST /v1/session/:id/restart`) may carry `viewing`: the space path of the doc or page open when it was sent, `/<path>` in the acting group or `wuhu://<group>.localspace/<path>`. It must be at most 1024 bytes, a valid space path without whitespace, control characters, quotes, `<`, `>` or `&`, and readable by the poster at send time (a missing and an unreadable path are refused alike); otherwise the post is refused `400 invalidArgument` with `reason: "viewing"` and an explaining message, before anything is stored. On a restart, `viewing` without a message is refused `400 invalidArgument` without that reason. It is stored group-qualified in the `message_viewing` side table, never checked again, and delivered to each recipient as its group names it: hostless in the recipient's own group, `wuhu://<group>.localspace/<path>` otherwise. The header renders it as `<viewing>…</viewing>` right after `<device>`; a message without it renders as before. Every value interpolated into a header tag (sender, handle, source, message and reply ids, device and its name, viewing, sender group) renders with `&`, `<` and `>` escaped as `&amp;`, `&lt;` and `&gt;`, so no value can close its tag and open another; a device name longer than 64 characters (grapheme clusters) or containing a control character, a line break, `<`, `>` or `&` is refused `400 invalidArgument` with the reason at `PUT /v1/device` and `PATCH /v1/device/:id`; names already stored are untouched. A session never sets it: the session gate refuses a post body naming `viewing` (even `null`) with `400 invalidArgument`.
- Reading a conversation (`GET /v1/conversation/:id/messages` and `observe`, `GET /v1/session/:id/conversation`, a script's `conversation()` and `dm()`): a box when the reader's group reads its group; a DM when the reader is in it or it is homed in the reader's group; a human-only channel (`kind: users`) when the person is a member, or the reader is a session whose group reads the channel's home group. A group read edge alone never admits a nonmember person. Public-read callers cannot read channels; the dev person reads channels only through ordinary membership. Anything else reads as an unknown conversation (404 `notFound`; `dm()` answers null). Channel attachment bytes, file tools and directory listings, including content-origin reads, enforce this same contract. An open conversation observation revalidates readership on membership/group changes and stops when access is revoked. `GET /v1/conversations` lists the person's memberships and readable channels, or a session's memberships and channels in readable groups, ordered most-recent-active first (last message position descending; channels with no messages last).
- `observe` is a socket on the conversation's cell: it sends the messages past `after`, then each message in the step that posts it. Readership is checked when it opens and again at each post: a reader who no longer reads the conversation is closed at the next post instead of being sent it, and nothing ends the stream between posts (a removed key still does, below).
- A session route (`/v1/session/:id/…`: `transcript`, `direct`, `context`,
  `home`, `log`, `entry/:ref`, `compact`, `restart`, `tags`, `title`,
  `interrupt`, `resume`, `archive`, `unarchive`) answers a session whose group
  the acting group does not read as an unknown session (404 `notFound`),
  before any effect.
- In SQL, `conversations` shows the acting group's non-channel conversations plus memberships and readable channels under the read contract above; `messages` and `conversation_members` follow it. `message_senders` (`n`, `sender_session_id`, `sender_grp`, `sender_title`) gives each visible message's poster group; `watermarks` shows only the reader's own rows (a session's id or a person's persona). `notifications` shows the acting group's plus the reader's own, but channel message notifications require channel readership regardless of recipient. Qualified group and wildcard views enforce the same channel gate; removing a member also hides historical notifications from queries and observations.


## Certificate pinning

What the server hands out for a client to enroll with — `EnrollMintOutput`, `ShareLoginOutput`, `MachineAddOutput` and `MachineRotateOutput` — carries a `fingerprint` only when `serve` runs the certificate it generated into `<folder>/tls`. With `--cert`/`--key`, self-signed or not, it is absent everywhere and clients check the certificate against their system trust store. `serve` records the certificate's fingerprint and which kind it is in the deployment record, so the offline `wuhu user invite` follows the same rule; a record written by a server from before the kind was recorded reads as unknown and yields no `fp` until the next boot rewrites it. Re-enrolling replaces a client's pin: a CLI `login` or `machine-v2 join` with an `fp` records it over the old one, and one without drops the host's pin once the server passes system trust, which is how a client pinned under the old rule moves to system trust. When system trust rejects the server, an existing pin carries the enrollment and stays.

## Bearer assertions

A person's request carries `Authorization: Bearer <assertion>`, a JWT the client signs with an enrolled key (encoding: SpaceContract's SPEC). Claims are `key`, `space`, `exp` and an optional `nbf`, in whole Unix seconds; other claims (an `iat`, say) are ignored, except `session`, which fails to parse. The gate checks the scheme and shape, the `space` claim, the key row, the signature, that the key is a person's, then the window. The window is the server's clock with no leeway: `exp` is exclusive, and `nbf`, when present, must not be later than now. Every refusal is 401 `unauthorized` with the message it always had; the error envelope (`ToolError`: `code`, `message`, optional `hint`, `token`, `reason`) tells the window apart only by `reason`:

- No `reason`: the credential is gone or never was — no live person key matches (revoked, expired, never enrolled, or a machine or space key, byte-identical so a response leaks neither existence nor capabilities; the person check precedes the window so a stale assertion cannot tell them apart either), a missing bearer where one is required, another scheme, a malformed assertion, another space's, a bad signature.
- `reason: "assertionExpired"` (past `exp`) or `"assertionNotYetValid"` (before `nbf`): a genuine signature by a live person key, refused only for its times, which the client chose by its own clock. The client re-signs with times corrected by `now` from `GET /v1/server` and retries; the key is fine.

Removing a key ends what it holds open. A streamed response (no `Content-Length`: SSE observe/watch, conversation and session streams) or a WebSocket that a person key opened through the production wall (a `.wmd` socket by the assertion in its `hello`) is held against that key until it ends. `DELETE /v1/key` (self or addressed) ends every one held by that key, and `DELETE /v1/accounts/:id` every one held by any key of the account, as soon as the row is gone: a response finishes cleanly with no in-band frame, a WebSocket closes. The client's reconnect then meets the revoked-key 401 above. A hold re-reads the key row after it registers, so a removal racing the open still ends it. Other keys keep theirs. Session exec-token requests, machine connections and content-origin read-cookie streams are never held, nor is anything under `--dev`, which has no wall. A hold is released when its stream ends, so the ledger is bounded by the streams open now.

## Endpoints

- In flat mode (`--content-host-pattern`, requiring `--origin` and exclusive with `--group-certificate`), the pattern starts with exactly one `{group}` and is a DNS authority; its port, if present, must match the origin. Group hosts substitute a valid `GroupID` prefix into the template, excluding ids with `--` at positions 3–4 (reserved for IDNA); hosts other than the origin host or a pattern match return 421 before either plane. `/v1/server` advertises `contentHost` instead of `contentBase`. Read/viewer cookies are `__Host-wuhu_read` / `__Host-wuhu_viewer`, retaining the legacy attributes, with no legacy-name admission or emission. The service worker reads the prefixed viewer name first, then the legacy name. Share links and the smart banner follow the template, not `<group>.<host>`: a content link is `https://` plus the template with `{group}` replaced (`https://<group>--<tenant host>/<path>`, `shared--…` for `shared`), and a refused top-level navigation there gets the same 303 to the web app; the banner's `app-argument` folds `?group=<g>` (other than `shared`) into `wuhu://<g>--<tenant host>/<path>`. The dotted `<group>.<host>` forms get 421. Without the flag, host routing, discovery and cookies are unchanged.

- `GET /v1/server` — discovery for API clients: `ServerInfo` with `origin` (`--origin`, absent without it) and `contentBase`, the `host[:port]` a client writes after `<group>.` for a group's content origin (`https://<group>.<contentBase>`): the `--origin` authority, else `localhost:<port>`. Public, outside the API wall. `features` lists `groups` (the server takes the `wuhu-group` header) , `observe-batch` (opt-in whole-revision filesystem observation) and `watch-batch` (whole-revision `/_/space/watch` responses), and `group` is the group the request names, unchecked: an exec token's session group, else the header, else `shared`. `now` is the server's clock when it answered, Unix epoch seconds with a fraction: a client that signs its own assertions learns its clock offset from it (see Bearer assertions); the answer carries `Cache-Control: no-store` and an HTTP-date `Date` of the same instant. It carries no list of groups; that is `GET /v1/groups`.
- `GET /v1/groups` — `[GroupSummary]`, every group not removed, with its `name` (what the apps call the project; absent for unsigned discovery) and where the caller stands: `member` (it writes there: a person's writable groups, a session's own group only), `readable` (a group the caller reads by the one access rule: an open group, a group listing its acting group or its account, the settings group; the caller acts in `shared` unless the credential is a session) and `admin` (its role there is `admin`). The settings group is not listed. The caller is the request's credential alone; for a person the group the request names by `wuhu-group` header changes nothing, and it need not be a member of it. A session's exec token naming a group other than its own is still 403 `groupMismatch` at the session gate, as on every route. A readable group the caller is not a member of is reached only through a member group's hostful paths (`wuhu://<g>.localspace/…`): naming it by `wuhu-group`, or minting `/_/session` on its content host, is 403 `groupForbidden`. Public discovery outside the API wall, like `/v1/server`: unsigned production discovery has every flag `false`; unsigned dev discovery uses the ordinary admin account, and a bearer that fails verification is 401. The flags are optional in the contract so a newer client reads an older server; a client treats a missing `admin` as not an admin.
- `GET /v1/f/<path>` · `PUT /v1/f/<path>` — the byte lane for space files,
  paired with the text-only JSON tools. `GET` answers the raw bytes with the
  content type derived from the path extension (`mimeType(for:)`, the same
  table the content origin uses — content type is never stored) and the
  version token as a quoted `ETag`; `path@rev` reads a historical view.
  `?group=<id>` names that group's file, as `wuhu://<id>.localspace/<path>`
  does for the tools (a group the acting group does not read is 404, a
  malformed id 400); the CLI's `cat` and `put` send a qualified path this way.
  `?machine=<id-or-name>` names a machine's file, as `machines://<id-or-name>/<path>`
  does for the tools; a machine file is read whole up to one wire frame
  (`VFSDefaults.maxReadBytes`), `415` past it, and a session reaches the
  machine as itself on both verbs. `PUT` writes the request body verbatim,
  honors `If-Match`, bounds the body at 64 MiB (`413` past it), and answers
  the `WriteOutput` shape (`{rev, token}`). Both live under `/v1` so the API wall gates them exactly
  like `POST /v1/tools/*`: `--public-read` opens the content origin, never
  this. Tool failures map onto HTTP status (`notFound` → 404, `conflict` →
  409, `unauthorized` → 403, `unsupported` → 415, `provider_auth` → 502,
  …) instead of the tools route's flat 422; 401 stays the credential's.
- `GET /v1/live/<path>` (and `/v1/wmd/<path>`, its name in clients built before `.canvas`, whose `error` frames say `notWmd` for `notLive` because those clients decode a closed code set) — the live channel of a `.wmd` or `.canvas` document, a WebSocket with no subprotocol (wire: SpaceContract's SPEC). Browsers put no `Authorization` on an upgrade, so the wall lets it through bare and nothing is read from its headers: the first frame, `hello`, carries the assertion and the group, and is checked as the same request with those headers would be. `?group=<id>` names another group's document as on `/v1/f`; a machine file (`?machine=`) or `path@rev` is no live document and answers `notFound`. Refusals are an `error` frame, then close: a missing or bad `hello` or assertion `unauthorized` (a missing assertion resolves to the ordinary dev person only on `--dev`), an unreadable group `forbidden`, a reserved path `forbidden`, a missing path `notFound` unless the hello sets `create: true` and the caller may write it (then it is created empty). A socket whose `hello` has not come within `liveHelloDeadline` (10 s on the injected clock) is closed. The caller writes where the file tools would let it write; where they refuse the write (another group's role, a foreign session home, a page on a home) it connects read-only. Its access is re-evaluated as groups and roles change, and a socket that loses write or read (its group goes private, its role is removed) is closed with `readOnly` or `forbidden`. A client outrunning its node (256 frames buffered either way) is closed; it reconnects and syncs anew. `welcome`'s `name` is a person's display name, else handle, else persona, and a session's title.
- `POST /v1/transcribe` · `GET /v1/transcribe` — private speech to text and availability probe, resolved through shared `/capabilities.json` rather than credential priority. POST retains raw audio Content-Type/body; the capability routes section below defines options, rich metadata, bounds and typed errors. Both sit under `/v1` and the API wall gates them.
- `POST /v1/machine-v2` registers a named machine and returns its id, one-time token, optional generated-certificate fingerprint and confirmed group. A public-key request enrolls directly and can link the person's device; a device link without a public key is refused. `POST /v1/machine-v2/enroll` consumes a machine-v2 token and enrolls the box's key.
- `GET /v1/machine-v2/challenge` mints a bounded, expiring one-shot challenge. `GET /v1/machine-v2/connect` requires `wuhu-fetch-tunnel.v1` and verifies the key-signed challenge plus addressed machine ids before upgrade. Missing, malformed or replayed handshakes are 401 `keyInvalid`; definitive authorization refusal is 401 `machineNotAuthorized`, while an authorization outage is retryable 503 `machineAuthUnavailable`. The handshake is the machine's credential, independent of the person API wall.
- WebSocket routes self-gate because upgrades bypass plain-handler middleware. The machine tunnel verifies its signed handshake; the exec caller endpoint verifies its principal, registry access and actor ownership before admission.
- Shared record/admin routes remain `GET /v1/machine` (list with attachment; each `MachineStatus` also names `device`, the device whose `machine_id` links it, and `lastSeen`, Unix seconds of its last presence evidence when not attached and once attached at all), `POST /v1/machine/:id/rotate` (kick and fresh v2 token), `POST /v1/machine/:id/revoke` (kick), `PUT /v1/machine/:id/name` (rename), `PUT /v1/machine/:id/group` (move), and `PUT /v1/machine/:id/scope`. Legacy machine registration, connect and challenge routes are removed.
- Every space has a hidden `settings` group holding `/models.json`, `/model-groups.json`, `/capabilities.json` and `/machine-v2-upgrade.json`; the server reads them from there and nowhere else, and migration 003 deleted `shared`'s copies. Every group reads it, and only a space admin writes any of its files or takes it as a session's home. It is never listed by `GET /v1/groups`.
- `group_roles` is the one access table: `(subject_kind, subject, grp, role)`, where `subject_kind` is `account` or `group`, `role` is `read`, `write` or `admin` (ordered), and an open group (`groups.visibility`) needs no row. A person's role in a group is the best of its account's row, its acting group's row, an open group's `write`, and space admin; a session's is its own group's `write` plus its group's row, with a live top-level agent `admin` of its own group. Space admin is `admin` in `group_roles` for the settings group and administers every group; an account's `admin` flag (`GET /v1/accounts`, `AccountPayload`) is that rule. Guests (`accounts.guest`) read only their account's rows and create no sessions. `GET /v1/group/:id` returns `{id, alias, open, secrets, entries}` to anyone who reads the group; `PUT /v1/group/:id` `{alias?, open?, secrets?}` and `PUT`/`DELETE /v1/group/:id/access` change visibility, the secrets switch and the list for a group admin only.
- A machine belongs to one group (`machines.grp`). Without a body `group`, a new machine joins the acting group; with one, that group. Either way the caller must administer it (`403 adminRequired`); no personal-group default. A body `group` must exist (`404 unknownGroup`). V2 registration follows this policy and echoes the actual group in `MachineAddOutput.group`; `wuhu machine-v2 add --name N --group G` and the global `wuhu --group G machine-v2 add --name N` send only the registration target in the body, not the acting-group header. The CLI checks the echo when an explicit target was requested; environment and folder group settings do not set a registration target. A route that names a
  machine or an exec, the listing and `POST /v1/exec` see only machines in a
  group the acting group reads, 404 otherwise. Using one takes its
  `machines.scope`: `owner` admits the machine's own group alone,
  `reachable` every group with write in that group (enrollment takes a body
  `scope`, default `owner`; machines from before the switch are
  `reachable`). The listing shows only the machines the caller can use. `PUT /v1/machine/:id/scope` `{scope}` switches it for an
  admin of the machine's group. A move needs an admin of the
  machine's group and of the target, a rename an admin of the machine's
  group (403 `adminRequired`: its name is every group's handle on it); rotate
  and revoke need a human admin of the machine's group. The machine's notes live in the tree of its current
  group, and a move carries them there in one transaction with one revision in each written group: `/_/machines` in
  a group's tree lists the machines of that group. An exec's row is homed in
  its caller session's group, a person's in the group they act in, else the
  machine's; the person exec routes (list, status, kill, the caller WS) see
  only execs homed in a group the acting group reads.
- `POST /v1/exec` reserves an unopened operation through the machine cell; one not opened within 60 seconds reaps. `GET /v1/exec/:id` WebSocket adapts the unchanged MachineContract wire to an `ExecStream` socket. It has no retained caller leg or replay: closing stops the operation. After sending exit, the adapter drains the existing terminal wire acknowledgment before closing the transport; a worker/socket drain without exit closes immediately. Listing/status read cell rows; kill mails stop(callerCancelled).

## Scripts on sessions: `wuhu:session`

`run_script` creates and drives sessions as its own session, through the same
code the `create_session` and `request` tools run:

```js
import { createSession, request, setTags, archive, unarchive, interrupt, resume } from "wuhu:session"
await createSession({ title, kind, topLevel, provider, model, effort, template,
                      tags, message, expectsReply, stallSeconds, request, key }) // { id, requestId? }
await request(id, message, { stallSeconds, schema, fields }) // { requestId }
await setTags(id, tags)                                   // replaces the list
await archive(id, { force: true }); await unarchive(id); await interrupt(id); await resume(id)
```

- Every call is checked when it runs, against the script's session as it stands then: an archived session is refused ("session X is archived and may no longer act on sessions"). `setTags`, `interrupt` and `resume` are allowed on the session itself and its descendants only; a root agent created with `topLevel` is not its creator's descendant. `archive` and `unarchive` also admit the session's creator and, from a top-level agent, any session of its own group (the rule: "only the session itself, its creator and admins of its group may"). Force self-archive is always refused ("can't force-archive itself; its parent, an ancestor or a human archives it"). Non-force archive of the script's own session is refused mid-turn: the call is part of that turn, so the session cannot settle ("can't archive itself mid-turn … its parent, an ancestor or a human archives it"). A detached script that outlives the turn can archive it once it has settled. The same subtree busy check and leaf-first archive apply. Archive asks each archived session's running scripts to stop through `LoopConfig.archived`, the archiving script included, and returns; each ends within the stop grace.
- `createSession` follows `create_session`: the kind is the explicit one, else the template's, else `agent` with `topLevel`, else `task`; the tree is capped at 16 levels; `topLevel` is for agents only, makes an agent, refuses `expectsReply`, and delivers `message` as a DM from the creator. Without `expectsReply`, `message` is a DM to a child too. Creating a child below a parent reserved for archive or already archived is refused, including from a detached script. Errors reuse the tool's wording with a `createSession:` prefix.
- Every `createSession` call creates: a script's call is tool call `script:<uuid>`, a page's `page:<uuid>`. A `key` option is ignored.
- A session that was created but whose template clone or brief failed
  afterwards rejects with an `Error` whose `id` is the new session, so the
  caller can message it or archive it.

## Scripts on machines: `wuhu:machine`

`run_script` reaches the space's machines through one module:

```js
import { machine, machines } from "wuhu:machine"
await machines()                     // [{ id, name, attached }]
const m = machine("mac-mini")        // name or id; no round trip
await m.stat(path)                   // { kind, size, mtime: Date, token } | null
await m.list(dir)                    // [{ name, kind, size, mtime: Date }]
await m.read(path)                   // Uint8Array, at most 8 MiB
await m.readText(path)               // string; throws if the bytes are not UTF-8
await m.write(path, data, { ifMatch }) // string or bytes -> the new token
await m.remove(path); await m.mkdir(path); await m.move(from, to)
await m.exec(cmd, { cwd, env, secrets, timeout, maxOutput })
                                     // { code, signal, stdout, stderr, truncated }
const p = await m.spawn(cmd, { cwd, env, secrets, stdin })
p.id; p.lines(); for await (const { stream, data } of p) {}
p.write(data); p.end(); p.kill(); await p.wait() // { code, signal }
```

- Every call resolves the machine and refuses at once when it is not
  attached ("machine X is not attached"); nothing waits for a machine to
  come back. Paths and `cwd` are absolute on the machine; `cwd` defaults
  to `/`.
- Files go over the same VFS ops as the fs tools. `write` creates the parent
  directories and carries at most 12 MiB minus 64 KiB, so its base64 frame
  stays under the frame ceiling below. `remove` is recursive. `stat` answers
  `null` for a missing path; other failures throw `code: message`.
- `exec` and `spawn` both run `sh -c cmd` as an exec minted in the registry
  (`POST /v1/exec` with `script: <run id>` as the session, recorded in the machine cell), so `wuhu ps` lists it under its `ex_`
  id; the worker then dials `/v1/exec/:id` like the CLI does. `secrets` names secrets of the machine's group
  (`{ VAR: "SECRET_NAME" }`, *Exec secrets come from the machine's group*);
  the agent injects and masks them. `env` names and the env/secrets overlap
  are checked as for the exec tool. A `wuhu:secret` placeholder in the
  command, an env value or stdin is refused: only `fetch` fills one in, and
  `secrets` is how a group secret reaches a machine. `timeout` is milliseconds
  (exec only). A command the box cannot spawn ends with exit 127 and a
  `wuhu:` line on stderr.
- `exec` collects the whole output: `maxOutput` defaults to 1 MiB and is
  capped at 4 MiB (`timeout` at the script's max lifetime); `truncated` says the agent stopped at it. `signal` is the
  signal number when a signal ended the command (`code` is then `null`).
- `spawn` streams. `lines()` yields `{ stream: "out" | "err", text }` in
  arrival order, split on `\n` per stream, a trailing `\r` dropped, decoded as
  UTF-8 with replacement on the server. Iterating the process itself yields
  raw `{ stream, data: Uint8Array }` chunks. A process has one reader: the
  second `lines()` or iteration throws. A reader that leaves before the end
  (`break`, `return`, a throw) discards the rest: what is buffered is dropped
  and later output is acknowledged unread, so the process never blocks. `write`/`end` exist only with
  `{ stdin: true }`; writes go out in call order. `kill()` sends TERM to the
  process group and KILL five seconds later. `wait()` resolves with the exit
  and does not read output.
- Flow control: each process may hold 1 MiB its script has not read. The
  agent stops sending past that and the process blocks on its pipes; nothing
  is dropped. A line still open when 1 MiB is held is handed over as it
  stands. The window of a running process, and each running `exec`'s
  `maxOutput`, count against the script's 64 MiB buffer budget; a process
  that has ended counts only the output it still holds unread. At most 8 processes run per script;
  a ninth `spawn` throws until one exits.
- Lifetime: a process lives only while its script runs. Teardown closes each caller stream, and MachineCell stops its operation as callerGone. A replacement cell wake detects orphan streams; unopened reservations expire after 60 seconds. A script-started exec cannot be backgrounded: MachineCell.background refuses it with invalidInput. No minted-exec kill list or script-release endpoint is used.
- Machine loss and server restart end the script's live heap, not prove that its OS processes exited. A stream close or orphan-stream discovery stops its operation as callerGone; no script-restart owner announcement is retained.

## Exec flow

1. A box connection attaches `BoxSocket` before HTTP upgrade; a worker that cannot host the machine cell refuses with 503 and the box redials. `BoxLink` runs FetchTunnel and replaces in-flight exchanges by tag; the hub route map remains only for writes and copy.
2. A tool job mails start, whereas a streaming caller reserves an exec id then opens `ExecStream`. The cell records one start intent before emitting it. A lost/ambiguous start is reconciled by UUID and never retried.
3. `BoxLink` puts bulk bytes in the worker's bounded MachineBuffers. Each cell answer step writes offsets and tail before emitting its next poll acknowledgment. Streaming output pointers are released by consumed cursors; a full window stops polls.
4. The cell owns presence, retry/deadline wakes, stop intent and terminal delivery. Tool finished retains the tail until taken; detach routes completion to the session. A roll closes worker sockets but never stops a tool/background exec: the box redials and polling resumes from committed offsets.

## Exec secrets come from the machine's group

Every exec surface carries secret names as `ENV_NAME → SECRET_NAME`. At operation admission the server resolves them from the machine's current owning group's secret store, not the caller's group, and sends `secretValues` in the `exec.v1` input. The supervisor injects and masks these values; they are not written as plaintext registry fields or diagnostics. Missing stores or names refuse the start before spawn with a typed diagnostic. There is no agent-local vault or capability-negotiated legacy secret lane.

A resumed operation retains its admitted input and environment rather than resolving a new start under a moved group or changed secret. A `wuhu:secret` placeholder is not a secret name: scripts refuse one in command, env or stdin before minting.

## Session execs act as their session

An exec started by its record's caller session receives that session's credential, so the nested `wuhu` CLI acts as the session rather than the box's wallet. A person starting an exec does not inherit session authority merely from its registry row.

- **Signed credentials.** Session and exec bearers are `wst_`-prefixed ES256 JWTs signed by the identity cell's current signer and verified against its current key set. Both `iss` and `aud` must equal `wuhu:space:<space id>`; the signature, `space`, expiry and `credential` purpose are checked locally. Internal credentials do not depend on an HTTPS origin or directory registration. A session credential has purpose `session` and no machine/exec claims; an exec credential has purpose `exec` and names its machine and exec. External OIDC tokens have no credential purpose and cannot authenticate here.
- **Liveness and expiry.** Every use rereads session existence, live lifecycle and current group. An exec also requires its durable exec row to have no terminal state. Machine, caller and original group are immutable after admission, so a verified credential does not revalidate those minted attribution claims against the row. Exec credentials remain marked as exec authority, never the worker's authority. Worker credentials are minted immediately before each API request or connection dial, expire after 300 seconds, and are not retained across waits; exec backgrounding, script updates and cleanup mint when they send. Exec expiry derives from the exec's original issue time and timeout, capped at 24 hours; retries cannot extend it. A caller channel start with a non-positive timeout is refused as `invalidInput` before recording its deadline or minting a credential. Expiry is HTTP 401 `credentialExpired`. Signed credentials survive process rollover while the rows and signing keys permit them; there are no token maps, revoke hooks or credential-attempt tombstones. Sessionless script-run bearers remain random process-local tokens, revoked when their run ends or is cancelled.
- **Owned names.** `sessionCredential: {token, spaceURL, expiresAt}` supplies `WUHU_EXEC`, `WUHU_TOKEN`, `WUHU_SPACE_URL` and `WUHU_TOKEN_EXPIRES_AT`; the supervisor overwrites caller values and masks the token on output. The CLI does not fall back to anonymous or wallet authority when this credential expires.
- **External OIDC.** `wuhu id-token` presents `WUHU_TOKEN` to `<WUHU_SPACE_URL>/v1/id-token`; the route rechecks the same signed credential and live rows, then emits a 60-second token for an external HTTP(S) origin. The internal space audience and non-HTTP(S) audiences are refused. Exec OIDC tokens retain machine/exec claims; session OIDC tokens do not. `WUHU_ID_TOKEN_URL`, `WUHU_ID_TOKEN_REQUEST` and `wit_` grants no longer exist. Older CLIs whose `id-token` command requires those environment names cannot mint tokens against this server.

Resume of a session with unreadable stored transcript/history is refused with a conflict explaining that the data cannot be loaded and directing the caller to Start over. The HTTP and `wuhu:session` script surfaces both retain that guidance; readable errored sessions still resume normally.

## Session Start over

`POST /v1/session/:id/restart` opens an empty-summary generation, preserving armed observations, one-shot and cron timers and queued input. Queued messages reach and wake the new generation; a bare restart remains inert. The head shows the active subscription list before the restart note. The two-sentence note tells agents to catch up from their own box using the `read-box` skill (for example, read its last 2–5 messages); tasks are directed to their DM with their parent, never a nonexistent task box. Error, hold, run and retry state and park reminders are cleared, pending compaction commands are discarded, and the model/executor may change. Running scripts, children, open requests, home files, conversations and prior-generation history are unchanged. Archived and busy sessions still receive typed refusals; an errored session can be started over.

## Resume and restart

Tool and background operations keep UUID, committed offsets, bounded tail and verdict across a roll. Unconsumed bulk bytes belong only to the old worker and are lost. Streaming callers do not reconnect or replay: a close stops the operation, and an orphan stream found after rollover is stopped as callerGone. An unopened reservation reaps after 60 seconds. There is no caller grace or terminal endpoint-retention window.

A poll answer is recorded before acknowledgment; a rolled-back answer is requested again from its previous offset. Repeated ranges do not change cursor or tail. Output-budget clipping keeps only its admitted prefix and stops the operation. Lease silence reports unknown remote outcome, never an invented exit status; timeout sends stop then waits 30 seconds for the machine's real termination.

## Resolver arm (M5): fs tools over `machines://`

`handler()` wires the tool context with a machine seam: `hub.vfs(machine:op:)`
and `hub.search(machine:query:)` open caller-owned cell sockets for reads, metadata, mutations other than writes, and search; writes and copy retain the machine owning group's `MachineOperations` until their replacement.
On a v2 machine every start a session caused carries `StartRequest.caller`
`{session, title, group}`, read from the session record at start time: file
tools and search take the session from `MachineSeam.caller` (set by
`ToolExecutor` around each tool call, and by `MachineSeam.attributed(to:)`
on a script's machine access; the parent owner binds it itself at `execute`, `placeImage` and `capabilityInput`, so each operation uses its actual calling session), exec from the leg that sent the start. A v2 exec belongs to one actor (a session or a person by account): the session that minted it, reserved from the mint; for a callerless exec, the one that sent its start, or before that the one attached. Another actor's dial of `/v1/exec/:id` is refused with 409 `execAttached` (the hub closes a leg that races past that check), so it can neither type into nor read the exec; an opened operation admits no new caller leg. The caller and the session credential are the record's session only when that session's own leg sent the start — a person's own (callerless) exec runs unattributed and without the credential. Starts no
session caused, and sessions that can no longer be read, carry none; the
field is display-only for the machine's audit and never authorizes.
Fs tools called with a `machines://<id>/<path>` address route through
FSResolver to the machine backend; space addresses are untouched. Ruling 2
scope holds — machine fs is raw:

- Machine paths are not restricted by the space path grammar (`@`, spaces,
  `//` all pass through raw). The one carve-out: a trailing `@<digits>`
  revision suffix on a machines:// address is rejected `unsupported` (never
  silently stripped, never treated as a raw name), and so is a `rev` input
  field — machine fs has no revisions, journal, history, or observe.
- Version tokens are the agent's mtime strings, opaque; outputs carry `token`
  but no `rev` (`rev` is optional in Write/Edit/List/Move outputs). `rm`
  returns `{}`; `mv` returns `{dangling: []}` (no links on a machine) and
  refuses to cross backends.
- `edit` is composed server-side (ruling 14) by the same tool code path as
  the space edit: read → TextEdit fuzzy apply → write with `ifMatch` = the
  read token. A token mismatch surfaces the space conflict contract — code
  `conflict` plus the re-read hint.
- `write` mkdirs the parent first, mirroring the space fs's implicit
  directories.
- grep/find run one FileSearch query on every backend: the space walks
  itself, a machines:// address runs it on the machine as `search.v1`
  (an agent without `search.v1` is refused before starting). Same
  walk order, hidden names, budgets and cursors, and every file read a range
  at a time whatever its size, so pages hold the same items across backends
  modulo the `machines://<id>` prefix (`SearchParityTests`). A cursor is bound
  to its backend: the group, the machine or the system files.
- Error mapping: machine `notFound`/`conflict`/`invalidArgument` keep their
  codes, `tooLarge` → `unsupported`, everything else → `internal`. A machine
  that is not attached (or a round trip severed mid-flight) fails
  `unavailable`; an id failing the `mc_` shape fails `invalidPath`.

The content plane's tool context has no machine seam: machines:// addresses fail `unavailable` there.

`serve()` sets `ServeOptions.maximumWebSocketFrameBytes` to `MachineHub.maximumFrameBytes` (16 MiB). This bounds incoming WebSocket frames, including the shared exec caller channel. Machine operations use the bounded v2 fetch tunnel and their operation-specific payload limits, not single-frame legacy VFS round trips. Oversized or missing data follows those typed operation contracts rather than selecting a different transport.

## Per-call inference accounting

The kernel metrics sink writes every `InferenceMetric` to `inferences` alongside the existing `logs/inference.jsonl` line. Uncached input subtracts cache reads and writes from WuhuAI's total input; billed output includes reasoning. Missing usage and unreported reasoning remain null. Compaction uses the same sink.

Stored Claude Code inference rows remain queryable; no executor produces new ones.

## Subtree archive

`POST /v1/session/:id/archive` accepts no body or `{ "force": false }`; `{ "force": true }` forces the operation. A malformed body returns `invalidArgument`. A busy non-force archive returns HTTP 409 `conflict` with a `busy: id (title), ...` list. The CLI accepts `session archive <id> [--force]`; code mode accepts `archive(id, { force: true })`. The app's unchanged empty-body call is non-force.

Archiving a session takes its entire parent-chain subtree, leaves first and root last. A separately created top-level agent has no parent and is not included. Only the root's archive rights are checked. Without force, every session is checked for the existing unfinished-work condition (retired sessions are never busy, even with queued input); refusal archives nothing and names every busy session by id and title. With force, busy sessions are interrupted before any archive write, and every open request in the subtree, including an undrained request, is closed with a final-kind message saying the session was archived before reporting. Its requester receives that message even outside the subtree. Unarchive remains single-session, subject to the archive grace window.

## Capability HTTP surface

Authenticated `POST /v1/web-search` accepts `{ query, provider?, count? }` and returns the shared normalized search result. `POST /v1/image` accepts `{ prompt, images?: [base64 PNG], provider?, model?, quality?, size? }`, bounds its body to 36 MiB and decoded references to 25 MiB aggregate/at most five, and returns `{ b64JSON, mimeType: "image/png" }` for the create-only local CLI output. Image data is private request data, not a public Wuhu URL.

`POST /v1/transcribe` retains raw audio Content-Type/body and the existing response's text/provider/model/language/durationSeconds fields, adding optional segments/words/confidence/usage. Query options are language/provider/model/timestamps (comma-separated words,segments)/diarize (true/false). It resolves the same `/capabilities.json` selection as scripts and images before buffering up to 25 MiB; duration must be established locally and must not exceed two hours. MP4/M4A fragments use track timescales and decode/sample timing, not zero-duration initialization headers; unestablishable duration is rejected before provider I/O with invalid_argument and a re-encode hint. No ChatGPT-first picker remains. `GET /v1/transcribe` retains available/provider/model for existing clients; explicit configuration failures mark unavailable. App/browser/CLI need no new provider picker. Unconfigured capabilities synthesize Codex; explicit broken active/overrides produce typed errors without fallback.

Capability error bodies preserve code/message/hint. HTTP mapping: invalid_argument/unsupported_feature → 400 (streaming upload byte overflow → 413); provider_auth → 502 (the server's provider credential failed, not the caller's: 401 is the caller's own); provider_region/provider_entitlement → 403; provider_rate_limited → 429; provider_not_configured/provider_unavailable → 503. No upstream diagnostic bodies, credentials or signed result URLs are logged/returned. The existing authentication wall remains; session exec tokens may call these four capability routes, preserving group scoping and without access to credential-management routes.
## Partial-loading routes

`GET /v1/conversation/:id/messages?tail=100&paged=true` returns `ConversationHistoryOutput`: ascending messages, exclusive `before`, `hasEarlier` and `headPosition`. An older request adds `before`; the maximum paged tail is 100. Existing unpaged message responses retain their shapes. The channel/box/DM read contract above applies to each page.

`GET /v1/session/:id/lines?generation=G&after=P` (SSE) is the transcript lines stream, one `SessionLineEvent` per message, from the session cell's `TranscriptTail`: `reset(generation)` then every line of the current generation, or, when `generation` names the current one, the lines past `after` and the prompt lines again; then each line as the store writes it, and a `reset` for each new generation. `generation` and `after` come together or not at all (else 400). A line's `message` keeps thinking and names an inline image instead of carrying it. Clients place lines by position and tell them apart by key; a line with `prompt` true can arrive after later lines and does not move the client's cursor. The stream and the conversation stream share one SSE helper, which logs a failure that ends a stream. `GET /v1/session/:id/lines/page?generation=&before=&limit=200` returns `SessionLinesPageOutput`: the generation (default current), its last `limit` (1–200) lines before exclusive `before`, ascending, and `hasEarlier`. Both apply session read authorization; the stream closes once its viewer stops reading the session's group.

## Kernel Responses transport

SessionRuntime owns the bounded Responses socket registry and its structured sweeper. Model and credential resolution happen per attempt; selected WebSocket transport never falls back to SSE. The process composition root explicitly installs the live connector, while offline callers inject it. Session commit acknowledgements use actual persisted entries and current rendered attribution, and lifecycle changes invalidate the registry entry. `codex.rate_limits` uses a separate validated `rate_limits.primary/secondary` projection (`window_minutes`, `used_percent`, `reset_at`), not the `/wham/usage` schema. Zero/negative windows, percentages outside 0–100, missing values and nonfinite values are ignored. Quota observation never changes inference token usage or durable transcript state.

Assembled-runtime WebSocket tests exercise the production inference closure rather than substituting a test LoopConfig: actual durable assistant/tool commits establish a warm provider-ID continuation, successive successful calls release leases, provider 401/409 and cancellation invalidate owned leases before resume, and on-connect/inference/post-completion quota reaches the runtime UsageBoard.

The session runtime logs unexpected session-service termination errors instead of silently swallowing them; cancellation is normal shutdown.

## Configured AI disclosure

`SpaceServer.serve(aiDisclosureFile:)` / `wuhu serve --ai-disclosure <json-file>` reads a disclosure object once at startup, before store creation or listener binding. The file format is `{"version":"trial-2026-10","providers":[{"name":"DeepSeek","location":"China","via":"Wuhu metering proxy","policy":"https://wuhu.ai/privacy"}]}`: nonempty version, at least one provider, nonempty name/location/via, and an absolute HTTPS policy URL without credentials. ## Server identity (OIDC)

First startup generates one ES256 P-256 signing key under the server-state `identity/` directory. The directory is mode 0700 and key files are mode 0600. A key id is SHA256 of the public key, encoded base64url; each private key lives in `<kid>.p256`, never in SQLite. Malformed or missing keys are not replaced. Back up the complete identity directory as well as the database.

Unauthenticated `GET /.well-known/openid-configuration` on the space API host returns `issuer`, `jwks_uri` and `id_token_signing_alg_values_supported: ["ES256"]`. `GET /.well-known/jwks.json` returns `keys` with the public EC key (`kty`, `crv`, `alg`, `use`, `kid`, `x`, `y`), never private `d`. Issuer is the configured HTTPS `--origin` (hosted: the tenant's own origin). Missing/non-HTTPS origin or unavailable identity gives HTTP 422 with code `oidcConfiguration`; never infer issuer from request Host. Group content hosts do not host these discovery routes.

For each OIDC kernel inference attempt, runtime supplies a freshly signed JWT. Audience is the canonical origin of the provider's `baseURL`, including HTTP, without user information, path, query or fragment. Tokens use `alg: ES256`, `typ: JWT`, `kid`, raw 64-byte ECDSA signatures, and claims `iss`, `aud`, integer `iat`, `exp = iat + 300`, unique `jti`, `space` (space id), `group` (group id), and `session` (session id, when acting). `sub` is `<group>/<session>` or `<group>` without a session. The kernel obtains the group from its persisted session record, never from client claims. Invalid audience/issuer and identity key-unavailable/signing failures become typed inference `invalidInput` 422 errors with static hints naming provider baseURL, HTTPS --origin or server identity key configuration. Unknown signer diagnostics remain suppressed; no credential/provider fallback or private error details are exposed.

`GET /v1/id-token?audience=<origin>` authenticates with the signed session or exec credential described above, before the device wall. It answers 401 for invalid credentials, expired credentials (`credentialExpired`) or ended execs; 403 for archived sessions or changed groups; 400 `invalidArgument` unless the audience is a canonical HTTP(S) origin; 503 `fetchIdentityUnavailable` without a server identity; identity failures as `/v1/identity`. Success is `{token, expiresAt}`, `Cache-Control: no-store`: a JWT as for inference but with `exp = iat + 60` and extra `machine` and `exec` claims only for exec authority. Sessionless script bearers cannot mint OIDC tokens.

The one `IdentityCell/server` in the space worker owns `server_identity`: issuer choices, allocated directory ID, confirmation or failure, pending work and a schedule of key ids and phase timestamps. Every signer, proof and JWKS request reads the durable schedule through a cell read handle, then loads key material through the key-store client. Default `self` preserves the existing issuer and claims. `directory` selects `https://id.wuhu.ai/<id>`; exact canonical HTTP(S) audience-origin overrides win over the default. Directory registration and key replacement submit compact ES256 proofs; no private key, space name or address is sent. IDs must be 32 base64url characters. Directory minting is refused until confirmed: `directoryUnavailable`, `unknownId` or `unlistedKey` remain typed failures, never a fallback to self. Persisted confirmation survives worker/process changes. Own-host discovery remains self-issued so self overrides still work.

Authenticated `GET /v1/identity` returns `{defaultIssuer, overrides, publicationFailure, state, rotating}`. Issuers are resolved URLs, or null for a directory choice before the first ID is allocated. `state` is `publishing`, `confirmed` or `failed`; `publicationFailure` is null until work actually fails and otherwise the last failure code. Only codes, never key material, are logged on failure. `GET /v1/identity/issuer-for?origin=<canonical-origin>` returns `{issuer}` and refuses an unallocated directory issuer. Both reads are available to enrolled humans and session execs, never anonymous production readers. `PUT /v1/identity` accepts exactly `{defaultIssuer:"self"|"directory"}`, `{audience:<canonical-origin>,issuer:"self"|"directory"}`, or `{audience:<canonical-origin>,remove:true}`. Writes require a human space-admin (including the dev person), never a session. A `worker.call` records each intent serially and returns its row snapshot immediately; no admin route waits for directory HTTP or key generation. A call refused with `Evicted` answers 503 `unavailable` with `Retry-After: 1`, as on every route (see Worker shutdown); an already pending rotation or incompatible registration returns 409 `identityBusy`. Invalid audience input is refused before writing. Configuration is server-wide. When no issuer choice uses the directory and no directory ID has been allocated, changing choices drops queued directory recovery, retries and directory failures; an in-flight registration cannot adopt a returned ID or restore a directory retry. Changing issuer is a breaking verifier migration: trust both issuers first.


Rotation is automatic 90 days after initial schedule creation or the previous rotation's completion. `POST /v1/identity/rotate` records it immediately and returns the accepted identity row snapshot; it requires the same human space-admin authority as settings and returns 409 `identityBusy` when a rotation is already pending. Day 0 durably stores a new private key before publishing old and new together, keeps signing with old, and begins the overlap clock only after directory confirmation when applicable. After one day it durably switches to the new signer. After two days, and at least one full day after the actual switch, it replaces the directory set with only new, signed by new, then removes old from its own JWKS and persisted schedule. A delayed switch extends the overlap so recently minted old tokens remain valid. All three mint sites share this signer. Restart resumes the persisted phase, retries unconfirmed publication, and never generates a second pending key. Cell wakes advance the schedule; directory failures retry on the cell wake. Own and directory public JWKS retain both keys throughout overlap.

When the cell has no row, host bootstrap reads `identity/settings.json` once and imports its issuer choices and raw-key schedule into per-kid files and the cell row; absent schedule state adopts `identity/identity.p256` and starts the 90-day clock at the initializing cell step's own time. Only an imported schedule carries its known historical rotation timestamp; the controller supplies no clock for a fresh bootstrap. Once initialized, neither legacy file is read again or modified. SQLite holds key ids only, so copying `space.sqlite` never copies signing authority.

`POST /v1/identity/register-new` records a request to register the current public key set under a fresh ID, returning the accepted row snapshot without awaiting the directory. Only confirmed completion mail replaces the saved ID; failed work preserves the old ID and minting status and retries on the cell wake. This human space-admin-only recovery permanently changes every directory-selected audience issuer; verifiers must migrate. It is not an automatic fallback for `unknownId`/`unlistedKey`. A purely self-issued space without an allocated ID receives 422 `directoryNotSelected`. Pending rotation is 409 `identityBusy` unless publication failed with `unknownId` or `unlistedKey`; that recovery registers both keys and preserves phase timestamps. Restore the complete server-state backup when preserving the old issuer is required.


## Proxied page fetch

`import { fetch } from "wuhu:space"` on a content-host page has the standard browser `fetch(input, init)` signature, accepts URL/string/Request input and returns a streaming `Response`. It sends `POST /_/space/fetch?url=<target>&method=<method>&headers=<JSON object>&page=<location.pathname>` with the raw request body. Query values are percent-encoded. Supported target methods are GET, POST, PUT, PATCH, DELETE and HEAD; every endpoint method other than POST is a typed 405 `fetchMethodInvalid`. RequestInit signal cancellation reaches the transport. The SDK never detours to direct browser fetch.

Admission requires Origin equal to the page's own content origin, Sec-Fetch-Site same-origin, and a live read cookie bound to that group. An anonymous viewer is 401 `fetchViewerRequired`, including under --public-read or --dev without a viewer cookie. No exec bearer is admitted: sessions cannot currently load content pages as themselves. The viewer token claim remains an opaque stable id so later session viewers can use their session id without a token-shape change. Human viewers use the account's persona handle (stable id), or account id when no persona exists; never email. `page` is the page's hostless absolute percent-decoded path, validated like other page writes, and remains a page-supplied claim, not an authenticated document identity.

Only the content host group's `/fetch.json` is read, fresh on every call, never a readable neighbour's or shared group's list. Its shape is `{"allow": ["https://dashboard.example.com"]}`: exact HTTP(S) origins (scheme, host, effective port), no user information, path, query, fragment or wildcard. An optional trailing `/` is accepted as an empty origin path. Host/scheme case and default ports canonicalize. Listed LAN/private origins are allowed. Missing, empty or unreadable list is 403 `fetchListMissing` naming `/fetch.json`; malformed entries are 400 `fetchListInvalid`. An unlisted target or redirect is 403 `fetchOriginForbidden` naming `/fetch.json`, before connection to that origin.

Target headers and body pass through except Cookie, Host, hop-by-hop headers and content length (the transport computes it). A page-set Authorization is refused as 403 `fetchAuthorizationForbidden`; only the server sets Authorization. Response Set-Cookie, hop-by-hop headers and connection-nominated headers are stripped, and Wuhu-Viewer is overwritten with the authenticated cookie account. The page worker recognizes Wuhu-Fetch-Result and does not bump its write epoch, purge query caches or notify the shell about an upstream 401. The response streams without collecting its body. The transport resolves each hop's host once, pins the connection to that numeric address using AsyncHTTPClient's DNS override, and keeps the original authority for Host/TLS verification. Redirects are followed only to listed origins, with a newly minted audience on each hop, up to 20 hops; 303 and POST 301/302 become GET, while 307/308 retain method/body. Invalid redirects or exhausted limit give 502 `fetchRedirectInvalid`.

The request body cap is 10 MiB (`413 fetchBodyTooLarge`) and one 60 s deadline covers upload, DNS, all hops and response streaming. Inbound deadline cancellation terminates the request-body read; policy refusals and timeout responses explicitly close the connection without a keep-alive drain. Pre-response deadline expiry is `504 fetchTimeout`; connection failure is `502 fetchUpstreamUnavailable`. A response stream already committed cannot replace its HTTP status with JSON: deadline/network failure closes it and browser body consumption rejects normally. Cancellation disposes the outbound connection. DNS runs off the cooperative executor; a cancelled wait does not permit a later connection. Fetch policy refusals have JSON `{code, message}` and the SDK rejects with SpaceError. Successfully forwarded responses carry `Wuhu-Fetch-Result: upstream`, even for upstream 4xx/5xx, so they return an ordinary Response rather than becoming policy errors.

The existing server identity signer and discovery JWKS sign fetch JWTs, never a second key. Each hop gets `Authorization: Bearer <jwt>` with ES256/kid, iss = the audience-selected issuer, aud = canonical target origin, iat, exp = iat + 60, jti, space (space id), group (host's group id), sub (group), path (page claim), viewer (opaque authenticated stable id). Missing identity/issuer or signing failure is 503 `fetchIdentityUnavailable`, with no signer/provider/credential fallback.

## Script fetch identity

The assembled script host has a dedicated opt-in identity transport using the same `ServerIdentity` key as page fetch and inference, with the acting session’s recorded group and stable space id. It mints a fresh ES256 JWT once per call with a 60 s lifetime and session claims, registers it with script masking before I/O, and sends it only to redirects on the explicitly named URL’s canonical HTTP(S) origin. Cross-origin redirects receive no Authorization; no redirect mints another token. Redirects are bounded at 20 and use a single 60 s deadline that also bounds DNS resolution; expiry is checked before each hop. POST becomes GET on 301/302, and non-HEAD becomes GET on 303; 307/308 retain method/body.

Single-hop HTTP connections disable automatic redirects and share the page path’s DNS-pinned streaming transport. Scripts preserve Set-Cookie response headers (pages still strip them). No page allow-list is consulted. Ordinary script fetch still uses its existing transport unchanged. Directory confirmation failures are directoryUnavailable; other identity configuration/mint/signing errors are fetchIdentityUnavailable, with no fallback. DNS, transport, timeout and invalid-redirect failures retain ordinary script fetch error behavior. Token echo masking is best-effort, not a guarantee against split/encoded echoes reaching JavaScript; audience binding and the 60 s lifetime bound their use. The private key never enters scripts, responses or the space.

View-provider routes (`/_/views/kanban`, `list`, `wall`, and `map`) refuse a `path` resolving under conversation attachments with 403 `attachmentViewForbidden`. They inspect the first `path` query value, matching the provider's URLSearchParams lookup, before returning a trusted provider frame. A malformed target URL receives 400 `invalidViewPath`. Copy an attachment definition to an ordinary space path before opening it as a view.


Session Start over reports the number of unreadable queued inputs dropped in its restart note, appended to the normal catch-up text. Readable queued inputs retain FIFO order and dedup identity and still wake the new generation. Open requests stay open; the new generation's park backoff starts over, since it counts only the reminders its own transcript shows.

## Removed Claude Code executor

All model providers run in the kernel. `POST /v1/session`, session templates and `POST /v1/session/:id/restart` accept `executor: "kernel"` only; any other value is HTTP 422 `{ "code": "invalidArgument", "message": "unknown executor: <value>" }` (a template names itself in the message). A session-tool call returns a failure with the same code; code-mode creation throws an error naming it. No rejection creates a session or changes its generation. A session stored on any other executor is retired: its transcript pages, log and entries read empty, it never runs, and unarchiving it is refused with HTTP 422 `{ "code": "executorNoLongerSupported", "message": "executor no longer supported" }`. Start over must explicitly name a provider to hand a live one over; a bare restart cannot switch its executor. The session id, box, home, tags, children, subscriptions and readable queue input are retained.

The Claude Code installer, process loop, stream parser, mirror/history translation, image transport, MCP routes and loopback listener, usage probes and inference accounting hooks are removed. Old turns no longer appear in transcript/history routes; raw stored rows and external logs are not deleted. `/v1/session-tools` exposes only the kernel roster.

## Human-only channels

`POST /v1/conversation` accepts `{members: [persona], title?: string|null}` and returns `ConversationPostOutput` with the new conversation id. It creates a `users` channel homed in the acting group; every initial member must be a person, not a session. `POST /v1/channel/:id/add` and `/remove` accept `{people: [persona]}`; `/rename` accepts `{title: string|null}`. Creation and each mutation validate atomically. Unsigned production creation is unauthorized. Person members and sessions whose group reads the channel's home group may manage it; Public content readers cannot access channels; the dev person must be a member like any other person. Session ids, empty identities and blank non-null titles are invalid arguments; unread/non-channel ids answer as unknown conversations. Adding a member is idempotent, removing an absent member is harmless, and `null` clears the title. `ConversationPayload` has nullable `title`; the UI falls back to members' names. The nullable title side table is additive and needs no ALTER, data reset or backfill.

Sessions read, post and manage without joining the channel; legacy session membership rows grant no person access. Plain messages notify people but do not wake a session unless addressed. Mentions, reply targets and the existing attention window still deliver to sessions. CLI `channel create|add|remove|rename` and `wuhu:space` `createChannel`, `addChannelMembers`, `removeChannelMembers`, `renameChannel` expose the same management services.

### Whole-revision observe frames

`GET /v1/observe?glob=…[&from=N]&batch=1` opts into `event: revision` frames carrying `RevisionEvents` (`rev` and a nonempty array of matching `MutationEvent` values). A revision arrives whole in commit order, replay is grouped strictly after `from`, and qualified globs retain the same group prefix on every event path and move destination. Without `batch=1`, the existing unnamed single-mutation SSE frames and bytes are unchanged. SQL observation is unchanged. The server advertises `observe-batch` through discovery; the web file feed requests it and publishes/checkpoints once per revision.

## Space host composition

`SpaceHost.open` assembles one space's routes and background runtimes independently of its listener. Its explicit `configDirectory` owns credentials and group secrets; `allowEnvironmentCredentials: false` prevents provider-key lookup in the process environment. `run()` owns a single cancellation-scoped background task; cancelling its caller cancels that task. `shutdown()` is self-contained and idempotent: it prevents later runs, cancels background and in-flight handler work, cancels all admitted legacy and bounded WebSocket sessions before aborting their transports, awaits all owned tasks, then flushes metrics and performs any configured development export. Caller cancellation likewise cancels an owned WebSocket session before abort releases its transport. A deferred upgrade session invoked after shutdown begins is aborted without running its body, including an upgrade returned before shutdown. The host exposes its open `Space` for trusted in-process administration. `SpaceHost.loadDisclosure(from:)` applies the same file parser and validation as single-space serve, which passes the loaded AIDisclosure to open rather than rereading it.

`SpaceDirectory.host(for:)` is the listener's dispatch seam. Its handler returns 421 for an unknown host. `SingleSpaceDirectory` returns its one host for every request hostname, retaining the existing single-space Host behavior. `SpaceServer.serve` still binds exactly one listener with its unchanged TLS, flag, import and export policies.

`SpaceLogContext` carries the space id in a task-local during assembly, request dispatch, deferred WebSocket sessions and background work. Executables install its swift-log metadata provider so all logs emitted in those scopes include `space`. Listener/process diagnostics outside a space scope have no tenant id.

Host shutdown owns and cancels response-body forwarding through completion, with demand-driven bounded buffering; SSE from an old host closes before stop/delete returns. Host assembly owns the web-push HTTP transport and asynchronously shuts it down even before run or after listener bind failure. Session registry disposal also occurs on the never-run path. Shutdown drains in-process machine exec callers before closing the space database. Development export, database close, and HTTP transport shutdown are all attempted even if an earlier step fails; shutdown rethrows the first error, including on repeated calls. `serve` logs the graceful drain through `wuhu.serve`: one line when the wait ends before the bound, carrying its duration, and past the bound one line per request the shutdown is about to end, carrying its method, path, HTTP version, age and activity.

## Notification delivery

Each space boots two never-finishing `NotificationDeliveryJob` instances, `web-push` and `push-relay`, on its shared wuwei worker. Each transport has one lease: a second worker starting beside it cannot deliver the same cursor concurrently. `start` rebuilds from the grant rows, reads due notifications, sends through the injected transport, and commits the cursor or retry time in a job step. Dead grants and expired browser subscriptions are deleted in job steps. Registration and device revocation remain host writes to common, unowned grant tables; notification rows remain PersonCell's writes.

Each notification insert mails `.changed` to both delivery jobs in the same person-cell step. A waiting job wakes immediately for local mail; mail committed through another space is discovered by the holder’s next worker scan. Each job drains queued mail before reading due deliveries and waits for mail for at most 15 seconds when none is due, so persisted retries also progress without new notifications. No host observation task drives delivery. A drain cancels effects and stops between deliveries. A successor resumes from the persisted cursor, never from in-memory drain state. A send that returns successfully during cancellation commits its cursor before quiescence releases the lease, so its successor does not replay that notification. A send that throws cancellation leaves the cursor pending without backoff. Delivery remains best effort: an interrupted send without a recorded result can be repeated, and gateway acceptance is not proof of delivery to a device. Gateway 400/413 advances past the unsendable notification; dead-grant responses withdraw the grant; transient transport or rendering failures preserve the cursor and persist backoff. Cancellation and eviction never become transport failures or increment backoff.

## Live account creation and admin

`GET /v1/accounts` lists every account to any live account but a guest (`memberRequired`), including the dev person; an `AccountPayload` carries id, kind, name, admin flag, creation time and guest flag, never a key, token or invite. `POST /v1/accounts`, `DELETE /v1/accounts/:id` and `POST /v1/accounts/:id/admin` authorize through the account's space-admin flag, not its acting group or personal-group admin status. Refusals retain code `adminRequired`. Unsigned dev requests use the ordinary owner account; verified bearer requests retain their enrolled account. `POST /v1/enroll` remains self or space admin.

Creating a human account creates no group or membership in `shared`. `admin:true` grants the settings-group admin role. A person creates and administers an ordinary group through the group API; machine registration, secrets and observers require the existing role on a real group.

## Person profiles

`PUT /v1/user/me/profile` requires an account for the authenticated principal. The dev person uses the same profile, avatar and settings routes as enrolled people.

## Machine v2 connection ownership

The existing `MachineHub` authorizes the live machine key and exact singleton machine identity against current membership. The listener constructs its `BoxLink` directly over the shared worker and runs the tunnel and link in one structured connection lifetime. Exec preparation rechecks that captured credential before resolving secrets and session credentials. No machine route registry, file coordinator, encrypted operation store or server-private machine-v2 key participates in this path. Historical machine-v2 key files are not read or removed at startup; the appended migration drops the old encrypted-operation tables without carrying their work forward.

Presence belongs to the machine cell, not a membership scan or a host task. Box attach schedules a describe; a valid answer records attached and schedules the next describe at one third of its lease. Silence for the lease records lost, closes the box socket and finishes live exec waiters with an unknown outcome. A replaced box socket cannot clear the replacement. `acceptingStarts == false` refuses new exec starts with `leaving`; the existing wire has no graceful-leave handshake. Machine moves retain the same cell and membership determines status visibility.

## Machine v2 production lifecycle

`SpaceHost.open` mounts the machine-v2 routes over its existing `MachineHub` inside the configured session gate, production wall and host routing. The public handler and the tools' in-process `bindMain` binding do not mount these listener-only routes. The host runs sessions without a separate machine-v2 recovery service. Exec rows, cursors and bounded tails belong to the shared worker's machine cell; box redial reconciles live operation UUIDs without repeating a start. Worker drain closes sockets but does not stop tool execs; closed streaming callers are stopped immediately rather than retained for reconnect.

`POST /v1/machine-v2` accepts optional body `group` under the registration-group policy above, requires a valid globally unique machine name, atomically creates the account, separately enrolled machine identity, explicit v2 membership and one-time token in a single space-writer transaction, and returns the ordinary token/fingerprint. An insertion failure leaves no half-created identity and the name remains retryable. `POST /v1/machine-v2/enroll` checks that membership inside the token/key claiming transaction before mutation; a token without v2 membership is refused without consuming it or mutating credentials. Consuming a machine account's token (`POST /v1/enroll/consume` and `POST /v1/machine-v2/enroll`, so also a rotate's re-key) leaves a receipt in the claiming transaction (a person's invite or share-login token stays strictly one-time): replaying the consumed token with the same pubkey returns the same key while that key lives and the token's original expiry has not passed; any other pubkey stays `401 tokenInvalid`, and a receipt dies with its key (rotation, revocation, removal). `GET /v1/machine-v2/:id` verifies membership either for a readable person/session principal or via a fresh signed v2 dial credential. Moving a machine updates its v2 membership alongside the existing move transaction; read visibility is checked on every dispatch.

With `pubkey` in the body, `POST /v1/machine-v2` is one-call enrollment for a machine that holds its own key (the Wuhu app): the name stays globally unique (`409 machineNameTaken`), the group follows the same registration policy, and one transaction creates the account, machine, v2 membership and live `exec-machine` key (created by the calling person) with no join token; the response is the `EnrollConsumeOutput` that token enrollment returns. A malformed key is `400 invalidArgument`, an already-enrolled key `409 keyTaken`. The call is idempotent for a retry: when the name is already held by a v2 machine in the same group whose live `exec-machine` key is this `pubkey` and was enrolled by the same calling person, the same transaction returns that machine and key unchanged (`200`, same body, re-applying any `device` link) instead of `409`. A different key, a different person, another group, or a key since rotated or revoked is still `409 machineNameTaken`. Optional `device` links the machine to one of the caller's own devices in the same transaction; another account's or an unknown device is `404 unknownDevice`, a session naming a device is `403`, and `device` without `pubkey` is `400`. `POST /v1/machine-v2/:id/revoke` lets the machine drop its own credentials: it is authenticated only by fresh MachineV2Connect headers whose machine set is exactly `:id` and whose live key resolves to that machine, then, in one space-writer transaction, re-checks that the presenting key is a live exec-machine key of that machine's account and purges every credential of the account; the machine's live connection is kicked after the commit. A rotation therefore lands wholly before (the presenting key is dead: `401`) or wholly after, and a revoke signed before a rotation never deletes the replacement. The production wall admits it unauthenticated like the signed status GET. On every machine-key path (signed status, connect, self-revoke) only a definitive refusal is `401` (`keyInvalid` for a bad handshake, `machineNotAuthorized` for an unknown, revoked or misaddressed key); a database or internal authorization failure is retryable `503 machineAuthUnavailable`, logged as an error naming the step and the cause, and a machine must retry rather than discard its key. Token and one-call enrollment map non-domain failures to the same `503 machineAuthUnavailable`. The machine row stays, so a person can re-enroll it through rotate.

`GET /v1/machine-v2/challenge` and the bounded `/v1/machine-v2/connect` upgrade authenticate by the new MachineV2Connect signing domain. Challenges are consumed once and never reused across a server incarnation. The signed allowed machine set is validated before upgrade and for every dispatched Fetch request, including current enrolled-key validity and caller group readability. Replacing a tunnel aborts outstanding exchanges; an old connection's teardown cannot remove the replacement. A missing live route is typed `machineUnavailable`, never another transport route. Presence reports attached after a description and lost after lease silence, with `silentSince` from the last answer or membership registration if never answered. Missing owning-group evidence after a concurrent removal is `unknownMachine`, not synthesized silence. Rotation/revocation aborts the machine connection. Connection close alone never records detached presence.

## Machine v2 agent upgrades

The server tells each v2 machine which agent to run; the machine installs it. The machine's own key-signed `GET /v1/machine-v2/:id` (its hello) carries `upgrade`, a `MachineV2Upgrade`, and `GET /v1/machine-v2/:id/upgrade` returns the same object alone. That route is key-signed only (fresh MachineV2Connect headers whose machine set is exactly `:id`, same `401`/`503` split as the signed status read) and passes the production wall like it; a person's or session's status read never carries `upgrade`.

The target is the server's own stamped version unless `/machine-v2-upgrade.json` in `settings` pins one. That file is `{"pause"?: bool, "pin"?: "N.N.N[-dev.N|-beta.N]", "machines"?: {"mc_…": {"pause"?, "pin"?}}}`; a machine's field overrides the global one, `null` means unset. It is read on every hello, so a pin or pause applies at the machine's next hello. The parse is strict: an unknown key, a wrong type, a malformed version or machine id makes the whole file unparseable. A missing or unparseable file means "follow the server"; an unparseable one is logged once per distinct content.

`status` is `paused` (pause in effect; `artifacts` empty), `unstamped` (no pin and the server is `0.0.0-unstamped`, as every check and test build is, so there is no version to name), `unpublished` (no platform's archive exists for the target; never a guess at another version), `unreachable` (the release host failed, timed out after 5 s, or served a malformed sidecar) or `ready`. Only `ready` lists `artifacts`, one per published platform: `{platform, url, sha256}` with `platform` `macos-arm64` or `linux-amd64`, `url` `https://wuhu.ai/releases/wuhu-<v>-<platform>.zip|.tar.gz`, and `sha256` the archive's digest from its immutable `.sha256` sidecar (`<hex>  <archive name>`). The server resolves a version from those sidecars, never from `latest.json`. One `MachineReleaseJob` per space owns a durable resolution row per version; old rows remain valid across rolls because releases are immutable. Boot durably requests the stamped server version. A hello reads the row without awaiting HTTP; no row answers `unreachable`. Every nonfinal hello durably mails a lookup request; only the job judges whether the last lookup is 60 s old, with its step clock. Complete published answers are final; partial published answers stay `ready` with their available artifacts. There is no autonomous retry timer. Consuming a due request and recording its pending intent share a step before the HTTP effect, so a roll during lookup repeats it and updates the same row. Historical rows are retained, one per server version or admin pin, not per hello or retry. `version` is the target (absent when the server is unstamped and no pin names one), `pinned` whether a pin chose it.

The skew window this serves: a server keeps working with agents of the previous release, whose descriptors it reads on every describe. Before starting an operation, `MachineOperations.open` refuses any top-level input field a kind's closed (`additionalProperties: false`) input schema does not declare, `409 kindUnavailable` with `reason: agentTooOld`, `inputs` and `started: false`, so an older agent never receives a field it would reject or silently ignore.


## Model group placement

Session create, templates, child tools/scripts/CLI and Start over accept `modelGroup` plus optional effort, exclusive with provider/model. HTTP create and Start over return optional `modelGroup` requested intent and active concrete `provider`/`model`. Direct execution establishes a durable concrete binding on first use; group placement and pin persistence are atomic with session creation or generation reset; active telemetry changes never repin a running session in this slice. `GET /v1/session/:id/model-route` returns requestedTarget, activeProvider, activeModel and optional persisted route/evidence and append-only decisions under normal session visibility. Every timestamp in this endpoint is an ISO 8601 UTC string ending in `Z`: route/decision `placedAt`, failure `firstFailureAt`/`lastFailureAt`/`deadline`/`retryAt`, evidence `observedAt`, and window `resetsAt`. Absent timestamps remain absent; numeric percentages/capacities/scores remain numeric. Internal stored payload/evidence encoding is unchanged. CLI list exposes requested_model_group, active_provider/model and phase through the same scoped route SQL projection; inspect returns the structured route endpoint. `GET /v1/providers` retains the providers array and adds groups (ordered aliases, concrete references, effective effort intersection/default and policy); no group is disguised as a provider/model list. Malformed group discovery returns a typed error rather than silently omitting the group.
## Idle agent cache warming

`kernelInference` decides warming once, where the reply is built, from the request it answered: an agent whose model has a `cacheWarming` policy, whose request reaches the floor (`reachesCacheWarmingFloor`), and whose provider's five-hour window has quota left (the same `UsageBoard` `GET /v1/providers` exposes; absent or expired windows do not) leaves a `WarmingSchedule` on the reply — the policy's interval, lifetime and max pings. Everything else leaves nil: a task, no policy, a low window, a context under the floor. The cell owns the wake from there: a ping at the last reply plus the interval, at most max pings, only while the reply is younger than its lifetime. A ping is an ordinary inference step with `ping` set: one attempt, no retry, and no route-failure record or move, so a ping never changes the session's model route. Its failure ends warming and leaves the session idle, not errored, with the notice as an unanswered line; a failed tool continuation of a ping does the same with the tool results as the last lines. `SessionRuntime` runs no warmer. All turns continue through normal rendering and replay safety.

## Account-bound replay safety

Before each session request the runtime resolves the configured credential/endpoint binding. A changed identity or legacy unscoped account-bound content forces a local portable handoff before any request; normal OAuth token maintenance does not change the binding. Binding and route epoch survive ordinary compaction as optional transcript metadata. The initial request uses the persisted model-route epoch; a portable credential-boundary handoff advances the transcript replay epoch without repicking the group member. Start over discards the transcript binding and obtains a new placement epoch. Responses socket continuations and provider cache/thread keys are scoped by binding and epoch. Direct sessions remain direct; configuration errors never select another provider.

Behavior changes: legacy live transcripts with unscoped signatures/encrypted reasoning/hosted records lose signed replay once when adopted into a portable generation. Custom/proxy origins default to `opaqueReplay: none`, so their opaque outputs are projected to portable content on replay unless the operator explicitly asserts `affine` upstream account affinity. Anthropic/Claude providers in none mode must offer only `none` effort; a thinking-enabled declaration is a typed catalog error rather than a request with invalid unsigned thinking or silently disabled thinking. Responses none mode remains valid with reasoning projected to ordinary text.

Group-agent warming follows the persisted concrete pin for opt-in and quota; group preference edits and alternate-account usage never repick or gate the active member. Ordinary replay handoffs retain that pin, and Start over clears warming state with the new placement.

## Compaction placement and route failure episodes

Quota-aware group compaction re-runs headroom placement using current/reset-aware usage and relative capacities; the same member creates no epoch/history churn. A move projects all retained content through portable handoff, retains the produced summary/pre-reads, rejects an oversized indispensable handoff, and commits the generation/pin/evidence together. Direct sessions and manual select pins do not move automatically. A target requested through the compact tool replaces this placement for that compaction: a provider/model binds the session to that concrete route and leaves any group; a group id (matched exactly first, so it may contain a slash; only a non-group string is read as provider/model) places within that group from its declared members (joining it from a direct or other-group session); the current target is a no-op; an effort-only change on the same target keeps the epoch, member and transcript and updates only the configured effort. Every other requested move is a portable handoff with a new epoch; re-placing within the session's own group carries the ordinary route notice, any other move a short `Model switched X → Y (requested at compaction)` context notice. An unknown, unconfigured, effort-invalid, unplaceable or too-large-to-hand-off target is refused before any write, leaving route, history and generation unchanged; a concrete target equal to the group's current member still leaves the group. Placement checks local configuration strictly, but candidates with typed login/auth/quota runtime refusal, the held member included, are ineligible rather than failures, and the held member is left out while its route episode is an authentication refusal. A chosen candidate's late typed credential-refresh/refusal failure at resolution removes it and re-runs the scorer on remaining eligible members; exhausted alternatives are `noUsableMembers`. Other resolve errors remain typed failures.

A session never switches members mid-generation. Typed upstream quota/auth refusals, recognized credential-refresh login refusal on the held provider and recognized service/connection outages are recorded as a failure episode on the held route: source/reason/code, first/latest failure times, retry time (for quota the refusal's reset if still ahead, else the usage board's; a minute for an outage) and consecutive count; an outage refuses from its third consecutive failure. Removed group definitions retain the original typed invalid-route error without recording refusal. Normal inference resolves only the held member's credentials. Configuration, unknown/model-permission errors, arbitrary 401/403, parser errors and ambiguous transport errors are never recorded. An episode with a future retry time makes the next held-member inference wait for it (`ModelRouteWaiting`), however far off; an authentication episode errors the session until the credential is fixed and the session resumed, or Start over. Success clears the episode without repinning. Restart/resume keep it; interrupt/archive cancel active waits. A recorded outage throws `ModelRouteWaiting` at the failed attempt, so outages never count toward the loop's bounded-failure park. A `compact` request posted during a wait, mid-turn included, ends it and folds mechanically so compaction placement can move; that placement leaves the held member out while its quota episode has a future reset, unless no other member is usable. Start over runs the same headroom placement and leaves out the held member while its episode is an authentication refusal, unless it is the group's only member; group readiness still refuses Start over while any member needs login. History rows written before switching was removed may read `lastResort:<cause>`.

## Optional server traces

The standard OpenTelemetry environment configures traces: `OTEL_EXPORTER_OTLP_ENDPOINT=http://collector.example:4318` (or `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`) enables asynchronous OTLP/HTTP export with `service.name=wuhu-server`, `service.version` set to the binary's release version and `host.name` set to the hostname; without an endpoint, or with `OTEL_SDK_DISABLED=true`, nothing is installed and every span is a no-op. `SpaceServer.serve(telemetryEnvironment:)` is the embedding equivalent; it takes the variables rather than reading the process. An endpoint that is not an HTTP(S) URL without credentials, query or fragment stops the server before it opens the space, and so does, as `UnsupportedTelemetrySetting`, a value swift-otel would accept and then `fatalError` on: the gRPC protocol (only OTLP/HTTP is linked), a Jaeger-remote or X-Ray sampler, or a propagator other than `tracecontext` and `none`. Any other malformed `OTEL_*` value is ignored and its default kept. swift-otel's diagnostics reach the server log only at error level, whatever `OTEL_LOG_LEVEL` says: below error they echo raw variable values, `OTEL_EXPORTER_OTLP_HEADERS` included. In their place a failing export logs one warning, without metadata, and stays silent until an export succeeds, which re-arms it; a batch tick that drops spans because the queue is full logs one warning with only `queue_size` and `dropped_count`, and stays silent until a tick drops none.

swift-otel's tracer behind `InstrumentationSystem` (OTLP/HTTP protobuf, its batch processor) exports the server process's spans. Spans are written only through the `ServerTelemetry` vocabulary, whose attribute names and values are closed. Tracing writes nothing to the space database, the transcript, the queue, the prompt or the tool list, and the loop never branches on span state.

Each machine v2 HTTP exchange made in a trace is one `machine.exchange` client span under the span that made it, with the trace owner's `wuhu.session.id` and `wuhu.group.id`: `machine.id`, `machine.exchange.kind` (describe, start, poll, stop, input), `operation.id` when it names one, `http.response.status_code` and `machine.exchange.head_ms` once a response head arrives, `machine.exchange.elapsed_ms`, `wuhu.outcome` ok or errored, and on failure `error.type` (the operation error code, `unknown` for one this build does not define) with error status. Its context goes to the machine as the tracer's propagation headers (W3C `traceparent`); machines ignore it today. Exec exchanges run in the box link rather than a retained caller relay. An exchange outside any trace, such as a machine's presence poll, starts no span.

A session's loop opens no spans of its own. Each provider request it makes is a root `model.attempt`: `gen_ai.provider.name`, request and response model, `wuhu.effort`, `wuhu.model_group`, `wuhu.transport`, finish reason, GenAI token usage with cache read and creation, `wuhu.usage.reasoning_tokens`, `wuhu.ttft_ms`, `http.response.status_code`, `error.type`, `wuhu.inference.id`, and `wuhu.cache.expected_tokens` and `wuhu.cache.idle_ms` from the session's last reply in its generation. A script's completion is a `model.attempt` too.

`script.run` (`wuhu.script.kind` call, command or handler, `wuhu.script.source.sha256`, `wuhu.updates`, outcome released, failed or killed) is a root, a handler's under its firing (an in-process call; nothing crosses the worker line); a CLI script is its own root. A handler firing is a root `handler.firing`: `wuhu.subscription.id`, `wuhu.firing.id`, `wuhu.firing.kind` (observe, timer, stream), `wuhu.observer`, `wuhu.lag_ms` behind a timer's due time, `wuhu.wakes`, outcome. Every span under a root carries `wuhu.session.id` and `wuhu.group.id`. No message, argument, result, script source or error description is recorded; the provider's error text on a failed attempt (`exception.message` and the status description) is the one exception.

## Machine tool transport routing

MachineHub routes every file/search call and attachment through `MachineFileClient` over the cell's caller-owned `FileBulk` socket; `MachineFileTransfer` composes those same connections into a one-attempt copy pump. Execs use `MachineCell`, with `BoxLink` adapting the existing FetchTunnel exchange protocol and `ExecSocketLink` adapting the existing CLI channel frames to the cell's `ExecStream` socket. Each caller adapter mints its opening nonce from the injected UUID generator once per connection; the cell's durable admission binds that nonce rather than a local socket counter. A missing kind returns `unknownKind`; there is no transport fallback.

Roster and v2 status read the cell-owned `machine_presence` through current membership. `GET /v1/machine-v2/:id` exposes state, observedAt, reason and the registration's current group to authorized readers and the signed machine. Creation uses the explicitly requested group or the acting group under the existing registration policy.

The cell records a start intent before emitting it and never repeats an ambiguous start. A box redial describes and polls live operation UUIDs from committed offsets. Retry/backoff, lease silence, timeout stop and its 30-second unresolved answer are cell deadlines, not host timers. A poll answer commits its cursor and bounded tail before the next poll acknowledges that offset. Bulk output and stdin are worker-local windows addressed by pointers, never database rows or mail; unread buffered bytes are lost at worker roll, while committed cursors, tail and verdict survive. Streaming `consumed` frees the window and resumes polling; caller close stops immediately with no reconnect retention.

Stdout/stderr EOF is independent of process termination; output continues draining until terminal evidence arrives. A stdin `operationEnded` after a fast exit closes only input. Native status wins when known; typed failures become an exit diagnostic on stderr, and timeout without a verdict after the 30-second grace reports an unknown outcome. Output-budget cut stops the process after the admitted bytes. Process limits and tunnel admission remain bounded by the box's description and available lanes.

In-process caller sockets are structured under the hub's caller scope. Shutdown closes them and joins their transport work; there is no retained caller endpoint or exec relay job. File callers and copy pumps belong to their connection or active job effect and retain no host recovery task.

## Web content

`WebContent` injects the optional SPA, view-provider files and shell JavaScript into `handler`, `SpaceHost.open` and `serve`. The library embeds no web assets; an empty value serves API/content routes without the SPA or shell injection. `serve` applies `webAppDirectory` only to the SPA, retaining injected providers and scripts.

## Worker exec jobs

Tool execs do not call HTTP or construct an `ExecSession`: `ToolCallJob` mails `start` to the machine cell and waits for `finished`. It leaves with exactly one of `taken` (committed alongside the answer), `detach` (wait, yield or drain), or `abandon` (interrupt, stopping the process and dropping the waiter without a later session notice). External `stop`, including the cancel tool and CLI kill, changes only process intent and preserves the waiter/background recipient. A detached exec ends as one session notification with its bounded tail. Archive interrupts the active tool and kills remaining live tool-call execs; rolling the worker never stops a tool exec.

Scripts and CLI callers still reserve through `POST /v1/exec` and stream through the upgrading route. Reservation mints a fresh id; the old session/tool-call claim/spec replay and legacy exec tables are gone. Own list/detail retains `toolCallID`; terminal own kills remain `alreadyEnded`, and unknown/foreign execs remain `notFound`.

## Group creation and alias boundaries

`POST /v1/groups` takes `{alias, name?}` from a live non-guest human member and returns 201 `GroupDetail`; the creator becomes admin, the group starts open, and its `name` defaults to the alias. `PUT /v1/group/:id` takes any of `{alias, name, open, secrets}` from a group admin and returns the `GroupDetail`, which carries `name`. A name is trimmed, then 1–64 characters with no line break, control character, `<`, `>` or `&` (400 `invalidName`); a personal group takes none (403). Migration 015 named `shared` "Shared" and every other non-personal group after its alias, else its id. A session's `PUT /v1/group/:id` carries `name` alone (`setGroupName` in `run_script`), never from an exec token; its alias and access stay a person's. Sessions use `createGroup({alias, owner})` in `run_script`, transported through the same route with a mandatory human owner (account id, persona id or person alias). Session exec tokens are refused on POST, including CLI calls. A guest, removed account, machine or absent owner is 403 `memberRequired`; a malformed alias is 400 `invalidAlias`, and a reserved spelling is 409 `aliasTaken`. Human callers may not choose a different owner.

Every group boundary resolves aliases to permanent ids before authorization: the acting header, group-detail/access routes, machine registration/move, session creation, secrets, file addresses, imports and content hosts. Current and retired aliases return the same canonical group detail. Old content-host aliases redirect unconditionally with 307 and `Cache-Control: no-store` to the current alias before read admission, preserving path and query. The browser mints its host-only read cookie on that current host; alias names are not confidential. Id URLs remain usable. GET /v1/groups retains exactly its existing four keys (`id`, `member`, `readable`, `admin`); aliases appear in group detail; CLI group list remains one discovery request and prints ids. Shared retains its id. Personal groups have no independent alias, and a person's alias resolves to their personal group.

`GET /v1/machine/:id/status` resolves a machine id or current/retired alias and returns its `MachineStatus` to a caller who may use the owner group. CLI exec/name resolution and script machine handles use that boundary, then operate only on the canonical id. Names may contain underscores but cannot squat a syntactically valid machine id.

`POST /v1/groups` returns 201 `GroupDetail` for the newly allocated group; it passes through the normal bearer wall and stream credential binding. Only GET discovery is public. Legacy clients may submit machine names with hyphens; the server maps those to underscores before validation and allocation.

## Group observers

`POST /v1/group/:id/observers` (`ObserverInput` → 201 `ObserverOutput`), `GET /v1/group/:id/observers` (`ObserversOutput`) and `DELETE /v1/group/:id/observers/:name` (`ObserverOutput`) arm, list and cancel a group's observers. Arming and cancelling need write on the group, listing read; the dev person follows these ordinary roles. A missing group is 404 `notFound`; the store's refusals map by code: `invalidArgument` 400 (also exactly-one-trigger and handler path problems), `conflict` 409, `notFound` 404. Session exec tokens reach these routes through the session gate as their session.

A sessionless script is an observer's handler in one firing or a person's terminal script (`SessionlessScript`). Its token (`ExecTokens.scriptToken`, minted by `ExecTokens.runSessionless` for the run and revoked when it returns, or at once when it is cancelled) is the one credential it has: `RequestCredential.script`. The gate routes it through `sessionlessRouter`, an allowlist acting as the script's principal in its group (the observer, or the person in the group they act in): discovery and group reads, `/v1/f/*`, `/v1/observe`, the conversation reads, the space tools that sessions have over `/v1/tools/:name`, secrets, the machine verbs a session's scripts share (`addMachineRoutes`: the machines its group may use, their directories, and execs minted for its script, owned by `<name>@<group>` or, for a person's run, `@<account>` (whose legs are the person's), homed in the group and given no session credential), `POST /v1/session` (top-level in its group; an observer's admitted under its hourly cap), `POST /v1/session/:id/request`, `POST /v1/conversation/message` and `POST /v1/inferences` (attributed to an observer's group and firing, or to a person's personal group and run). Naming another group by `wuhu-group` is 403 `groupMismatch`; everything else, the observer routes and an exec outside a script included, is 403. An observer never writes a session home; a person's run writes what the person can write. The evaluator closes its caller streams when the run ends; MachineCell owns callerGone and orphan cleanup independently of the run's revoked token.

`POST /v1/scripts` from a signed-in person (a device key's wallet credential) runs the script on the server's worker as that person, acting in the group the request names: the same SSE stream as a session's run, with the stream closing cancelling it. Its inferences are attributed to the person's personal group, with the run's id `terminal-<uuid>` as their firing; it is attribution only, nothing is charged. The dev person runs as its ordinary account; non-person principals get 403.

`DELETE /v1/machine/:id` accepts a machine name or id and no body. Only a human admin of its owner group may delete; sessions and observers are refused even when group admins. The handler reads the machine and the group it authorized against, has each device owner unlink its own devices, then calls the machine's last step, `delete(in:)`: it refuses a machine that has left that group (`notFound`), marks its presence deleted, closes live attachments and the tunnel, ends live exec/file operations and removes their rows and buffers, deletes its v2 membership and its machine row, and mails the space cell to free every name and the account's cell to remove itself. The host then deletes the notes subtree in one revision. Success does not wait for the cleanup mail: the name may be freed and the account removed before or after the response. A worker that does not host the machine hears `Evicted`, which is either a refusal or an unknown outcome — the device detach steps before the call may already have committed, and wuwei allows a call to have landed before it answers `Evicted` — so a refused or failed delete is repeated, and a repeat that answers `notFound` means the first one landed. A crash between the step and the notes write leaves the notes folder behind, unowned and harmless. Remote supervisors retire when their agent receives definitive machineNotAuthorized on reconnect, otherwise their existing lease expires; deletion does not claim an acknowledged remote stop. A missing machine is 404 notFound and success is an empty JSON object. Revoke and rotate retain their existing semantics. There is no privileged run_script export: scripts act as sessions/observers, not human admins.

## Worker shutdown

SIGINT and SIGTERM stop serving in the order a replacement process on the same port needs: the listener closes, connections arriving from then on reach the other process; every request already running answers over its own connection, which is marked to close after that response, for at most one second on the process's clock (`ServeOptions.gracefulDrain`, set once in `SpaceServer.serve`) — past it a running handler is cancelled and its connection closed, though one whose await ignores cancellation still holds the drain, as before; WebSockets and streaming responses are closed, their clients reconnecting as after any restart. The host drains after that: cancelling `SessionRuntime.run()` quiesces session execution without releasing leases, `SpaceHost.shutdown()` awaits that background shutdown, closes host services and finishes their writes, then `Space.close()` releases the quiesced worker's leases as its last database write before closing the database.

A route whose wuwei call is refused with `Evicted` — the space is held by another serving process, or this one is draining — answers 503 `unavailable` with `Retry-After: 1` from one wrapper every route passes through, never a bare 500. Reads take no lease and are untouched. That wrapper sits around both host planes — the API and a group host's page API under `/_/space/*` — and stays on the in-process API entry the session tools dial. A tool boundary may only throw its own `ToolRunError`, so an eviction crosses it as `ToolRunError.evicted` (never inferred from `.internal`), and the file routes, the tool routes and the sessionless tool route rethrow it to the wrapper; the machine v2 routes rethrow a refused revoke too, instead of answering their own 503 without a retry.

A start that finds the space served by another process still binds. Its provisioning reads first, because reads take no lease, and writes the shared Everything sidebar only when it is missing; a provisioning write or `--dev-import` refused with `Evicted` is skipped, not done — a sidebar deleted while the other process serves comes back on the next start that wins the lease, and a dev import refused during an overlap is not applied — and it does not fail the start. `IdentityController.load` reads the identity cell first and writes only when it is empty; the dev person too, except that in dev mode its `setAdmin` can still be refused when the owner was demoted during an overlap. The deployment record is mailed to `SpaceCell`, so it stays durable and lands when the serving process releases its lease rather than being dropped. `worker.create` and `worker.send` write store rows, not cell leases, so a second start registers its jobs and mail as usual.


## Machine file caller lifetime

Every file caller uses one in-process `FileBulk` socket on the machine cell, whose opening is the start and whose final frame is the result. SpaceTools and the routes keep their existing authorization checks before opening; optional caller display attribution is unchanged. The socket is a local wuwei endpoint: another worker cannot attach, and no worker-to-worker forwarding or host registry exists. BoxLink adapts the existing bounded tunnel polls, including byte and record channels, into the same worker buffer facility exec uses; a transport payload is never an unbounded whole body.

`MachineFileClient` copies each payload before explicitly sending its next wanted offset. Worker-buffer admission acknowledges the box, bounded by the per-channel window; the separate consumer offset releases buffered data and gates completion, so polling can run ahead without retaining anything across a worker roll. After typed range loss a read discards its materialised prefix and its caller opens a new UUID at the original requested file offset and length. It does not stat, generate an ifMatch pin or use the diagnostic lost offset as a resume cursor; any explicitly supplied start inputs pass through unchanged. A list discards partial records and opens a fresh list, then sorts its complete bounded result. One adapter helper gives stat, read, list and search exactly one restart with the unchanged request, then propagates a second loss as typed `rangeLost`; a tool job effect re-run after a worker roll is a new operation with a fresh budget. All existing public caps remain: 8 MiB collected VFS reads/list records, the script-write bound, 64 MiB byte PUT and copy-to-space limits; no script streaming API or binding change is introduced.

A file socket sends `started` at box dispatch, not at socket attachment. If it closes before that marker the client reports `machineUnavailable` with `started: false` for reads and mutations alike; after it, missing read ranges and unknown mutation outcomes retain their typed behavior. The collector and socket belong to the active connection or ToolCallJob effect, not a host task. Closing or cancelling the effect closes its peer and discards cache. Read/find/grep effects redo from the top after a worker roll and commit only the replacement's complete answer. A dispatched mutation whose socket ends before its result yields typed `outcomeUnknown`, with no automatic redo. A silent dead agent is answered when the remaining advertised presence lease expires (default 60 s since its last answer), or sooner if it reconnects and disowns the operation; session tools use the in-process connection, not the CLI transport deadline. Mutating tool failures keep code `unavailable` and prefix `outcomeUnknown`, instructing the model to read the path before retrying. The additive migration discards legacy in-flight file records; no old operation is carried to the new path.

Known buffer-retention gap: a completed exchange whose answer is dropped by a box-socket replacement can leave at most 64 KiB retained per occurrence, until a later operation-window discard or process exit; a late answer actually delivered for a deleted operation discards its window.

Writes wait for accepted-start input readiness, stream bounded byte pointers and a commit record, and use the existing box staged-write protocol and version/atomic-rename rules. Only the final copy commit may complete from a successful terminal verdict before its input receipt; data and data-EOF deliveries still require receipts, and failed verdicts remain failures. Copy keeps its existing source stat and generated read ifMatch pin, incrementally hashes the stream, verifies byte count, and retains at most its bounded channel windows (or the unchanged 64 MiB caller landing). All tool/script/CLI copies share CopyTool: overwrite false reports an unknown outcome on range loss; overwrite true permits one whole-attempt range-loss restart from byte zero. A second loss propagates, and a job re-run after roll is a new effect with a fresh restart budget. Machine-to-space copy performs exactly one final space write.

Machine-to-machine copy waits for target READY before opening its pinned read, then overlaps target acceptance with at most one source piece (the box's advertised file piece, at most 4 MiB) of demand-gated read-ahead. The source connection runs in a joined child task; the parent owns the sequential sink, incremental hash and count. Existing cell cache windows do not change. Source FINISHED and every target data acceptance precede EOF and COMMIT. The child rethrows a failed source call after notifying the chunk stream, so a cancelled parent iterator cannot mistake silent stream termination for successful source completion; an error from the parent sink still wins. Source failure is observed when any sink acceptance already in flight returns; until then both connections remain open, and caller cancellation ends a stuck sink wait. Once observed, source failure closes both connections without committing, as do sink failure and cancellation; whole-attempt retry policy is unchanged. Whole-frame input acceptance reclaims its acknowledged buffers synchronously before the caller allocates its next frame, independent of post-commit task scheduling.

`wuhu-tool-call` identifies calls for deterministic message/request/report identities, not tool-answer replay. `GET /v1/receipt` is removed; file/tool HTTP writes and session creation are new operations when explicitly requested again. Kernel mutation jobs never replay an effect after a lost result.

## Person-owned avatars and sidebar settings

`PUT /v1/user/me/avatar` takes raw PNG bytes (PNG signature, at most 4 MiB), and `DELETE /v1/user/me/avatar` is idempotent; both return 204. The profile stores only the bucket hash; bytes past the bucket's inline threshold go to the configured object store. Delete clears the hash without deleting bucket bytes. `GET /v1/user/:person/avatar` returns `image/png`, a content-hash ETag and `Cache-Control: private, no-cache`, answers `If-None-Match` with 304, and returns 404 `notFound` when absent. The exact GET/HEAD route also exists on the shared content origin, admitted only by its existing live read cookie and membership gate, never anonymous `--public-read`; no cookie is accepted at the API origin.

`GET /v1/user/me/settings` returns `{hidden:[{group,path}]}` sorted and unique. `PUT /v1/user/me/settings/sidebar` takes `{group,path,hidden}` and returns the complete snapshot from the same person-cell call that applies the toggle. These account-owned settings are not files or revisions. Devices refresh initially, on foreground and after their own toggles; no new stream is opened.

## Development identity

`SpaceHost` awaits `Space.ensureDevPerson()` before exposing a dev handler. Handler factories receive the resolved account/persona, not a dev boolean. A missing bearer on a dev handler resolves to that ordinary account; a verified bearer always selects its own account and an invalid bearer is never replaced by the dev person. Persona claims must belong to the resolved account. Management, group creation, profile, settings and avatar routes use ordinary account authority; key-bound self-revocation, device enrollment and push subscriptions still require an actual signed key. Dev content admission returns that account and read-cookie minting follows the normal account path. Public-read content instead uses a read-only public reader, never the dev person.
