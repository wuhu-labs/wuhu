# Real server-restart recording

`machine-v2-server-restart.json` is the sanitized native machine-handler recording from scratch run `final-24c-3`, operation `121C8441-F0F0-4D11-80C7-B5D865DE55F1`, on 2026-10-14. The production source, static executable, clean source snapshot, separately recorded canary driver and each selected native recording file are identified by hashes in `provenance`.

The real server was SIGKILLed after dispatch permission was durably consumed and its script consumed stdout `before` through offset 6. The same executable reopened the same SQLite database and key, stopped the actual child with `serverRestart`, resumed stdout at 6, drained stderr and acknowledged the native terminal token. The post-SIGKILL boot began at `2026-10-14T13:48:45.824133+00:00`. Recovery selection uses final SQLite request IDs and start times, excludes every precrash request ID (including outstanding polls that completed after the crash), and preserves native handler arrival-index order through the completed terminal acknowledgement. There is exactly one recorded start POST; it is evidence for reconstructing the already-consumed claim, not a request replayed during recovery.

The fixture contains only actual sanitized request/response envelopes and safe observed prefix/cursor/process facts. It omits credentials, private keys, encrypted database metadata and unrelated exchanges. Response bodies, status, terminal tokens and agent instances are unmodified. Offline request matching normalizes only the transport origin, JSON key order, regenerated correlation/request headers, absent versus zero `holdMs`, and absent versus default 65536-byte `limit`; the observed 20000-ms initial poll remains distinct. Other policies must match or fail.

The replay runs production `OperationClient`, `MachineV2Coordinator`, the encrypted SQLite operation store and durable key loader with no process or network dispatch. It persists the recorded prefix before reopening the database, then compares final cursors and verdict to the real terminal response. The broader live canary failed later at uninstall (`invalidJSON`); this fixture proves only the completed real server-restart segment, not an overall passing canary.
