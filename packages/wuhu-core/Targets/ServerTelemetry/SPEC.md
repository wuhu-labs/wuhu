# ServerTelemetry

Content-free server tracing, exported as OTLP/HTTP JSON using Fetch. `ServerSpan` captures a task-local trace parent and emitter at creation; finishing emits only a typed span name, bounded allowlisted attributes, ids and timestamps. With no installed or task-local emitter, spans have no context and finishing is a no-op. Trace context is explicitly serialized across worker calls and queue boundaries rather than inferred from a session-global current span.

`SpanBuffer` accepts synchronously without awaiting network I/O. Each process holds at most 1024 finished spans (configurable for tests), and a sender removes at most 64 each second. The parent owns the HTTP sender; the worker only relays a bounded batch over its admitted control protocol. On full capacity new spans are dropped and counted. An export failure drops both the in-flight batch and queued spans, counts them, and emits one static warning per failure streak. A subsequent successful batch resets the warning streak. There are no retries or disk spooling. The owner first stops span-producing work, cancels the periodic sender, then invokes an awaited shutdown drain even if its task is cancelled. Shutdown closes admission, serializes with any in-flight batch, drains batches within a two-second total deadline and counts any remainder as dropped. An interrupted periodic batch is retained for that final drain. The server supplies a dedicated HTTP client with a two-second deadline and no redirects.

`OTLPExporter` accepts an HTTP(S) collector base URL or an explicit `/v1/traces` URL; credentials, query and fragment are refused. Each resource has `service.name=wuhu-server`. Span payloads never contain messages, prompts, arguments, commands, paths, outputs or error descriptions. The only strings admitted by instrumentation are names, identifiers, enum outcomes/error codes and numeric sizes/counts.
