# SpaceCore

Each group has its own revision journal: `revisions(grp, rev, mtime)` and `revision_actors(grp, rev, actor, via)` are keyed `(grp, rev)`. A mutation mints `MAX(rev) + 1` in the written group, never the acting group; the actor is only attribution. `currentRevision(in:)`, listings, history, observation cursors, attributions and historical reads resolve revisions in their group. A ceiling is valid exactly when `1 ≤ rev ≤ group maximum`, even when that group did not mint the number; a never-written group has maximum 0. A cross-group file/table move adopts at the destination, then deletes the source only if the whole captured subtree still has the same path/revision pairs; a crash or a refused source delete leaves a duplicate, never a loss. Each written group mints its own revision. Machine notes instead leave their source and enqueue their destination adoption in one durable source step; adoption merges directory pairs, replaces corresponding non-directory nodes and leaves unrelated destination children in place. Table-row closure uses the source revision and destination history the destination revision. Firing effects identify revisions as `"grp/rev"`. Migration 046 projects old journals and attributions by distinct filesystem-version `(grp, rev)` pairs, retaining their numbers/timestamps and all filesystem/table histories, then inserts each existing group's old-global-maximum floor. New groups have no seed. `/v1/context` exposes `"revs": {"<group>": n, …}` whose keys are exactly the groups the caller may read files in, including settings; the dev person follows ordinary account access and public readers follow shared’s content-read reach; script modules freeze each group at its entry in that map, collected through each group's FilesCell read handle.


## Database lifetime

`Space.quiesceWorker()` cancels and awaits the worker without releasing its leases; its scheduler continues renewing them until release, and the quiesced worker stays attached to the space. `stopWorker()` also releases the leases, ends its scheduler and discards only the worker it quiesced, so the next `worker` has a fresh id and can claim them. Migration 053 adds the addressable lease's draining flag: the worker marks every lease it holds draining when quiescence begins, and a successful claim clears it. A call through another worker waits while that holder is draining, then claims a released or expired lease here; a serving holder still refuses with `Evicted`, including one that wins a held call's claim race. The held call has no timeout; caller cancellation throws `CancellationError`, and caller worker quiescence throws `Evicted`.

`Space.inMemory()` opens an isolated SQLite memdb database with no scratch directory or database file. The memory opener uses SQLite’s in-memory rollback journal, while file-backed spaces retain WAL. Memory readers hold read transactions: a concurrent writer commit waits for them, up to the five-second busy timeout, then throws a SQLite busy error. Cancellation interrupts long queries and releases their read transaction. Sandbox readers attach the same memory database; files, tables, revisions, identities and queries follow the same implementation as `Space.open`. An unavailable memory VFS throws a SQLite database error, never opens a disk substitute. Memory databases copy a schema template without an identity, then run ordinary preparation. Both opening paths run the same ordered migrations and seed their own identity; existing file-backed data is retained. Migration 001 establishes the baseline for fresh and existing databases. `MigrationRunner` runs them on the writer's own connection, each registered identifier that is missing from `grdb_migrations(identifier TEXT NOT NULL PRIMARY KEY)` in registration order, in one `BEGIN IMMEDIATE` transaction with its identifier inserted in it — the ledger GRDB kept, read and written in the same shape, so a database at any applied set opens and gets exactly its missing migrations; foreign keys stay as the connection was opened with them, so the writer enforces them throughout a migration, and a ledger identifier this binary does not know is `unknownMigrations`. Applied migrations are never run again. The space's log gets a notice before each migration an open applies (`migration 008: applying`) and one once its transaction commits (`migration 008: applied in 412 ms`, measured on the space's injected date); a failing body rolls back and leaves the ledger untouched, and logs only the first. A file-backed space's writer gets a 64 MiB page cache and every read connection a 16 MiB one on its attached database, each with a 2 GiB mmap (`PageCache` in SpaceSQL); the runtime-owned wuwei readers get the same 16 MiB cache on the space database and are named `wuwei.reader.<n>` to the log; there are at most four idle cached connections and no limit or capacity wait for active read spans; a memory space's writer keeps SQLite's defaults. The writer of both openers sets `PRAGMA secure_delete = OFF` on every connection it opens, so freed pages are not zeroed whatever the linked SQLite's compile-time default; read connections never free pages. A file-backed space's writer, its wuwei reader and every sandbox read connection report the statement SQLite's profile callback saw run for 100 ms or more as one warning through the space's log — the connection (`writer`, `wuwei.reader.<n>`, `read.<n>`), the milliseconds, and the statement as prepared cut at 500 characters (`SlowStatement` in SpaceSQL).

Migration 005 removes the obsolete session blob ownership table without changing stored image bytes or transcript references. Worker media reads resolve both blob hashes and attachment paths independently of the session’s current group access.

The shared wuwei writer holds each writing job stretch in one SQLite transaction through `SQLiteWriter`, using the same mutex and semaphore-held transaction as FileDatabase, without a host queue or GRDB adapter. Commit callbacks only schedule worker pokes and never synchronously enter a lane. Code on a held stretch must not take `SpaceRuntime.hosting` (the worker-making/lifecycle lock), whose holders can wait for the writer; unlike wuwei’s own lifecycle entry points, this host-side lock order is a caller invariant, not dynamically checked.

## Scope context

The worker computes scope context after a tool call; the session cell holds its notice lines until that reply's last answer and writes its delivery metadata to `session_seen`. Historical lines are not folded to rebuild deduplication state.

## Direct messages

`SessionStore.post` refuses every `.dmUser` post by a session, including a readable person–person DM addressed by id, and refuses either side posting into a person–session DM with `SessionStoreError.humanAgentDirectMessage`, whether opened with `.dm(with:)` or addressed by an existing conversation id, for either poster. The refusal text is exactly: "There is no DM between human and agent. To notify a human, post in your conversation box, optionally specifying the reply target's message ID: it notifies whoever wrote there last and anyone who wrote there in the past 24 hours." The transaction writes no message, conversation, notification or queue input on refusal. Existing person–session DMs remain readable; there is no deletion or migration. People’s person–person DM posts, session–session DMs, boxes, group conversations, requests and reports are unchanged. Only an agent's box creates ordinary-message reply duty, never a person–session DM.

## Inferences

`inferences` is an induced, read-only SQL table available through query, observation and scripts with the same group visibility as `sessions`: the unqualified name reads the acting group, a group-qualified name reads a readable group, and the wildcard-qualified name includes `grp`. Opening an existing database creates the table and indexes idempotently; there is no backfill.

Each call has `id`, `session`, `at` (UTC start), `provider`, configured `model`, optional API-reported `served_model`, `effort`, `input`, `cache_read`, `cache_write`, `output`, `reasoning`, `outcome`, `error`, `duration_ms` and `ttft_ms`. `input` is uncached input; total input is `input + cache_read + cache_write`. `output` includes billed reasoning; `reasoning` is its reported subset or null when unavailable. Usage is null when a failed call reports none. Outcomes are `ok`, `networkError`, `httpError`, `timeout` and `cancelled`.

`Space.recordInference` is the one door and writes nothing itself: it resolves the payer's group (a session's through its record, an observer's or a terminal script's named by the payer) and mails the row to that group's cell, whose `inferred` step inserts it `ON CONFLICT (id) DO NOTHING` — the log is the payer group's, owned through `grp`, and no host write reaches it. A session that does not exist throws what the record read throws. Observations wake on insertion. No lifecycle operation deletes inference rows: archive, compaction and Start over leave them intact.

## Archive support

`SessionStore.archiveSubtree(root)` returns records in descendant-before-parent order using the parent chain, not `created_by`. `closeRequestsForArchive(id)` posts one replay-safe final-kind message for every still-open request row, including undrained input, fails the row in the same write, and cancels its deadline subscription on the parent. The wording explicitly says the session was archived before reporting; it does not claim the requested work was completed. `trimSlotsForArchive(id)` deletes the session's retiring slots and clears handler firings. The record writes of the session verbs (`retitle`, `retag`, `markInterrupted`, `markResumed`, `archive(grace:)`, `unarchive`, `restart`) are `SessionCell`, the session cell's; the store has no async form of them. Creating a child below an archived parent fails with `parentUnavailableForCreation`; a separately created top-level agent remains allowed.

## Subscription progress

`SessionCell.observed(session, subscription, token:, _:)` is the session cell's step for what main saw of a plain slot (`Observed`): a `change` puts its notice on the slot's topic (replacing the one the model has not seen, due no sooner than the slot's throttle past the last it saw; the children watch has none) and moves the slot's marker, delivery sequence and last-fired time; `quiet` moves the marker alone; `failed` puts the slot's last notice and deletes its row. It answers `ignored` and writes nothing for a slot that is gone, one armed again since (the token is the arming's observation incarnation) and a marker the slot already has; a session that can no longer act (archived) is told nothing and its row is deleted (`ended`, as after `failed`).

The session-observation SPI exposes both a fresh registration snapshot and its change stream, including observation callback identities. The firing registry reloads a fresh snapshot on task completion rather than relying on a due-time key change to wake it. Stored subscription schema and existing off-minute due rows are unchanged.

`requests` (migration 008; 027 dropped `kind` and `key`; 028 added `conversation_id`, backfilled from the request message, and deleted the rows whose request never posted) holds one row per request, id = the request message id, owned by its conversation's cell (`ConversationCell.owned`), and is the only store of a request's state: the request's conversation (the task's DM with its parent, else its own box) writes it in its cell, in the step that writes the message: `openRequest(terms:)` checks who asks (`notTheParent`, `requestAlreadyOpen`) and inserts it with the request message, `report` closes it with the final, and archive fails it; creating a session with `expects_reply` writes no row before its request message, and a task that errors leaves it open. A schema'd final whose content is not JSON matching the schema throws `reportRefused(id, violations:, left:)` and posts nothing; the `RequestTerms.refusalLimit`-th refusal instead posts a final-kind failure and fails the row. Migration 008 backfills a row for every request message (`done` with a final-kind message, archive closes included; `overdue` past its deadline; else `open`), throws if any request message lacks exactly one row, logs the counts, and drops `messages.deadline_at`.

`openRequests(task)` lists that session's open rows: what it owes, and the only source the kernel's park, nag and wake decisions read. A request message is delivered as a request only to its task; any other session it reaches (a mention) gets a plain message without its request id.

`openRequest(stallSeconds:)` stores the seconds on the row and, when the requester is a live session, puts a `requestStall` notification on the requester's queue under topic `quiet:<request>`, due that many seconds after the request message. A progress report puts it again, due that many seconds after the report; the final and archive clear the topic. The notice only says the task has reported nothing for that long; it reads no task state.

## Removed executor

A stored executor other than `kernel` decodes as `SessionExecutor.retired(kind:)`. Creation, resume, restart and unarchive throw `ExecutorUnavailableError` with description "executor no longer supported"; hydration returns record and queue metadata without reading its old transcript; boot eligibility selects only `kernel` sessions. Queue input, identity, box, home, tags and children remain stored. Only Start over onto a supported executor clears the record; restart away opens a kernel generation and retains readable queued input and subscriptions. The removed executors' stores are dropped by migration 002.

`SessionCreation.markErrored` updates only the session's durable error/run state and returns no value. It reads neither legacy typed payloads nor transcript lines and emits no person notification; unreadable dates or executor/record payloads cannot roll back the update.

The boot scan is one query: live kernel sessions with work or an open `requests` row.

## Image fitting

`ImageFitting.prepare` makes the copy a transcript keeps: a PNG or JPEG is always decoded, fitted to the limits (`ImageLimits.intake` by default) and re-encoded, so the result carries the source's pixels and none of its metadata, is the same bytes for the same source, and passes `fit` unchanged. One no codec here decodes is refused. Any other format is handed to `fit`. `ImageFitting.fit` passes images whose measured dimensions and byte count already fit through byte-identically. Oversized images are decoded, resized to the long-edge and patch limits, and encoded to the byte limit. If fitting fails, the explicit `[image not sent: … this server could not re-encode it]` note is returned; no oversized fallback image is sent. Unmeasurable bytes within the byte budget pass through for the provider to judge. `ImageFitting.png(rgba:size:)` encodes unpremultiplied RGBA8 rows losslessly with the same codecs (ImageIO on Apple, CImageCodec on Linux), nil on a platform with neither.

Apple platforms keep ImageIO, including its thumbnail EXIF orientation transform and PNG/JPEG encoding behavior. Linux decodes PNG and 8-bit JPEG with Bazel-pinned libpng and libjpeg-turbo; palette, grayscale, 16-bit and alpha PNG inputs normalize to RGBA8. JPEG EXIF and PNG eXIf orientations 1–8 are applied using bounds-checked TIFF views without copying chunk payloads. Bilinear interpolation weights colors by alpha. Both encode a PNG source as PNG when that fits the byte limit and as JPEG when it does not, and any other source as JPEG. Linux composites transparency on white for JPEG and tries qualities 85, 70, 55, 40 and 25; ImageIO encodes at 85 only. If bytes still do not fit, both retry at three-quarters of the long edge down to one pixel. Oversized other formats remain explicitly refused.

Image fitting refuses absurd header dimensions and uses checked arithmetic before invoking the model sizing calculation; `ImageLimits.fitted` computes its area ratio without overflowing integer multiplication. Linux decoding and C encoding reject images above 40 million pixels before allocating pixel buffers. Before libpng sees a PNG, a bounded chunk scan validates lengths and CRCs, requires a complete terminal IEND, and keeps only critical pixel chunks, transparency and fixed-size color/gamma chunks. Compressed text, ICC and other ancillary payloads never reach libpng and cannot expand into metadata allocations; eXIf orientation is applied separately in Swift. TurboJPEG confines libjpeg error longjmps to its C implementation, stops on truncated-input warnings, caps progressive scans at 100, and caps internal memory at 128 MiB. Bad input returns a fitting refusal rather than aborting the process.

## Guarded schema and historical inspection

`alterTable` accepts an optional VersionToken and allowDropColumns (the checked service requires the token and defaults the drop acknowledgement to false). Table liveness/kind is checked before the token, so missing, moved, deleted and non-table paths report notATable rather than a stale-token conflict. The liveness check, token check, omitted-column check, schema journal and DDL occur in one transaction; failure rolls everything back. Type changes remain refused. `tableSchema` reads the live header/token or a historical header/token, checking revision existence and node liveness in the same read transaction. Missing paths are notFound; non-table nodes are notATable. Historical tokens identify the historical node version, not an overwrite receipt. The checked SpaceToolContext boundary resolves caller paths, validates headers, and enforces group, session-home and protected-layer policy for HTTP and scripts; trusted core calls do not acquire a wallet identity. Template name allocation and non-live creation are one FilesCell step; a live instance uses that allocated name in a create-only document write.

## Guarded file creation and historical restoration

`writeFile(path, data, in, acting, ifMatch, createOnly)` resolves machine-note aliases and delegates to its FilesCell step. With createOnly, any current node conflicts before deduplication or replacement. A supplied version token is compared in that same transaction. The existing VFS write entry point keeps its optional-token semantics. `checkout` accepts optional ifMatch/createOnly checks against the current head inside the restoration transaction, before comparing content, minting a revision or altering file/table materialization; a file's historical bytes are read from the bucket before that transaction, a version under the ceiling being one no writer changes. When both the historical node and live head are files with the same blob hash, checkout returns the live revision and current token without minting a revision, journaling history or emitting a mutation. Table checkouts always mint a revision, even when their restored rows are identical; restoring nonexistence keeps its existing deletion behavior. `history` supports an exclusive after revision and optional limit; the ordered join is a StructuredQueries selection and its limit is applied by the database.

`Space.fs(..., listingLimit:, listingByteLimit:)` optionally bounds listing hydration in the live-head, historical-version and machine-alias queries before Entry arrays are allocated. Non-nil limits must be positive. Cursor hydration stops when the running escaped-name size plus a conservative 256-byte metadata allowance per entry crosses listingByteLimit, throwing listingResultTooLarge. No full row array is hydrated first; historical listings convert each cursor node directly into an entry. The default remains unlimited for existing callers; script services select their cap plus lookahead and fixed hidden-root overhead.

Start over is an empty-summary compaction without a retained tail or pre-reads, using the same generation-head writer as compaction. It preserves armed observations (including callback identity and firing progress), and one-shot and cron timers; the new head lists the slots its caller passes (the cell's `session_armed`), or what the stores hold for a session whose cell has no list yet. The cell retains its nags, including owed replies and park reminders; the store writes no settle snapshot or historical checkpoint. Error, hold, run/heartbeat/progress and retry state are cleared; the executor/model may change. Readable queued rows are neither marked delivered nor removed: a nonempty readable queue sets `has_work` (the cell that restarts advances into it), while subscriptions and the restart note alone remain inert. Session identity, conversations, prior generations, home files, children and open requests in either direction remain unchanged.

Start over validates each pending queue payload and its stored dates. Unreadable inputs are dropped from delivery and counted explicitly in the restart note; their original rows remain intact. If any input is unreadable, all readable pending rows move in FIFO order to IDs above the old queue head with their `input_id` and payload unchanged, and the tail/checkpoint advances past the unreadable originals in the same transaction. Re-enqueuing a moved input deduplicates against its unchanged identity. An all-unreadable queue remains inert and no longer prevents hydration or archive.

## The bucket

`bucket_objects(hash PRIMARY KEY, size, line_count, content, object_key, stored_at, CHECK ((content IS NULL) <> (object_key IS NULL)))` holds every stored byte: content-addressed and grow-only, so a hash names the same bytes for the life of the space and nothing deletes a row — a put whose step was then refused leaves a name nothing refers to. Bytes up to 256 KiB sit inline in `content`, with `line_count` left unrecorded and counted from the bytes when asked; past that they sit in the space's object store under `blobs/<hash[0..2]>/<hash[2..4]>/<hash>`, with their size and line count in the row. The row is written by the step that first names the hash, on the step's own connection (`Bucket.put`, `INSERT OR IGNORE`); a caller with no step to ride in, bytes whose step is reached by mail or a hash a caller needs named first, takes the door `Space.bucket.put(bytes)`, one step of the space's cell. A message never carries bytes. Reads go through a read handle, external bytes fetched host-side; a file read is head then bytes, two reads that need not be one snapshot because the bucket only grows. Migration 045 moved `blobs` and `blob_objects` into it.

## Box notifications

A box post appends a `conversationMessage` notification row only for person members, other than its sender, who are the box's latest writer or wrote there within the 24 hours before the post's routing time (inclusive). A write is a post with no sender session and no observer firing; a group observer's post is none, so an observer is never a writer. The latest writer is chosen by message position, never by timestamp: a person's own post makes them the latest writer, so it notifies only others who wrote within the window; a session's or observer's post notifies the latest earlier person writer as well. A member who never wrote there gets none. Membership is unchanged: a quiet member still reads the box. Only a box post reads writes: it reads on the box's own index back to the window's start and, only when the window holds no person post, back to the latest one. Channel and DM notifications and session routing are unchanged.

## Human-only channels

`users` conversations are channels. They have people-only members and an optional title stored in `conversation_titles`; an absent row or NULL title preserves the members' names fallback. The additive side table opens on existing spaces without ALTER or backfill. Existing users rows are channels; historical session member rows confer no human access and no new session memberships are inserted.

`createConversation(members:title:in:)`, `addChannelMembers(_:people:as:)`, `removeChannelMembers(_:people:as:)` and `renameChannel(_:title:as:)` manage channels. Validation and each mutation are atomic. Any membership operation naming a session throws `ChannelError.sessionMember`; person aliases (including historical aliases and case variants) resolve to canonical directory ids before create/add, and unknown people throw `ChannelError.unknownPerson`. Remove deletes both the supplied spelling and its person-alias target, including legacy raw rows, with no directory validation; removing a nonmember stays a no-op. Person–person DMs resolve the recipient through the person directory before choosing their deterministic id and storing members, so aliases share one conversation and unknown people throw `SessionStoreError.unknownPerson`. The authenticated sender id is preserved. A blank non-null title is refused. Person members manage, read and post. Every session whose group reads the channel's home group reads and posts without becoming a member, and manages when its role there is write or admin. Each of the four is one call to the conversation's cell. Other people cannot read or post, even in a group that reads the home group. An unread channel is indistinguishable from a missing conversation. The public content reader neither creates, reads nor manages channels; the dev person has the same membership rules as every person. `conversations(reader:group:)` retains most-recent-active ordering by last message position descending.

A conversation's rows (`conversations`, `conversation_members`, `conversation_titles`, `messages`) are written only in steps of its cell, and an account's inbox (`notifications`, `watermarks`) only in steps of its person cell. The space's writer enforces it once its worker exists: `ConversationCell.owned` and `PersonCell.owned` name each table's owner column (`id`, `conversation_id`, `owner_account`), and a statement on the writer that writes such a row outside its owner's step aborts with "a row of <table> belongs to another addressable". Migrations run before the worker and are not guarded. An agent's box needs no row to be read: from the session's creation `conversation(_:)`, its pages and its live tail answer for an empty box homed in the session's group with the session as its one member, and the first post writes the row. Until then the box is absent from `conversations(reader:group:)` and from SQL over `conversations`. A task has no box at any time.

Channel plain messages notify person members but enqueue no session unless addressed. Mention, reply-target and the attention window retain their existing behavior: after an agent answers, subsequent messages reach it only while both its message-count and time windows are open; the window closes at whichever bound passes first. Tasks do not join the attention window; a person's post never wakes a task. SQL conversation, member, message and channel-message notification views enforce the same channel readership, including qualified group and wildcard views. `readsFile(_:in:as:)` applies channel readership before group readability for file/attachment access, attachment-copy sources and parent directory listings. Removing a person from a channel also prevents copying its attachments into another conversation. `observeConversation(_:after:as:)` revalidates its principal in each snapshot, wakes on membership and group-read changes as well as messages, and terminates on loss of readership. Everything sidebars observe channels and the person's notification/read-marker unread state.

An attachment is a row of its conversation, not a file of the group's journal: `attachments` (conversation, path, blob hash, size, created) is owned by the conversation's cell. `SessionStore.post` stages each upload's bytes by hash and hands them to the call; the post's step records them in the bucket and places the upload at `/_/conversations/<id>/attachments/YYYY/MM/DD/HHmmssZ/<name>` (the next free `-<n>` on a clash), writing the row with the message, so a refused post leaves only a name nothing refers to. `Space.fs` answers everything under `/_/conversations/` in a group's tree from the rows of the conversations homed there (`AttachmentFolders`): files and implicit folders, with no revision, history or mutation event, the same at any `rev`; the journal refuses every mutation there, as it always did (reserved paths). Migration 029 copied the journal's attachment files into rows and 031 deleted the journal's own: heads, versions and induced docs under `/_/conversations`, leaving their revisions and blobs.

## Subscription handlers

A session with a live child has a `children` slot (kind `.children`), armed in the write that creates or unarchives a child and deleted in the write that archives its last: an observation of its live children that errored, put on its queue under the topic `children` when a child joins them and never when one leaves. Neither `subscriptions`, `armedSubscriptions(_:)`, `<session-state>` nor cancel shows it.

`SubscriptionSlot.handler` is an optional space module path. The existing subscription payload stores its distinct arming incarnation, last error, failure-streak flag, and current firing (its attempt token, running or retiring); legacy payloads decode with these fields absent. `ArmedSubscription.armedAt` is the original registration time. Re-arming an existing subscription ID is a crash retry and returns its persisted truth unchanged. Cancelling then re-arming mints a new handler incarnation and observation callback identity.

`ObserverCell` writes a handler slot's row, in the cell's step; nothing else writes a session's handler slot. `arm` inserts the slot its session armed (one that stands is left as it is), `pend` replaces the input that waits, `begin` names the firing on the slot, records last-fired and logs it running, `finish` ends it: success clears the last error and takes the input, reschedules a cron or retires a one-shot; a failure records the error and notifies only on the first of a streak; a firing whose slot went meanwhile marks its wakes as the slot's last; one whose owner can no longer act is logged cancelled and tells no one. `end` is a source that refused to go on (a stream, a query that can no longer run): a session's slot ends with its last notice, a group's pauses with the reason. `retire` deletes the row. Script filesystem/table/message effects remain immediate and at-least-once, not part of the step.

Archive preserves registrations for unarchive within grace. The registration observation tracks owner lifecycle (`orphaned`). Main retires nothing: a firing that comes due, or rows that change, while the owner cannot act end the slot in its owner's step without running the handler or telling anyone; slots that neither fire nor change remain after unarchive.

Silent handler retirement does not enqueue a notification or wake the owner. `SessionCell.armedSlots` returns what the stores hold of a session's own slots (its `subscription_slots` rows but the children watch, the plain timers on its queue, its streams) and which of them run a handler: what a session from before `session_armed` lists at its first step.

Handler-backed timers and observations are not guaranteed model wakes and do not suppress an open request's park backstop. `armedSlots` returns handler IDs alongside the registration projection; the cell retains both in its own armed-slot state. Plain timers retain their prior wake guarantee.

## Group observers

`subscription_slots` keys every slot by owner kind and owner. Session arming and named group observer arm/cancel run in their LoopCore cells. A group observer is keyed by group + name; its generated subscription id remains the listed and callback id. Names are slugs (lowercase letters, digits and hyphens, at most 64), `status` is `armed` or `paused`, and `sessions_per_hour` defaults to 10. An armed name refuses with conflict, a paused name is replaced, and a handler and live group are required. The observer cell counts committed admissions during the last hour; admission precedes allocation and consumes a unit even if creation later crashes. At cap the cell pauses with its refusal as last error; a paused firing cannot create. Cancelling deletes its slot but leaves sessions it made. A query that becomes invalid pauses the group observer until rearmed. Aggregate and group subscription lists are SpaceCell reads.

An observer acts as `Actor.observer(Observer)`: its group's role, nothing of its own. What it creates records it: `created_by`, `requester` and `sender` are `<name>@<group>`, and `sessions.firing`, `requests.firing`, `messages.firing` and `inferences.firing` carry the firing id (`inferences.session` is null for an observer's inference). A person's terminal script's inference has the person's acting group as its `grp` and the run's id as its `firing`. An observer's revisions record `via` `firing:<id>` in `revision_actors`. `beginSubscriptionHandler` writes the firing's `subscription_firings` row (owner, subscription, name, group, `at`) as `running` before it is dispatched; `finishSubscriptionHandler` ends it `ok` or `failed` with its `error`, or `cancelled` when its slot or attempt is gone, `cancelFiring` ends one whose task was cancelled, and `interruptFirings` ends every `running` one as `interrupted` when the firing loop starts. Ending a firing records `effects` as `{sessions, requests, messages, revisions}`: the ids stamped with the firing and the revisions attributed to it. A finish deletes ended firings without effects older than seven days. A group slot's wakes are dropped: it has no agent. `subscription_firings` is an induced table grouped like `sessions`; `subscriptions` lists group slots with `name`, `status` and `sessions_per_hour` and a null `session_id`.

## Observation

`ChangeSource` publishes the set of table names a committed writer transaction touched, once to each subscription that intersects it, only after COMMIT returned and another connection can read it; a rollback publishes nothing. The writer installs SQLite's update hook and an authorizer once when opening; their union collects main-database INSERT, UPDATE and DELETE table names for a cell step, a job stretch and the runtime's own outer writes alike. The transaction-began callback clears the set; the committed callback publishes and clears it, or rollback clears it, before releasing the writer. A savepoint rolled back inside a step may leave extra table names in the set. The wakes leave after the source's lock is released, so no subscriber code runs in the commit path and nothing there waits for the writer. Writes outside the writer's transactions or on any other connection are not heard by the hooks: a file-backed space's task reads `PRAGMA data_version` on the writer connection once a second, on the space's injected clock, and a value that moved publishes every table of the database to the same source, so the other process's commit in a roll wakes every watch within the second. A commit of the writer's own connection never moves it. Foreign-key actions are not heard.

The authorizer sees writes to WITHOUT ROWID tables (`session_lines`, `attachments`, `person_hidden_sidebars`) and predicate-free deletes of unowned tables that SQLite's update hook misses through its truncate optimization. A statement that writes no rows may therefore wake that table's subscribers. This is correct because wuwei prepares every statement inside the transaction that runs it, with no statement cache.

`ObservationJob` is the space's one observation job, created with the space's worker. Every client stream is a publish-only socket on it — `RowsStream` (a statement's snapshots) and `FileStream` (a group's file commits) — and each runs as its own watch beside the others for as long as its socket is attached. `attached` registers the watch; `closed` removes it, ending its child where it stands, throttle or no throttle. `start` is one long effect beside the lane loop: the effect runs every registered watch as its own child, from the moment it registers to the moment it goes, and the lane alone sends and closes. A wake is registered once per run of the lane loop and of the long effect, before either looks at the results or the watch set, so a result or an attach that lands at any point after it is not missed. A rows watch keeps only its newest unpublished snapshot; a file watch drops none. A watch ends on a refused statement, a failed read or a lost group, and its socket closes; a region subscription that ends closes it too. The socket's own close ends the watch with it, and the next worker greets only the sockets still attached.

A rows watch resolves its scope, its tables and its region on every wake, after its throttle, and publishes only a changed snapshot. Its region always includes the space's table registry (`tables`), so retiring a table ends a query even when no materialized rows remain. A file watch checks reach through SpaceCell before each bounded FilesCell journal page, then publishes complete revisions in order, folding a move into one event carrying both ends and filtering by its glob. A page selects at most 64 revisions and includes every version row of those revisions; catch-up loops until the page is not full. A revoke interleaved after a page's access check may leave that final page visible; the next page's check ends the watch. A cursor past the journal replays nothing until the journal passes it. Another process's writes wake every watch within the second, from the `ChangeSource` `data_version` poll, with no local write or attach. `mutations` flattens commits for SSE and scripts without changing their event shape.

`observeFS(glob:from:group:as:)` and `observeRows(_:parameters:throttle:viewer:as:)` attach and bridge as `observeConversation` does; an attach the worker cannot host — another process holds the job, or the space is closing — throws `ObservationsUnavailable` before a stream exists, and the observe routes answer 503 with `Retry-After: 1`. A drain closes the sockets and a client reconnects.

## Live documents

Document seed and merge-material reads share one `worker.read` snapshot across FilesCell, DocumentCell and bucket metadata as needed. Subtree checkpointing collects dirty document ids in one read scope before awaiting any checkpoint; moves similarly export rows and bucket locations before fetching external bytes or taking a write step. File-watch permission and its bounded commit page share one read scope. Current revision maps derive each group’s FilesCell read from the same scope that reads the principal’s reachable groups.

A `.wmd` or `.canvas` file is the canonical text of a live Loro document; its extension picks the `LiveFormat` (LiveDocument; the formats are WmdDocument's markdown and CanvasDocument's board) that configures the doc, projects it to text and merges an agent's text back. Migration 037 adds its rows, owned by the document's cell, and 039 adds a unique history identity to the state: `document_state` (the file revision the snapshot stands for, the frontier of snapshot plus log, the next log sequence, when the file fell behind it, and why a file is no document), `document_snapshot` (the snapshot itself, a row of its own so a changed frame's update of the state row rewrites a page and not the blob), `document_log` (the changed frames since the last checkpoint or fold, by `seq`) and `document_checkpoint` (the Loro frontiers each checkpointed revision holds). Only `removed` deletes that history; the document's lineage counter survives it: it commits in the same fs transaction that deleted, moved, replaced or checked out the file, closes the cell's connections with `notFound` and deletes the rows, one mail per document at or under the path, addressed to the document lineage captured by that mutating step and guarded by the revision the state stands for; a mail for a different lineage is a no-op, even before a recreated document has a file head. A postcommit poke only speeds delivery: if the removing worker dies without delivering, another worker’s scan finds the durable mail and clears the rows. A move does not carry the history along — the document at the new path starts from the file's text.

`DocumentCell` is one cell per document, keyed `<group><path>`, and the only writer of its document state; FilesCell alone writes its file head and journal. The Loro replica is not in the cell: `DocumentReplicas` holds one per document for the process, and a step uses an entry only while its frontier equals the row's, rebuilding from snapshot and log otherwise; an entry whose step rolled back is dropped, so a miss is a rebuild and never a wrong answer. The log folds into the snapshot every `DocumentCell.foldLength` (64) changed frames, which writes no revision and no file. Clients are the cell's sockets: `attached` welcomes or refuses, `receive` handles `sync` (the catch-up, then `synced`), `update` (import, log, relay, ack) and `presence` (relay only), `closed` sends the roster. A client update frame that leaves the actual replica shallow is refused `invalidUpdate` before any log, relay or ack; the throwing import discards the mutated cache entry and the next step rebuilds from unchanged rows. The envelope metadata is not trusted to establish complete history; update blobs and full snapshots remain accepted when they leave complete history. Nothing about a connection is kept: an update is imported and logged before it is relayed and acked, so an ack means durable, and an update a peer receives before its own catch-up waits inside Loro and applies when the catch-up lands — there is no update-before-sync gate and no presence replay (clients re-publish their selection every 10 s, against a 30 s expiry).

A step whose file is gone or replaced does not delete anything: a frame for it closes its socket with `notFound` before any log write, so an edit that arrives between a move's fs transaction and its `removed` mail is refused, never acknowledged (an acknowledgement would be a lost edit); an agent's prepared write answers stale and the host re-reads; a checkpoint returns and leaves what the log holds to the host. A connection may hear a roster before its welcome — the cell broadcasts a departure to every socket it holds, and it cannot know which have not been welcomed yet — and a client ignores controls until its welcome, as both shipped clients do.

`Space.liveChannel` attaches one authenticated client to the cell. Opening a missing live path is refused `notFound`, so a reconnect after a delete or move never brings the document back; only a writer whose hello asks to `create` gets it, empty. A reserved path (outside session homes and machine notes) is refused `forbidden`. The transport tells the cell when a connection's group or role access weakened: the cell refuses that connection — `forbidden` with no access left, `readOnly` for a writer that lost write — and closes it, so the refusal is the last frame the client sees; it reconnects, and its next welcome says what it may do.

Migration 052 creates `document_lineage` and `document_pending_checkpoint`, backfilling each existing `document_state` owner with lineage 1, sequence 0 and its `file_rev` as `seed_rev`; the pending table starts empty. The cell requires every stored document to have that lineage row.

A checkpoint compacts the replica into its snapshot, trims the log, puts its canonical bytes in the bucket, and stores pending `(seq, frontiers)` in the document's cell. Each seed increments a durable lineage counter that removal never deletes; checkpoint seq increases within that lineage, and seedRev names the seeded file revision or nil for a create. The document mails FilesCell `(path, hash, lineage, seq, seedRev, attribution, checkout)`. FilesCell retains one `(lineage, seq, rev)` row per path forever: a lower lineage drops; an equal lineage drops if its rev is no longer the head's, answers its current pair without writing for a lower/equal seq, and otherwise applies; a higher lineage or absent row is admitted only when seedRev equals the head's rev (nil is no head). Applying updates that row and the file, or only the row when the hash is unchanged, and mails `committed(lineage, seq, rev, previousSeq)`. Only an applied checkpoint sends that acknowledgement. The document maps an acknowledged rev to pending frontiers only when no mapping exists, deletes that pending row and skipped sequences strictly between previousSeq and seq, and announces the checkpoint rev to sockets; old-lineage acknowledgements are ignored. A file rev awaiting acknowledgement resolves read-only through its matching lineage/seq pending frontiers. The document is current when the head belongs to its lineage, or no checkpoint of the lineage has landed and the head still equals seedRev. Agent writes and read-triggered checkpoints call that same FilesCell step directly and then `doc.committed` before returning, so the returned rev already resolves as a guarded merge base. A file ancestor drops a checkpoint and mails document removal rather than throwing. A dropped agent checkpoint answers notFound. If the document is evicted after the files step lands, the handler still returns its durable revision; the committed mail supplies its acknowledgement. Checkpoints happen after 5 s idle, before a dirty document is read or moved/deleted, and on agent writes; keystrokes never mint a revision. A draining or remotely hosted document leaves a read at its last file checkpoint. External seed bytes are fetched by the host and passed to `seed`; the cell never awaits.

A move carries no document history. The host checkpoints the source first; a frame accepted between that checkpoint and the move may be lost with the move. A same-group move is one FilesCell step: inline indexable bytes are reparsed on its own connection; external document indices are staged by hash and destination path, and an unstaged external hash refuses versionMismatch before any write. A cross-group move imports current table header/rows with row ids but no source history and host-parsed index values. MachineCell mails its source FilesCell; that source exports its own nodes, current tables and index values, tombstones them and durably mails destination adoption in the same step. Adoption reads the machine's current group through MachineCell: it forwards the entries to another current group, drops them for a deleted machine, or merges them here. It merges directory pairs, replaces colliding nodes and their displaced subtrees, and preserves unrelated children. Machine-note link values targeting the old group are retargeted to the new group, including explicit old-group links, until a later write reparses them. Delete, move, checkout and rmdir derive live paths from affected heads and mail each DocumentCell `removed(rev, lineage)`; there is no registry or post-call host transaction.

An agent `write` of a live file is merged, not replaced: its text is diffed (a `.wmd` block by block, a `.canvas` by id) against what the writer read, the checkpoint its `ifMatch` revision names exactly (no checkpoint row at that revision is `versionMismatch`), and the changes apply from a fresh peer id drawn from the space's injected random generator, so edits made since survive. Without `ifMatch`, the base is the latest checkpoint. The host copies a coherent snapshot, log and selected checkpoint from a read, then rebuilds a private replica and computes the merge after that read ends, outside every database transaction and cache lock. It hands only the prepared update and write policy to the cell. The cell compares the history identity, not the frontier or file revision: typing, folds, checkpoints and unchanged-text commits keep the identity and cannot invalidate an update. A matching-history update must import completely; missing dependencies trap. A history replacement returns stale before import; the host re-reads and recomputes, at most three attempts, then answers `SpaceError.liveBusy`. A base missing on a re-read answers `versionMismatch` immediately. A checkout's exact-current revision and `createOnly` are checked again in the step. The document checkpoint is durable before its update is relayed, and the files handshake finishes before the agent receives its rev; rows of a removed history go by the `removed` mail. Text the format refuses is `SpaceError.liveSyntax(path:line:reason:)`; a folder that is a file is `SpaceError.notADirectory` and is refused live with `notFound`, before anything is written. A checkout's historical text, a write that creates the file, and a file's text seeding a new document merge as a restore: a `.canvas` id the board no longer has comes back instead of being refused. For an agent write, empty creation and inline or external file seeding also build their seed snapshot and update on the host; the cell installs them only while the captured head revision is unchanged and no valid history exists. Every seed mints a new identity, preserved by all writes of that history and cleared with its rows. An unchanged canonical hash keeps the current file revision while its checkpoint sequence still advances; concurrent typing is checkpointed. The document step imports, reconstructs a cache miss and serializes the snapshot and canonical text, but never aligns or diffs the agent's text. A file that is not UTF-8 or does not parse is foreign: a connection to it is refused `notLive`, a read returns its bytes, and a full write replaces it.

## Trusted import support

`createTable` accepts an optional `RevisionAttribution`, recorded atomically with table creation just as `commitRows` records row-mutation attribution. `removeEmptyDirectory(path, in, acting)` checks directory kind and child absence in the same write transaction as its tombstone: a nonempty directory returns false without a revision; a missing/non-directory path throws its typed SpaceError. It refuses root/reserved paths. This trusted core primitive never recursively removes children and is used by import staging cleanup.

## Trusted composition and provisioning

`Space.open(file:identity:objects:log:)` optionally supplies the durable identity when provisioning a new database. A malformed identity throws `SpaceIdentityError.invalid` before creating the file; reopening an existing database with a different identity throws `SpaceIdentityError.mismatch` before schema preparation, without overwriting its identity. Omitting identity retains the existing entropy-generated id and reopen behavior. The supplied identity seeds only a database without an identity row. The space reads and caches its identity at open; `identity()` does no database work. `storedSpaceIdentity(at:)` reads the stored identity on its own read-only connection with a five-second busy wait, without migrating or seeding the file.

A file-backed space is closed before anything else uses its file. `Space.open` starts the crash sweep, which holds the space, so one dropped unclosed releases its connections later, on its own; the last WAL connection's close checkpoints under an exclusive lock, and an unretried open of the file meanwhile fails `SQLITE_BUSY`. Whoever opens a space closes it with `close()`, on a thrown error too.

`UserRecovery.add(space:name:admin:)` returns the created AccountRecord and uses the same first-admin and reserved-name policy as the offline folder command. `UserRecovery.invite(space:account:server:ttl:)` validates the account and uses the same single-use device enrollment token, deployment origin/fingerprint and output/note format as the offline folder command. These overloads permit trusted in-process administration without opening a second database instance or requiring the server to stop; they add no HTTP authorization bypass.

## People and credentials

`PersonCell` is keyed by account id for every account kind. Notification recipients, watermarks and profiles keep their principal names, with `owner_account` routing them to the account’s cell; migration 044 backfills that column from personas and retains unmapped literal keys. An existing account-id principal maps directly to its account, and a persona maps to its account. Reads of an unknown inbox are empty; writes to an unknown person are refused. Conversation delivery skips stored members that map to no account.

Persisted account, key and device rows must decode their typed kinds, capabilities and dates. An invalid value traps as a programming bug or disk corruption; it is not a refused credential.

`Space` account, key, read-session, person join-token, persona, profile, device and push-grant handlers call the account’s cell for each mutation. An account keeps its `ac_` id; account creation creates no group or group membership. The settings group’s `setAdmin` step serializes admin changes, replaces the account’s existing settings role on promotion and refuses removal of the last live nonguest human admin. Account removal demotes in settings first, then tombstones the account and purges its keys, read sessions and join tokens in the person’s step, mailing the space cell to drop the account’s grants in every group: that step mails each group, whose own step deletes the account’s `group_roles` rows, a moment later. Credential reset purges those credentials and mails `closeBoxes` to the account’s machines in that same step.

`adoptPersona` returns the account’s earliest persona or creates its only new persona, reusing any existing account-reserved persona allocation. Different keys of one account no longer mint different personas; existing extra rows remain stored. `conversations(member:)` maps person principals to the account’s cell, which lists membership under the account id or any of its personas in one statement; session-member lists use the Space cell instead. A person’s join token is consumed with its new key in one person-cell step. Machine-account creation, enrolment and deletion are the space cell's claim, the account cell's idempotent birth and the machine cell's own step, in that order, and the account's removal is a fourth; the receipt behavior is unchanged.

Person profile handles live only in the Space cell’s case-insensitive alias namespace, including historical spellings. Setting a profile first claims or renames its current alias, then sets its display name in the person’s cell; a crash between those steps may leave the new handle with the old display name (nil for a first profile). A profile exists when it has a current person alias; historical aliases resolve to that profile, and profile lists sort by current handle. `UserProfile` carries principal, handle and optional display name; it has no timestamp. The dev person has an ordinary profile and settings.

The principal's profile row stores only the avatar's bucket content hash, without creating a handle. `setUserAvatar` validates the PNG signature and the 4 MiB `UserAvatar.maximumBytes` bound, puts the bytes through the bucket's handler door outside a step, then the account's person cell stores the hash; deletion clears only that hash. `userAvatar` reads the person's hash and loads its bucket bytes outside any step, returning the hash and bytes; other profile reads never load avatar bytes. Updates preserve the display name, and display-name writes preserve the avatar hash. Hidden sidebar addresses are a nonrevisioned `(owner_account, grp, path)` set; dangling group/path addresses remain valid. A toggle is one void person-cell message, and its caller reads the sorted complete snapshot in the same worker call. Settings refresh at launch, foreground and after the device's own toggle; there is no new stream.

`PersonCell` owns an account's rows — `accounts`, `account_keys`, `read_sessions`, `join_tokens`, `join_token_receipts`, `personas`, `devices`, `device_commands` — beside `notifications`, `watermarks`, `user_profiles` and `person_hidden_sidebars`, and `MachineCell` owns `machines` and `machine_v2_members` beside its presence, description and operation tables; each names its owner column, a write outside the owner's step aborts, and migration 048 adds the `owner` columns the older tables lacked. `message_devices`, written by a conversation's cell for its own messages, and the push tables, advanced and withdrawn by the delivery jobs, stay unowned.

## Machine v2 persistence and diagnostics

`machineV2Store(group:key:)` supplies the production OperationStore on new machine_v2_operations/channels/output tables; it never selects MemoryOperationStore or v1. The caller supplies a durable 256-bit symmetric key. Complete metadata/start inputs, pending writes and output payloads are AES-GCM encrypted with group/id authenticated context; input identity uses canonical keyed HMAC rather than a secret-bearing diagnostic summary. Wrong/lost keys are storeUnavailable, not plaintext recovery. These encrypted tables now serve writes and copy only; other file operations and exec belong to the machine cell below. Migration 011 indexes admission on `machine_v2_operations(machine_id, active, reserved_bytes)` and channel lookup on `machine_v2_channels(operation_id)`.

Claims atomically reserve capacity, persist dispatch_consumed and unique `(grp, owner_scope, invocation_key)` before returning the one-use dispatch bit. Changed machine/start input is invocationConflict. Updates atomically persist encrypted payloads, cursors, accepted offsets, pending identical writes, evidence generations, snapshots, caller budget and stop intent, and roll back every field on throw. Admission is by bytes alone: the described machine's buffer, shared by every group's operations on it; there is no count cap per owner scope, group or machine. Each refusal names its bound (`bufferBytes`, `machineBufferBytes`, `pendingInputBytes`, `outputBytes`, `inputBytes`), and a reused operation id is `operationExists`. Retained output is one sealed row per chunk; a row that does not open or does not match its id is `storeUnavailable`, never skipped. Output rows an earlier server kept per channel are recognized by their id: the operation's output is dropped (`discard`) and its next write deletes them. Terminal/unknown receipts release live admission slots immediately; actual retained output and pending input stay counted against the machine buffer budget until taken or pruned. Encrypted receipts and unread output remain recoverable for seven days. Lazy five-minute maintenance prunes expired terminal receipts. Retained input/output use the same per-kind channel window capacities as OperationClient. The same store contract suite runs against SQLite, with reopen, concurrent claim, privacy and wrong-key examples.

`machineV2Recovery(group:key:)` returns owner+record pairs for file operations still using OperationClient. Exec presence comes only from `MachineCell` description answers and its silence lease; there is no membership scan or per-machine describe task.

Machine exchanges are traced as OpenTelemetry spans by OperationClient, never in the space database: migration 013 drops the former `machine_v2_trace`, `machine_v2_incidents` and `machine_v2_problem_index` tables with their incident retention and problems maintenance rows, and leaves any `/wuhu/machine-v2-problems.table` content alone. Operational tables and encrypted payloads are not in the query catalog.

## Session rows

A session's own writes are `SessionCell` functions over its step's wuwei database, without a host bridge. Host session reads take one root SpaceCell handle, so their statements share one read-span snapshot; callers collect values before awaiting, and related cells come from one `worker.read` scope. Step hydration returns the record, generation, queue head and tail, `stepTry` (`session_runtime.step_try`, migration 018), which `markResumed` increments, and `legacy` from the step's database snapshot. It never decodes a stored typed transcript. A generation is legacy exactly when it has typed pointers and no transcript line. The cell opens a new pointer generation at its first work or job answer, leaving the legacy rows frozen.

## Machine v2 durable key validation

`machineV2HasEncryptedState` checks only the new v2 key-check/operation/channel/output tables. `validateMachineV2Key` authenticates the key check and every existing encrypted operation payload before dispatch can begin, and creates a key check only when absent. The authenticated check lives in its own `CREATE TABLE IF NOT EXISTS` table, so prior v2 rows and all v1 rows remain untouched. An absent external key with encrypted v2 state, a wrong key, or a malformed encrypted record is `storeUnavailable`; there is no plaintext or regenerated-key recovery. `machineV2RecoveryGroups` includes every group with stored operations, including removed groups, so startup cannot overlook an abandoned owner.

`consumeMachineV2JoinToken` reads the machine account's v2 membership before the consume step: a token of a machine with no membership row in its group is refused, and neither the token nor a key row is touched. A machine move is one machine-cell step over its row and its v2 membership, preserving immutable operation-owner groups.

Retained buffer reservations are counted across all caller groups sharing that machine; group and script admission remain group-scoped. Claims are serialized in the same store transaction, and cross-group capacity rejection reveals only `capacityExceeded`.

`machineV2PresenceEvidence(machine, group:)` returns only that owning group's persisted typed state, observation timestamp and optional reason. A registered member with no presence row is explicitly lost/neverAttached since its registration time; an unknown machine or different group returns nil. Missing-route routing can preserve confirmed detached/leftAt evidence across restart instead of inventing lost. Malformed stored state or timestamp throws `storeUnavailable`, never a synthesized state or date. Callers still authorize access before selecting the owning group.

Attached and detached observations record the fresh local answer/goodbye time. A lost transition preserves the previous observation timestamp, including a prior lost silence origin; a never-observed member uses its registration time. Consequently lost evidence supports stable silentSince diagnostics without synthesizing the time of a failed route lookup or changing the coordinator's monotonic lease accounting.

`addMachineV2(name:group:)` is a chain of steps: the space cell claims the name (writing the alias alone and mailing the newborn's account), the account's cell creates the machine account if it is absent and mails the machine its row, the machine's cell writes the row and the v2 membership, and the account's cell mints the one-hour single-use exec-machine join token. A taken name writes nothing; a crash after the claim leaves the name reserved with no machine, and one after the row leaves a machine a `machine rotate` can key. Names follow the normal machine-name validation and global uniqueness rules.

`enrollMachineV2(name:group:pubkey:device:enrolledBy:)` is the token-less one-call form, and runs the same steps as `addMachineV2` with the key and the optional device link in place of the join token. It is idempotent per person: when the name is the current name of a v2 machine in the same group whose live exec-machine key is `pubkey` and was created by the same non-nil `enrolledBy`, it returns that machine and key without writing (re-applying the device link); a key already enrolled is `alreadyExists` before the name is looked at, and any other held name is `machineNameTaken`. Consuming a machine account's join token writes a `join_token_receipts` row (token hash → pubkey, cascading with the key, pruned at the token's original expiry) in the claiming transaction, so a consumed machine token replayed with the same pubkey returns the same live key and any other pubkey is `JoinTokenRejected`; a person's token writes no receipt and stays strictly one-time.

## Durable model routes

`session_model_routes` and append-only `session_model_route_history` are additive `CREATE TABLE IF NOT EXISTS` domain tables. Existing tables/rows are unchanged; old direct sessions have no route and no backfill; their first execution establishes a concrete binding with nullable group/member. Group creation and Start over commit a legacy-readable concrete executor_config plus additive intent and `SessionModelRoute` with the owning session-cell step. Failed/busy operations cannot partially replace a pin. `modelRoute` reads it; `establishInferenceModelRoute` reads an already committed pin unchanged rather than repicking, or mails a proposed binding to the session cell before the inference outcome and returns that proposal. Interrupt/resume and reopen preserve route epoch and placement evidence. Ordinary compaction can atomically replace a quota-aware group pin; a retained pin has no history churn. Start over replaces or clears the pin atomically without erasing previous decisions; switching to a direct target clears it. Rows include concrete provider/model, nullable group/member and phase `pinned` (groups) or `bound` (direct); payload carries requested group, effective effort, member, binding fingerprint, placement time/reason and all headroom evidence. FK deletion follows session deletion. The scoped readonly SQL projections `session_model_routes` and `session_model_route_history` follows `sessions` group visibility, including qualified/wildcard reads; it is not an editable space `.table`. Failure provenance lives in the existing route payload, not a new table.
## Cache warming

The session cell owns warming: `session_state.warming` keeps the last reply's schedule, the cell step time it landed at and the pings spent since, and the cell's `nextWake`/`wake` do the rest (LoopCore). SpaceCore keeps only the writes the cell makes on its rows. Additive migration 034 drops the retired `session_cache_warming` table with its rows; nothing reads them.

## Session run state

The induced `sessions` row carries `run_state` for kernel sessions. The session's cell says what its turn owes whenever the turn moves (`SessionCell.show`), in the step that writes the transcript: `tool` while a call of the model's reply is unanswered, `inference` while the model owes the next step or only due input waits, and `no_run` otherwise; `work` is `has_work` for the first two. Interrupt, error, archive and Start over write `no_run`; a resume shows the turn again. The row is written only when the value changes: each change stamps `run_progress_at` (null for `no_run`) and moves `last_activity_at`. A pending tool call survives restart and its exec rejoins, so a session waiting in one keeps reading `tool`. `run_heartbeat_at` stays null.

## Atomic route transitions and durable failure episodes

The held route payload optionally carries typed failure source (`upstream`/`credentialRefresh`), reason/code, first/latest failure times, retry time and consecutive count. `updateInferenceModelRouteFailure` mails the session cell, which updates only payload/phase (`waiting` for a refusing episode, otherwise `pinned`) when the expected epoch is still current; stale or absent-route mail changes nothing, without history churn. Start over clears it; success clears it without repinning. No schema change or new table is required.

A `ModelRouteTransition` compares the held epoch and requires a changed group intent, member or concrete target with a new epoch, a replay binding; requested compaction targets may leave, join or change groups. A same-epoch transition is effort-only: everything but effort must match, and it updates only executor_config and the route payload, without history or line changes. Only a new generation commits one, together with its concrete executor_config, pin/history, carried lines and prompt invalidation. A transition with a binding strips account-bound content from the carried lines. Failure at any write leaves the old pair intact; reopen after successful commit sees the new pair. Existing lines remain immutable, and obsolete route-transition epoch writes conflict. History rows carry the placement reason (`create`, `startOver`, `compaction`); rows written before mid-generation switching was removed may read `lastResort:<cause>`.

## Machine value construction

`MachineRecord` and `ExecRecord` expose value initializers for semantic owner adapters. Their store representation, authentication, exec replay receipts and database schema are unchanged; these initializers do not grant persistence or authorization authority and do not make store records Codable.

`SessionStore.put` and `SessionStore.clear` mail the owning SessionCell; the cell checks the session and writes the queue in its step. Conversation/request delivery sends the same mail within the caller's step. No queue receipt is returned to the host.

## Retired worker schema

The existing `session_worker_incarnations`, `execution_worker_owners`, `session_worker_assignments` and `worker_script_owners` table declarations remain unchanged. Runtime code neither reads nor writes them; removal is deferred to a separately authorized schema change. Script heaps do not survive restart; there is no script-exec restart announcement registry.

`Space.close()` finishes live filesystem subscriptions, cancels and drains the space-owned query observation and the session observation workers and its `data_version` poll, and explicitly closes the idle runtime read connections and the writer; a live span's reader closes when the span is released. It attempts both readers and writer even if one fails, throws the first close failure, and is idempotent after success; database operations through the space and retained stores must finish before close and must not be used afterward. Hosts drain their services before closing the space, so no SQLite file handles or deferred close/checkpoint remain when shutdown returns. Observation admission after close is refused (`ObservationsUnavailable`) and starts no worker, because the runtime marks itself closing under the lock that hands the worker out. It quiesces the space's worker first and releases its leases only after the final host write, immediately before closing the runtime reader and writer.

`Space.worker` is the space's one wuwei worker, on the shared backend over the space's own database (its own SQLite writer for change tracking, and runtime-owned read connections the space closes) and on `DependencyScheduler`, made when first asked for. A read handle lazily holds one snapshot until its last derived handle is gone; `worker.read` closes a shared snapshot on synchronous scope exit, and nested reads inside a step use that step’s connection. File spans can delay WAL checkpointing, not commits; a memory span crossing an await that needs the writer fails loudly at the five-second busy timeout, so asynchronous callers materialize values before awaiting. Every module of the space gives it its kinds and clients before starting it; a session's mail pokes it after the commit that posted it. `Space.stopWorker()` quiesces it and releases its leases and ends its timers, and the next `Space.worker` is a new one, as after a restart of the process.

Message handles and device names are resolved when queued inputs enter the transcript, in the drain transaction. Stored attribution survives hydration unchanged; directory renames affect only messages admitted afterwards.

The same drain transaction decides each delivered message's earlier exchange, so the delivered text can differ from the conversation's. The first message drained from a conversation in a generation carries the session's last message there and the one it answered (its reply target, else the message before it) when that last message predates the generation's head (compaction or Start over) and no message from that conversation is already in the generation, kept by compaction or delivered earlier; a session's first generation, which has no head, carries none. The decision and the quoted text, attributed as of the drain, are stored in the message line: hydration, reopening and rendering never recompute them, and later posts or renames never touch them. `StaleExchangeTests` pins this.

Migration 042 drops `session_receipts` and `session_api_receipts` and deletes stale direct-route pins that disagree with their stored concrete executor, preserving route history. Session creation, subscription arming, device commands and file/image tools no longer record or replay tool answers; kernel mutation jobs do not repeat their effect after restart. Call ids still namespace deterministic conversation-message identities. The legacy `exec_jobs` table, when present, remains empty and unused.

## Machine cells and exec ownership

`resetCredentials(account:)` and a successful `revokeMachine(_:presenting:)` purge the credentials and mail `MachineCell.closeBoxes` in one person-cell step, the key check and the purge in the same step so a rotation lands wholly before or wholly after it. `deleteMachine(_:by:)` is the machine cell's own last step, called by its host after the device owners' detach steps: it removes the machine's rows and closes its sockets, then mails the space cell to free its names and the account's cell to remove itself. A caller whose worker does not host the machine hears `Evicted`, as every call does in this shape.

`BoxSocket.Opening` requires the exact authenticated `pubkey` captured by the transport. In the attached writer step, before replacing an existing box or emitting a describe request, the cell requires that exact `account_keys` row to still belong to the account bound to its machine id. Credential purge and attached acceptance therefore serialize on the same writer: close mail cannot be consumed before a delayed revoked attachment and then admit that attachment. A rejected first attachment still initializes baseline presence for its close handler, but publishes no describe or attached presence. Capability, expiry, group membership and account-lifecycle checks remain in upstream route authorization; this attached gate only rechecks exact-key existence and machine-account binding.


`MachineCell/<machine id>` owns `machine_presence`, `machine_descriptions` and `machine_operations`. Migration 033 drops `machine_execs`, `script_execs`, `machine_v2_presence` and encrypted exec-operation rows with their channel/output retention; no in-flight exec is migrated. Write/copy rows and keys remain on the existing encrypted path until their replacement; the file socket path below owns the other file operations. `Space.reserveExec` calls the machine cell to create an unopened reservation; it reaps after 60 seconds. Listing, status and script ownership read the cell's operation rows.

Migration 036 creates the final presence, description and file-operation tables, discarding the former presence rows and all pre-roll exec operations without migrating descriptions, leases or in-flight work. The same machine cell owns a small presence row containing lease/describe deadlines and fixed polling, result-size and exec-window limits, and a separate last accepted description containing kinds, schemas and availability. A validated describe updates both in one step; within each kind, input and output channel names share one namespace and must be unique across both directions, otherwise describe is invalidResponse and the box is closed. Positive description, snapshot, input and box answers renew the last accepted lease duration; transport and preparation failures do not. Attaching a socket never renews the lease. Each new socket receives one initial describe with a five-second handshake deadline, using the existing describe deadline; only its valid description proves that socket. A never-described or previously lost machine stays publicly lost while that handshake is pending. A previously attached machine stays publicly attached during a quick reconnect, preserving its last observation time, but the cell records an internal handshaking state and sends no operation requests until that socket describes. A previously detached machine stays detached until its description answer. A failed initial describe exchange does not clear or extend the handshake deadline. Handshake expiry loses the machine and closes the socket, finishing waiting and outstanding operations with the same lease-silence outcomes as lease expiry. The central driver loads the full description at most once in a turn, only when a batch has undispatched file starts or opened exec starts; dispatched answers, credit, polling, status evidence and wake deadlines use the small row. A pending opening is recorded before that central admission/dispatch pass. A replacement box receives describe before any operation request; existing operations reconcile from committed offsets only after that socket's valid describe answer. Losing the lease retains the last accepted description and observation time; the public description reader still returns no description while the public presence is not attached.

A start records its immutable request (argv, cwd, environment, secret names, caller/session/group, UUID and original admission time), waiter, offsets, bounded 50 KiB combined tail, combined cursor, cut, verdict, stop intent and deadlines. Secret values and bearer tokens never enter a row or mail. Non-positive timeouts are refused as invalid input before reservation/start can mint a credential or record a deadline. A lost machine refuses a new start immediately. A start during a quick healthy reconnect waits in the cell for that socket's describe answer, bounded by its handshake deadline and the unchanged last-answer lease; it is never dispatched into the unproven socket. After the answer, admission refuses beyond `(streams - 2) / 3` dispatched live operations. Dispatch intent and the one start emission commit together. An ambiguous start is polled by UUID, never sent again; `unknownOperation` states explicitly that start may not have arrived and was not retried.

A `BoxSocket` answer records output offsets and tail in the step that emits the next poll with those offsets as its acknowledgment. A failed step emits no ack and retains the worker bytes; a repeated range does not advance the cursor or duplicate the tail. A verdict can precede the pipe tails; completion waits for both final offsets to be present and committed. Final-offset evidence merges per channel across reordered answers: a known final offset never disappears or changes. Terminal acknowledgments are recorded per channel; an operation retires only after both channels acknowledge and the box reports output consumed, or the box has forgotten the drained operation. A known verdict suppresses control polls; a committed channel end suppresses further output polls after its offset acknowledgment. Answers without progress back off that purpose from 100 ms to 2 seconds; progress resets the retry and immediately acknowledges committed offsets. Terminal acknowledgment purposes continue on this backoff until output is consumed. Retry backoff, initial handshake, periodic describe, silence lease, timeout stop and its 30-second answer grace are all `nextWake` deadlines. Every due deadline advances or clears in `wake`, even after a crash with no socket: describe deadlines clear without a box and attach re-arms them; silence still expires at its original lease. A replacement box reconciles live operations from committed offsets after its handshake succeeds. A deleted cell removes its operation rows, finishes waiting callers once, closes its sockets and retains a presence tombstone and its last accepted description; late waiter acknowledgments to that tombstone are consumed.

A channel-end indication on a matching output or terminal-acknowledgment response contributes its `through` endpoint as final-offset evidence, merged with the same immutable per-channel conflict check as explicit `finalOffsets`, even before a verdict or when overlapping bytes are ignored. An end below already admitted output is invalid, as is any final offset below admitted output. Honest overlapping end responses may name a later endpoint without admitting their bytes; polling continues from the committed cursor to obtain the missing suffix. Only an empty exec output response with `from == through == current offset` establishes the poll-suppressing end and proves the box received the offset acknowledgment; advancing output and overlapping replays do not establish it. File ends suppress polling only on contiguous cache-admitted output or an empty response at `received`; overlapping file responses never advance `received` or establish that end. Terminal-acknowledgment responses contribute end evidence but never establish the poll-suppressing end. An established end freezes the admitted offset, which must equal its known final offset. Every output response must stay at or below any known final offset, even when its overlapping data is otherwise ignored. Contradictions fail with `invalidResponse` before publishing output, terminal retirement or acknowledgment cleanup. The first file `invalidInput`, `invalidResponse` or `outcomeUnknown` failure and first exec `invalidResponse` failure emit one warning with machine, operation, kind, failure code, row state and existing cursor maps, never payloads, paths, keys or tokens; ordinary transport, range-loss, cancellation and disconnect events do not receive this diagnostic. File validation uses `received`, not the caller's consumption offset; completion still waits for explicit consumption.

`MachineBuffers` is a worker dependency, not durable state: bounded channel windows and stdin are addressed by worker id, operation, channel and range. `MachinePointer` ranges use byte offsets for data and record offsets for records; both payload kinds share the existing 4 MiB encoded-byte budget per operation/channel. Offset-addressed cache lookup returns a retained suffix without acknowledging it or allocating another retained piece; explicit release trims the cache before the consumer offset. Overlapping replays retain only the suffix at or beyond that explicit release floor; their original wire pointers need not remain readable. Payload lookup rejects another worker’s pointer, and the exec Data API retains exact-pointer reads and cursor-based replay semantics. `ExecStream` transports pointers, stdin/eof, kill and consumed cursors. Its opening requires a fresh connection UUID nonce; an admitted operation stores that nonce, never a worker-local socket id. Input, output, exit, consumption, backpressure and close authority match the opening nonce. Box replacement clears an orphaned binding even when its stop is already pending, so a later worker reusing the same local socket id cannot inherit another exec's bytes or terminal event. Poll limits fit the advertised limit and channel/caller window. A full output window stops channel polling until consumed advances. Committed stdin offsets and EOF state select the next input before post-commit buffer cleanup; duplicate data receipts cannot consume a queued EOF. Initial wire replay of accepted or queued stdin is acknowledged without re-emitting accepted bytes; an accepted EOF is idempotent. Delivered output pointers stay readable until the adapter drains its queued frames and releases the operation. Close stops the remote operation; unopened or orphaned streaming operations cannot acquire replay/reconnect legs. Bulk output unread at rollover is lost; the tail, cursor, verdict and operation identity survive.

A foreground tool waiter receives `finished`, which retains the tail until `taken` commits alongside the tool answer. `detach` switches an unfinished operation to session completion mail; if finished was already queued, it sends that retained end to the session immediately and clears the tail. The job's interrupt is `abandon`: it stops the operation, clears the waiter and tail, and does not notify the session later. External `stop` only stops the process and preserves the waiter/background recipient. Drain/retry never stops a tool exec. A finished mail stranded at a completed job is ignored.

## Transcript lines

Migration 026 adds `session_lines(session_id, generation, position, at, role, key, message, meta)`. Lines are the durable transcript and the model request's input, in position order. `SessionCell.append` writes already rendered lines after the generation's last and returns the first position taken; it never decodes old typed items, rewrites a line or moves one. `SessionCell.droppable` tests whether anything beyond the head and context-pressure notices would be left behind. `transcriptLines` excludes prompt lines; `lines`, `lineGenerations`, the paginated lines API and the transcript files read stored lines.

`SessionCell.writeGeneration` appends any closing lines, advances the generation, writes the new head and optional kept line range, then appends any following notice and invalidates the frozen prompt in one transaction. Carried lines lose their inference metadata and context-pressure notices; `portable` or a route transition's binding also strips account-bound content. The store does not fold a transcript, reconstruct obligations or write typed items. Held mid-turn notices and the execution state belong to the cell's own row, not this line store.

`storeInferencePrompt(…, opening:tools:)` reads an already committed matching rendering or stages a proposed rendering and mails it to the session cell before the inference outcome. It returns that winner or proposal without requiring the job and cell to share a worker. The cell stores only a matching pending generation/revision and writes position 0: `{"rendered": <hash>}`, naming the blob that holds the `TranscriptPreamble`. Positions 1 and 2 are the prompt's opening (`PromptOpening`: keys `group` and `session`, user-role text, an empty one absent), written in the same cell step and stored nowhere else; a new generation's transcript therefore starts at position 3. A generation opened before that starts at 1, has no opening (`PendingPrompt.opening` is false) and gets its whole prompt as the system text. `StoredTranscriptLine.isPrompt` identifies the `system`, `group` and `session` keys. Lines are not in the query sandbox.

Migration 032 drops `session_commands`; `session_pointers`, `session_contents` and `session_generations` remain frozen. `session_legacy_items` is a read-only sandbox view, not a persisted SQLite view: pointers join contents by session and content id, then sessions supply group visibility. Its columns are `session_id`, `generation`, `position`, `kind` (the stored payload's top-level JSON key) and the unchanged `payload`. An unqualified name reads the acting group, a qualified name reads a readable group and the wildcard-qualified name adds `grp` for all readable groups. Query, observation and scripts share that catalog; direct access to the backing tables remains forbidden.

`/_/session-transcripts/<id>/` (`SessionTranscripts`) serves `current.jsonl`, `current.outline.txt` and `<generation>.jsonl`/`.outline.txt` for each generation with lines, rendered from the rows on every read, in the session's own group only; the root lists nothing. A JSONL record is `{position, at, role, key, meta?, message}`, `meta` (stop reason, usage) only on a line that has one; it drops reasoning and names inline images; the outline is `<position> <at> <role> <key> <first 160 characters>`. Writes, removes and moves throw `sentViewReadOnly`, and `refuseWrite` refuses every path under it.

`/_/rendered/<hash>` (`RenderedFiles`) serves a generation's `TranscriptPreamble` (system text and tool list, sorted-key JSON) from the bucket, where `<hash>` is its SHA-256: immutable, without revisions, read-only like the transcripts, and there only for a group one of whose sessions has it as a line 0 or as its current prompt; the root lists nothing.

## Groups, settings and administration

Groups have no person-specific ownership or access rule. Migration 047 copies each shared avatar file's head hash into its principal's `user_profiles.avatar` without reading, validating or size-filtering bucket bytes, and copies valid inline hidden-sidebar addresses into account-owned `person_hidden_sidebars`; malformed or external sidebar JSON is skipped. It deletes a former personal group only if it has no non-settings file history, table, session, conversation, machine or group observer (paused included). Others become ordinary private groups, named by id, with their owner's admin row restored and grants retained. Existing aliases and identity/allocation records stay unchanged; survivors resolve by permanent id without inserting an alias. Secret-only groups are empty for this rule; secret files and shared avatar files are left unused, not deleted.

The one access rule is `group_roles`: one row `(account_id, source_group, grp, role, created_at)`, exactly one of `account_id` and `source_group` set, each with its foreign key, `role` `read`, `write` or `admin` (ordered). A group is `open` (`groups.visibility`) or private; an open group gives every member account and every session `write`, a private one gives only what its list says, and the settings group reads to everyone and administers to space admins. Reach is one hop: an actor reaches its acting group, every open group, the settings group, the groups listing its acting group, and — for a person — the groups listing its account. A person's role in a group is the best of its account's entry, the acting group's entry, an open group's `write`, and space admin (`admin` everywhere); a session's is the best of its own group's `write` (its own group, every open group) and its group's entry, with a live top-level agent `admin` of its own group. Guests (`accounts.guest`) hold only their account's entries: no open-group reach, no new admin grants, and no sessions. `read` grants reading only; file, table and message writes take `write`. `GroupAccess.readable`/`role` are the whole rule; query, find/grep, watch, web pages, machines, conversations and DMs all resolve through them (DMs keep their membership rule).

`GroupCell` (key: the group id), on the space's worker, is the group as a wuwei cell: it owns its `groups` row and its `group_roles` rows, and only its own steps write them — `create` (its row and its owner's admin grant), `name`, `setVisibility`, `setSecretsScope`, `setGrant` and `removeGrant` and `dropGrants` (the account’s removal reaching it: its entries for that account go, no others), each checking only the group’s own invariants (it is live, what the list names exists, no group is listed in itself, a guest is no admin). Its reads (`role(of:acting:)`, `reads(_:)`, `isHumanAdmin(_:)`, `writes(from:)`, `refusesWrite(_:by:acting:)`, `grants()`, `record()`) load the group's own row, its list and the settings group's list through StructuredQueries and apply `GroupAccess.Snapshot`'s rules, the same ones `Space`'s methods apply over the whole table. `grants()` checks nobody: its caller asks `role` first. `reads(_:)` is the per-group test `readable(by:)` filters by (`Snapshot.reads`), which grants a public reader shared’s content-read reach, reads a page with its viewer's rights and always lets a person read the seat they take: where `role` is nil or the page group's. `SpaceCell` (the one key `space`) is the group namespace and what spans groups: `groups()`, `resolve(_:)`, `memberGroups(of:)`, `isGuest(_:)`, `group(of:)`, and `readable(by:)`, `writable(by:)` and `administered(by:)` for a principal, which discovery (`GET /v1/groups`) and a page's admission read; its steps are `claim` (a group’s alias, id and its claim’s mail), `rename`, `draw` (an allocation), `dropGrants` (one mail to every group it lists), `recordDeployment` and `saveWindowResets`, and it owns `allocations`, `allocation_freeze`, `aliases`, `space_deployment`, `space_deployment_certificate` and `usage_window_resets`. `Space.cell` and `Space.cell(of:)` are the read handles. The `owned` guards are active for the space namespace, groups/grants, conversations/messages/requests/attachments, person inbox rows, machine rows/operations, inference rows and the per-group file, revision, index and user-table journals. FilesCell owns `fs_heads`, `fs_versions`, `revisions`, `revision_actors`, `docs`, `links`, `doc_custom_attrs`, `tables`, `table_schema_versions` and `table_rows` using their existing `grp` column. Materialized user tables remain unguarded, with FilesCell steps their only writer. File adapters contain no host write transactions; static journal queries use StructuredQueries, and materialized table DDL/DML uses built SQL on the cell's database. `RevisionAttribution` is Codable so checkpoint mail retains its actor and source. Migrations run before those runtime guards. The public `Space` verbs keep their signatures and stay the authorization: they check the caller through a read handle, then call the cell. `allocate` and `claim` may hear `Evicted` for a step that landed.

A page writing for its viewer acts as `Actor.page(Page)`, the page's path and its viewer (an account-backed `Person` in the page’s group). Its role in a group is its own group's, capped at `write`; it reads what its viewer reads. A page therefore writes a group only where its group writes and its viewer reads; the viewer's own write or admin never widens it. It is no conversation member, administers nothing and holds no exec. Its revisions record the viewer's persona `via` the page path.

Human admin authority is the `admin` role: directly held, or a space admin (`admin` in the settings group) over every group. The account admin flag derives only from that role. Top-level agents still administer their own group, never the settings group, and no session takes the settings group as its home. `groups.secrets_scope` and `machines.scope` each choose `owner` (the group alone) or `reachable` (every group with `write` in that group); secrets default to `owner`, machines enrolled before the switch are `reachable` and new ones default `owner`. `Space.homeGroup` lets a person land a top-level agent where they write; a session lands one in its own group unchanged, and anywhere else only where its group holds `admin` — an open group's write is not its sessions' admin. The settings group is nobody's home.

Migration 003 backfills personal-group owners and admin rows only for live accounts: a removed account keeps neither. It creates the hidden settings group and copies `shared`'s `models.json`, `model-groups.json`, `capabilities.json` and `machine-v2-upgrade.json` into it with new revisions, versions and heads over their existing blobs, then deletes them from `shared` as ordinary file deletes so the journal keeps their history. Settings are readable from every group and writable only by a space admin . Instruction composition uses only the system files, the session's own group and its home.

Migration 004 extends that table into the access table and drops `group_edges`, `group_reads`, `group_members` and `group_epoch`. Every live member's membership becomes `write`, every admin row stays `admin`, and every pair the old closure reached becomes a `write` entry for its source group, so no reach is lost. It makes `shared` open, leaves every other group private, gives `owner` visibility to the secrets of every group, marks existing machines `reachable`, and adds the `guest` flag (default false).

## Group identities and aliases

`createGroup(alias:name:owner:)` checks through a read that the owner is a live human non-guest, then runs two steps: the space cell's `claim` refuses a taken alias, draws a `.group` id from the shared three-word allocator, writes the alias row and mails the newborn its `GroupClaim`, and the group's own `create` writes its open row and grants the owner admin. The host calls `create` once the claim returns, besides the claim mailing it: both arrivals are real — the mail survives a crash after the claim — so whichever lands first makes the row and the other finds it, and a created group exists when `createGroup` returns. `resolveGroup(_:)` is the single spelling-to-id boundary; all persistence and authorization use ids. It accepts existing group ids and current or retired group aliases only; a person alias never names a group. A retained group id may also be a persona id and still resolves by its group row. `renameGroup(_:alias:by:)` requires group admin and is one space-cell step: the alias becomes the group's `current` row in `aliases` and every past spelling stays reserved. `nameGroup(_:name:by:)` sets `groups.name` (Migration 015; what the apps call the project, defaulting to the alias) under the same admin rule; `SpaceError.invalidGroupName` refuses an empty, over-64-character, multi-line or markup name. `AliasError` distinguishes invalid labels, reserved labels and an ineligible owner.

Migration 006 creates the permanent case-insensitive `aliases` namespace for group aliases, person handles and machine names. Database triggers reserve a spelling on insert/update and reject reuse by any other entity; retired spellings remain reserved. Existing non-personal groups gain aliases (`shared` retains both id and alias); personal groups gain none. Existing people and machine labels take precedence over derived group aliases; live-key machines precede people, who precede revoked machines. Labels replace `-` with `_`, sanitize invalid legacy machine characters, and take deterministic length-bounded numeric `_n` collision suffixes. Machine account names follow the migrated machine names. Existing ids, foreign keys and content stay unchanged. Person handles and machine names resolve retired aliases to their current record. A group's current alias lives in `aliases` alone, in the row it marks `current`, which the space cell writes; migration 043 moves `groups.alias` there, drops the column and the two triggers that copied it, so a rename is one step and nothing is mailed.

Revoking a machine retains its current and retired alias reservations: its names resolve to it and stay taken by every group and every alias kind until the machine is deleted, which frees them all. There is no keyless succession: a wiped box that must register afresh under the same name deletes the dead machine first, and the `machineNameTaken` refusal says so when a revoked machine holds the name. Machine records and their stored history remain by id, and a machine's name lives in `aliases` alone — migration 048 moves it there and drops `machines.name`.

`session_prompts(session_id, generation, revs, rendered, session)` holds a session's prompt for its generation: `revs` is a JSON map from group id to revision for its acting group and every readable group. The first inference captures the map through each readable group's FilesCell read handle; an unwritten group is 0. The session step receives that map and never reads the journals. Creation leaves the row absent; template completion, compaction and Start over delete it in their session step, so the next generation's prompt is as of its next wake. Until then `promptRevisions` is nil and session-home discovery reads live. A pending row keeps its generation, map and opening policy; stale mail cannot replace it. `storeInferencePrompt` reads a committed matching rendering or stages and returns a proposal, mailing its hash before the inference outcome; the cell stores it only while generation/map still match and no rendering has won. `rendered` names the immutable blob containing the system text and tools, and opening text comes from lines 1 and 2. Migration 030 named literal line 0 preambles by hash (045 moved their blobs to the bucket); 046 expands each old prompt revision over every existing group without changing its number. These inference APIs use mail rather than local calls, so an inference job may run on another worker. `InstructionRenderer` resolves each space partial's group to its frozen revision, including group aliases; a group outside the frozen reach is a missing partial. System and machine partials remain unversioned. Frontmatter is dropped, `wuhu_queries` and partials run through injected tools, and failures render one inline error line. `SkillCondition` parses a skill's `wuhu_when`; a malformed one lists the skill with its error.

`deleteMachine(_:by:)` admits only a direct human admin of the machine's current group (or the dev seat), checked through the group's cell before any step; the machine's step carries the group it authorized against, and a machine that has moved out of it is `notFound`, as one that had moved between two concurrent moves is for the second. The owners write what they own: the machine's cell takes its v2 membership, machine row and operations, the space cell frees every current and retired alias, and the account's cell deletes its personas and its own devices with their command/message links, purges the credentials and tombstones the account. Human-owned device links are unlinked by their owners' cells before the machine row goes, so a link that appears in between fails the deletion call and the caller retries. Surviving creator references stay, pointing at the tombstoned account, which access ignores. The machine's step durably mails its group's FilesCell to delete the notes subtree in one revision, even when that subtree is empty. The machine's deletion step itself finishes live callers with `unknownMachine`, removes cell-owned operations and closes sockets, and leaves the presence tombstone behind; a start admitted before it races on the same membership rule, so it cannot recreate a reservation after the step. Operation claims require membership in the same writer transaction, so an admitted start racing deletion cannot recreate reservations after the commit; later writes cannot recreate deleted operation rows.

Session scheduling reads line metadata without fetching message bodies: `transcriptLineCount` excludes prompt keys, `lastReplyPosition` selects the newest assistant position, and `droppable` is an EXISTS query over non-head, non-pressure transcript keys.

## Push outbox rows

`web_push_subscriptions` and `push_relay_grants` are common, unowned tables. Registration in the recipient’s person cell preserves a same-recipient cursor, resets retry state, and starts a new recipient at the newest notification; device-key-scoped revocation deletes the grant. Due-delivery reads return the oldest unseen notification for each eligible grant, ordered by notification number and grant key, and never mutate rows; expired browser subscriptions are excluded.

Outbox mutations are `JobDatabase` operations using StructuredQueries: acceptance advances `notification_cursor` and clears `consecutive_failures` and `retry_at`; a retry increments failures and sets `retry_at`; both set `updated_at` from the job's supplied date. Withdrawal deletes a dead grant; browser expiry cleanup deletes expired subscription rows. These operations run through the shared database's host-write path inside a job's step so ChangeSource observes their changes. `Space` registration and revocation handlers sequence the recipient’s person cell; delivery jobs still mutate these unowned grants directly. There are no host cursor-commit or retry APIs.

Notification inserts and `.changed` mail to both stable `NotificationDeliveryJob` addresses commit in the same `PersonCell` step. The two jobs drain queued mail before reading due deliveries, wake on local mail without clock advancement, and find remote-space mail at the next worker scan. A 15-second receive timeout also drives retries and expiry cleanup. `NotificationDeliveryClient` injects transport effects and refusal classification; due-row reads and typed mutations remain in SpaceCore.

Agent SQL slots join the same `ObservationJob` by durable `ObservationMail.watch` / `unwatch`, not a host registry observation. Only the job writes its owned `observation_slots` table (slot identity, statement, principal source, reply recipient and last marker). It hydrates and reruns every durable watch after a roll; unchanged snapshots are silent. Each changed marker commits with its `observed(slot, rows, marker)` mail, staged before the marker write; a query that no longer runs mails `failed(slot, reason)`. The job carries no delivery policy or slot throttle. Watches run side by side with sockets; results and mail share the existing lane loop, and cancellation does not consume queued results. Each registration has a distinct run identity even when an unwatch/watch pair reuses the same slot key; retirement drops its queued results and rejects late results from that run. Duplicate watch mail leaves the standing row and its marker untouched.

SQL watches derive their current scope and execute the caller statement within one read-connection transaction. The trusted scope resolver uses only server-authored StructuredQueries selects; the sandbox authorizer is reengaged before caller SQL is prepared. Its actual read tables join the query's region, so grants, account/session lifecycle and principal group changes wake precisely the watches that read them. Slot principals derive a session's group anew on every statement run.

Group observer arm/cancel/replacement and hourly-cap pause change watches within the named observer cell's step. Creation mails the parent to arm its children watch in the parent cell; children watch end keeps its existing archive/unarchive lifecycle. An archive changes no handler/plain registration: a watch follows its slot through grace, and the owner retires/unwatches it when a changed snapshot fires while archived. Children keep their existing archive/unarchive watch lifecycle and arm with the empty-result baseline marker, so the parent hears no initial empty result.

Migration 035 historically mailed owner re-establishment messages for pre-job SQL subscriptions. Its one-use `SessionCell.rewatch` handler is now removed; no ongoing registration or compatibility path remains.

Script execs are caller-stream operations, not released by a script-owned kill list. Stream close and replacement-worker orphan discovery stop them as callerGone; an unopened reservation expires after 60 seconds. `MachineCell.background` refuses a request with a script using invalidInput, so script processes cannot outlive their script. Tool exec backgrounding is unchanged.

## Machine file sockets

`MachineCell` also owns `machine_file_operations`, created by migration 036, which discards all legacy encrypted operations and retention without carrying in-flight work; migration 041 adds the output channels a row was dispatched with, so a later step polls a channel for no more than it holds without reading the description again. `FileBulk` is a caller-owned socket whose opening starts a fresh operation. There is no separate start call, finished mail, identity binding, cancel-by-id or reattach. The cell is not an authorization boundary: callers authorize machine access before opening, and `StartRequest.Caller?` remains optional display attribution. Socket membership plus its recorded worker-local id controls its operation; the worker identity fences that id across a roll.

Stat, mkdir, remove, move and search return their bounded JSON result on the socket. Read bytes and list records use worker-tagged `MachinePointer`s into `MachineBuffers`; no contents enter rows, mail or cell frames. Each channel persists separate consumed (`offsets`), offered and cache-admitted (`received`) cursors, with consumed ≤ offered ≤ received. Polls acknowledge `received`, advancing only after a contiguous matching pointer is retained in the current worker cache; stale or overlapping answers never admit a suffix or channel end, and a gap reports `rangeLost`. Prefetch runs independently of caller consumption up to 4 MiB per channel, reserving the full normal poll budget (the box's file piece, 64 KiB unless it advertises more, at most 4 MiB) before every poll, including record channels. Record offsets count records, while cache budgets count encoded bytes; logical credit excludes consumed prefixes even if physical cleanup is pending, and a physical capacity refusal retries without admitting the answer. The caller names its wanted channel offset with `want`, monotonically bounded by the last offer; it releases the consumed cache prefix and receives the next cached range, never beyond `received`. Only one offer is outstanding; cache admission is not caller consumption. Completion and terminal acknowledgments still wait for explicit consumption of every final offset. Both exec and file admission share the same tunnel budget: one control lane plus every output lane and one input lane if any input channels exist, with two streams reserved for the tunnel.

A missing retained range, foreign pointer, expired box range or lost worker buffer yields typed `rangeLost(offset:)`; the cell never starts a replacement operation. One adapter helper permits one fresh stat, read, list or search; collectors discard their materialised prefix and reuse the original request. A second range loss in the same caller operation is returned as typed `rangeLost`; the restart count is local to that adapter call, and a job effect re-run at a roll is a new operation with a fresh budget. The diagnostic lost offset is not a resume cursor; there is no stat or generated ifMatch dependency. A box that forgets an unreported mutation yields `outcomeUnknown`, never a repeated mutation. Closing an unfinished socket stops it with `callerGone` and discards its worker cache; cleanup remains cell-owned until STOP is accepted or the box lease is lost. Accepted STOP proves stopReason was recorded, not that the asynchronous stage cancellation has already finished; existing box receipt retention releases unacknowledged evidence, without acknowledging abandoned output on the caller’s behalf. A roll closes the socket and reports lost range or unknown mutation rather than inheriting another worker's pointer. An undispatched row reports `machineUnavailable` with `started: false`; a new opening without an attached box waits in `pendingStart` while the presence lease is alive. The caller receives `started` when the cell dispatches the operation, before emitting the box start; a socket that closes before that marker is known not started for every kind. A START preparation refusal proves that START never entered the tunnel; it clears dispatched state and deletes the failed row without sending STOP. A failed row accepts its STOP snapshot or `unknownOperation` as cleanup without revalidating previously rejected evidence; transport failures retry STOP and other late answers are ignored. Accepted STOP or full terminal acknowledgment deletes the file row: no retired record or result is retained. No connection task or materialised bytes survive their caller connection or job effect.

File input uses the same caller-owned socket: after accepted start, `ready` advertises its input channels once; a valid control snapshot while reconciling also proves the dispatched operation exists and supplies readiness without repeating START, including when that snapshot is already terminal; byte or record pointers are sent in bounded chunks and `accepted` follows the box receipt. An `operationEnded` refusal of pending input enters control reconciliation rather than inventing a failure or treating refusal as a terminal verdict. An existing control poll is retained; a nonterminal snapshot resumes running and the original pending pointer, while a terminal snapshot supplies the actual result. Only accepted input offsets and EOF state enter the row. These durable cursors determine which queued input remains pending, including EOF. On receiving a whole-frame `accepted`, the caller synchronously reclaims acknowledged input with `MachineBuffers.accepted` before allocating its next frame; no file-cell post-commit task reclaims input. Partial receipts retain only the active bounded frame until whole-frame acceptance, and socket close discards the operation. Accepted predecessors cannot fill either the logical or physical input window. A complete receipt retires its input flight before advancing the row, so cleanup before the next chunk or box reattachment does not imply lost input; an outstanding flight with genuinely missing pending payload still yields `outcomeUnknown`. Migration 038 drops the old encrypted operation/channel/output/retention/maintenance/key-check tables; membership and the current cell tables remain.

Session creation is a LoopCore handler: it reads checks, calls `Space.allocate`, then calls the newborn SessionCell. `SessionCreation` is its Codable input and provides structured cell database operations; `Observer` is Codable for that input. Allocation and session insertion are separate commits. `SessionStore` retains its space reference for those upper-module handlers, not a host transaction door. Generic `SessionStore.rows` is removed. Generation/restart writes are SessionCell step methods; shared read helpers take wuwei Database. `stageBlob` puts prompt bytes through the bucket's door before the session's hash-only prompt step; blobs remain outside this ownership move.

Machine metadata, description and presence reads use `MachineCell` snapshots; cross-machine lookup, alias resolution, listings, access filtering and exec queries use `SpaceCell` snapshots. Machine folder resolution uses the same reads, while transaction-local path validation stays with the host writes.

`ensureDevPerson()` resolves the current or historical `owner` handle to a live human, ensures its settings-admin grant and returns its account and existing canonical principal (persona or account id). If the handle is unclaimed it creates an ordinary admin account, enrolls a generated public key, adopts its allocated persona, claims the handle and removes that bootstrap key; the private key is discarded. A group, machine, guest or removed person holding the handle is a typed startup error, not a renamed or resurrected account. No schema migration or accountless inbox is involved. `Person.account` is required. `Actor.publicReader` has shared’s content-read reach and no member, write, admin, channel, exec or control authority. Session errors no longer mail a literal `owner` inbox.
