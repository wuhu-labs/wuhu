# SpaceCore

## Inferences

`inferences` is an induced, read-only SQL table available through query, observation and scripts with the same group visibility as `sessions`: the unqualified name reads the acting group, a group-qualified name reads a readable group, and the wildcard-qualified name includes `grp`. Opening an existing database creates the table and indexes idempotently; there is no backfill.

Each call has `id`, `session`, `at` (UTC start), `provider`, configured `model`, optional API-reported `served_model`, `effort`, `input`, `cache_read`, `cache_write`, `output`, `reasoning`, `outcome`, `error`, `duration_ms` and `ttft_ms`. `input` is uncached input; total input is `input + cache_read + cache_write`. `output` includes billed reasoning; `reasoning` is its reported subset or null when unavailable. Usage is null when a failed call reports none. Outcomes are `ok`, `networkError`, `httpError`, `timeout` and `cancelled`.

`Space.recordInference` inserts a call for an existing session and derives its group from that session. Observations wake on insertion. No lifecycle operation deletes inference rows: archive, compaction and Start over leave them intact.

## Archive support

`SessionStore.archiveSubtree(root)` returns records in descendant-before-parent order using the parent chain, not `created_by`. `closeRequestsForArchive(id)` posts one replay-safe final-kind message for every still-open request, including undrained input, and cancels its deadline subscription on the parent. The wording explicitly says the session was archived before reporting; it does not claim the requested work was completed. The store's `archive(id, grace:)` and `unarchive(id)` remain single-record persistence operations; the session service owns subtree orchestration and runtime interruption.

Archive reservations are shared by all `SessionStore` values of a space. `reserveForArchive(id, token:)` serializes reservation with session creation, `isReservedForArchive(id)` checks it without waiting for runtime work, and `releaseArchiveReservation(id, token:)` only releases the matching token. Creating a child below a reserved or archived parent fails with `parentUnavailableForCreation`; a separately created top-level agent remains allowed by this storage gate.

## Subscription progress

`SessionStore.fireSubscription` accepts a reschedule only when the new due time, serialized at the database's millisecond precision, is strictly later than the currently stored due time. An equal timestamp, backwards timestamp, absent due timestamp or sub-millisecond change that persists unchanged throws the session-observation SPI's `NonAdvancingSubscription` error, including the attempted and stored due times. A removed subscription row instead throws a stale-callback error. Both reject the fire before enqueueing its notification; the transaction leaves both queue and subscription progress untouched.

The session-observation SPI exposes both a fresh registration snapshot and its change stream, including observation callback identities. The firing registry reloads a fresh snapshot on task completion rather than relying on a due-time key change to wake it. Stored subscription schema and existing off-minute due rows are unchanged.

Request-deadline firing commits the parent queue notification, owner deadline notification and subscription retirement in one transaction. A failed write leaves all three effects uncommitted and the slot retryable; replay after retirement cannot append another owner notification.

## Bounded transcript history

`SessionStore.transcriptHistory` reads a recent tail or one exclusive backward page in a database snapshot. Limits are 1 through 200. Older reads require the generation and before position together; Claude older reads also require the projection history epoch. The output carries ascending positioned entries, a backward boundary, authoritative extra-row exhaustion, the snapshot head and bounded origin attribution. Kernel reads select at most limit+1 pointer/payload rows and one indexed boundary assistant candidate; they do not hydrate the generation. The first leading tool-call result chooses the candidate via immutable chronological source-content row order, then verifies current-generation membership, preceding position and exact call ownership. A missing or excluded candidate yields no origin, never an older fallback. Generation heads do not participate in this lookup; compaction carries chronological source intervals without rewriting content. SQLite-managed VACUUM and VACUUM INTO preserve the relative source ordering used here. The legacy full snapshot is unchanged.

Bounded transcript observations read at most 201 forward entries. Generation changes, missing or stale Claude epochs, unavailable projections and forward lag beyond 200 produce a reset-only page. The HTTP owner closes that stream so the client refreshes its recent tail. Claude preparation is request-owned, cancellable and checkpointed; it performs one bounded chunk rather than scanning archives or starting an eager background walk. The derived Claude tables are disposable, and their identity is distinct from the session runtime generation.

The additive schema creates `claude_history_progress`, `claude_history_items`, `claude_history_seen` and `claude_history_calls`, plus the `claude_code_handovers_by_session(session_id)`, `session_contents_assistant_history(session_id)` partial assistant index and `session_pointers_by_content(session_id,generation,content_id,position)` indexes. No existing table columns change. Opening an existing space creates these disposable structures without changing source history. The first creation of the kernel partial assistant index evaluates JSON across existing source rows and builds its index synchronously: this one-time O(source history) startup work is not a bounded page read, and no fixed startup-time bound is claimed for arbitrary spaces. Subsequent opens reuse the indexes. Malformed source JSON cannot be indexed; valid source payloads are the storage invariant. Old binaries ignore them; raw-pointer and indexed handover-head watermarks detect writes made while running an old binary and force a fresh projection epoch on the next viewed preparation. No space reset or authoritative data migration is needed. Preparation is O(history) in total and bounded per request, not a constant-time cold open.

Marking a session errored preserves corrupt transcript payloads; if transcript decoding fails, its error notification omits assistant text rather than rolling back the visible error state. Unreadable dates or executor/record payloads likewise cannot roll back the durable error update; an unreadable record receives an owner notification without transcript text.

The boot scan evaluates record decoding and parked-task eligibility per session. Its optional synchronous failure handler can collect an ID/error and return to skip only that session; the default handler throws. Database-wide read failures still throw. Corrupt settle history cannot roll back an otherwise valid session’s errored state; when parent failure notification cannot decode history, an owner error notification is emitted instead.

Start over alone writes an optional settle boundary (retired queue tail and sent-message sequence) alongside the new head’s settle snapshot. Valid historical obligations carry over exactly as before, while undrained inputs are still retired. If historical payload decoding or date parsing fails, Start over seeds an empty settle snapshot. Later store folds use the latest restart checkpoint and only subsequent queue/message events, even after compaction; prior payload rows remain unchanged. Heads without a restart boundary retain their prior serialized bytes. Older dev.88 decoders ignore the optional boundary and retain the head and explicit settle snapshot; their store-side full-history folds remain legacy behavior.
