# SpaceCore

## Database lifetime

`Space.inMemory()` opens an isolated SQLite memdb database with no scratch directory or database file. The memory opener uses SQLite’s in-memory rollback journal, while file-backed spaces retain WAL. Memory readers hold read transactions: a concurrent writer commit waits for them, up to the five-second busy timeout, then throws a SQLite busy error. Cancellation interrupts long queries and releases their read transaction. Sandbox readers attach the same memory database; files, tables, revisions, identities and queries follow the same implementation as `Space.open`. An unavailable memory VFS throws a SQLite database error, never opens a disk substitute. Memory databases copy a schema template without an identity, then run ordinary preparation. Both opening paths run the same ordered GRDB migrations and seed their own identity; existing file-backed data is retained. Migration 001 establishes the baseline for fresh and existing databases. Applied migrations are recorded transactionally in `grdb_migrations` and never run again. The space's log gets a notice before each migration an open applies (`migration 008: applying`) and one once its transaction commits (`migration 008: applied in 412 ms`, measured on the space's injected date); a failed migration logs only the first. The once-only links reindex remains post-open maintenance because it reads external object storage and parses documents. A file-backed space's writer gets a 64 MiB page cache and every read connection a 16 MiB one on its attached database, each with a 2 GiB mmap (`PageCache` in SpaceSQL); a memory space's writer keeps SQLite's defaults. The writer of both openers sets `PRAGMA secure_delete = OFF` on every connection it opens, so freed pages are not zeroed whatever the linked SQLite's compile-time default; read connections never free pages.

Migration 005 removes the obsolete session blob ownership table without changing stored image bytes or transcript references. Worker media reads resolve both blob hashes and attachment paths independently of the session’s current group access.

## Scope context

Nothing of scope context is staged here: the worker computes it after a tool call and appends it as an ordinary notice behind the tool result, and the notice entries carry the hash-to-first-path map that rebuilds generation-scoped dedupe state.

## Direct messages

`SessionStore.post` refuses every `.dmUser` post by a session, including a readable person–person DM addressed by id, and refuses either side posting into a person–session DM with `SessionStoreError.humanAgentDirectMessage`, whether opened with `.dm(with:)` or addressed by an existing conversation id, for either poster. The refusal text is exactly: "There is no DM between human and agent. To notify a human, post in your conversation box, optionally specifying the reply target's message ID: it notifies whoever wrote there last and anyone who wrote there in the past 24 hours." The transaction writes no message, conversation, notification or queue input on refusal. Existing person–session DMs remain readable; there is no deletion or migration. People’s person–person DM posts, session–session DMs, boxes, group conversations, requests and reports are unchanged. Only an agent's box creates ordinary-message reply duty, never a person–session DM.

## Inferences

`inferences` is an induced, read-only SQL table available through query, observation and scripts with the same group visibility as `sessions`: the unqualified name reads the acting group, a group-qualified name reads a readable group, and the wildcard-qualified name includes `grp`. Opening an existing database creates the table and indexes idempotently; there is no backfill.

Each call has `id`, `session`, `at` (UTC start), `provider`, configured `model`, optional API-reported `served_model`, `effort`, `input`, `cache_read`, `cache_write`, `output`, `reasoning`, `outcome`, `error`, `duration_ms` and `ttft_ms`. `input` is uncached input; total input is `input + cache_read + cache_write`. `output` includes billed reasoning; `reasoning` is its reported subset or null when unavailable. Usage is null when a failed call reports none. Outcomes are `ok`, `networkError`, `httpError`, `timeout` and `cancelled`.

`Space.recordInference` inserts a call for an existing session and derives its group from that session. Observations wake on insertion. No lifecycle operation deletes inference rows: archive, compaction and Start over leave them intact.

## Archive support

`SessionStore.archiveSubtree(root)` returns records in descendant-before-parent order using the parent chain, not `created_by`. `closeRequestsForArchive(id)` posts one replay-safe final-kind message for every still-open request row, including undrained input, fails the row in the same write, and cancels its deadline subscription on the parent. The wording explicitly says the session was archived before reporting; it does not claim the requested work was completed. `trimSlotsForArchive(id)` deletes the session's retiring slots and clears handler firings. The record writes of the session verbs (`retitle`, `retag`, `requestCommand`, `markInterrupted`, `markResumed`, `archive(grace:)`, `unarchive`, `restart`) are `SessionRows`, the session cell's; the store has no async form of them. Creating a child below an archived parent fails with `parentUnavailableForCreation`; a separately created top-level agent remains allowed.

## Subscription progress

`SessionRows.observed(session, subscription, token:, _:)` is the session cell's step for what main saw of a plain slot (`Observed`): a `change` puts its notice on the slot's topic (replacing the one the model has not seen, due no sooner than the slot's throttle past the last it saw; the children watch has none) and moves the slot's marker, delivery sequence and last-fired time; `quiet` moves the marker alone; `failed` puts the slot's last notice and deletes its row. It answers `ignored` and writes nothing for a slot that is gone, one armed again since (the token is the arming's observation incarnation) and a marker the slot already has; a session that can no longer act (archived) is told nothing and its row is deleted (`ended`, as after `failed`).

The session-observation SPI exposes both a fresh registration snapshot and its change stream, including observation callback identities. The firing registry reloads a fresh snapshot on task completion rather than relying on a due-time key change to wake it. Stored subscription schema and existing off-minute due rows are unchanged.

`requests` (migration 008; 027 dropped `kind` and `key`; 028 added `conversation_id`, backfilled from the request message, and deleted the rows whose request never posted) holds one row per request, id = the request message id, owned by its conversation's cell (`ConversationCell.owned`), and is the only store of a request's state: the request's conversation (the task's DM with its parent, else its own box) writes it in its cell, in the step that writes the message: `openRequest(terms:)` checks who asks (`notTheParent`, `requestAlreadyOpen`) and inserts it with the request message, `report` closes it with the final, and archive fails it; creating a session with `expects_reply` writes no row before its request message, and a task that errors leaves it open. A schema'd final whose content is not JSON matching the schema throws `reportRefused(id, violations:, left:)` and posts nothing; the `RequestTerms.refusalLimit`-th refusal instead posts a final-kind failure and fails the row. Migration 008 backfills a row for every request message (`done` with a final-kind message, archive closes included; `overdue` past its deadline; else `open`), throws if any request message lacks exactly one row, logs the counts, and drops `messages.deadline_at`.

`openRequests(task)` lists that session's open rows: what it owes, and the only source the kernel's park, nag and wake decisions read. A request message is delivered as a request only to its task; any other session it reaches (a mention) gets a plain message without its request id.

`openRequest(stallSeconds:)` stores the seconds on the row and, when the requester is a live session, puts a `requestStall` notification on the requester's queue under topic `quiet:<request>`, due that many seconds after the request message. A progress report puts it again, due that many seconds after the report; the final and archive clear the topic. The notice only says the task has reported nothing for that long; it reads no task state.

## Removed executor

A stored executor other than `kernel` decodes as `SessionExecutor.retired(kind:)`. Creation, resume, restart and unarchive throw `ExecutorUnavailableError` with description "executor no longer supported"; plain hydration returns an empty transcript, as do `transcript` and `transcriptSnapshot`; boot eligibility selects only `kernel` sessions. Queue input, identity, box, home, tags and children remain stored. Only Start over onto a supported executor clears the record; restart away opens a kernel generation and retains readable queued input and subscriptions. The removed executors' stores are dropped by migration 002.

Marking a session errored preserves corrupt transcript payloads; if transcript decoding fails, its error notification omits assistant text rather than rolling back the visible error state. Unreadable dates or executor/record payloads likewise cannot roll back the durable error update; an unreadable record receives an owner notification without transcript text.

The boot scan is one query: live kernel sessions with work, a command, or an open `requests` row. Corrupt settle history cannot roll back an otherwise valid session’s errored state; when parent failure notification cannot decode history, an owner error notification is emitted instead.

Start over alone writes an optional settle boundary (delivered queue tail and sent-message sequence) alongside the new head’s settle snapshot. Valid historical obligations carry over exactly as before, while undrained inputs stay queued for delivery into the new generation. If historical payload decoding or date parsing fails, Start over seeds an empty settle snapshot. Later store folds use the latest restart checkpoint and only subsequent queue/message events, even after compaction; prior payload rows remain unchanged. Heads without a restart boundary retain their prior serialized bytes. Older dev.88 decoders ignore the optional boundary and retain the head and explicit settle snapshot; their store-side full-history folds remain legacy behavior.

## Image fitting

`ImageFitting.prepare` makes the copy a transcript keeps: a PNG or JPEG is always decoded, fitted to the limits (`ImageLimits.intake` by default) and re-encoded, so the result carries the source's pixels and none of its metadata, is the same bytes for the same source, and passes `fit` unchanged. One no codec here decodes is refused. Any other format is handed to `fit`. `ImageFitting.fit` passes images whose measured dimensions and byte count already fit through byte-identically. Oversized images are decoded, resized to the long-edge and patch limits, and encoded to the byte limit. If fitting fails, the explicit `[image not sent: … this server could not re-encode it]` note is returned; no oversized fallback image is sent. Unmeasurable bytes within the byte budget pass through for the provider to judge. `ImageFitting.png(rgba:size:)` encodes unpremultiplied RGBA8 rows losslessly with the same codecs (ImageIO on Apple, CImageCodec on Linux), nil on a platform with neither.

Apple platforms keep ImageIO, including its thumbnail EXIF orientation transform and PNG/JPEG encoding behavior. Linux decodes PNG and 8-bit JPEG with Bazel-pinned libpng and libjpeg-turbo; palette, grayscale, 16-bit and alpha PNG inputs normalize to RGBA8. JPEG EXIF and PNG eXIf orientations 1–8 are applied using bounds-checked TIFF views without copying chunk payloads. Bilinear interpolation weights colors by alpha. Both encode a PNG source as PNG when that fits the byte limit and as JPEG when it does not, and any other source as JPEG. Linux composites transparency on white for JPEG and tries qualities 85, 70, 55, 40 and 25; ImageIO encodes at 85 only. If bytes still do not fit, both retry at three-quarters of the long edge down to one pixel. Oversized other formats remain explicitly refused.

Image fitting refuses absurd header dimensions and uses checked arithmetic before invoking the model sizing calculation; `ImageLimits.fitted` computes its area ratio without overflowing integer multiplication. Linux decoding and C encoding reject images above 40 million pixels before allocating pixel buffers. Before libpng sees a PNG, a bounded chunk scan validates lengths and CRCs, requires a complete terminal IEND, and keeps only critical pixel chunks, transparency and fixed-size color/gamma chunks. Compressed text, ICC and other ancillary payloads never reach libpng and cannot expand into metadata allocations; eXIf orientation is applied separately in Swift. TurboJPEG confines libjpeg error longjmps to its C implementation, stops on truncated-input warnings, caps progressive scans at 100, and caps internal memory at 128 MiB. Bad input returns a fitting refusal rather than aborting the process.

## Guarded schema and historical inspection

`alterTable` accepts an optional VersionToken and allowDropColumns (the checked service requires the token and defaults the drop acknowledgement to false). Table liveness/kind is checked before the token, so missing, moved, deleted and non-table paths report notATable rather than a stale-token conflict. The liveness check, token check, omitted-column check, schema journal and DDL occur in one transaction; failure rolls everything back. Type changes remain refused. `tableSchema` reads the live header/token or a historical header/token, checking revision existence and node liveness in the same read transaction. Missing paths are notFound; non-table nodes are notATable. Historical tokens identify the historical node version, not an overwrite receipt. The checked SpaceToolContext boundary resolves caller paths, validates headers, and enforces group, session-home and protected-layer policy for HTTP and scripts; trusted core calls do not acquire a wallet identity. Template allocation/creation continues to use its existing atomic transaction.

## Guarded file creation and historical restoration

`writeFile(path, data, in, acting, ifMatch, createOnly)` resolves machine-note aliases and delegates to LiveFS's checked transaction. With createOnly, any current node conflicts before deduplication or replacement. A supplied version token is compared in that same transaction. The existing VFS write entry point keeps its optional-token semantics. `checkout` accepts optional ifMatch/createOnly checks against the current head inside the restoration transaction, before comparing content, minting a revision or altering file/table materialization. When both the historical node and live head are files with the same blob hash, checkout returns the live revision and current token without minting a revision, journaling history or emitting a mutation. Table checkouts always mint a revision, even when their restored rows are identical; restoring nonexistence keeps its existing deletion behavior. `history` supports an exclusive after revision and optional limit; the ordered join is a StructuredQueries selection and its limit is applied by the database.

`Space.fs(..., listingLimit:, listingByteLimit:)` optionally bounds listing hydration in the live-head, historical-version and machine-alias queries before Entry arrays are allocated. Non-nil limits must be positive. Cursor hydration stops when the running escaped-name size plus a conservative 256-byte metadata allowance per entry crosses listingByteLimit, throwing listingResultTooLarge. No full row array is hydrated first; historical listings convert each cursor node directly into an entry. The default remains unlimited for existing callers; script services select their cap plus lookahead and fixed hidden-root overhead.

Start over is an empty-summary compaction without a retained tail or pre-reads, using the same generation-head writer as compaction. It preserves armed observations (including callback identity and firing progress), and one-shot and cron timers; the new head lists the slots its caller passes (the cell's `session_armed`), or what the stores hold for a session whose cell has no list yet. Park reminders and pending compaction commands are removed. Error, hold, run/heartbeat/progress and retry state are cleared; the executor/model may change. Readable queued rows are neither marked delivered nor removed: a nonempty readable queue sets `has_work` (the cell that restarts advances into it), while subscriptions and the restart note alone remain inert. Session identity, conversations, prior generations, home files, children and open requests in either direction remain unchanged.

Start over validates each pending queue payload and its stored dates. Unreadable inputs are dropped from delivery and counted explicitly in the restart note; their original rows remain intact. If any input is unreadable, all readable pending rows move in FIFO order to IDs above the old queue head with their `input_id` and payload unchanged, and the tail/checkpoint advances past the unreadable originals in the same transaction. Re-enqueuing a moved input deduplicates against its unchanged identity. An all-unreadable queue remains inert and no longer prevents hydration or archive. Start over also clears `parkReminderCount` and `lastParkReminderAt` on retained open requests without changing their other fields or closing them.

## Box notifications

A box post appends a `conversationMessage` notification row only for person members, other than its sender, who are the box's latest writer or wrote there within the 24 hours before the post's routing time (inclusive). A write is a post with no sender session and no observer firing; a group observer's post is none, so an observer is never a writer. The latest writer is chosen by message position, never by timestamp: a person's own post makes them the latest writer, so it notifies only others who wrote within the window; a session's or observer's post notifies the latest earlier person writer as well. A member who never wrote there gets none. Membership is unchanged: a quiet member still reads the box. Only a box post reads writes: it reads on the box's own index back to the window's start and, only when the window holds no person post, back to the latest one. Channel and DM notifications and session routing are unchanged.

## Human-only channels

`users` conversations are channels. They have people-only members and an optional title stored in `conversation_titles`; an absent row or NULL title preserves the members' names fallback. The additive side table opens on existing spaces without ALTER or backfill. Existing users rows are channels; historical session member rows confer no human access and no new session memberships are inserted.

`createConversation(members:title:in:)`, `addChannelMembers(_:people:as:)`, `removeChannelMembers(_:people:as:)` and `renameChannel(_:title:as:)` manage channels. Validation and each mutation are atomic. Any membership operation naming a session throws `ChannelError.sessionMember`; person aliases (including historical aliases and case variants) resolve to canonical directory ids before create/add, and unknown people throw `ChannelError.unknownPerson`. Remove deletes both the supplied spelling and its person-alias target, including legacy raw rows, with no directory validation; removing a nonmember stays a no-op. Person–person DMs resolve the recipient through the person directory before choosing their deterministic id and storing members, so aliases share one conversation and unknown people throw `SessionStoreError.unknownPerson`. The authenticated sender id is preserved, including the unenrolled `--dev` seat. A blank non-null title is refused. Person members manage, read and post. Every session whose group reads the channel's home group reads and posts without becoming a member, and manages when its role there is write or admin. Each of the four is one call to the conversation's cell. Other people cannot read or post, even in a group that reads the home group. An unread channel is indistinguishable from a missing conversation. The anonymous principal, including the `--dev` seat and `--public-read` reader, neither creates, reads nor manages channels; management returns the same unknown-conversation refusal as for a nonmember person. `conversations(reader:group:)` retains most-recent-active ordering by last message position descending.

A conversation's rows (`conversations`, `conversation_members`, `conversation_titles`, `messages`) are written only in steps of its cell, and a person's (`notifications`, `watermarks`) only in steps of theirs. The space's writer enforces it once its worker exists: `ConversationCell.owned` and `PersonCell.owned` name each table's owner column (`id`, `conversation_id`, `recipient`, `identity`), and a statement on the writer that writes such a row outside its owner's step aborts with "a row of <table> belongs to another addressable". Migrations run before the worker and are not guarded. An agent's box needs no row to be read: from the session's creation `conversation(_:)`, its pages and its live tail answer for an empty box homed in the session's group with the session as its one member, and the first post writes the row. Until then the box is absent from `conversations(reader:group:)` and from SQL over `conversations`. A task has no box at any time.

Channel plain messages notify person members but enqueue no session unless addressed. Mention, reply-target and the attention window retain their existing behavior: after an agent answers, subsequent messages reach it only while both its message-count and time windows are open; the window closes at whichever bound passes first. Tasks do not join the attention window; a person's post never wakes a task. SQL conversation, member, message and channel-message notification views enforce the same channel readership, including qualified group and wildcard views. `readsFile(_:in:as:)` applies channel readership before group readability for file/attachment access, attachment-copy sources and parent directory listings. Removing a person from a channel also prevents copying its attachments into another conversation. `observeConversation(_:after:as:)` revalidates its principal in each snapshot, wakes on membership and group-read changes as well as messages, and terminates on loss of readership. Everything sidebars observe channels and the person's notification/read-marker unread state.

An attachment is a row of its conversation, not a file of the group's journal: `attachments` (conversation, path, blob hash, size, created) is owned by the conversation's cell. `SessionStore.post` stores each upload's bytes by hash before the call; the post's step places the upload at `/_/conversations/<id>/attachments/YYYY/MM/DD/HHmmssZ/<name>` (the next free `-<n>` on a clash) and writes the row with the message, so a refused post leaves only an unnamed blob. `Space.fs` answers everything under `/_/conversations/` in a group's tree from the rows of the conversations homed there (`AttachmentFolders`): files and implicit folders, with no revision, history or mutation event, the same at any `rev`; the journal refuses every mutation there, as it always did (reserved paths). Migration 029 copied the journal's attachment files into rows and 031 deleted the journal's own: heads, versions and induced docs under `/_/conversations`, leaving their revisions and blobs.

## Subscription handlers

A session with a live child has a `children` slot (kind `.children`), armed in the write that creates or unarchives a child and deleted in the write that archives its last: an observation of its live children that errored, put on its queue under the topic `children` when a child joins them and never when one leaves. Neither `subscriptions`, `armedSubscriptions(_:)`, `<session-state>` nor cancel shows it; an errored task's owner notice is `session_errored` like any session's.

`SubscriptionSlot.handler` is an optional space module path. The existing subscription payload stores its distinct arming incarnation, last error, failure-streak flag, and current firing (its attempt token, running or retiring); legacy payloads decode with these fields absent. `ArmedSubscription.armedAt` is the original registration time. Re-arming an existing subscription ID is a crash retry and returns its persisted truth unchanged. Cancelling then re-arming mints a new handler incarnation and observation callback identity.

`ObserverRows` is what a handler slot's observer cell writes of its row, in the cell's step; nothing else writes a session's handler slot. `arm` inserts the slot its session armed (one that stands is left as it is), `pend` replaces the input that waits, `begin` names the firing on the slot, records last-fired and logs it running, `finish` ends it: success clears the last error and takes the input, reschedules a cron or retires a one-shot; a failure records the error and notifies only on the first of a streak; a firing whose slot went meanwhile marks its wakes as the slot's last; one whose owner can no longer act is logged cancelled and tells no one. `end` is a source that refused to go on (a stream, a query that can no longer run): a session's slot ends with its last notice, a group's pauses with the reason. `retire` deletes the row. Script filesystem/table/message effects remain immediate and at-least-once, not part of the step.

Archive preserves registrations for unarchive within grace. The registration observation tracks owner lifecycle (`orphaned`). Main retires nothing: a firing that comes due, or rows that change, while the owner cannot act end the slot in its owner's step without running the handler or telling anyone; slots that neither fire nor change remain after unarchive.

Silent handler retirement does not enqueue a notification or wake the owner. `SessionRows.armedSlots` returns what the stores hold of a session's own slots (its `subscription_slots` rows but the children watch, the plain timers on its queue, its streams) and which of them run a handler: what a session from before `session_armed` lists at its first step.

Handler-backed timers and observations are not guaranteed model wakes and do not suppress an open request's park backstop. Hydrated/current transcripts and returned compactions carry handler IDs as transient metadata alongside the durable registration-ID projection; plain timers retain their prior wake guarantee. Neither projection is stored in transcript Codable bytes or historical entries.

## Group observers

`subscription_slots` (migration 009) keys every slot by its owner: `owner_kind` `session` or `group`. A group's slot carries a `name` unique in that group (a slug: lowercase letters, digits and hyphens, at most 64), a `status` (`armed` or `paused`) and `sessions_per_hour` (default 10). `armObserver` refuses a taken name (`conflict`), a slot without a handler and a removed group; arming the name of a paused observer replaces it. `cancelObserver` deletes it; what it made stands. `createSession(observer:)` stamps the firing and admits the session in the write that inserts it, counting the sessions created by `<name>@<group>` in the last hour (a replayed receipt is not admitted again); at the cap it pauses the slot with the refusal as `last_error` and refuses (`observerPaused`, as does a paused observer's firing still in flight). A group observer whose query turns invalid is paused with the error by its cell (`ObserverRows.end`). A paused slot does not fire until armed again.

An observer acts as `Actor.observer(Observer)`: its group's role, nothing of its own. What it creates records it: `created_by`, `requester` and `sender` are `<name>@<group>`, and `sessions.firing`, `requests.firing`, `messages.firing` and `inferences.firing` carry the firing id (`inferences.session` is null for an observer's inference). A person's terminal script's inference has the person's personal group as its `grp` and the run's id as its `firing`. An observer's revisions record `via` `firing:<id>` in `revision_actors`. `beginSubscriptionHandler` writes the firing's `subscription_firings` row (owner, subscription, name, group, `at`) as `running` before it is dispatched; `finishSubscriptionHandler` ends it `ok` or `failed` with its `error`, or `cancelled` when its slot or attempt is gone, `cancelFiring` ends one whose task was cancelled, and `interruptFirings` ends every `running` one as `interrupted` when the firing loop starts. Ending a firing records `effects` as `{sessions, requests, messages, revisions}`: the ids stamped with the firing and the revisions attributed to it. A finish deletes ended firings without effects older than seven days. A group slot's wakes are dropped: it has no agent. `subscription_firings` is an induced table grouped like `sessions`; `subscriptions` lists group slots with `name`, `status` and `sessions_per_hour` and a null `session_id`.

## Filesystem observation

`observeFS(glob:from:group:)` yields `FSCommit` values, each with a group, revision and nonempty matching event array. A commit is delivered atomically, in serialized database commit order, by a transaction-scoped buffer emitted after a successful commit while the writer is still held. The buffer is discarded on every rollback, including SQLite-initiated rollbacks that GRDB does not notify, and rebuilt on deferred external-blob retries. AsyncStream yields buffer without waiting for subscribers: a stalled consumer never blocks database writes. Cross-group moves yield a filtered commit in each affected group's stream. Unmatched revisions yield nothing. Recipient selection and filtering hold the subscriber mutex; delivery releases it before yielding so cancellation cleanup can remove a subscriber without a lock inversion. The serialized writer remains held through delivery, preserving commit order even when filesystem callers are concurrent.

With `from`, the subscription is registered before reading the journal snapshot. Replay groups the journal events by revision and filters each group by the glob; the live copy of every replayed revision through the snapshot ceiling is dropped whole. The `mutations` stream adapter flattens commits for legacy SSE and script consumers without changing their event shape.

## Live nodes

A `.wmd` or `.canvas` file is the canonical text of a live Loro document; its extension picks the `LiveFormat` (LiveDocument; the formats are WmdDocument's markdown and CanvasDocument's board) that configures the doc, projects it to text and merges an agent's text back. Migration 014 adds its rows, shared by both kinds: `wmd_snapshots` (one snapshot per node), `wmd_log` (the updates logged since, by `seq`) and `wmd_checkpoints` (the Loro frontiers each checkpointed file revision holds). Every row is keyed by `(grp, path)` and lives exactly as long as the file: a delete, a move onto the path and a checkout that removes it drop them in the same mutation. A move carries them along, across groups too, and records that the latest checkpoint also wrote the move's revision; a move to another extension, or of a file its rows no longer describe, drops them.

The node is the only writer of its file. Nodes live in the space's hub, one actor per `(group, path)`, from the first connection or agent operation until nothing uses them. Every writer of a live file goes through it: the file tools, `/v1/f`, a checkout (its historical text is written as an agent write based on the current revision), a template instantiation and a machine move (the rows travel with the notes; see above). Each log append and checkpoint checks, in its transaction, that the file's head is still the revision the node holds; a node whose file a delete or move took closes every connection with `notFound` and is dropped. Its client does not reopen anything: it finds the file anew, at its new path or not at all.

`Space.liveChannel` connects one authenticated client to a node. A connection's update is imported, appended to the log and only then relayed and acked; a failed append drops the node, so memory never holds an edit the log lacks. An update before the client's `sync` is a `protocolViolation`, one with missing dependencies `missingDependencies`. Opening a missing live path is refused `notFound`, so a reconnect after a delete or move never brings the document back; only a writer whose hello asks to `create` gets it, empty. A reserved path (outside session homes and machine notes) is refused `forbidden`. While a connection is open the channel re-evaluates its access whenever groups or roles change: losing write closes it with `readOnly`, losing read with `forbidden`.

A checkpoint writes the canonical text as the file, the snapshot and the frontiers in one revision and trims the log it holds; the checkpoint frame then goes to every connection. Checkpoints happen when editing has been idle `LiveNode.idleCheckpoint` (5 s on the injected clock), when the last connection leaves or the server closes it, before a read of a node with uncommitted edits, on every agent write and on a graceful stop (`Space.close` checkpoints every live node before anything else, uncancellably). `Space.open` sweeps the documents a crash left with logged edits and checkpoints them. Keystrokes never mint a revision. A file whose head is not the revision of a checkpoint row (written before the node existed, or by an older server) seeds a new document from its text, and its history restarts there.

An agent `write` of a live file is merged, not replaced: its text is diffed (a `.wmd` block by block, a `.canvas` by id) against what the writer read, the checkpoint its `ifMatch` revision names exactly (no checkpoint row at that revision is `versionMismatch`), and the changes apply from a fresh peer id drawn from the space's injected random generator, so edits made since survive. Without `ifMatch`, the base is the latest checkpoint. The write is committed before it is relayed; a failed commit drops the node. Text the format refuses is `SpaceError.liveSyntax(path:line:reason:)`. A checkout's historical text, a write that creates the file, and a file's text seeding a new document merge as a restore: a `.canvas` id the board no longer has comes back instead of being refused. A file that is not UTF-8 or does not parse is foreign: a connection to it is refused `notLive`, a read returns its bytes, and a full write replaces it.

## Trusted import support

`createTable` accepts an optional `RevisionAttribution`, recorded atomically with table creation just as `commitRows` records row-mutation attribution. `removeEmptyDirectory(path, in, acting)` checks directory kind and child absence in the same write transaction as its tombstone: a nonempty directory returns false without a revision; a missing/non-directory path throws its typed SpaceError. It refuses root/reserved paths. This trusted core primitive never recursively removes children and is used by import staging cleanup.

## Trusted composition and provisioning

`Space.open(file:identity:objects:log:)` optionally supplies the durable identity when provisioning a new database. A malformed identity throws `SpaceIdentityError.invalid` before creating the file; reopening an existing database with a different identity throws `SpaceIdentityError.mismatch` before schema preparation, without overwriting its identity. Omitting identity retains the existing entropy-generated id and reopen behavior. The supplied identity seeds only a database without an identity row.

A file-backed space is closed before anything else uses its file. `Space.open` starts the crash sweep, which holds the space, so one dropped unclosed releases its connections later, on its own; the last WAL connection's close checkpoints under an exclusive lock, and an unretried open of the file meanwhile fails `SQLITE_BUSY`. Whoever opens a space closes it with `close()`, on a thrown error too.

`UserRecovery.add(space:name:admin:)` returns the created AccountRecord and uses the same first-admin and reserved-name policy as the offline folder command. `UserRecovery.invite(space:account:server:ttl:)` validates the account and uses the same single-use device enrollment token, deployment origin/fingerprint and output/note format as the offline folder command. These overloads permit trusted in-process administration without opening a second database instance or requiring the server to stop; they add no HTTP authorization bypass.

## Machine v2 persistence and diagnostics

`machineV2Store(group:key:)` supplies the production OperationStore on new machine_v2_operations/channels/output tables; it never selects MemoryOperationStore or v1. The caller supplies a durable 256-bit symmetric key. Complete metadata/start inputs, pending writes and output payloads are AES-GCM encrypted with group/id authenticated context; input identity uses canonical keyed HMAC rather than a secret-bearing diagnostic summary. Wrong/lost keys are storeUnavailable, not plaintext recovery. Tables are additive; existing machine/exec rows keep their meaning. Migration 011 indexes admission on `machine_v2_operations(machine_id, active, reserved_bytes)` and channel lookup on `machine_v2_channels(operation_id)`.

Claims atomically reserve capacity, persist dispatch_consumed and unique `(grp, owner_scope, invocation_key)` before returning the one-use dispatch bit. Changed machine/start input is invocationConflict. Updates atomically persist encrypted payloads, cursors, accepted offsets, pending identical writes, evidence generations, snapshots, caller budget and stop intent, and roll back every field on throw. Admission is by bytes alone: the described machine's buffer, shared by every group's operations on it; there is no count cap per owner scope, group or machine. Each refusal names its bound (`bufferBytes`, `machineBufferBytes`, `pendingInputBytes`, `outputBytes`, `inputBytes`), and a reused operation id is `operationExists`. Retained output is one sealed row per chunk; a row that does not open or does not match its id is `storeUnavailable`, never skipped. Output rows an earlier server kept per channel are recognized by their id: the operation's output is dropped (`discard`) and its next write deletes them. Terminal/unknown receipts release live admission slots immediately; actual retained output and pending input stay counted against the machine buffer budget until taken or pruned. Encrypted receipts and unread output remain recoverable for seven days. Lazy five-minute maintenance prunes expired terminal receipts. Retained input/output use the same per-kind channel window capacities as OperationClient. The same store contract suite runs against SQLite, with reopen, concurrent claim, privacy and wrong-key examples.

`machineV2Recovery(group:key:)` returns owner+record pairs, including stop intent, for slice 5 to reconcile by ID and stop dead script owners; it never returns a new start permission. `registerMachineV2` validates the separately enrolled identity/group and records explicit membership. `recordMachineV2Presence` persists attached/detached/lost evidence, descriptions, local observation timestamps and reasons supplied by the coordinator; it does not derive presence from connection state or use peer timestamps. Slice 5 owns authenticated tunnel routing/coordinator startup and persistent key provisioning.

Machine exchanges are traced as OpenTelemetry spans by OperationClient, never in the space database: migration 013 drops the former `machine_v2_trace`, `machine_v2_incidents` and `machine_v2_problem_index` tables with their incident retention and problems maintenance rows, and leaves any `/wuhu/machine-v2-problems.table` content alone. Operational tables and encrypted payloads are not in the query catalog.

## Session rows and compact commands

A session's own writes are `SessionRows` functions over a transaction its caller holds: the session cell's, on the space writer's connection that wuwei lends it; `SessionStore`'s async methods of the same name wrap them in a write of their own. `materializeCompactRequest` puts a pending compact command's instructions into the transcript once, as a `compactRequest` notification (an empty one for no instructions), so the forced step answers a transcript of its own; the command stays pending until `append` or `writeCompaction` with `completingCompact` ends it in its write. Start over deletes standing commands. Hydration returns the generation from the same database snapshot as the transcript, and `stepTry` (`session_runtime.step_try`, migration 018), which `markResumed` increments.

## Machine v2 durable key validation

`machineV2HasEncryptedState` checks only the new v2 key-check/operation/channel/output tables. `validateMachineV2Key` authenticates the key check and every existing encrypted operation payload before dispatch can begin, and creates a key check only when absent. The authenticated check lives in its own `CREATE TABLE IF NOT EXISTS` table, so prior v2 rows and all v1 rows remain untouched. An absent external key with encrypted v2 state, a wrong key, or a malformed encrypted record is `storeUnavailable`; there is no plaintext or regenerated-key recovery. `machineV2RecoveryGroups` includes every group with stored operations, including removed groups, so startup cannot overlook an abandoned owner.

`machineV2DetachedMembers` reads confirmed, group-filtered detached presence at startup. The coordinator preserves that goodbye across server restarts and silence; only new valid description evidence reattaches it.

`consumeMachineV2JoinToken` checks machine-account membership in the additive v2 table inside the enrollment transaction before consuming a token or installing its key. Passing today's machine token leaves both token and key rows untouched. A machine move atomically updates its v2 membership/presence group while preserving immutable operation-owner groups. Existing enrollment behavior is unchanged.

Retained buffer reservations are counted across all caller groups sharing that machine; group and script admission remain group-scoped. Claims are serialized in the same store transaction, and cross-group capacity rejection reveals only `capacityExceeded`.

`machineV2PresenceEvidence(machine, group:)` returns only that owning group's persisted typed state, observation timestamp and optional reason. A registered member with no presence row is explicitly lost/neverAttached since its registration time; an unknown machine or different group returns nil. Missing-route routing can preserve confirmed detached/leftAt evidence across restart instead of inventing lost. Malformed stored state or timestamp throws `storeUnavailable`, never a synthesized state or date. Callers still authorize access before selecting the owning group.

Attached and detached observations record the fresh local answer/goodbye time. A lost transition preserves the previous observation timestamp, including a prior lost silence origin; a never-observed member uses its registration time. Consequently lost evidence supports stable silentSince diagnostics without synthesizing the time of a failed route lookup or changing the coordinator's monotonic lease accounting.

`addMachineV2(name:group:)` creates the machine account, separately named machine, owning-group v2 membership and one-hour single-use exec-machine join token in one serialized transaction. Every insert failure rolls back the complete enrollment, so retry can reuse the name; no half-created identity or token survives. Names follow the normal machine-name validation and global uniqueness rules.

`enrollMachineV2(name:group:pubkey:device:enrolledBy:)` is the token-less one-call form: one transaction creates account, machine, v2 membership, live exec-machine key (created by `enrolledBy`) and optional device link. It is idempotent per person: when the name is held by a v2 machine in the same group whose live exec-machine key is `pubkey` and was created by the same non-nil `enrolledBy`, it returns that machine and key without inserting anything (re-applying the device link); otherwise the held name is `machineNameTaken`. Consuming a machine account's join token writes a `join_token_receipts` row (token hash → pubkey, cascading with the key, pruned at the token's original expiry) in the claiming transaction, so a consumed machine token replayed with the same pubkey returns the same live key and any other pubkey is `JoinTokenRejected`; a person's token writes no receipt and stays strictly one-time.

## Durable model routes

`session_model_routes` and append-only `session_model_route_history` are additive `CREATE TABLE IF NOT EXISTS` domain tables. Existing tables/rows are unchanged; old direct sessions have no route and no backfill; their first execution establishes a concrete binding with nullable group/member. Group creation and Start over commit a legacy-readable concrete executor_config plus additive intent and `SessionModelRoute` with the session/generation/receipt transaction. Failed/busy operations cannot partially replace a pin. `modelRoute` reads it; `establishModelRoute` returns an already committed pin unchanged rather than repicking. Interrupt/resume and reopen preserve route epoch and placement evidence. Ordinary compaction can atomically replace a quota-aware group pin; a retained pin has no history churn. Start over replaces or clears the pin atomically without erasing previous decisions; switching to a direct target clears it. Rows include concrete provider/model, nullable group/member and phase `pinned` (groups) or `bound` (direct); payload carries requested group, effective effort, member, binding fingerprint, placement time/reason and all headroom evidence. FK deletion follows session deletion. The scoped readonly SQL projections `session_model_routes` and `session_model_route_history` follows `sessions` group visibility, including qualified/wildcard reads; it is not an editable space `.table`. Failure provenance lives in the existing route payload, not a new table.
## Cache warming scheduling

The additive `session_cache_warming` table stores only an agent's next deadline, configured interval, ping count and warming origin; its legacy `last_offer_tokens` column is unused. Warming claim and queue insertion are atomic and require a live, normally held, idle kernel agent whose transcript, not counting pending warming notices, reaches the floor (`Transcript.reachesCacheWarmingFloor`); below the floor the claim fails without spending a ping or moving the deadline, and every enqueued notice offers compaction. The input is a context system notice with subscription id `cache-warming`; it creates no message/unread/notification record. The assistant commit atomically moves its deadline; a real-input inference also resets its counter. Warming-origin tool continuations preserve the count. Enqueue alone and silent handler firings do neither. Compaction preserves counters and origin. Start over deliberately clears all warming state. Restart recovery defers overdue deadlines by one interval and preserves counters. Rendering remains the ordinary append-only transcript path, without a persisted second copy of the prompt.

## Portable handoff storage

`writePortableHandoff` commits a projected generation with a bound head and no pending tool calls. Rewritten contents require new IDs; unchanged message/receipt pointers retain their original identities and old contents are never mutated. New generation, bound head, work state and prompt revision commit atomically. This uses existing contents/pointers/generation storage; replay metadata is additive optional JSON, with no SQL schema change.

## Session run state

The induced `sessions` row carries `run_state` for kernel sessions. The session's cell says what its turn owes whenever the turn moves (`SessionRows.show`), in the step that writes the transcript: `tool` while a call of the model's reply is unanswered, `inference` while the model owes the next step or only due input waits, and `no_run` otherwise; `work` is `has_work` for the first two. Interrupt, error, archive and Start over write `no_run`; a resume shows the turn again. A forced compaction (the hard context limit, or a compact command) can start from a settled turn, so the cell calls `markCompacting`, which writes `inference` for a live, unheld, unerrored session until the turn next moves. The row is written only when the value changes: each change stamps `run_progress_at` (null for `no_run`) and moves `last_activity_at`. A pending tool call survives restart and its exec rejoins, so a session waiting in one keeps reading `tool`. `run_heartbeat_at` stays null.

## Atomic route transitions and durable failure episodes

The held route payload optionally carries typed failure source (`upstream`/`credentialRefresh`), reason/code, first/latest failure times, retry time and consecutive count. `updateModelRouteFailure` compares the expected epoch and updates only payload/phase (`waiting` for a refusing episode, otherwise `pinned`), without history churn. Start over clears it; success clears it without repinning. `modelProviderRefusing` supplies member-scoped warming suppression (quota/auth account-wide, service failures model-specific). Only live normally held sessions whose refusing episode stands (`ModelRouteFailure.stands(at:)`) count; a newer successful same-group/provider inference supersedes it (same model for service failures), without changing the other session's persisted episode. No schema change or new table is required.

A `ModelRouteTransition` compares the held epoch and requires a changed group intent, member or concrete target with a new epoch, a bound account-neutral transcript, and no pending kernel calls; requested compaction targets may leave, join or change groups. A same-epoch transition is effort-only: everything but effort must match, and it updates only executor_config and the route payload, without history or transcript changes. Only a compaction commits one, together with its concrete executor_config, pin/history, portable contents/new generation, work state and prompt revision; a portable handoff never changes the route. Failure at any write leaves the old pair intact; reopen after successful commit sees the new pair. Existing contents/receipts remain immutable, and obsolete epoch writes conflict. History rows carry the placement reason (`create`, `startOver`, `compaction`); rows written before mid-generation switching was removed may read `lastResort:<cause>`.

## Machine value construction

`MachineRecord`, `ExecRecord`, `ExecClaim` and `ScriptExecOwner` expose value initializers for semantic owner adapters. Their store representation, authentication, exec replay receipts and database schema are unchanged; these initializers do not grant persistence or authorization authority and do not make store records Codable.

`Sessions.enqueue` and `Sessions.clear` write nothing to `session_queue`: they post `SessionMail` (`put`, `clear`) to the session's cell in the caller's transaction, after the existence and archive-grace checks, and the cell's step makes the queue write (`SessionRows.put`, `clear`). `SessionStore.onMail` binds the poke that follows such a commit; nothing is returned about the queue.

## Retired worker schema

The existing `session_worker_incarnations`, `execution_worker_owners`, `session_worker_assignments` and `worker_script_owners` table declarations remain unchanged. Runtime code neither reads nor writes them; removal is deferred to a separately authorized schema change. Script restart cleanup consumes only `script_execs`.

`Space.close()` finishes live filesystem subscriptions, cancels and drains the space-owned query, filesystem replay, and session observation workers, and explicitly closes every read connection and the writer. It attempts both readers and writer even if one fails, throws the first close failure, and is idempotent after success; database operations through the space and retained stores must finish before close and must not be used afterward. Hosts drain their services before closing the space, so no SQLite file handles or deferred close/checkpoint remain when shutdown returns. Observation admission after close returns a finished stream (or `TaskScopeClosed` for throwing observations); it does not start another worker. It stops the space's worker first.

`Space.worker` is the space's one wuwei worker, on the shared backend over the space's own database (its writer, and one read-only connection the space closes) and on `DependencyScheduler`, made when first asked for. Every module of the space gives it its kinds and clients before starting it; a session's mail pokes it after the commit that posted it. `Space.stopWorker()` drains it and ends its timers, and the next `Space.worker` is a new one, as after a restart of the process.

Message handles and device names are resolved when queued inputs enter the transcript, in the drain transaction. Stored attribution survives hydration unchanged; directory renames affect only messages admitted afterwards.

The same drain transaction decides each delivered message's earlier exchange, so the delivered text can differ from the conversation's. The first message drained from a conversation in a generation carries the session's last message there and the one it answered (its reply target, else the message before it) when that last message predates the generation's head (compaction or Start over) and no message from that conversation is already in the generation, kept by compaction or delivered earlier; a session's first generation, which has no head, carries none. The decision and the quoted text, attributed as of the drain, are stored with the transcript item: hydration, reopening and re-rendering never recompute them, and later posts or renames never touch them. `StaleExchangeTests` pins this.

Receipt writes accept a synchronous `onCommit` effect, invoked on the database writer after successful commit, before a subsequent database read can observe the result. Rollback does not invoke it. Tool-call exec results use the worker’s transcript append boundary instead of a separate receipt. The legacy `exec_jobs` table, when present, is retained empty and unused for rollback compatibility.

## Tool-call exec claims

`claimExec` atomically rejoins by caller and tool-call id, preserving the first claim’s optional opaque `toolSpec`. The nullable `machine_execs.tool_spec` column is added idempotently when an existing database opens; existing rows remain null. `setExecEndOwed` sets or clears the durable end-delivery obligation on an owning caller’s tool-call exec only. `owedExecs` (and `owedExecs(caller:)` for one session) returns tool-call execs with that obligation, terminal or live, ordered by start and id; `bootSessions` treats a session owed one as unparked. Existing detached job rows transfer their spec and owed flag into the exec registry, then are deleted from the retained legacy table so reopening cannot re-owe a delivered end. Request-stall clocks pause from the oldest live tool-call exec’s start rather than a separate job row; ordinary and script mints do not pause that clock.

`liveToolExecs(caller:)` selects that caller’s nonterminal tool-call records for main-owned archive relay cleanup. `forgetOwedExecs(caller:)` clears only that caller’s tool-call exec end obligations, live or terminal; archive bookkeeping uses it before revoking the worker token.

## Transcript lines

Migration 026 adds `session_lines(session_id, generation, position, at, role, key, message, meta)`. A generation has lines only when it opened with them: `Sessions.append` and `writeGeneration` write the settled lines of what they append in the same transaction, rendering from the last item that flushes held notices, and never rewrite or move a line; an append to a generation without lines writes nothing (one indexed lookup). `storePrompt(…, opening:tools:)` writes position 0 when it stores the prompt: `{"rendered": <hash>}`, naming the blob that holds the `TranscriptPreamble`. Positions 1 and 2 are the prompt's opening (`PromptOpening`: keys `group` and `session`, user-role text, an empty one absent), written by the same call and stored nowhere else; a generation's transcript therefore starts at position 3. A generation opened before that starts at 1, has no opening (`PendingPrompt.opening` is false) and gets its whole prompt as the system text. Until the loop reads lines, typed items stay the truth and lines are read only by `lines`, `lineGenerations`, `lineDifference`, `sessionTranscripts(in:)`, the lines page (`lines(_:generation:before:limit:)`) and the cell's transcript tail (`SessionRows` `lineEnd` and `lines`, which can add the prompt lines, `StoredTranscriptLine.isPrompt`: keys `system`, `group` and `session`); they are not in the query sandbox. `lineDifference` returns the first position where the stored lines and the render of the typed items disagree (a hash and a 120-character excerpt per side); stored lines past the render do not count.

`/_/session-transcripts/<id>/` (`SessionTranscripts`) serves `current.jsonl`, `current.outline.txt` and `<generation>.jsonl`/`.outline.txt` for each generation with lines, rendered from the rows on every read, in the session's own group only; the root lists nothing. A JSONL record is `{position, at, role, key, meta?, message}`, `meta` (stop reason, usage) only on a line that has one; it drops reasoning and names inline images; the outline is `<position> <at> <role> <key> <first 160 characters>`. Writes, removes and moves throw `sentViewReadOnly`, and `refuseWrite` refuses every path under it.

`/_/rendered/<hash>` (`RenderedFiles`) serves a generation's `TranscriptPreamble` (system text and tool list, sorted-key JSON) from `blobs`, where `<hash>` is its SHA-256: immutable, without revisions, read-only like the transcripts, and there only for a group one of whose sessions has it as a line 0 or as its current prompt; the root lists nothing.

## Groups, settings and administration

A group may record an owner (`groups.personal_account`, unique): a person's own group, seeded with that person as its admin. It is hidden from discovery and from other people, and it keeps its content, sessions and machines. A new human gets that group and no membership in `shared`. A personal group is private and its list is its owner's alone: an entry naming it is refused (`SpaceError.personalGroupPrivate`), and its files read only to its owner (any person) or to a session of that group. Nobody else reads it, space admins included.

The one access rule is `group_roles`: one row `(account_id, source_group, grp, role, created_at)`, exactly one of `account_id` and `source_group` set, each with its foreign key, `role` `read`, `write` or `admin` (ordered). A group is `open` (`groups.visibility`) or private; an open group gives every member account and every session `write`, a private one gives only what its list says, and the settings group reads to everyone and administers to space admins. Reach is one hop: an actor reaches its acting group, every open group, the settings group, the groups listing its acting group, and — for a person — the groups listing its account. A person's role in a group is the best of its account's entry, the acting group's entry, an open group's `write`, and space admin (`admin` everywhere but another person's own group); a session's is the best of its own group's `write` (its own group, every open group) and its group's entry, with a live top-level agent `admin` of its own group. Guests (`accounts.guest`) hold only their account's entries: no open-group reach, no personal group, no admin, and no sessions. `read` grants reading only; file, table and message writes take `write`. `GroupAccess.readable`/`role` are the whole rule; query, find/grep, watch, web pages, machines, conversations and DMs all resolve through them (DMs keep their membership rule).

`GroupCell` (key: the group id), on the space's worker, is the group as a wuwei cell. It is formal for now: it owns no table and takes no mail, and its reads (`role(of:acting:)`, `reads(_:)`, `grants()`, `record()`) load the group's own row, its list and the settings group's list through StructuredQueries and apply `GroupAccess.Snapshot`'s rules, the same ones `Space`'s methods apply over the whole table. `grants()` checks nobody: its caller asks `role` first. `reads(_:)` is the per-group test `readable(by:)` filters by (`Snapshot.reads`), which grants the anonymous --dev seat its acting group's reach, reads a page with its viewer's rights and always lets a person read the seat they take: where `role` is nil or the page group's. `SpaceCell` (the one key `space`) is the same for what spans groups: `groups()`, and `readable(by:)`, `writable(by:)` and `administered(by:)` for a principal, which discovery (`GET /v1/groups`) and a page's admission read. `Space.cell` and `Space.cell(of:)` are the read handles. `groups` and `group_roles` stay main's to write until their owner flips.

A page writing for its viewer acts as `Actor.page(Page)`, the page's path and its viewer (a `Person` in the page's group; no account is the `--dev` seat). Its role in a group is its own group's, capped at `write`; it reads what its viewer reads. A page therefore writes a group only where its group writes and its viewer reads; the viewer's own write or admin never widens it. It is no conversation member, administers nothing and holds no exec. Its revisions record the viewer's persona (none for the `--dev` seat) `via` the page path.

Human admin authority is the `admin` role: directly held, or a space admin (`admin` in the settings group) over every group but another person's own. The account admin flag derives only from that role. Top-level agents still administer their own group, never the settings group, and no session takes the settings group as its home. `groups.secrets_scope` and `machines.scope` each choose `owner` (the group alone) or `reachable` (every group with `write` in that group); secrets default to `owner`, machines enrolled before the switch are `reachable` and new ones default `owner`. `Space.homeGroup` lets a person land a top-level agent where they write; a session lands one in its own group unchanged, and anywhere else only where its group holds `admin` — an open group's write is not its sessions' admin. The settings group is nobody's home.

Migration 003 backfills personal-group owners and admin rows only for live accounts: a removed account keeps neither. It creates the hidden settings group and copies `shared`'s `models.json`, `model-groups.json`, `capabilities.json` and `machine-v2-upgrade.json` into it with new revisions, versions and heads over their existing blobs, then deletes them from `shared` as ordinary file deletes so the journal keeps their history. Settings are readable from every group and writable only by a space admin (or the dev seat). Instruction composition uses only the system files, the session's own group and its home.

Migration 004 extends that table into the access table and drops `group_edges`, `group_reads`, `group_members` and `group_epoch`. Every live member's membership becomes `write`, every admin row stays `admin`, and every pair the old closure reached becomes a `write` entry for its source group, so no reach is lost. It makes `shared` open, leaves every other group private, gives `owner` visibility to the secrets of every group, marks existing machines `reachable`, and adds the `guest` flag (default false).

## Group identities and aliases

`createGroup(alias:name:owner:)` atomically draws a `.group` id from the shared three-word allocator, creates an open group, and grants its live human non-guest owner admin. `resolveGroup(_:)` is the single spelling-to-id boundary; all persistence and authorization use ids. It accepts group ids, current and retired group aliases, and person aliases naming their personal group. `renameGroup(_:alias:by:)` requires group admin and preserves all past spellings. `nameGroup(_:name:by:)` sets `groups.name` (Migration 015; what the apps call the project, defaulting to the alias, nil for personal groups) under the same admin rule; `SpaceError.invalidGroupName` refuses an empty, over-64-character, multi-line or markup name. `AliasError` distinguishes invalid labels, reserved labels and an ineligible owner.

Migration 006 creates the permanent case-insensitive `aliases` namespace for group aliases, person handles and machine names. Database triggers reserve a spelling on insert/update and reject reuse by any other entity; retired spellings remain reserved. Existing non-personal groups gain aliases (`shared` retains both id and alias); personal groups gain none. Existing people and machine labels take precedence over derived group aliases; live-key machines precede people, who precede revoked machines. Labels replace `-` with `_`, sanitize invalid legacy machine characters, and take deterministic length-bounded numeric `_n` collision suffixes. Machine account names follow the migrated machine names. Existing ids, foreign keys and content stay unchanged. Person handles and machine names resolve retired aliases to their current record.

Revoking a machine retains its current and retired alias reservations. A successor may claim a keyless machine’s names only in that same owner group, with no outstanding join token; enrollment atomically transfers all its alias rows to the successor and clears the old display name. Other groups and other alias kinds still see the names as taken. Machine records and their stored history remain by id.

`session_prompts(session_id, generation, rev, rendered, session)` holds a session's prompt for its generation: `rendered` is the hash of the blob with its system text and tool list (`StoredPrompt`, whose `opening` is read from lines 1 and 2), so a request sends all of it as stored and an upgrade changes neither before the next generation. Migration 030 moved every literal line 0 into `blobs` and named it from its line and its prompt row; a prompt stored for a generation without a line 0 had no recorded tool list and is rendered again. `activatePrompt` returns the stored prompt or the `PendingPrompt` (generation and revision) to render (creating a row for a session without one); `storePrompt` stores a rendering only while both are still current, since session operations such as a rename and Start over leave the space revision unchanged, and returns the one already stored if a racing inference won. Advancing the revision (creation, template clone, compaction, Start over) clears the rendering in the same commit. `InstructionRenderer` renders an AGENTS.md for a `PromptSession`: frontmatter dropped, `wuhu_queries` and partials read through injected space tools, failures as one `(template error in <path>: …)` line. `SkillCondition` parses a skill's `wuhu_when`; a malformed one lists the skill with its error.

`deleteMachine(_:by:)` admits only a direct human admin of the machine's current group (or the dev seat), rechecked inside the writer transaction. The same revision removes the machine notes subtree, every current and retired machine alias, v2 membership and presence, credentials, account and machine row, including account grants, personas and machine-account-owned devices with their command/message links. Surviving credentials lose their deleted-account creator reference; human-owned device links become nil. Machine-owned v2 operations, channel/output buffers and retention entries are deleted, and live exec records become machine-lost. Operation claims require membership in the same writer transaction, so an admitted start racing deletion cannot recreate reservations after the commit; later writes cannot recreate deleted operation rows.
