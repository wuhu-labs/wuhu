# OperationRuntime

`OperationAgent` owns one addressed machine and an injected authorization decision per request. Multiple agents may share a transport via an ordinary routing Handler; neither the reducer nor the client binds liveness to a connection. Unknown machines/kinds/operations and invalid channel/offset/schema/capacity cases are typed failures. A kind is decoded and prepared before admission, registered through a single `AnyOperationKind` erasure, and run without any process or filesystem assumption. The kind must validate its domain constraints and cooperate with cancellation at effect boundaries; the runtime cannot preempt arbitrary noncooperative in-process code or manufacture a stopped verdict before it returns.

The owner runs `await agent.run()` in its lifecycle task group and calls `shutdown()` to finish that lifecycle. Starts enqueue bounded work; executions and lease maintenance are owned by a discarding task group. Shutdown disables new starts and requests cancellation. A socket close, agent re-registration or discovery never renews an operation.

The production `OperationState` and `ChannelState` are the functional core used directly by the deterministic simulator. Every valid operation request renews only that operation. Lease expiry sets irreversible stop intent; later polls cannot revive it. A late start receives only its own local initial lease. Stop and terminal verdicts are immutable; a natural completion that wins a stop race remains completed. Kinds can publish immutable terminal evidence independently of finite output-tail draining; final offsets remain absent until each output ends. Kinds use writableBytes and availableInput for nonblocking pipe integration; a published terminal tail remains drainable under backpressure without waiting behind stop intent. hasRetainedOperations and inspect are lifecycle inspection only, never a poll or lease renewal. inspect returns retained metadata for authenticated supervisor identity discovery. Kind validation runs during preparation before admission. State polls/stop bypass channel backpressure.

Channels are bounded suspending handles, not unbounded producer streams. Poll JSON does not escape slashes; registration budgets terminal metadata plus the bounded result and worst-case byte/record wire payload against the shared 256 KiB aggregate response cap (these registration checks are `OperationAgent.validate(descriptors:limits:)`, public so composers serving kinds outside an agent apply the same ones), and the Handler checks the encoded envelope before returning it. Output bytes split to bounded windows, records publish atomically up to their cap, and full windows suspend producers while control requests remain usable. A snapshot kind can coalesce its own bounded unpublished staging value before calling send; already-offset records cannot be replaced. Input writes accept only a contiguous prefix, preserve retained overlap identity, return accepted offsets/blocked, and make fully accepted duplicates no-ops. Input EOF is fixed at the accepted offset. Output polls reclaim only the explicitly acknowledged prefix, reject stale/ahead offsets, and never infer acknowledgement from terminal state. Admission reserves all live channel windows; an output channel frees its reservation only when it has ended and its retained payload is empty, including published finite tails. Snapshots expose optional bufferReservationBytes for a supervising registry; absent on old responders, accounting stays conservative. A finished operation keeps its retained input charged until it is dropped, even after every output has been consumed. It is dropped as soon as it settles (terminal token and every output prefix acknowledged) and every output channel has carried the terminal acknowledgement on its own poll: an older server acks stdout and stderr in turn, or acks with no channel and then on its one channel, and each later ack must still find the operation. A settled operation some channel never acked is dropped one retention window after the last request, preserving its settled inventory state. One that never settles is dropped `OperationAgent.receiptRetention` (60 seconds, its own constant, injectable for tests) after its caller's last request, and that drop records lost operation evidence. Admission caps retained receipts (`receipts`) and reserved channel bytes (`bufferBytes`); there is no active-operation cap. Each refusal is `OperationError.capacityExceeded(reason, used:limit:requested:)` naming the bound.

The finite receipt cache rejects duplicates while retained. At-most-once across arbitrary delayed duplicate POSTs beyond retention is not promised: the client consumes one durable dispatch permission and the transport must never replay start. Agent recovery of real execs belongs to the supervisor slice; this runtime never recreates an unknown operation.

Linux/macOS tests run the production Handler, registered no-process kinds, client, store and reducers with injected faults. The same test kinds compile in the iOS CI test lane. The test README maps named examples, seed sweeps and later-slice fault rows. Real pipes/process groups/supervisor recovery, filesystem faults, tunnel framing/authentication, SQLite, services and rollouts are explicitly not proven by these process-free simulations.

A kind can request an irreversible stopped verdict with `OperationCancellation.stop(reason:)`; it sets stop intent and throws cooperative cancellation. Typed OperationErrors raised during input preparation are preserved (for example search.v1's `details.search`), not flattened to invalidInput. Other decode failures remain invalidInput.

`admissionUsage()` returns a swept snapshot of retained receipts and reserved channel bytes for a composed owner to apply one shared machine budget. The snapshot is not an atomic reservation; the owner must serialize or version its admissions across awaited probes.

An optional `KindAvailabilityProvider` is the machine's gate. Describe then reports `availability` for every linked kind (available unless the provider says otherwise) plus the unlinked names the provider marks non-available; a provider's `available` for an unlinked name is dropped. A start for a kind the provider marks non-available is refused with the typed refusal right after the start body decodes, before input preparation, admission or any operation state: nothing is created or charged. The provider is read on every describe and start, so a gate change needs no agent rebuild. Revocation: the provider's optional `changes` stream is the gate's change signal. `run()` consumes it; on each signal the agent re-reads the gate and gives every running operation whose kind is no longer available a stop intent with `KindAvailability.stopReason`, so it ends with a real `stopped` verdict (consentRevoked, permissionRevoked, kindUnavailable) while other kinds keep running. A start that was admitted just before a change re-checks the gate after insertion and before the operation becomes runnable, so no operation slips between the sweep and its creation and a revoked kind never runs its effect: such a start still answers 201 and ends `stopped` with the revocation reason. Without a provider describe omits `availability` and starts are unchanged.
