# InferenceKit

Each executor attempt, including forced-compaction calls and failed or cancelled attempts, produces one `InferenceMetric`. It carries call start, session, configured provider/model/effort, API-reported served model when available, outcome/error, duration, optional time to first event, and optional usage. The metrics sink is also called on failures. Failed or cancelled attempts retain the last reported partial usage, when present. Usage remains in WuhuAI's total-input form until the server normalizes it for storage. Existing `logs/inference.jsonl` encoding stays unchanged, including zero for unreported reasoning. A provider `malformedModelMessage` is reported as `httpError` with error kind `malformedModelMessage` and no HTTP status; failed streamed partials are removed from the live attempt hub and never returned as completed inference.

## Image limits

Provider `imageFamily` optionally selects `claude` or `openAI` limits independently of dialect. Without it, `anthropic` uses Claude limits and `responses`/`codex` use OpenAI limits. Unknown values produce the existing entry-local `CatalogError.invalidProvider`. The provider's resolved limits flow into request media fitting, context estimation, compaction and cache warming.

## Kernel endpoints

`ProviderCatalog.resolve` builds an Anthropic-dialect endpoint (other than DeepSeek's) with 1-hour automatic prompt caching (`AnthropicPromptCache.oneHour`), and a Responses endpoint with a hashed session/binding/route-epoch cache key. Codex uses the same scoped base key for prompt cache, session and thread affinity.

## Portable tool-turn reasoning

The executor retains the configured provider, model and effort. The one named exception (WuhuAI doctrine 5) is Claude's own rule, which requires signed thinking at the start of a thinking-enabled tool continuation: a Claude model (`ResolvedModel.isClaude`, decided from the model id, a `claude` token as in `claude-opus-5-5` or `anthropic/claude-sonnet-4-6`, whatever the host or dialect, so a proxy serving Claude is included) on an Anthropic Messages endpoint temporarily receives `reasoning: none` when the current turn contains a carried assistant tool call without same-scope, same-provider signed thinking at the start of its content. `keptCount` is the persisted generation boundary, so legacy adoption, credential/account or provider-route changes, atomic group switches, compaction placement and ordinary compaction all use the same decision; restart needs no transient flag. Remaining calls in that turn stay off even when new calls acquire a binding. A new direct/conversation message or rendered notification starts a fresh turn and resets the decision, including timer, observation and cache-warming triggers. Only the synthetic portable-handoff/route notices continue the pre-boundary turn; they use reserved `replay-handoff`/`model-route` context source IDs. The exact legacy boundary notices persisted with the `context` ID by dev.117 remain continuations. Empty canceled context notices are absent from rendering and cannot reset the decision. Compaction that removes the entire tool tail may resume thinking immediately because the wire history no longer contains the incompatible tool use. Retained valid signed history keeps thinking enabled. Every non-Claude model (MiMo, DeepSeek, or any other model, whatever the host) never downgrades: it keeps its configured effort through tool continuations, portable boundaries and interleaved context notices, and its history is sent as carried. No provider flag changes this; the retired `acceptsUnsignedThinking` key is ignored when read. Nothing in InferenceKit or WuhuAI refuses thinking history; an upstream's own rejection surfaces as its error.

## Plan usage source

Provider `usage` is optional and accepts only `gateway`: the provider serves plan usage at `<baseURL>/usage` with its stored API key. It is valid only for a `responses` provider without OIDC auth; selecting another provider that declares it throws `CatalogError.invalidUsageSource`, and an unknown value is an entry-local configuration error.

## Opaque replay binding

Provider `opaqueReplay` is optional and accepts only `affine` or `none`; unknown values are retained as entry-local configuration errors and throw `CatalogError.invalidOpaqueReplay` only when that provider is selected. Invalid values survive encode/decode for editing; assigning a valid policy clears the entry-local error. An invalid entry never defaults into affine replay. The default is affine only for the dialect's exact HTTPS first-party origin: api.anthropic.com for Anthropic/Claude, api.openai.com for Responses, chatgpt.com for Codex. Nonstandard ports, credentials in URLs, HTTP, wrong-dialect origins and custom gateways default to none. An operator may explicitly declare affine only when the upstream account affinity is stable. DeepSeek's published seed declares affinity explicitly rather than inferring it from its Anthropic wire protocol.

Catalog reading does not reject an unrelated provider's replay policy. No effort is refused for its replay policy: an Anthropic/Claude provider with effective none replay validates and resolves with any listed effort, and its thinking history is sent portable; an upstream's rejection surfaces as its error. Thinking is never silently disabled. Mixed catalogs retain valid entries and capability fallback configuration, including Codex aliases, endpoint and originator; Responses none replay permits reasoning with portable projection. User policy values survive merge-only `wuhu models update`. Older dev.114 catalogs decode the additional setting as an ignored unknown key; this is compatibility for declaring policy before upgrading, not an old-server safety guarantee.

`ResolvedModel.bindingIdentity` is a nonsecret fingerprint of configured provider ID, credential identity epoch, endpoint, dialect, authentication, transport, originator and effective replay policy. It remains present in none mode so runtime can detect credential replacement before sending another request. `replayScope` equals that identity only for an affine provider with a verified credential identity; otherwise it is nil and WuhuAI cannot replay opaque records. Scopes contain neither credentials nor account identifiers. The scope excludes `routeEpoch`; callers supply the durable route epoch independently (`"0"` preserves source compatibility), and a portable handoff rotates it, including ordinary group compaction when headroom placement changes the member. Cache/thread keys and socket registry identity include binding identity and route epoch even when replay is disabled. Access-token refresh retains scope but may retire a socket so its next handshake uses the fresh bearer. OIDC without a verified identity seam remains unable to replay opaque records; its process-local boundary identity tracks unverified stable issuer/subject/audience claims rather than JWT issuance time or nonce, so ordinary short-lived JWT refresh cannot cause a handoff loop. Those parsed claims grant no replay authority.

The live credential resolver atomically resolves credentials and their persisted opaque identity. The store-free `environmentOnly` resolver verifies API-key equality and permits replay using a process-local opaque epoch; replacement, observed removal or restart rotates scope, without persisting credentials. Legacy closure resolvers without verified identity fail closed; they receive a process-local UUID tracking credential replacement, with nil replay scope. Test or custom credential implementations can use `CredentialResolver.bound` and explicitly provide `CredentialBinding`. An unverified resolver restarting changes binding and must cross the runtime's portable boundary before continuing an old transcript.

## OIDC provider authentication

`ModelsDocument.Provider.auth` is optional and accepts only `oidc`; absent preserves existing credential resolution. `ProviderCatalog` takes an optional server-owned `oidcToken(baseURL, session)` signing seam. An OIDC provider calls this seam once per resolution/attempt and never calls `CredentialResolver`. The optional `oidcBindingIdentity(baseURL, session)` seam supplies the stable configured issuer/audience/provider-route identity; it is checked before and after signing and hashed into the replay binding. A change during signing fails with a static typed 422 error. Missing identity disables opaque replay and uses process-local UUIDs keyed by stable issuer/subject/audience claims in a per-provider least-recently-used cache of 128 identities. Alternating session subjects retain independent epochs across ordinary JWT refresh; changing stable claims selects a different epoch, while eviction or process restart rotates a returning identity. Tokens without parseable stable claims instead key their local epoch by bearer equality. Verified identity preserves replay scope across ordinary JWT refresh and signer-key rotation. Kernel session runtime resolves the catalog per inference attempt, including compaction and retries. Anthropic/DeepSeek preserve their existing body policies but authenticate using a sensitive `Authorization: Bearer` header and no `x-api-key`; Responses uses sensitive bearer authentication for SSE and WebSocket handshakes. A fresh OIDC credential invalidates cached WebSocket authentication. Codex OIDC configurations fail validation with `CatalogError.invalidOIDCDialect`. Missing signer and invalid audience/issuer failures surface as typed `InferenceError.invalidInput(status: 422)` with static hints naming provider `baseURL` or HTTPS `--origin`, respectively. Server identity key-unavailable/signing failures also surface as static 422 hints naming the identity key configuration. Other signer failures follow `InferenceError.normalize`, including cancellation, with unknown diagnostic bodies suppressed. No failure includes signer secrets or falls back to stored credentials.

## Provider capabilities

`CapabilityClient.capability(kind)` probes only configuration for `image`, `transcription` or `web_search`. It uses the same provider, dialect, endpoint validity, default model and model-feature selection as execution, but never resolves credentials, sends HTTP, spends money, or reports account identity. It returns `{ kind, provider, dialect, model, authentication: "not_checked", features: { edit, timestamps, diarize } }`; this is configuration discovery, not evidence of working authentication, entitlement or regional availability. Credential IDs, endpoint URLs and headers are never included. Unknown kinds are `invalid_argument`; malformed configuration, missing explicit variants, invalid endpoints and incompatible dialects are `provider_not_configured` without fallback. The script export is `wuhu:ai` `capability(kind)`, and `GET /v1/capabilities/:kind` serves the same result/error policy.

The internal `CapabilitiesDocument` decodes the shared `/capabilities.json`, independently of the inference model catalog; clients construct `CapabilityClient` only through its public `load` factory, not a document initializer. `CapabilityClient.load(read:credentials:)` reads it at call time (the injected reader returns nil only for an absent file); malformed/unreadable configuration fails `provider_not_configured`. `CapabilityClient` owns all search, image and transcription resolution, including the existing image tool and dictation/CLI route. The old `ProviderCatalog.resolveTranscriber` ChatGPT-first picker is removed; its public low-level Codex/OpenAI transcribers remain for direct consumers, not provider selection.

Each of `web_search`, `image`, `transcription` is an optional `{ active?, providers: { id: { dialect, credential?, baseURL?, model?, models? } } }`. Persistence retains all variants and their settings together; changing active selects one at call time without replacing or deleting inactive variants. No file or no capability entry synthesizes `{ dialect: "codex" }` and resolves the configured ChatGPT credential. An empty providers map with no active also synthesizes Codex. A configured active or call override missing its variant/credential, or with a wrong/unknown dialect, returns a typed error without trying another provider. An override selects only a variant, never arbitrary credentials or an endpoint. Explicit Codex variants may omit everything except dialect. Native provider credentials are resolved per call; environment precedence/rotation remain CredentialResolver's existing contract. The config-writability trust boundary matches models.json and is deliberately not hardened here.

Dialects: `web_search` = `brave`, `exa`, `codex`; `image` = `openai-images`, `dashscope`, `codex`; `transcription` = `openai-audio`, `dashscope`, `codex`. Defaults: Brave `https://api.search.brave.com/res/v1`, Exa `https://api.exa.ai`, OpenAI `https://api.openai.com/v1`, DashScope Beijing legacy `https://dashscope.aliyuncs.com/api/v1`, Codex configured model-sheet URL/originator or `https://chatgpt.com/backend-api/codex`. API dialects default the credential ID to the variant ID. Codex uses its explicit credential ID, otherwise the existing model-sheet Codex provider or `codex`.

Model facts are `{ edit?: Bool, timestamps?: ["words", "segments"], diarize?: Bool }`; absent fields use the adapter's known-model facts, otherwise unsupported by default. Configured facts can describe a new model without adding vendor knobs. Options are provider/model overrides plus capability-specific count, image quality/size and audio language/timestamps/diarize. Quality maps Qwen draft/standard/fine/ultra to the four exact shipped models; draft editing fails. Codex/OpenAI have no distinct neutral ultra tier in this v1 adapter and reject it. Model+quality overrides conflict on Qwen. Hard requested transcription features that the selected model lacks return `unsupported_feature` before upload; missing requested metadata in a successful response is `provider_unavailable`, not fabricated success.

`CapabilityError` is code/message/hint. Codes: provider_not_configured, provider_auth, provider_region, provider_entitlement, provider_rate_limited, unsupported_feature, invalid_argument, provider_unavailable. Neither transport errors nor upstream bodies/credentials/signed URLs enter errors or logs. Provider auth headers are sensitive. Storage downloads use fresh unauthenticated requests, never bearer/account auth. Configuration/credential failures never remove module/tool declarations or retry another provider.

Search returns `query`, `provider`, `sources[{ title, url, snippet?, published? }]`, optional `text`. Brave GET and Exa POST return explicit normalized sources. Publication metadata uses Brave's ISO `page_age` (not its relative human-readable `age`) and Exa's `publishedDate`. Codex uses a dedicated hosted-web-search Responses call, retains output_item.done items when response.completed omits output, and exports sources/cited text only after a completion event, rather than claiming hidden hosted source bodies are preserved. Count 1–20, default 8. No persistent result cache/corpus, index, or training/evaluation on Brave results.

Images return PNG bytes internally, placed create-only by tools/CLI. OpenAI generation is JSON and editing multipart; Codex generation/editing use JSON, with data-URL references on edits; Qwen uses the native synchronous multimodal endpoint for both and immediately downloads its result. At most five private PNG references (Qwen 3.0/dedicated editors: three, 10 MiB each; general per-reference bound 25 MiB). No masks/bboxes, regional flags, streaming or vendor-specific options. OpenAI default is gpt-image-1; Codex gpt-image-2; Qwen qwen-image-3.0. Explicit model overrides are authoritative.

Transcription reads private uploaded bytes and returns one `Transcription`: required text/provider/model, optional language/durationSeconds/segments/words/confidence/usage. A span's text is required; start/end, speaker and confidence are optional. All times are seconds. Absent metadata is omitted, including a request's language hint when not returned by the provider. Speaker IDs are annotations without an accuracy guarantee. Audio is nonempty, at most 25 MiB and two hours; pure container timing parsing covers WAV, MP3, M4A/MP4 and WebM, rejecting unreadable timing rather than bypassing duration checks. MP4/M4A fragments use track timescales and tfdt decode times with trun sample durations or tfhd/trex defaults. Zero-duration movie headers never establish fragment duration; the bound conservatively covers decoded/presentation timeline ends and aggregate per-track sample duration. Missing/malformed fragment timing is invalid_argument before provider IO with a re-encode hint. WebM without Duration uses the final block time plus a conservative 120 ms Opus packet allowance. OpenAI plain transcription defaults to gpt-4o-mini-transcribe (including the direct OpenAITranscriber); explicit configured/call models remain authoritative. gpt-4o-transcribe-diarize supports timed segments and speaker labels, not words; its native diarized_json request omits timestamp_granularities and always sends chunking_strategy=auto even without requested speaker labels. Qwen defaults to qwen-audio-3.1-asr-flash-filetrans; qwen3-asr-flash-filetrans does not diarize. The managed `/files` upload → signed file URL → unsuffixed asynchronous `/services/audio/asr/transcription` → bounded task polling → unauthenticated result fetch → best-effort DELETE sequence is internal. Cleanup errors never hide the operation's result/failure; crashes/cancelled transports can leak staging files, without durable recovery machinery.

Brave/Qwen/Codex live acceptance occurs separately in a fresh test space. OpenAI/Exa adapters have deterministic synthetic offline request/response/error tests. Their October 5 live-check waiver was lifted on October 4 after fresh keys became available; all live provider checks remain the independent fresh-space acceptance phase, not evidence claimed by the implementation tests.

## Responses WebSocket kernel transport

A provider may set `transport` to `sse` or `websocket`; omission remains SSE. Unknown transport values are rejected, and WebSocket is valid only for `responses` and `codex` dialects. The catalog rereads configuration and credentials per attempt. No automatic fallback from WebSocket to HTTP/SSE occurs. Capability calls do not inherit the kernel transport setting.

`ResponsesSocketRegistry` belongs to one runtime, owns one Responses session per kernel session, and grants one exclusive lease per active inference. It compares provider, model, URL/configuration, and resolved credential material without persisting or logging that identity. Credential/configuration changes rotate the socket; manually constructed models without a catalog identity conservatively rotate on every acquisition. Lease IDs prevent stale completion or failed owned cleanup from making a newer inference idle or invalidating it. Acquisition conflicts are outside the owned-inference cleanup scope; every exit after successful acquisition releases or invalidates that lease, including provider 409 and cancellation. Idle entries expire after 300 seconds, retain at most 32 oldest-first, and are swept every 30 seconds. Active leases are never swept. Connections rotate before reuse at 55 minutes; cancellation of the structured registry runner shuts down every owned session and closes acquisition permanently.

`InferenceExecutor` selects the Responses WebSocket endpoint before applying media resolution. Its `acknowledge` accepts the actual committed `AssistantEntry`, including the provider-to-kernel tool-call map, and rerenders the actual resulting transcript with current attribution. LoopCore invokes it only after durable append and in-memory commit. The engine proves exact content/phase, full rendered prefix, options/tools/instructions, and resolved-media projection before admitting a continuation. A changed handle/device, lossy phase rendering, uncommitted output, or stale generation therefore uses a fresh full create, never fabricated history. Only new cached tool-result IDs translate back to provider IDs; full creates retain normal kernel ID normalization. Compaction, Start over, archive/unarchive, actor retirement, runtime shutdown, resolution failures, and a transport change invalidate the owned session.

Every physical create and received application event is tapped through the current attempt observer. Corrective subattempts have explicit indices in that attempt's log, and byte counters accumulate all physical subattempts. Response sizes count raw text UTF-8 or binary bytes at the receive boundary, not reserialized JSON, and malformed messages are included. Logs contain application JSON but never authorization/upgrade headers; idle events never append to an already-finished attempt. Codex quota callbacks belong to the session, separately from attempt logs and inference usage. Upgrade and metadata headers keep the existing Codex header projection.

Offline tests exercise default/invalid configuration, exclusive ownership, session isolation, stale lease release, credential/URL rotation, TTL/LRU/age policy, and shutdown. The LoopCore acceptance server uses `Serve.WebSocket.pair` against the real SessionService inference/commit/tool/render path and checks the second wire create, original provider call ID, and full-history fallbacks for missing acknowledgement, phase loss, attribution changes. No live provider evidence is claimed by these tests.

Every internal corrective reconnect and credential/header rotation reinstalls the current call’s session quota receiver before dialing, including quota emitted on connect before the first create and while idle after completion.

Registry shutdown tests keep an actual owned inference open, assert transport abort and its typed terminal failure, check the Void shutdown result and idempotence, and reject later acquisition with CancellationError. Cancelling the structured `run()` task enforces the same closed contract.

Outbound payload failures retain their typed metric kinds `requestTooLarge` and `requestTooLargeAfterCompaction`, both with status 413.

Context-pressure notices are ordinary durable transcript notifications written by LoopCore before inference. Rendering and acknowledgement only replay them; neither computes a new percentage. Offline kernel tests exercise a full create, warm deltas with historical notices, real tool commits and a forced reconnect for text and image histories, plus full HTTP/SSE histories for Responses, Anthropic and Chat Completions.

Provider capacity failures report `httpError` with their exact provider code (`websocket_backpressure`, `response_too_large` or `websocket_message_too_large`) in the metric's `error` field and the supplied status when available; they are never erased into `rateLimited`.

The `anthropic` provider dialect uses the kernel's Anthropic Messages endpoint. Claude itself is served through the gateway as a `responses` provider. Credential resolution never substitutes another provider or falls back to a removed executor. OIDC uses the server identity path, without reading stored credentials.

## Declared model groups and quota-aware placement

`/models.json` remains a provider-only catalog (legacy provider fields unchanged). `/model-groups.json` contains strict `kind: "group"` declarations keyed by group ID, with ordered `members[{id,provider,model}]`, `defaultEffort` and optional `policy`. A group without policy uses `{type:"quotaAware",holdDownSeconds:1800}`. Supported policies are `quotaAware` and `select` with a required member alias; ordered `fallback` is rejected. Quota-aware hold-down must be an integer in 0...86400; unknown kinds, policies and group/member/policy fields are typed configuration errors. Group/provider name clashes fail configuration. There is no nesting, duplicate alias or provider/model pair, or translation of reasoning efforts. Duplicate or malformed group structure remains an error. Invalid member declarations, including unsupported default/requested effort, are excluded from quota-aware placement and reported as member errors; at least one valid member is required, otherwise the first member error is raised. Discovery reports the valid members’ effort intersection. Explicit select never substitutes for an invalid selected member. Eligible providers have valid HTTP(S) endpoints, transport/auth combinations, positive input/output limits and usable context. Creation/Start over group readiness checks every declaration-valid member's local credential availability/kind and OIDC signer availability without making an inference. `validateReadiness(specifier)` exposes the same single-member check while preserving typed runtime credential refusals for candidate filtering; ordinary held-member inference does not resolve unused candidates. At compaction/last-resort placement, an unused member's typed login/auth/quota refusal removes that candidate without defeating healthy members, while missing/malformed local credentials and OIDC configuration remain typed errors. Missing alternate credentials are errors naming the member, not reasons to silently choose another account. A refresh readiness failure is sanitized and typed. Configuration is revalidated at use.

Providers may declare `capacity:{"five_hour":1,"seven_day":2}`. Keys must name a binding window of at least one model on that provider and values must be positive finite numbers; all other keys (including camelCase spellings) are `invalidCapacity`. Omission means relative size 1. Capacities are placement hints, not quota telemetry and not part of a pin's endpoint/auth fingerprint. Provider membership order is retained for discovery; quota placement breaks ties by member ID, not order.

`placeModelGroup(id:group:providers:usage:now:reason:)` is pure and accepts `create`, `startOver` or future `compaction` reasons. Each model declares optional `usageWindows:[String]`, defaulting to `["five_hour","seven_day"]`. Each observed binding window with a positive reported duration contributes remaining headroom `max(0,1-usedPercent/100) * capacity`. Its score is headroom divided by the fraction of the window left until reset, clamped to 60 seconds minimum and the full window maximum. Missing reset uses a full window; expired reset uses a fresh full-capacity/full-window estimate. Every binding window appears in evidence; unobserved windows have absent percentage, remaining headroom and score. The member's score is unknown if any binding window has no valid observation; otherwise it is the minimum window score (the bottleneck). This prioritizes capacity that will expire sooner while respecting every configured constraint. Existing five-hour/seven-day observations without a duration retain their known lengths. Invalid/unrecognized usage samples are unknown, not configuration errors. Known positive headroom beats unknown; unknown beats exhausted; exhausted members are not quota-placement candidates. Equal scores and all-unknown groups choose the lexicographically smallest member ID. No eligible member is `CatalogError.noUsableMembers`. Manual select obeys its declared alias regardless of telemetry; it never silently substitutes a member. A decision includes all per-member observed timestamps, raw percentages/reset times, capacities, computed headroom and scores.

`validateRoute` preserves a pin through member reorder, select preference edits, capacity edits and budget edits; removing/rebinding the alias or endpoint/auth/transport binding is `modelRouteInvalid`, never an automatic account detour. Group budgets come from the concrete active member. Quota-aware groups place at create, Start over and ordinary compaction; mid-generation movement is restricted to durable last-resort refusal episodes. Restart/resume preserve the pin and deadline.

Groups are session targets only. Concrete provider validation/default selection refuses a group with `unsupportedTarget`; one-shot `complete` surfaces the same typed code and capabilities use `unsupported_target`. Neither operation inherits the caller's pin or begins a group wait/switch.
## Idle cache warming opt-in

Each concrete provider model may declare `cacheWarming: { intervalSeconds?, maxPings?, minimumRemainingPercent?, floorTokens? }`. Absence disables warming; `{}` opts in with defaults 3300 seconds, 20 pings, 10 percent and 50000 tokens respectively. Intervals, counts and the floor are positive integers; the quota threshold is a finite number in 0...100. Null, booleans, unknown keys, invalid types and out-of-range fields throw `CatalogError.invalidCacheWarming`; they never disable warming silently or select another provider. Only idle kernel agents warm, never tasks or tool-free completions. The warming input follows the normal transcript/render path; it does not replay a stored prompt snapshot or override account binding rules.

## Attempt trace effects

`InferenceExecutor.trace` accepts an optional semantic `AttemptTraceClient`; it never opens files or receives a filesystem directory. HTTP fetches open a fresh sink per fetch, then emit the raw request body, two newlines and raw response chunks in order. WebSocket attempts open once and emit the existing request/event framing, including malformed/binary wire events. Sink appends are awaited before response chunks advance, and cancellation still ends the response tee. File placement, truncation and best-effort append policy belong to the owner adapter.


## Compaction placement and last-resort route transitions

Group runtime readiness keeps local declaration/credential-shape errors distinct from typed `credentialLoginRequired` refresh refusal and names the member. A held account's already-recorded login refusal may be tolerated while validating all alternate local credentials for a last-resort handoff; a missing key or malformed alternate remains a configuration error. Group placement uses the same headroom scorer at create, Start over and compaction. The runtime excludes the refusing member only when its fixed deadline expires; capabilities and complete remain concrete with no provider fallback.




An unexpected OIDC signer failure resolves to `InferenceError.oidcSigningFailed(provider:)`, naming the configured provider without carrying the signer's diagnostic/private material. Cancellation and typed configuration hints retain their existing cases. No OIDC failure resolves stored credentials or another provider.

## Catalog failure isolation

Only unreadable JSON or a non-object top level rejects an entire model or group document. Malformed declarations retain entry-local typed errors; semantic checks run at use through `validate` and `validateGroup`. A bad provider or group never prevents an unrelated target from resolving. `ProviderCatalog.providerErrors`, `groupErrors` and `groupMemberErrors` report declaration and use-time validation failures without resolving credentials. Typed encoding refuses malformed provider declarations rather than silently deleting them; settings writes and additive CLI updates preserve the original JSON bytes/values without re-encoding a typed document.
