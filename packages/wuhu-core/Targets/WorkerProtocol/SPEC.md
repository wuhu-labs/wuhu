# WorkerProtocol

Execution ABI 1 is independent of the diagnostic release string. `WorkerHello` negotiates ABI 1 and the intersection of capability names; both peers' required capabilities must be in that intersection. Unknown additive capabilities are ignored unless required. `WorkerClient.requireCapability` checks the negotiated intersection and throws typed `notNegotiated` or `missingCapability` before an adapter can send a capability-dependent effect. A successful agreement is immutable for an endpoint incarnation. No ABI intersection or missing capabilities is a typed refusal, never an in-process fallback.

`WorkerCall` explicitly carries `abi`, `id`, `operation`, `payload` and optional `traceContext`; `WorkerReply` carries `abi`, matching `id`, and exactly one of `result` or `error`. Operation names are stable protocol names, not serialized Swift enum cases. Domain payload codecs and their authorized dispatch belong to the owner adapter. The token admits one worker incarnation to one parent-bound endpoint; the caller cannot pick an arbitrary space through an envelope. Parent composition owns tokens, endpoint routing and session placement.

The transport uses HTTP framing over a private Unix socket, not a network listener. `WorkerListener` requires an owner-owned, non-symlink mode-0700 containing directory. A pre-existing path must be an owner-private mode-0600 socket: a probe-connect that succeeds refuses replacement; only connection refusal proves it stale and permits unlinking the same inode/device before rebinding. Non-sockets, unsafe sockets and ambiguous probe failures are never removed. It sets the socket to 0600. The parent owns the listener lifetime and removes its socket at shutdown or after cancellation of `run()`, only while the path still names its bound inode/device. A replacement listener bound during the old listener's handler drain is not removed by the old listener's shutdown. `WorkerClient` is injected with separate control and byte-stream fetch clients; parent/worker composition must give these independent connection pools so a streaming body cannot exhaust the lifecycle/control pool.

`WorkerListener.adopt(_:socket:expecting:initiallyAccepting:handler:)` is an opt-in inherited-listener primitive, not a production restart trigger. It consumes the supplied descriptor on success or refusal, sets close-on-exec before validation, and serves only after matching the source's independently supplied `InheritedIdentity`: descriptor device/inode and pathname device/inode are separate identities (they differ on Linux); numeric metadata uses bit-preserving unsigned conversion, including Darwin’s negative socket device. Validation requires a listening Unix stream socket at exactly the expected path, in the same owner-private directory and mode-0600 socket policy as bind. A regular file, datagram, non-listening socket, changed descriptor, changed pathname inode, symlink, unsafe permissions or wrong path produces typed `invalidConfiguration` without unlinking or rebinding the path. Server startup failure is typed `unavailable`. `initiallyAccepting: false` installs the NIO accept gate before registration and returns an already-paused listener; queued connections remain in the kernel backlog until explicit `resumeAccepting()`. The default remains accepting. Adoption retains close-on-exec and does not leak into a further exec. An adopter initially has no pathname-cleanup ownership: pre-commit shutdown closes its descriptors without unlinking the shared pathname. Only a committed adopter has the same inode-guarded cleanup as bind. Source composition must capture both identities before exec; constructing the expectation from the inherited descriptor does not establish provenance. The adopter does not transfer credentials, enable crash adoption, change execution receipt identities or change default placement.

`pauseAccepting()` reversibly disables only new accepts, without closing, shutting down, unlinking or rebinding the listening socket. Connections arriving during the pause stay in the same kernel backlog (subject to ordinary backlog capacity); already accepted connections continue unaffected. After the pause completes, `exportListener()` returns an owned close-on-exec duplicate with the source-pinned descriptor and pathname identities. Its descriptor is borrowed: keep the export alive through spawn, map it only into the intended child, and never clear the source's close-on-exec flag or consume/close that borrowed descriptor. The four public identity numbers are available for independent out-of-band transport. Export refuses outside the paused state or after pathname replacement. Bind and adoption retain one extra close-on-exec listener duplicate for safe export without racing NIO's descriptor closure/reuse; each export owns its own additional duplicate and closes it on release.

A pre-commit failure first shuts down the non-owning successor, then rolls back with `resumeAccepting()`: the source reclaims normal cleanup ownership and serves queued and new connections through its original handler and pathname. Export leaves cleanup with the source's handoff coordinator, not the adopter. If the source shuts down with an export pending, it preserves the pathname rather than unlinking under a possibly live successor. Only after the successor has adopted and passed readiness may composition call `finishHandoff()`, which permanently stops the paused source, relinquishes cleanup and returns a noncopyable `CleanupOwnership` capability. The ready successor consumes that capability with `commitHandoff(_:)`, validating both descriptor and pathname identities before taking cleanup ownership. Commit does not alter acceptance. A stopped, already-owning or mismatched successor refuses the consumed capability. For separate images, transport the returned capability's socket and identity over the trusted handoff channel and reconstruct it only on that authority; the numeric metadata is not a secret or an authentication mechanism, and deriving a commit from the inherited descriptor does not establish authority.

If the capability is lost in transit, or the source stops with a pending export before emitting a capability, neither stopped source nor uncommitted successor unlinks the shared path. This deliberate pathname leak is the accepted failure mode: removing a live successor's endpoint is worse. A new bind refuses while the listener is still live; after all inherited/export descriptors close, the existing owner-private stale-socket probe and inode guard safely reclaim the path. Composition must close abandoned exports and shut down failed adopters before rollback. An export remains pending until source resume, finish or shutdown, even if its handle is released earlier.

Transitions in progress, repeated pause/resume, export without ownership, and transitions after stop refuse with typed `invalidConfiguration`; transport failures are typed `unavailable`. Binding uses the already-bound adoption path but claims initial cleanup ownership before returning, so NIO never performs an unconditional Unix-path unlink behind this ownership boundary. These are explicit listener primitives only: there is no production trigger, credential transfer, crash adoption or placement-default change, and caller composition must prevent competing source/successor acceptors. Listener retirement retains the existing shutdown policy for established connections, not a new connection-draining guarantee.

The routes are POST `/worker/hello`, `/worker/call`, `/worker/upload` and `/worker/download`. All require the incarnation bearer token. Control bodies and replies are bounded at 1 MiB. Byte-stream metadata is a base64 ABI-1 call in `X-Wuhu-Worker-Stream`, bounded at 12 KiB decoded. Byte responses correlate via `X-Wuhu-Worker-ABI` and `X-Wuhu-Worker-Call`. Body chunks are streamed using Fetch/Serve flow control; request-body watermarks are 64/16 KiB. Each transfer has its own HTTP connection while active and closes on completion. Upload dispatch consumes its request stream before returning an empty acknowledgement with explicit Content-Length: 0; download requests have no upload body, and return a lazy response stream. Finite downloads declare their known Content-Length, including zero; unknown-length streams retain chunked framing. Full-duplex request-to-response body forwarding is not supported: use independent upload and download transfers. Transfer dispatch must not collect an unbounded body or hold a database transaction during consumption. EOF is normal completion; transport loss fails the stream and cancellation propagates through the Fetch body lifecycle. Error replies before streaming are typed JSON and close the connection without draining an unread request body. Peer disconnect cancels an idle server-side producer; errors while consuming a client response body map to `unavailable`, while task cancellation preserves `CancellationError`. Ordinary disconnect is `unavailable`. The optional continuity negotiation below permits a runtime to resume retained owner calls; this target never blindly resubmits effects or adopts execution by itself.

An endpoint may be composed with an admission closure that surrounds its entire handler, before authentication, body decoding, hello negotiation or credential mutation. Admission refusals use the same typed HTTP error response and connection-close contract as route refusals. The default closure admits requests unchanged.

The request handlers may execute concurrently. Hello must finish before the first effect. An incompatible repeat hello cannot replace an existing agreement. Errors in operation dispatch become correlated `WorkerProtocolError` replies with static diagnostics for unclassified internal failures. A capacity refusal for an oversized result is also correlated. Body size violations are `capacityExceeded` and malformed JSON is `invalidMessage`; cancellation propagates as cancellation rather than a remote failure reply. Authentication, malformed metadata, negotiation and route failures use an uncorrelated HTTP error response. Release strings never participate in negotiation.

`traceContext` is additive diagnostic metadata: trace/span ids and session/group ids only. It is captured when constructing a call and restored task-locally around admitted control/upload/download dispatch. It never grants authority or changes effect routing. Older calls without the field decode as untraced; no span payloads travel through this field.

## Retained-call negotiation

The optional `owner.continuity.v1` capability adds an endpoint journal UUID to hello and an optional `WorkerReceipt` (endpoint UUID, client UUID, monotonically increasing positive sequence) to calls. A client allocates at most 1024 unacknowledged calls and exposes their operation/identity/receipt metadata for inventory. Reconnect repeats hello with the original local capabilities and requires the same journal UUID; changed or missing identity is `unknownOutcome`, never permission to replay a possibly committed effect. Existing ABI-1 peers without this capability retain the original transport contract. Receipt sequencing, acknowledgement and effect execution are owned by the semantic adapter, not the HTTP transport.

A process supervisor closes its `WorkerClient` when the child is known dead or the incarnation is stopped. Closed clients refuse new admissions and reconnect with `unavailable`; retained callers terminate instead of waiting for a different child to assume an old journal. This is distinct from a temporary listener detach, which keeps the same client and journal open.

HTTP 5xx responses from a shutting-down listener are transport unavailability, not malformed semantic replies. Retained-call adapters may recover them only against the same journal identity; legacy calls gain no replay permission.

## Credential rotation

The optional `worker.credential-rotation.v1` capability adds POST `/worker/credentials/stage` and `/worker/credentials/confirm`. A `WorkerCredentials` actor can be shared by the endpoint and its reverse-direction client. Staging a successor switches outgoing authentication immediately and admits both credentials for at most ten monotonic seconds. Repeating the same stage is idempotent and never extends that deadline; a different overlapping successor is refused. Confirmation requires the successor credential and immediately revokes the predecessor. Without confirmation, the predecessor expires at the deadline while the successor remains valid. Staging and confirmation are idempotent after commitment, so a lost acknowledgement does not require re-enabling a predecessor.

Composition must durably record the pending successor in approved owner-private server state before staging either direction, arrange successor acceptance before switching reverse traffic, and finalize the stored credential only after successor-authenticated confirmation. Recovery uses the persisted successor, not a fresh grace window for the predecessor. These routes do not enable discovery or execution adoption, change receipt journal identities, or grant permission to replay effects. Runtime composition must explicitly opt in; ordinary token-based endpoints retain the original fixed-credential behavior unless the optional capability is negotiated.

A client does not automatically retry consumed request bodies. If an uncorrelated authentication refusal proves its outgoing credential changed since that request began, it reports `unavailable` rather than terminal `unauthorized`. This is a pre-admission transport refusal, not permission to replay effects against a different journal. Unknown tokens still receive `unauthorized`. Credentials use sensitive authorization headers and static errors; neither rotation request bodies nor credentials may be logged or put in tracing spans.


`WorkerCredentials(token:admission:)` optionally installs a synchronous sendable admission predicate, defaulting to allow. Server authentication consults it for each request, including body-consuming routes' final authentication recheck. A revoked bearer is unauthorized even if it is the current or pending successor credential; rotation cannot bypass the gate. Composition may retain only credential fingerprints for boot-time revocation, rather than storing another bearer copy. This predicate is inbound authentication policy, not an outgoing-token transformation or execution-adoption capability.

A same-process exec coordinator may instead authorize cleanup reconstruction from an independently validated private frame binding the unchanged parent PID/birth, source-pinned listener identities and exact configured space/worker inventory. Successful exec has destroyed the source image, so no source can call `finishHandoff()` or compete for cleanup. The trusted coordinator retains rollback descriptors until readiness and must never make this exception for another PID, arbitrary crash adoption or metadata derived from the inherited socket. This does not widen the listener primitive itself into a restart trigger.
